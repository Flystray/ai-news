Graphiti

When AI Agent can't remember when facts changed, it can't truly understand the world. Graphiti gives knowledge graphs a time dimension.

📌 项目背景

当前 AI Agent 面临一个根本性困境：传统记忆系统是静态的。无论是向量数据库做 RAG，还是 GraphRAG 做全局摘要，它们都把知识视为"一成不变的快照"。但现实世界并非如此——用户的偏好会改变，公司的架构会调整，股价会波动，政策会更新。

试想一个客服 Agent：用户上周说"我不喜欢短信通知"，这周却说"请用短信通知我"。传统 RAG 系统会同时检索到这两条矛盾信息，然后 Agent 就陷入了困惑。更糟糕的是，它完全不知道哪条是当前有效的。

Graphiti 正是为此而生。它由 Zep 团队开源（背后有 arXiv 论文 2501.13956 支撑），专门为 AI Agent 构建具有时间感知能力的知识图谱。与静态知识图谱不同，Graphiti 的 Context Graph 追踪事实随时间的演变，维护数据溯源，并在事实矛盾时自动失效旧信息——让 Agent 拥有"知道什么现在为真"的能力。

🚀 核心功能

1. 双时态模型（Bi-Temporal Model）

每条关系/事实边携带四个时间维度：

created_at系统摄入时间 valid_at事实生效时间 invalid_at事实失效时间 expired_at系统过期时间

知识图谱不只记录"什么为真"，更记录"从何时到何时为真"。这是从三维（实体-关系-实体）到四维（实体-关系-实体-时间）的升维。

2. 时序边失效机制（Temporal Edge Invalidation）

当新事实与旧事实矛盾时，系统不会删除旧数据，而是为旧边添加 invalid_at 时间戳标记其失效。检索时自动过滤掉已失效的边，确保 Agent 只看到当前有效的事实——永远不被矛盾信息困扰。

3. 多阶段数据处理管道

通过 add_episode() 添加数据时经历完整管道：

  • 提取：LLM 从文本识别实体和关系
  • 解析去重：全文检索+语义相似度+BFS 三路检索进行实体消歧
  • 矛盾检测：新旧事实冲突时触发时序边失效
  • 属性提取：根据自定义本体抽取属性值
  • 社区构建：Leiden 聚类算法生成社区摘要，提供全局视角

4. 混合检索系统

Graphiti.search() 融合四种检索策略：

  • 语义搜索：嵌入向量相似度
  • 关键词搜索：BM25 全文检索
  • 图遍历：BFS 从中心节点展开关联上下文
  • 重排序：RRF / Cross-Encoder / Graph Distance 三选一

5. 多提供商插件架构

数据库支持 Neo4j / FalkorDB / Kuzu / Amazon Neptune；LLM 支持 OpenAI / Anthropic / Gemini / Groq；嵌入支持 Voyage AI / Sentence Transformers / OpenAI——全部通过抽象基类解耦，切换只需改配置。

6. MCP Server + REST API + Docker

提供 MCP Server（SSE 传输，8000 端口）可直接接入 Cursor/Claude Code 等 AI 工具，REST API 便于外部服务调用，Docker 容器化一键部署。

7. 自定义本体与实体类型

支持预定义本体（Prescribed Ontologies）和学习型本体（Learned Ontologies）双模式。可定义结构化实体（如 Podcast、Person、Event）和语义关系（如 BELONGS_TO、MENTIONS），让图谱适应你的领域。

⚙️ 技术亮点

1. 双时态模型——知识图谱的"4D 升维"

传统知识图谱只回答"实体 A 和实体 B 是什么关系"，Graphiti 还能回答"这个关系从何时到何时成立"。在 DMR（Deep Memory Retrieval）基准测试中，Zep/Graphiti 达到 94.8% 准确率（标准），使用 GPT-4o Mini 时更是创下 98.2% SOTA。

2. 三路混合实体消歧——解决"同名不同物"

实体去重是知识图谱构建的著名难题。Graphiti 创新性地使用全文检索 + 语义相似度 + BFS 图遍历三路检索候选实体，再由 LLM 判断是否为同一实体。这种"检索+推理"的混合方案，比纯向量匹配的准确率显著更高。

3. Leiden 社区检测——从局部到全局的认知跃迁

借鉴微软 GraphRAG 的思路，用 Leiden 聚类算法将相同主题的实体聚类为社区，生成社区摘要和嵌入。让 Agent 不仅能在局部做精确检索，还能在全局层面理解知识结构——从"见树木"到"见森林"。

⚡ 快速上手

# 1. 安装 Graphiti
pip install graphiti-core

# 2. 启动 Neo4j（Docker 一键启动）
docker run -d --name neo4j \
  -p 7474:7474 -p 7687:7687 \
  -e NEO4J_AUTH=neo4j/yourpassword \
  neo4j:latest

# 3. Python 使用
from graphiti_core import Graphiti
graphiti = Graphiti(uri="bolt://localhost:7687",
                    user="neo4j", password="yourpassword")

# 添加数据（自动提取实体、关系、检测矛盾）
await graphiti.add_episode(
    name="user_conversation",
    episode_body="小明说他现在更喜欢用 Python 写代码"
)

# 搜索当前有效事实
results = await graphiti.search(
    query="小明喜欢什么编程语言"
)

# 4. MCP Server 模式（接入 Cursor/Claude Code）
python graphiti_mcp_server.py  # SSE 传输，默认 8000 端口

⚠️ 使用注意

LLM 调用成本高：实体提取、去重、属性抽取全流程依赖 LLM，构建大规模图谱的 Token 消耗不低，建议先用小数据集验证本体设计。
  • Pydantic 强绑定：自定义实体/关系后必须同步修改 Prompt，否则 LLM 输出格式无法通过校验——新手最常见的坑
  • 社区版已弃用：Zep Cloud Community Edition 于 2025 年 4 月弃用，自托管需直接使用 Graphiti + Neo4j/FalkorDB
  • 领域本体设计至关重要：通用提取往往不够深入，领域专家参与定义本体结构是保证图谱精度的关键
