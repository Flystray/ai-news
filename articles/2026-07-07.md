# LeanCTX：AI Agent 的上下文智能层，一个 Rust 二进制省下 60-90% Token

> 📅 2026-07-07 | ⭐ 3,121+ | 🍴 293+ | 🔧 Rust | 🔗 [GitHub](https://github.com/yvgude/lean-ctx) | [官网](https://leanctx.com) | [DeepWiki](https://deepwiki.com/yvgude/lean-ctx)

## 项目背景

2026 年的 AI Agent 生态有一个被反复讨论但很少被真正解决的问题：**上下文膨胀**。一个典型的 Claude Code 会话，光 `git status` 就吃掉 ~800 tokens，重复读同一个文件每次 ~2000 tokens，完整对话历史在每一轮都被重新发送。当 Agent 从"跑一个 Demo"变成"连续工作 8 小时"时，Token 消耗不是线性增长，而是指数级膨胀——开发者为噪音和冗余买单。

**LeanCTX**（Lean Context）正是针对这个痛点设计的。它由开发者 yvgude 开源，定位是 **AI Agent 的上下文智能层（Context Intelligence Layer）**——一个本地 Rust 二进制，插在 Agent 和你的代码/Shell/数据之间，负责**决定 Agent 读什么、压缩 Agent 发什么、记住 Agent 学过什么、保护 Agent 碰什么**。项目创建于 2026 年 3 月，目前 GitHub 收获 **3,121+ Stars**，最新提交就在今天（2026-07-07），活跃度极高。

项目的核心宣言很直白：*"Control what your AI can see."* 官方实测数据是 **60-90% 的 Token 削减**，冷启动场景最高可达 99%。

## 核心功能

### 1. 四层压缩引擎（Terse Engine）

LeanCTX 的核心是一个 **4 层压缩流水线**，从原始文件/Shell 输出到最终送入模型的上下文块，层层提纯：

- **第 1 层 · 确定性过滤**：剥离 badge、空行、注释、重复分隔符等纯噪音
- **第 2 层 · AST 骨骼提取**：用 tree-sitter 解析 **18 种语言**的语法树，只保留类签名、方法签名、类型定义，丢弃实现体
- **第 3 层 · 自适应密度调节**：语义路由器（Semantic Router）根据每次读取的上下文动态选择压缩级别——10 种读取模式（`map`、`signatures`、`entropy` 等），从"只看目录结构"到"完整源码"自动切换
- **第 4 层 · Agent 成型（Agent Shaping）**：根据目标 Agent 的特性（Claude Code 偏好结构化 JSON，Cursor 偏好代码块）重新格式化输出

最巧妙的是**语义路由器的自适应学习**：它内置了一个基于 **Thompson Sampling 多臂赌博机**的 `ModePredictor`，会根据历史压缩效果自动学习每种读取场景的最优压缩阈值。换句话说，系统越用越聪明。

### 2. 上下文连续性协议（CCP）

AI Agent 最让人头疼的问题之一是**会话失忆**——每次新开聊天，之前的上下文全部丢失。LeanCTX 的 **Context Continuity Protocol（CCP）** 解决了这个问题：

- **跨会话记忆**：自动持久化任务（Tasks）、发现（Findings）、决策（Decisions）三类上下文
- **冷启动优化**：新会话启动时，只需从 CCP 索引中恢复关键上下文，而非重新读取所有文件——官方称冷启动 Token 可降低 **99%**
- **属性图（Property Graph）**：维护代码实体之间的关系（调用链、依赖关系、继承层次），Agent 通过 `ctx_graph` 工具一次性获取结构化关系，而非逐个文件试探

### 3. Token Dense Dialect（TDD）

这是一个非常工程化的创新：LeanCTX 定义了一套**数学符号速记法**，用 `λ` 替代 `function`、`§` 替代 `section`、`∂` 替代 `partial`、`τ` 替代 `type`，把代码签名压缩到极致。官方实测可在压缩基础上再节省 **8-25%** 的 Token。虽然可读性有所下降，但模型理解能力不受影响——LLM 本身就对数学符号有天然的语义理解。

### 4. Cognition v2：仿人类认知的上下文召回

这是 LeanCTX 最有"研究味"的功能。它不满足于简单的 LRU 缓存，而是引入了两个认知科学模型：

- **艾宾浩斯遗忘曲线**：上下文条目的保留概率随时间衰减，但每次被"命中"（Agent 再次访问）会增强稳定性（`base_stability_days` 可配置）
- **赫布 eviction（Hebbian Eviction）**：经常一起被访问的上下文条目会形成"关联簇"，当容量超限时，优先驱逐孤立条目而非活跃簇

这让 Agent 的上下文管理从"先进先出"进化到"像人一样记住重要的、忘记无关的"。

### 5. 77+ MCP 工具生态

LeanCTX 作为 MCP Server 运行时，暴露 **77+ 个工具**供 Agent 调用，核心包括：

| 工具类别 | 代表工具 | 作用 |
|----------|----------|------|
| 上下文读取 | `ctx_read`、`ctx_map`、`ctx_signatures` | 按需读取文件，支持 10 种密度模式 |
| 图谱探索 | `ctx_graph`、`ctx_knowledge` | 查询代码关系图、知识库 |
| 会话管理 | `ctx_session`、`ctx_remember` | 持久化/恢复会话上下文 |
| 安全控制 | `ctx_guard`、`ctx_audit` | 路径边界检查、操作审计 |
| 压缩代理 | `ctx_compress`、`ctx_budget` | 手动压缩、Token 预算控制 |

支持 **30+ AI Agent**，包括 Claude Code、Cursor、Windsurf、Copilot、Gemini CLI、OpenCode 等，一行 `lean-ctx setup` 自动完成集成。

### 6. Shell Hook：95+ CLI 工具透明压缩

LeanCTX 不只服务 AI Agent，还能直接嵌入开发者工作流。通过全局 Shell Hook，它会自动拦截 `git`、`docker`、`cargo`、`npm` 等 **95+ 命令行工具**的输出并压缩后再展示。例如 `git status` 的输出从 ~800 tokens 压缩到 ~120 tokens，重复读文件从 ~2000 tokens 降到 ~13 tokens（命中 SessionCache 时）。

### 7. 安全护栏：从路径监狱到 Lean4 形式化验证

LeanCTX 在安全层面下了很大功夫：

- **路径监狱（Path Jail）**：Agent 的文件访问被限制在白名单目录内，`lean-ctx secure` 启用严格模式，`lean-ctx yolo` 放松
- **密钥防御**：自动检测并脱敏 `.env`、API Key 等敏感信息，防止 Agent 误读后发送给模型
- **Lean4 形式化验证**：核心安全属性通过 Lean4 定理证明器做了形式化验证——这在开源 AI 工具中极为罕见

## 技术亮点

### 单 Rust 二进制，本地优先

整个系统编译成一个 Rust 二进制文件，无需 Node.js/Python 运行时，无需外部服务。所有压缩、缓存、记忆都在本地完成，代码不会离开你的机器。这对于企业内部部署和隐私敏感场景来说是硬性需求。

### SessionCache：13 Token 重新读取

当 Agent 第二次读取同一个文件时，LeanCTX 不再从磁盘加载并重新压缩，而是直接从 SessionCache 返回一个极简指纹——**约 13 tokens**（相比首次读取的 ~2000 tokens）。缓存键基于文件路径 + 内容哈希，文件修改后自动失效。

### 实时仪表盘 + Token 预算控制

LeanCTX 提供实时上下文使用仪表盘，开发者可以看到每个 Agent 会话的 Token 消耗分布：哪些文件最贵、哪些工具调用最频繁、压缩率是多少。同时支持 Token 预算控制——设定上限后，超出预算时自动降级压缩级别。

### 可配置的认知模型

通过 `~/.lean-ctx/config.toml`，开发者可以调整认知参数：

```toml
[cognition]
forgetting_model = "ebbinghaus"  # 或 "linear"
base_stability_days = 7          # 记忆基础稳定性

[security]
mode = "enforce"                 # enforce / warn / off
```

## 快速上手

```bash
# 1. 安装（npm 全局安装，自动下载对应平台二进制）
npm install -g lean-ctx-bin

# 2. 一键集成（自动检测已安装的 AI Agent 并配置）
lean-ctx setup

# 3. 或指定特定 Agent
lean-ctx init --agent claude-code
lean-ctx init --agent cursor
lean-ctx init --agent gemini-cli

# 4. 启动 MCP Server（供 Agent 通过 MCP 协议调用）
lean-ctx mcp serve

# 5. 查看实时仪表盘
lean-ctx dashboard
```

### 手动集成 Claude Code

在 Claude Code 的 MCP 配置中添加：

```json
{
  "mcpServers": {
    "lean-ctx": {
      "command": "lean-ctx",
      "args": ["mcp", "serve"]
    }
  }
}
```

## 总结

LeanCTX 抓住了一个被多数 AI 工具忽视但实际成本巨大的问题——上下文膨胀。它没有用"更聪明的模型"来绕过问题，而是用工程手段正面解决：tree-sitter AST 提取代码骨骼、Thompson Sampling 自适应压缩、艾宾浩斯曲线管理记忆、Lean4 验证安全属性。这些技术选型显示出作者对"上下文工程"这一新兴领域的深入思考。

对于每天和 Claude Code、Cursor 打交道的开发者来说，LeanCTX 的价值是直接的——省 Token、省钱、省等待时间。对于 Agent 平台构建者来说，它的 4 层压缩流水线和 CCP 协议提供了可复用的架构蓝本。而对于研究"如何让 AI 更高效地使用有限上下文"的学术工作者，LeanCTX 的认知模型集成是一个值得关注的工程实践案例。
