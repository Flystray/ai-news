奥赛推理 强化学习 测试时扩展 数学推理

这篇论文在说什么？

数学奥赛金牌——IMO（国际数学奥林匹克）最高奖，通常只有全球最顶尖的高中生花数年时间精心准备才能拿到。但现在，一个 30B 参数的模型，在 200 步强化学习之后，在 IMO 2025 和 USAMO 2026 上都达到了金牌分数线。

这篇论文来自上海人工智能实验室、港中文、清华、上交、北大等机构，发布了一个叫 SU-01 的模型。他们的核心发现很反直觉：把模型变强的关键，不在于更大的规模或更多的数据，而在于训练顺序——先让模型死磕最难的题，再慢慢过渡到简单题。

他们管这个叫"反向困惑度课程"（Reverse-Perplexity Curriculum）。配合两阶段强化学习和测试时扩展，一个 30B-A3B 的"小"模型，就能和几千亿参数的系统同台竞技。

图源：原文 Fig.2 — SU-01 训练和推理流程总览

为什么要关注？

推理模型在过去两年突飞猛进。从 GPT-4o 到 o1，再到 o3，各大厂商都在竞争"谁能把数学题做对"。但主流方案普遍存在两个问题：

问题一：太依赖外部工具。 很多推理系统靠 Python 代码执行、形式化验证器、甚至专门的符号求解器——这些本质上是在"作弊"，把模型做不了的部分外包给了外部系统。真正意义上"自己推理"的模型其实很少。
问题二：规模大到离谱。 AlphaProof 用了上千万条形式化证明数据、几千步强化学习，才能达到金牌水平。普通研究者根本复现不了。

SU-01 想回答一个问题：能不能用更小的规模、更少的数据、更简单的 pipeline，做到同样甚至更好的效果？

答案是能。他们的整个训练 pipeline 大概是：

  • 340K 条 SFT 轨迹（全部小于 8K tokens）
  • 200 步强化学习
  • 无需外部验证器或代码执行
  • 就能稳定推理超过 100K tokens 的超长轨迹

图源：原文 Fig.4 — 训练各阶段性能进展曲线

核心方法

关键思路

整个方案分三步，听起来简单，做起来很讲究。

第一步：反向困惑度课程 SFT。

常规做法是按难度从低到高喂数据——先做简单题再做难题。这相当于考试时先让学生拿满分建立信心。

但 SU-01 偏偏反过来：先喂高困惑度（难）的样本，再逐步过渡到低困惑度（简单）的样本。

"This order repeatedly starts each pass from teacher trajectories that are most mismatched with the current policy, providing the strongest learning signal."
— 原文

说白了：模型每次训练周期开始时，都从"老师最会但学生最不会"的地方重新出发。这个信号最强，梯度最陡，模型学得最快。

实验也验证了这个设计的价值。用同样的数据、不同的排序方式，反向困惑度排序在 ProofBench-Advanced 上比随机排序提升了 8.3 个百分点。

第二步：两阶段强化学习。

SFT 注入能力，RL 放大能力。但他们没有一股脑全扔进去 RL，而是分了两个阶段：

  • 粗粒度 RL（Coarse RL）：用可验证奖励（答案对不对），训练模型的基本搜索和自我检查能力。数据量大（8967 个可验证提示），训练 96 步。
  • 精细 RL（Refined RL）：切换到证明级生成奖励——不是只判断答案对错，还要评估证明过程的严谨性。同时引入自我改进机制和经验回放。训练 104 步。

这个两阶段设计解决了一个实际问题：证明级别的奖励信号很难获取，直接从零训练 RL 很容易崩溃。 先用粗粒度 RL 打好基础，再精细化调整，成功率更高。

第三步：测试时扩展（TTS）。

这是最后一步，也是在 IMO/USAMO 上把分数从 21 分拉到 35 分的关键。

流程很简单：生成 → 验证 → 批评 → 改进 → 循环，直到通过验证或超出预算。

测试时一个题可以生成超过 100K tokens 的推理轨迹，中间的验证和修正循环是模型自己驱动的，不需要外部工具。

和其他方案比有什么不同？

方案参数量数据量外部工具TTSIMO金牌
AlphaProof极大（未公开）数千万形式化证明需要形式化验证器无是
o3（高计算版）极大未公开不确定是是
SU-0130B-A3B340K轨迹不需要是是

最大的差异在于：SU-01 不依赖任何外部工具或形式化验证器。 它的证明评估完全依赖模型自身的判断能力。这意味着部署门槛大幅降低，也意味着它能在更广泛的任务上工作——因为现实世界中的大多数问题没有"标准答案验证器"。

另一个关键差异是训练效率。200 步 RL、340K 条轨迹，这个量级在学术界是可复现的。不需要数千 GPU 小时，不需要自研的 AlphaCode 级别的数据生成流水线。

对开发者意味着什么？

可以直接试了。 模型已经开源在 HuggingFace：Simplified-Reasoning/SU-01，Apache-2.0 许可证。

规模友好。 30B-A3B 对应的是活跃参数（experts 路由后每次只激活 3B 参数），大多数 8×A100 的机器能跑起来。这比动辄几百 B 的大模型亲民得多。

三阶段训练流程有参考价值。 即使你不做奥赛推理，反向困惑度课程 + 两阶段 RL 的设计思路，完全可以用在别的地方。核心洞察是：让模型先直面最难的样本，比从简单到复杂更高效。

测试时扩展值得关注。 SU-01 + TTS 把 IMO 分数从 21 拉到 35——同样的模型，不同的推理预算，差距是 14 分。如果你有场景需要模型在复杂问题上少出错，可以考虑在推理阶段加入验证-修正循环。

不过也要清醒一点。 IMO P6（最难的压轴题）始终是 0 分，连 TTS 都救不了。这说明当前模型对"需要原创性洞察"的问题，依然有天花板。
