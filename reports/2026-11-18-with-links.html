别让 AI 摘要论文，TextFold 把原文折成五层地图

摘要工具都在比谁概括得更短，TextFold 反着做：不写摘要，把原文「折」起来。同一篇论文有五档详细程度，从章节主题地图一路展开到每个字，中间档直接用作者的原句，不换一个词。更反直觉的是，它连 AI 助手的回复也照折不误——在 Claude Code 里按一个数字键，长回复就从整段文字缩到一句话，而且不花一个额外 token。

数据来源：仓库 README 与官方格式文档 + 第三方评测（heatdrop.ai、findarepo、aiboss88 等，截至 2026-11-18）

项目背景：摘要省掉的，往往正是你要找的

用 AI 读论文的流程已经高度同质化：丢进去，吐出一段 200 字总结，遇到不清楚的地方再追问。问题出在两头。

一头是信任。摘要把推导链、实验条件、负结论这些「不性感但关键」的内容压没了，你不知道模型删了什么、凭什么删。想回原文核对，得在 20 页 PDF 里重新定位那一段——定位的成本常常比重读一遍还高。中文技术社区对这个痛点的讨论很直接：「论文太长，直接让 AI 总结，又怕它把关键的推导和条件省掉」（一起港湾论坛）。

另一头是上下文经济学。agent 读长文档时，要么整篇塞进上下文烧 token，要么用一段摘要做决策——后者等于把判断权交给一次有损压缩。以一篇 30 页的系统论文为例，整文进上下文动辄数万 token，而它的章节地图只有几百个词；多数任务其实只需要其中两三节，但「哪两三节」这个判断，摘要本身给不了。第三方评测 heatdrop.ai 的判断是：TextFold 的语义缩放阅读体验「确实不一样」，但如果你只读短文档，它就是「为不存在的问题准备的一堆机器」。这句话反过来也成立：只要你的日常是长文档——论文、报告、agent 的长回复——折叠比摘要更适合当默认阅读态。

star 曲线支持这个判断。findarepo 用自己的快照实测：33 天里从 164 颗星涨到约 1,200，近 7 天净增 183，星标可信度检查通过（无刷星迹象）。

核心功能

1. 五级折叠：每一级都交代自己从哪来

一篇文档折成五级，逐级放大：

级名称每段变成
5Topic几个词，全文变成章节卡片地图
4Takeaway一句话，说清这一节确立了什么
3Key论点加一句理由
2Brief1–3 句作者原话，逐字保留
1Full原文本身

关键设计在 2 级和 3 级之间：Brief 以下是作者的话，Key 以上是模型的话，而模型写的每一行都锚定到它依据的 Brief 句子上。放大到 Key 级，读到的每个论点都能展开成作者的原句。缩放是连续的——留下的词滑到新位置，其余的淡出，你可以停在任何中间状态，或者只展开某一段。高亮和页边笔记跟着缩放走：你在 Full 级划的重点，缩到 Takeaway 级还在原地。

2. 折叠 agent 的回复，零额外成本

Claude Code 装上插件后，每条回复上方出现级别行，按 1 到 5 切换：5 是一句话结论，3 是每段的论点，1 是原文。这里的折叠不走第二次模型调用——TextFold 让模型「结论先行」，每段的关键句放前面，折叠只是把后面的内容收起来，所以不花 token、不花时间，且任何级别下读到的都是模型的原话。短回复（80 词以内）保持原样不折，避免为了折而折。Pi 编辑器有对应的扩展，连思考过程也能折——一段长编码回合的推理链可以缩到几行，会话恢复后级别设置保留。

3. 给 agent 的取文口：先看地图，再决定烧多少上下文

python3 -m textfold get https://arxiv.org/abs/2512.23916        # 最粗一级：每节的 topic
python3 -m textfold get 2512.23916 --level key --section 3      # 第 3 节的论点与理由
python3 -m textfold get report.pdf --json                       # 完整折叠文档

agent 先拿到 topic 地图，判断哪一节相关，再按级展开——上下文消耗从「整篇文档」变成「地图 + 相关节」。尚未折叠的文档会先用你接入的模型折叠，之后走本地缓存，不再调模型。

4. 入口近乎全覆盖

粘贴链接支持 arXiv、PubMed Central、bioRxiv、medRxiv、Wikipedia、GitHub README；拖文件支持 PDF、Word、PPT、Excel、EPUB、CSV、图片、Markdown。浏览器扩展（Chrome/Edge/Brave）一键把当前页面——包括登录态、付费墙内、脚本渲染的内容——送进 TextFold，文章识别逻辑与浏览器阅读视图同源。Zotero 7 用户可以直读本机文献库，不走任何云端账号；Obsidian 有社区插件 TextFold Bridge，笔记可以互相引用到具体段落。

5. 边读边问，答案自带证据链

选中一段向 AI 提问，回答按「短答在前、每条要点链接到它依据的段落」的结构给出；勾选联网查证时，本机 agent 会搜索网页并把引用来源列出来。问题默认以全文为上下文作答，而不是只检索相似段落，这对「答案在论文另一头」的场景很关键。

技术亮点

1. 锚定契约：两种文本永不混合

TextFold 定义了一个开放格式（textfold/doc，目前 version 0），核心条款只有两条：full 和 brief 是作者的话，逐字不改；key、takeaway、topic 是模型写的，每行必须带 evidence 字段，指向它在 full 里依据的句子。连最粗的 topic 也不是自由发挥——它是从 takeaway 里逐字复制的名词短语。这份契约让任何程序都能验证：哪一行是 AI 写的，它基于哪几句话。折叠文档还带机器可读的 provenance 字段（模型名、生成时间），对应欧盟 AI 法案第 50(2) 条的 AI 生成内容标注要求——在一个阅读工具里做到这一步，少见。

2. 「折叠」与「摘要」的成本结构完全不同

摘要的代价每次都要付：新文档、新追问、新摘要，token 重复燃烧，且每次结果可能不同。折叠是一次性投资：五个级别写好后存进本地库，缩放、检索、问答都在缓存上进行，GET /api/doc/<id> 可以在不调模型的情况下取任何一级。两种成本结构在 agent 场景里差距更大——同一个文档被多个任务反复引用时，摘要方案每次都要重新压缩并承担新的信息损失，折叠方案只折叠一次，所有引用共享同一套锚点，检查器还能机器化地核对「这行 AI 结论依据的是哪几句原文」。代码结构也支撑这套机制——55 个 Python 模块里有专门的 ladder.py（级别阶梯）、semantic.py、record.py，解析管线覆盖 JATS、PDF、Office、Wikipedia 等格式，公式用 KaTeX 按 LaTeX 的 Latin Modern 字体排版。

3. 集成密度是护城河

从 trafilatura（网页正文抽取）到 MinerU（扫描 PDF 引擎，可选装）再到 PDFium（图片裁切），TextFold 把一整条文档解析管线包进了一个本地应用，又同时接住 Claude Code、Pi、Zotero、Obsidian、WebMCP 五个生态。单作者加上 27 位贡献者在 45 天里做到这个完成度，节奏接近每日一个 release。

局限

  1. 折叠质量没有基准。 AI 写的三个级别靠模型自觉，项目未提供任何准确率或遗漏率评测，第三方也还没有系统实测「折叠是否丢关键信息」。「官方未说明」这不是一次性疏忽，而是这类产品的普遍空白。
  2. Brief 逐字不等于无损。 每段保留哪 1–3 句仍由模型挑选，选错句的风险存在，尤其推导密集的数学论文。
  3. 重依赖场景有额外成本。 扫描版 PDF 需要安装 MinerU 引擎（约 3.4GB 下载）；DOI 论文依赖 Europe PMC 有开放全文；ChatGPT 计划桥接需要 Node.js。
  4. 开发节奏爆发式。 findarepo 测得过去 26 周中仅 5 周有提交（不过最近 5 周连续），474 次提交高度集中在近一个多月，单作者主导，bus factor 为 1。
  5. 浏览器折叠仅支持 Chromium 系（Chrome/Edge/Brave），Firefox 不支持。
  6. 社区还太薄。 open issues 只有 9 个，HN 上没有独立讨论，长期维护意愿需要观察。

适用人群

  • 科研与医学文献重度读者：arXiv、PubMed Central 是一等公民，Zotero 直连、PDF 并排对照、笔记随缩放保留——每天读 5 篇以上论文的人省下的定位时间最可观。
  • agent 工程师：textfold get 的逐级供文模式可以直接接进 RAG 前置管线，让 agent 用几百 token 的地图决定是否展开全文。
  • AI 助手重度用户：Claude Code/Pi 插件把长回复变成可缩放的，5 键一按就是结论——对每天盯 agent 干活的人是刚需。
  • 非英语文献读者：逐句翻译且公式保持排版，原文的折叠级别按原文语言书写，不会被强制二次翻译。

快速上手

# Python 包方式（任意系统，Python 3.9+）
python3 -m pip install textfold
python3 -m textfold serve
# 打开 http://localhost:3017

# Claude Code 插件（需 Claude Code 2.1.287+）
claude plugin marketplace add chenxiachan/textfold
claude plugin install textfold@textfold

macOS/Windows 有打包好的桌面应用（含 Python 运行时，已签名公证）。首次启动会自动发现本机的 Claude Code、Codex、Pi；都没有的话，可以一键接入 OpenRouter 的免费模型，或在设置里填 API key（Anthropic、OpenAI、DeepSeek、Qwen、GLM、Kimi、Ollama 等）。常见坑：扫描版 PDF 别急着报错，先确认要不要装 3.4GB 的 MinerU 引擎；Windows 上 PDF 引擎安装位置可在设置里改到非 C 盘。

原文可溯性Brief 逐字保留，AI 行带 evidence 索引并排原文，人工对照多数不可溯源
agent 集成CLI、开放格式、Claude Code/Pi 插件无部分提供 API

表格后说句实话：TextFold 不是摘要工具的替代品——你需要快速知道「这篇讲什么」时，200 字摘要仍然更快，五级折叠的第一次生成也要等模型把各级写完。它的价值在第二步：确定相关之后，你不用从头再读，从地图直接放大到那一节，且放大路径上的每句话都能回溯到原文。这类「结构化阅读」和「翻译对照」也不是竞争关系，easyread 解决的是语言门槛，TextFold 解决的是信息密度门槛，长英文论文的读者可以两个都用。如果你的阅读工作流里没有「第二步」，装它纯属占硬盘。

写在最后

两点判断。第一，TextFold 把「AI 辅助阅读」的默认交互从「替你读」改成了「带你缩放」，锚定契约让 AI 的每句话都能摊开成作者的原话——这是把可验证性做进了产品结构，而不是留在提示词里。第二，五级地图 + textfold get 这条路子，给「agent 如何经济地读长文档」提供了一个可复用的答案：先地图、后展开、锚点回查。

具体建议：读论文的人先装桌面应用接 Zotero 试一周，重点感受「从地图直接放大到目标段落」和摘要后追问的效率差；搞 agent 的人直接看格式文档和 CLI，把逐级供文接进你现有的管线，先在「整文进上下文」和「地图 + 相关节」之间跑一组 token 消耗对比再决定是否常驻。项目 45 天涨了约 1,000 颗星，但单作者项目的风险模型要按「作者某天不维护了」来建——好在格式是开放且版本化的，你的折叠文档和笔记可以整体导出，锁定风险不大。
