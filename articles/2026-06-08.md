## 一、项目背景：Agent 时代的 token 困境

2026 年，AI 编程助手（Claude Code、Cursor、Codex）已成为开发者标配。但一个日益尖锐的问题浮出水面：**Agent 调用工具后返回的大量 JSON、检索到的 RAG chunks、数百行错误日志——这些内容在喂给 LLM 之前，到底需不需要全部发送？**

以 Claude Code 为例，一次典型的工具调用（文件搜索、代码分析）可能产生 **10,000+ token 的上下文**，其中 90% 是冗余的：JSON 里重复的字段名、日志里相同的模板前缀、代码文件里大段无关注释。这些内容不仅消耗 token 预算（直接转化为 API 账单），更占用宝贵的上下文窗口长度。

**Headroom 的解题思路**：在内容到达 LLM 之前，用一个独立的工程层对上下文进行智能压缩。它不是简单的截断，而是**理解内容类型后精准压缩**，并且——**压缩后的原文随时可以取回**。

## 二、核心功能（7 大模块）

### 1. 四合一接入形态

Headroom 提供四种接入方式，覆盖从个人用户到企业级集成的全场景：

| 接入形态 | 命令示例 | 代码改动 | 适用场景 |
|----------|----------|----------|----------|
| **Agent Wrap** | `headroom wrap claude` | 零 | 已有编码 Agent 的用户 |
| **透明代理** | `headroom proxy --port 8787` | 改环境变量即可 | 不想改业务代码 |
| **Library SDK** | `compress(messages)` | 1 行 import | 自研 AI 应用 |
| **MCP Server** | `headroom mcp install` | 配置文件 1 行 | Claude Desktop / Cursor 用户 |

### 2. 六大压缩算法

Headroom 不是"用一个 LLM 总结所有内容"，而是**对内容先分类后路由**，三路专用压缩器各司其职：

- **SmartCrusher（Rust 实现）**：专攻 JSON/结构化数据。识别字段名的统计模型、对数组做代表性采样、保留异常值和错误信息。JSON 压缩率可高达 **95%**。
- **CodeCompressor（AST 感知）**：基于 tree-sitter 解析抽象语法树，保留函数签名和控制流，删除注释和样板代码。支持 Python、JS、Go、Rust、Java、C++ 等语言。
- **Kompress-base（ML 文本压缩）**：自研 8B 参数模型，部署在 HuggingFace（`chopratejas/kompress-base`），基于海量 Agent 交互轨迹训练。专门处理自然语言文本和对话历史的"保意压缩"。

### 3. CCR 可逆压缩系统

这是 Headroom 最核心的设计哲学：**压缩 ≠ 删除**。

```
压缩时：原始内容 → 压缩版 + ref_id + 原文落盘本地
需要时：LLM 调用 headroom_retrieve(ref_id) → 取回原文（零成本磁盘读取）
```

与"调 LLM 再做一次总结展开"的本质区别：
- **信息精度**：原文一字不差 vs LLM 可能存在幻觉
- **展开成本**：本地磁盘读取（零 API 调用）vs 需要再调一次 LLM
- **延迟**：极低 vs 增加一次 LLM 调用延迟

### 4. CacheAligner：账单降幅远超 Token 降幅

这是 Headroom 最容易被忽视的"杀手锏"。

Anthropic 和 OpenAI 对 prompt 前缀做 KV cache——**相同前缀可复用已计算的 attention key/value，成本降低至 1/10**。任何对前缀的修改都会导致 cache 失效。

CacheAligner 做两件事：
1. **稳定前缀**：将 system prompt、工具定义等固定部分 hash 化，hash 相同则复用 cache slot
2. **延迟压缩**：只压缩真正变化的部分，cache 命中的部分原样保留

**实际效果**：即使 token 压缩了 90%，因 KV cache 持续命中，真实账单成本可降至 **1/20**。

### 5. 跨 Agent 共享记忆

同一项目里，Claude Code、Cursor、Codex 各自跑出来的关键决策和代码理解，去重后跨 Agent 共享。后续 Agent 可节省 **40-60%** 的初始扫描 token，换 Agent 不丢上下文。

### 6. `headroom learn`：自学习改进

扫描历史中失败的 session，自动将"哪条命令错了、为什么错"写进 `CLAUDE.md` 或 `AGENTS.md`，实现 **Agent 越用越聪明**的自动经验积累。

### 7. 图像压缩

支持多模态场景下的图像压缩，通过训练的 ML 路由器实现 **40-90%** 的图像 token 压缩，适用于包含截图、图表等视觉内容的 Agent 工作流。

## 三、技术亮点（3 大核心）

### 亮点一：ContentRouter 内容类型智能分发

Headroom 不是简单地对所有内容一视同仁，而是先做类型判断再路由：

| 内容类型 | 判断信号 | 路由目标 | 压缩策略 |
|----------|----------|----------|----------|
| JSON 数据 | `json.loads` 成功 + 顶层 3+ 键 | SmartCrusher | 字段名 hash + 冗余键裁剪 + 数组采样 |
| 源代码 | 文件扩展名 + shebang + 代码风格 | CodeCompressor | AST 解析 → 保留函数签名/控制流 |
| 自然语言 | 默认路由 | Kompress-base | ML 模型"保意压缩" |

**设计哲学**：不让 LLM 总结 JSON——规则压缩效率更高、更稳定、零幻觉风险。

### 亮点二：CCR 完整可逆架构

CCR（Compress-Cache-Retrieve）不是事后补救，而是从架构层面保障了**压缩永远是安全的**：

- 原文**永不删除**，存储在本地 CompressionStore
- 压缩后生成短哈希 ref_id，嵌入系统 prompt 中
- LLM 在检测到压缩可能导致错误时，可主动调用 `headroom_retrieve` 工具取回原始内容
- retrieve 是纯本地磁盘读取，不产生 API 调用成本

这使得 Headroom 可以在 **90%+ 压缩率**下仍然保持高可靠性，完美解决了"省钱但怕丢信息"的顾虑。

### 亮点三：Rust 核心 + TOIN 联邦学习

Headroom 的关键路径用 Rust 重写（SmartCrusher、Tokenizer、Relevance Engine），保证压缩延迟 **< 50ms**，不影响 Agent 响应速度。

同时，TOIN（Tool Intelligence Network）是一个**隐私保护的学习层**：
- 只存储工具输出结构的**哈希指纹**（不存储实际值）
- 跨会话学习哪些字段重要、哪些可压缩
- 通过联邦学习在用户间共享压缩模式，**不共享原始数据**

## 四、性能实测数据

### Token 压缩率

| 工作负载 | 压缩前 Token | 压缩后 Token | 节省比例 |
|----------|-------------|-------------|----------|
| 代码搜索（100 条结果） | 17,765 | 1,408 | **92%** |
| SRE 事故调试 | 65,694 | 5,118 | **92%** |
| 日志分析（演示案例） | 10,144 | 1,260 | **88%** |
| GitHub Issue 分类 | 54,174 | 14,761 | **73%** |
| 代码库探索 | 78,502 | 41,254 | **47%** |

**规律清晰**：结构化重复内容（JSON、日志、搜索结果）压缩率最高（88-92%），自由探索类任务相对较低（47%），但仍有可观节省。

### 准确性验证

| 基准测试 | 类别 | 基线 | Headroom | 差异 |
|----------|------|------|----------|------|
| GSM8K | 数学推理 | 0.870 | 0.870 | **±0.000（无损）** |
| TruthfulQA | 事实性 | 0.530 | 0.560 | **+0.030（提升）** |
| SQuAD v2 | 问答 | — | 97% | 压缩率 19% |
| BFCL | 工具调用 | — | 97% | 压缩率 32% |

**结论**：压缩后答案质量完全不变，数学推理 100% 无损，事实性问答甚至略有提升——因为压缩去除了干扰信息。

## 六、适用人群

### 🎯 强烈推荐

- **AI 编码助手重度用户**：每天使用 Claude Code / Cursor / Codex，单次任务消耗数万 token

## 七、快速上手（60 秒）

```bash
# 安装
pip install "headroom-ai[all]"    # Python 3.10+

# 方式一：包装现有编码 Agent（最简单）
headroom wrap claude              # 一条命令接入 Claude Code
headroom wrap codex               # 接入 OpenAI Codex
headroom wrap cursor              # 接入 Cursor

# 方式二：透明代理（零代码改动）
headroom proxy --port 8787
# 然后设置环境变量：OPENAI_BASE_URL=http://localhost:8787

# 方式三：嵌入代码（Python）
from headroom import compress
compressed = compress(messages, model="claude-3-sonnet")

# 查看节省效果
headroom perf
```

多 Agent 协作共享记忆：
```bash
headroom wrap claude --memory     # 启动时启用跨 Agent 记忆
headroom wrap codex --memory      # 复用 Claude 的缓存索引
```

## 八、总结

Headroom 不只是"省 token 的工具"，它的设计体现了对 Agent 时代工程问题的深刻理解：

1. **分层专用**：不同内容类型用不同压缩器，不走"LLM 统一处理"的省力捷径
2. **可逆保障**：CCR 架构确保压缩永远是安全的，不怕信息丢失
3. **Cache 协同**：CacheAligner 让 token 压缩和 KV cache 命中不是两个孤立优化，而是协同增效

在这个 Agent 调用越来越频繁、token 成本越来越高的 2026 年，Headroom 提供了一条**低成本、高质量、零风险**的上下文优化路径。它可以无缝接入 Claude Code、Cursor、Codex 等主流工具，也可以嵌入自研应用——无论你是个人开发者还是企业团队，都值得一试。
