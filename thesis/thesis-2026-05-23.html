这篇论文在说什么？

CMU 的团队做了一个很巧妙的事：他们把 Agent 的推理过程拆成了三个系统，让模型学会"什么时候该做规划、规划多远"，而不是像现在的主流方法那样无脑拉长推理链。

结果很惊人：30B 的模型，性能媲美 685B~1T 的超大模型，同时推理 token 消耗减少了 25.8%~95.3%。

核心是他们提出的 SR²AM（Self-Regulated Simulative Reasoning Agentic LLM）架构，把"要不要规划"、"规划多远"这个决策权交给了模型自己，通过强化学习训练出一个"配置器"来动态调节。

*图源：原文 Fig.1 — SR²AM 的三系统交互架构*

为什么要关注？

现在的 Agent 推理有个通病：训练时推理链越练越长，token 哗哗地消耗，但准确率并没有同比提升。

问题出在哪？现在的推理模型（比如 o1、DeepSeek-R1 这类）本质上是在做"无约束的思维链"——模型想推多久就推多久，没有任何机制来控制它"要不要规划"、"规划到什么深度"。

这就导致：

• 资源浪费：很多简单问题被过度推理

• 效率低下：推理 token 暴涨，成本飙升

• 不可控：你没法预测模型会"想"多久

"How should an agent decide when and how to plan? A dominant approach builds the agent as a reactive policy with adaptive computation (e.g., chain-of-thought reasoning), trained end-to-end with the expectation that planning will emerge implicitly from sufficient data and compute. Without control over the presence, structure, or horizon of planning, however, these systems typically increase reasoning length dramatically during training, leading to inefficient token consumption that does not reliably translate to accuracy gains."

— 论文原文，Abstract

这段话把问题说得很直白：我们指望规划能力从数据和算力中"自己长出来"，但实际上它没长好——反而学会了"想废话"。

核心方法

关键思路：三系统解耦

SR²AM 把 Agent 的推理过程拆成了三个系统，各司其职：

系统 职责 类比
System I（反应执行） 细粒度推理、直接执行动作 直觉反应，"看到什么就干什么"
System II（模拟推理） 用世界模型预测未来状态，做规划 深思熟虑，"如果我这样做，会发生什么"
System III（自调节） 决定"要不要规划"、"规划多远" 元认知，"现在情况复杂，需要想远一点"

这个设计最巧妙的地方在于 System III 的存在——之前的 Agent 系统要么永远在规划（慢但准），要么完全不规划（快但容易错），没有一个"动态调节"的机制。

*图源：原文 Fig.2 — v1.0 的计划重建流程*

技术细节：两阶段训练

SR²AM 有两个版本，训练方式略有不同：

v0.1（可行性验证）：先用多个独立的提示式模块组成多模块系统，让这个系统跑任务并记录决策轨迹，再用这些轨迹去微调一个 8B 的小模型。

v1.0（主要方法，可扩展）：收集预训练推理 LLM（DeepSeek-V3.2）的原始思考-行动轨迹，用标注 LLM 从轨迹中"重建"出结构化计划（当前状态 → 提议动作 → 预测未来状态），再把重建后的计划附加到原始思考内容上，先用监督学习（SFT），再用强化学习（RL）微调。

强化学习使用 GRPO（Group Relative Policy Optimization）算法，奖励由三部分组成：答案正确性、结构遵守、最终答案可提取性。每个提示采样多条轨迹，计算组归一化优势。

效果怎么样？

实验结果相当硬核，我直接上数据：

重点：SR²AM-v1.0-30B 只用了同级模型 4.7%~74.2% 的推理 token，就达到了差不多的性能。

这个消融实验说得很清楚：三个系统各司其职，缺了谁性能都掉。

*图源：原文 Fig.3 — RL 训练过程中，SR²AM 的 token 消耗增长温和，而无调节推理的 token 消耗飙升*

一个反直觉的发现：强化学习之后，模型的平均规划深度（horizon）增加了 22.8%，但规划频率只上升了 2.0%。意思是：模型学会了"规划得更远"而非"更频繁地规划"。这正是我们想要的——该深想的时候深想，不该想的时候别墨迹。

和其他方案比有什么不同？

最大的不同在于：SR²AM 把"要不要规划"这个决策本身也学到了模型参数里，而不是靠人工规则或外部编排器。

方案类型 代表方法 缺点
无约束思维链 o1、DeepSeek-R1 推理长度不可控，token 浪费严重
外部编排 Agent LangGraph、CrewAI 依赖外部逻辑，消耗上下文窗口
固定规划策略 某些 Agent 框架 不管什么任务都做同样深度的规划
SR²AM（本文） 自调节模拟推理 学会动态决策规划时机和深度

另外，这篇论文和前几天提到的 "Compiling Agentic Workflows into LLM Weights"（把工作流编译进模型权重）思路上有点像——都是让小模型通过微调获得原来需要外部编排或大模型才能做的事情。

对开发者意味着什么？

实用价值很高，几条具体建议：

1. 如果你在做 Agent 系统：别再无脑让模型"多想想"了，试试给模型一个"要不要规划"的选择权。这个思路可以用提示工程先试起来——在 prompt 里加一个"是否需要制定计划"的决策步骤。

2. 关注推理效率：现在很多团队在卷"推理深度"，但这篇论文告诉我们，规划时机的选择可能比"规划多深"更重要。省下来的 token 就是真金白银。

3. 代码已开源：github.com/sailing-lab/sr2am —— 虽然复现需要一定资源（30B 模型 + RL 训练），但思路可以直接借鉴。

4. 这个"三系统"框架有通用性：不只是 Agent 推理，任何需要"决策要不要多想一步"的场景都可以套用——比如 RAG 里决定"要不要多查一次"、代码生成里决定"要不要先写计划再写代码"。

"We argue that efficient agentic reasoning benefits from a decomposition of decision-making into three interacting systems: simulative reasoning (System II) that grounds deliberation in future-state prediction using a world model, self-regulation (System III) that decides when and how deeply the agent plans at each turn through a learned configurator, and reactive execution (System I) that handles fine-grained reasoning and action."

— 论文原文，Introduction 第3段

说的直白一点：把"想不想规划"这件事也交给模型自己判断，而不是靠人工规则定死。这个"元决策"能力，才是高效 Agent 推理的关键。
