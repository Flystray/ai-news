## 🎯 它是什么

herdr 是一个**专为 AI 编码代理设计的终端多路复用器（Agent Multiplexer）**。它由土耳其开发者 Oğulcan Çelik 全职开发，2026 年 3 月底开源后迅速蹿红——Hacker News 首页讨论获 287 分，GitHub Stars 以每周 4,500+ 的速度增长，目前已达 19.7k。

简单来说：如果你同时在终端里跑 Claude Code、OpenAI Codex、GitHub Copilot CLI 等多个 AI 代理，herdr 让你在一个终端里统一管理它们，并且**一眼看清每个 Agent 是在工作、被阻塞、已完成还是空闲**——这是 tmux 等传统终端复用器完全做不到的事。

## ✨ 核心功能

### 1. Agent 状态感知（Agent-Aware）
herdr 最大的创新是将 Agent 的语义状态可视化为四种信号：
- 🔴 **Blocked** — Agent 等待输入或权限确认
- 🟡 **Working** — Agent 正在 actively 处理任务
- 🔵 **Done** — 任务完成，结果待审阅
- 🟢 **Idle** — Agent 空闲等待新任务

传统 tmux 只能看到"窗格里有个进程在跑"，herdr 却能读懂这个进程在做什么。

### 2. 零配置检测，开箱即用
herdr 通过"**启发式检测 + Socket API 显式报告**"双重机制识别 Agent 状态：
- **启发式检测**：扫描进程名和终端输出，自动推断 Claude Code、Codex、Copilot CLI 等主流 Agent 的状态，无需任何配置
- **Socket API 钩子**：支持的 Agent 可通过 `pane.report_agent` 方法发送显式生命周期报告，获得更精确的状态追踪

已原生支持 15+ 主流 Agent：Claude Code、OpenAI Codex、Pi、Droid、Amp、GitHub Copilot CLI、Devin CLI、Grok CLI、OpenCode、Kilo Code CLI、Hermes Agent 等。

### 3. 持久化会话，断连不丢进度
Agent 一次任务可能跑几十分钟，SSH 断了或终端关了容易丢进度。herdr 采用**客户端-服务器架构**：HeadlessServer 在后台持久化管理所有 PTY 会话，客户端可以安全分离（`ctrl+b q`），稍后从任意终端——甚至手机 SSH——重新连接恢复。会话状态可在客户端断开和服务器重启后存活。

### 4. Agent 也能调用 herdr —— Socket API
herdr 暴露了一套 **Unix Socket JSON-RPC API**，Agent 可以编程式地：
- 创建工作区、拆分窗格、启动其他 Agent
- 读取任意 pane 的输出内容
- 阻塞等待某个 Agent 进入 idle 状态
- 订阅实时事件

这意味着你可以构建"**主控 Agent**"来编排多个子 Agent：A 改代码、B 审查、C 跑测试，三个同时进行，主控 Agent 盯着状态就行。

### 5. 鼠标原生 + 键盘双模操作
不同于 tmux 的纯键盘范式，herdr 同时支持：
- 鼠标点击切换 pane、拖拽调整大小、右键分屏
- tmux 风格 prefix 键（`Ctrl+B`）供键盘党使用
- 上下文菜单和浮动面板

你可以按场景选择交互方式，不用被迫适应某一种范式。

### 6. 三层组织：Workspace → Tab → Pane
- **Workspace（工作区）**：以项目为单位，通常对应一个 Git 仓库或文件夹
- **Tab（标签）**：工作区内的标签页
- **Pane（窗格）**：真正在跑的终端进程——注意，这是**真实的 PTY 终端**，不是工具自己"重新解释"过的 Agent 视图

## ⚙️ 技术亮点

### 亮点一：混合 Agent 检测机制
herdr 的 Agent 状态检测结合了两种策略：**启发式推断**（无需修改 Agent）和 **Socket API 显式报告**（支持更丰富的状态）。对于 screen-manifest Agent（如 Claude Code、Codex），herdr 读取实时屏幕快照并匹配已知的 UI 模式（权限提示、确认对话框、空闲状态）；对于深度集成 Agent，则通过生命周期钩子直接获取精确状态。Blocked 检测采用保守策略——只匹配已知的 approval UI 模式，避免误报。这种"零侵入 + 渐进增强"的设计让 herdr 开箱即用，同时支持更深度的集成。

### 亮点二：三种执行模式，覆盖全场景
| 模式 | 启动方式 | 说明 |
|------|----------|------|
| **Client/Server（默认）** | `herdr` | 后台服务器持久化会话，轻量客户端负责 TUI 渲染和输入 |
| **Monolithic** | `herdr --no-session` | 单进程运行，适合快速测试和简单场景 |
| **Headless API** | 无 UI 模式 | 纯 Socket API 控制，适用于 CI/CD 自动化和脚本编排 |

三种模式使 herdr 既能作为日常开发工具，也能融入自动化流水线。

### 亮点三：Rust 实现，极致轻量
- **单二进制 ~10MB**，零依赖（无 Electron、无 Node.js、无 GUI 框架）
- **内存占用 <15MB**（6 pane + 3 agent 场景实测）
- **启动 <100ms**
- **事件驱动检测**，非轮询，CPU 影响可忽略
- 客户端使用 `ratatui` 构建 TUI，服务器管理真实 PTY，终端后端基于 Ghostty

对比 cmux（~50MB+ Swift 二进制、macOS 独占）和 Warp（桌面应用、非终端原生），herdr 的轻量和跨平台优势非常明显。

## 🚀 快速上手

```bash
# 安装（macOS / Linux）
brew install herdr
# 或一键脚本
curl -fsSL https://herdr.dev/install.sh | sh
# Windows Beta
powershell -ExecutionPolicy Bypass -c "irm https://herdr.dev/install.ps1 | iex"

# 启动 herdr（进入项目目录）
herdr

# 在 pane 中启动 Agent
claude

# 垂直分屏
ctrl+b v

# 在另一个 pane 启动另一个 Agent
codex

# detach（Agent 继续在后台运行）
ctrl+b q

# 从任意终端重新连接
herdr

# 远程服务器使用
herdr --remote ssh://user@server:2222

# 安装 Agent 原生集成（获得更精确的状态）
herdr integration install claude
herdr integration install codex
```

## 💡 为什么值得关注

1. **解决了一个真实的新痛点**：AI 编码 Agent 的普及催生了一个此前不存在的工具品类——"Agent 感知型终端复用器"。herdr 是这个品类的先行者之一。
2. **增长势头凶猛**：4 个月从 0 到 19.7k Stars，每周新增 4,500+，Hacker News 287 分热议，社区关注度极高。
3. **设计哲学清晰**：不替换你的终端、不把你锁进 GUI、尊重终端原生体验——只是把你的工作方式组织得更适合 AI Agent 时代。
4. **递归式 Agent 编排**：Socket API 让 Agent 能驱动 herdr，这意味着 Agent 可以自我编排——一个 Agent 可以 spawn 其他 Agent、等待它们完成、读取输出、继续下一步。这是迈向多 Agent 自主协作的关键基础设施。
5. **全职开发，迭代极快**：作者 Oğulcan Çelik 全职维护，v0.4.0 阶段每周多个 release，功能演进迅速。

## ⚠️ 注意事项

- **v0.4.0 成熟度**：项目很新，API 可能变动，配置稳定性尚未保证
- **Blocked 检测保守**：screen-manifest Agent 只匹配已知的 approval UI 模式，新或不常见的提示可能显示为 idle
- **Windows 支持为 Beta**：稳定性不如 macOS/Linux
- **插件生态年轻**：相比 tmux 十年积累的生态（tpm、tmuxinator 等），herdr 的 marketplace 还在早期
