### 📌 项目背景

你用 Claude Code 写代码，每月烧几百块的 API 费；你手上又攒了好几个平台的免费额度——Gemini 每天 1500 次、Groq 每分钟 30 次、Qwen 的免费 tier……但每次切换模型都得改配置、换 SDK，烦得要命。而且单靠一个付费 API，配额一打满你的 Agent 工作流就断了。

**OmniRoute** 就是为这个痛点而生的。它是一个**本地优先的开源 AI 网关**，核心理念极其简单：**一个端点，连接 177 个 AI 供应商，自动帮你把免费额度用到极致，永远不会因为配额耗尽而卡住。**

它用 TypeScript/Next.js 构建，在本地启动一个 OpenAI 兼容的 API 端点（`http://localhost:20128/v1`），你写的代码、用的 Claude Code/Cursor/Copilot 都指向这个地址，OmniRoute 在背后做四件事：智能路由、自动回退、Token 压缩、格式翻译。对调用方完全透明——你只看到一个"永远可用的 AI API"。

项目由巴西开发者 diegosouzapw 于 2026 年 2 月创建，4 个月即获 5.9k stars、1026 forks，以 MIT 协议开源。它整合了 RTK 和 Caveman 的压缩管线，可节省 15%-95% 的 Token，官方统计每月有约 19 亿个免费 Token 通过其管道流动。

### 🚀 核心功能（7 大能力）

**1. 四级 Combo 自动回退：永远不断供的 AI 服务**

这是 OmniRoute 最核心的"撒手锏"。它把供应商按付费优先级分成四层，请求按层自动降级：

- **第一层 Subscription（订阅）**：Claude Pro、OpenAI Plus 等付费订阅额度，优先消耗
- **第二层 API Key**：DeepSeek、Groq、xAI 等按量付费 API，Subscription 耗尽后自动切
- **第三层 Cheap（低价）**：GLM（0.6$/M token）、MiniMax（0.2$/M token）等超低价模型
- **第四层 Free（免费）**：Qoder、Kiro、Qwen、Gemini CLI 等完全免费的端点

触发回退的条件不是简单的 "请求失败就切"，而是综合了 **429 限速、402 余额不足、连接超时、熔断器状态** 等多个维度。对调用方来说，你的代码永远看到 200 OK，无需处理任何错误重试逻辑。

**2. 14 种智能路由策略：不只是简单的轮询**

OmniRoute 提供了 14+ 种路由策略，远超同类工具的 "轮询+FIFO" 组合：

- `priority`（优先级）、`weighted`（加权）、`round-robin`（轮询）：基础策略
- `P2C`（Power of Two Choices）：随机选两个最佳候选人，取更优者——经典分布式算法
- `cost-optimized`（成本最优）：自动选最便宜的可用模型
- `context-relay`（上下文接力）：跨账号切换时注入对话摘要，保留上下文连续性
- `fill-first`（填满优先）：先耗尽一个账户再切下一个，最大化免费额度利用
- `quota-aware P2C`：综合配额余量、回退冷却、最近错误率和连续命中次数挑选最优账号

**3. RTK + Caveman 堆叠压缩管线：最高节省 95% Token**

OmniRoute 集成了一套双层压缩管线。RTK 层负责 context 压缩——通过智能摘要和上下文窗口管理，将冗长的对话历史压缩为精炼的提示词；Caveman 层对请求体进行格式精简——去掉 SDK 不识别的冗余字段（如 `x_groq`、`usage_breakdown`）、压缩 tool call 结果。官方数据显示压缩率在 15%-95%，意味着原本花 1 美元的请求，通过压缩可能只需要 5 美分。

**4. 三态熔断器 + Quota 预检：防患于未然**

OmniRoute 实现了经典的三态熔断器（Closed → Half-Open → Open），具备自适应退避和历史状态追踪，并且状态写入 SQLite 的 `domain_circuit_breakers` 表，服务重启后仍然有效。更精妙的是 **Quota Preflight（配额预检）**——在发出请求前主动探测供应商限额，而非等到返回 429 才被动处理。如果已知某个供应商即将耗尽配额，路由层会提前将其从候选池中排除。

**5. Hub-and-Spoke 格式翻译：一套代码适配所有模型**

所有供应商的请求/响应格式差异由 OmniRoute 内部消化。它以 OpenAI Chat 格式为 Hub（中心），Claude Messages、Gemini、OpenAI Responses 为 Spoke（辐条），实现双向互转。这意味着你只需用一套 OpenAI SDK 的代码，就能调用 Claude、Gemini、Groq 等所有供应商的模型——无需引入多个 SDK、不需要记忆不同的 API 格式差异。

**6. 多协议统一接入：REST + MCP + A2A 三位一体**

OmniRoute 不只是一个 HTTP 代理。它在同一个端口上同时提供：

- **OpenAI 兼容 REST API**（`/v1/*`）：面向所有编程工具的标准接口
- **MCP Server**（29 个工具）：支持 Claude Code、Codex 等 IDE 的 MCP 协议
- **A2A JSON-RPC 2.0 Server**：面向 Agent-to-Agent 通信场景

这种设计意味着同一个 OmniRoute 实例，既可以作为编程 IDE 的底层代理，也可以作为 AI Agent 系统的 MCP 工具提供方，还可以作为多 Agent 协作的 A2A 通信中继。

**7. 完整运维面板：Dashboard + Playground + Eval + 日志**

OmniRoute 自带一个功能齐全的 Dashboard（React 19 + Tailwind 4 + Recharts + Zustand + Monaco Editor），提供：

- **Combo Builder**：可视化构建路由回退链
- **Health Panel**：实时展示各供应商的健康状态、冷却计时器、熔断器状态
- **Playground**：内置 Monaco Editor，直接测试不同路由策略的效果
- **Eval 评分面板**：对比不同模型的输出质量
- **成本分析**：按模型/供应商/时间段查看 Token 消耗和费用

### ⚙️ 技术亮点

**1. 单进程 Next.js 16 一体化架构，却支撑了企业级网关能力**

OmniRoute 所有模块——OpenAI 代理、MCP Server、A2A 端、Memory/Skills、Sync Token——都运行在同一个 Next.js 16 进程中，数据层使用 better-sqlite3（WAL 模式）共 26 张表。这种"重单体"设计在性能上并非最优（冷启动后所有状态绑在单进程 SQLite 里，无法水平扩展），但在 **0 配置部署** 和 **个人/小团队场景** 下是巨大的工程优势——`npm install -g omniroute && omniroute` 即可上线。

**2. Provider Executor 策略模式：每个供应商一个执行器**

源码中 `open-sse/executors/` 目录下，每个 AI 供应商对应一个独立的 Executor 类实现 `BaseExecutor` 接口。DefaultExecutor 处理通用 OpenAI 兼容供应商，CodexExecutor、KiroExecutor、CursorExecutor、AntigravityExecutor 等针对特殊协议做定制化请求构建和响应解析。这种设计使得添加新供应商只需新增一个 Executor 文件，核心路由逻辑完全不受影响。

**3. Context-Relay 上下文接力：跨供应商不掉记忆**

当回退机制触发供应商切换时（例如从 Claude 订阅切到 Gemini 免费），Context-Relay 通过 `contextHandoff` 服务自动注入上一轮对话的摘要，确保 AI 不会因为切换模型而"失忆"。这个特性对长时间运行的 Agent 工作流（7×24 代码审查、自动化测试）至关重要——不会因为回退到免费模型就丢失上下文。

**4. 防重试风暴：Anti-thundering-herd mutex + semaphore**

当某个供应商整体不可用时，所有等待的请求同时触发重试会导致"惊群效应"。OmniRoute 用互斥锁（mutex）和信号量（semaphore）控制并发重试，确保同一时刻只有有限数量的请求尝试恢复连接，避免对上游供应商造成二次冲击。同时服务端支持 `Wait-For-Cooldown` 模式——所有请求在冷却期间排队等待，而非重复失败。

**5. TLS 指纹伪装 + Header 重排：绕过供应商反爬**

免费 API 端点通常有严格的反爬机制。OmniRoute 内置了 TLS 指纹伪装（模拟真实浏览器的 JA3 指纹）和 CLI Header 重排（将请求头按正版 CLI 的顺序排列），提高通过免费端点反爬检测的成功率。这一层对用户完全透明，但大幅提升了免费额度的实际可用率。

### ⚡ 快速上手

**Step 1：安装（5 秒启动）**
```bash
npm install -g omniroute
omniroute start
# Dashboard: http://localhost:20128
# API Endpoint: http://localhost:20128/v1
```

**Step 2：配置供应商**
打开 Dashboard → Providers 页面 → 添加你的 API Key（Anthropic、OpenAI、Gemini、DeepSeek 等）

**Step 3：在 IDE 中使用**
```bash
# Claude Code
export ANTHROPIC_BASE_URL=http://localhost:20128/v1

# Codex CLI
export CODEX_API_BASE=http://localhost:20128/v1

# Cursor
# Settings → API Base: http://localhost:20128/v1
```

**Step 4：Docker 部署（生产环境）**
```bash
docker run -d \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  --restart unless-stopped \
  diegosouzapw/omniroute:latest
```

### ⚠️ 使用注意

- **单进程架构**：不适合高并发生产环境，≥100 QPS 建议评估分散部署
- **TLS 伪装合规风险**：绕过免费端点的反爬机制可能违反某些平台的服务条款
- **学习成本**：14 种路由策略 + Combo Builder 有上手门槛，新手建议先只用默认配置
- **数据安全**：所有请求经本地代理，API Key 存储在 SQLite 中，注意保护 `~/.omniroute/` 目录权限
- **上游依赖**：如果所有免费端点同时改动 API，OmniRoute 需要等上游更新
