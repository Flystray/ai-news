核心功能

1. Max Mode：并行采样选优

每轮并行生成 N=5 个候选方案（temperature=1），independent 推理但不执行，由同一个模型作为 judge 选出最优。SWE-Bench Pro 提升 10-20%，代价约 4-5 倍 token 消耗。

2. Goal 驱动停止条件

用户用自然语言设定停止条件（如"所有测试通过且代码已提交"），独立 verifier 模型在 Agent 每次想"收工"时审查完整对话历史，防止"乐观终止"。无限循环概率 < 0.5%。

3. 四层分层记忆系统

层级文件生命周期作用
L1notes.md会话级主 Agent 唯一可写的草稿区
L2checkpoint.md会话级11 字段结构化状态快照
L3MEMORY.md项目级跨会话持久化知识
L4tasks/*/progress.md任务级单任务进度追踪

4. Dynamic Workflow

主 Agent 生成 JavaScript 脚本在隔离沙箱中确定性执行，通过 agent()/parallel()/pipeline() 控制并发——"if 不会忘分支，for 不会提前退出"。

5. Dream & Distill：自我进化

  • Dream（每 7 天）：合并、去重、压缩记忆，收敛为紧凑状态
  • Distill（每 30 天）：识别重复工作模式，固化为可复用 skill/命令

技术亮点

Writer Subagent 的"单写者不变式"

主 Agent 不维护自己的记忆——完全外包给独立的 writer subagent，不共享主 Agent 的注意力和 token 预算。每个结构化文件只允许一个 actor 写入，最简并发写冲突防止。

Checkpoint"早触发"策略

在上下文预算的 20%/45%/70% 处触发 checkpoint——而非直觉上的"快满了再压"。因为模型在高利用率下的结构化提取能力显著退化（lost in the middle），且压缩本身也需要空间。

Rebuild：物理窗口切换时不丢语义

上下文窗口接近上限时，Runtime 切断当前窗口、开新窗口、用持久化文件重建上下文，总注入控制在约 65K tokens。Agent 在新窗口醒过来直接干活，无需重新确认目标。

亮点总结：小米团队用 487 次 commits 证明了一件事——好的记忆系统、独立的 verifier、确定性的 workflow 编排，这些 Runtime 层的工程创新同样能让 Agent 的能力上一个台阶。

快速上手

# 一行安装
curl -fsSL https://mimo.xiaomi.com/install | bash

# 或 npm
npm install -g @mimo-ai/cli

# 启动
mimo

首次启动选 "MiMo Auto"（限时免费通道），零配置直接开用。支持 DeepSeek、Kimi、GLM 等 75+ LLM Provider，可从 Claude Code 一键迁移认证。

适用人群

  • 终端编程习惯者：需会终端、Node/npm、基础 Git
  • 多文件修改/重构/跨模块排查工程师：MiMo 最擅长的场景
  • 低成本尝鲜的个人开发者：MIT 开源 + 限时免费
  • Agent 记忆与长任务研究者：四层记忆 + Dream/Distill 设计值得深入

局限与风险

  1. V0.1.0 早期版本：GitHub Issues 已有安装失败、WSL 异常等问题
  2. Benchmark 未独立复现：官方自测数据需第三方验证
  3. Max Mode 实验性：需手动开启，token 消耗 4-5 倍
  4. 安全边界：务必在受控环境（非核心仓库、有 Git 保护）中运行
