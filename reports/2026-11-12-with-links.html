让 AI 画 3D 零件，现在的通行做法是生成一段 OpenSCAD 或者一个 STL 网格——能打印，但改不了：想把外壳高度从 24 毫米调到 32 毫米，只能让模型重新生成一遍，赌它这次没画错。SolidCraft 走的是另一条路：它本身是一个带参数化特征时间线的 3D CAD 应用，用纯 Rust 从零写了草图约束求解器和 B-rep（边界表示）内核，再内置一个 MCP（Model Context Protocol）服务器，让 Claude Code 这类 agent 像人一样在时间线上建模。AI 画出来的不是一次性网格，而是一串可以打开、可以改尺寸、可以整链重算的特征步骤。这是最反直觉的一点：它不是「AI 版 CAD」，而是「CAD 原生接上了 agent」。

项目背景：改一个尺寸，为什么要推倒重来

参数化建模是 SolidWorks、Fusion 360 这类商业软件的立身之本：先画二维草图、标尺寸、加约束，再拉伸成实体，每一步操作都记录在时间线上。改一个参数，整条链路自动重算。这套东西好用，但两头的体验都有缺口。

商业软件这一头，是授权费和封闭。机械行业的同行对 SolidWorks 一年数万元的授权费用并不陌生（今日头条报道语，见文末来源[1]），Fusion 360 也是订阅制。免费替代品 FreeCAD 存在了十几年，但参数改动后模型重构失败是社区里抱怨多年的老毛病[1]，复杂模型的约束求解时常翻车。

AI 这一头，问题更根本。当前让大模型「生成 3D 模型」的方案，无论输出 OpenSCAD 代码还是 STL/3MF 网格，产物都是一个「结果快照」：没有草图约束，没有特征树，没有任何可编辑的结构。dev.to 的技术分析说得很准——agent 写完一个 STL，你想改一个尺寸就得从头再来[2]。有人给 FreeCAD 接过 MCP 插件，Hacker News 用户 mijoharas 的体验是 agent 建不出干净、可编辑的草图[3]。

SolidCraft 的判断是：问题不出在 agent 身上，出在目标产物上。与其让 AI 生成不可编辑的网格，不如给它一个真正的时间线式 CAD 作为工具——每一步都可检查、可撤销、可按参数重建。2026 年 10 月 7 日仓库创建，11 天涨到约 5,900 星[1]，截至 2026-11-12 已到 15,843 星，Hacker News 的 Show HN 帖拿到约 130 分、37 条以上讨论[4]。

核心功能

1. 参数化特征时间线：改一个数，全模型重算

这是整个项目的支点。所有操作——拉伸、旋转、扫掠、放样、圆角、倒角、抽壳、拔模、打孔、螺纹、阵列、镜像——都记录在一条可编辑的时间线上。关键尺寸以命名变量写在参数表里，改一个值，引擎沿时间线重新求值，所有依赖它的拉伸、孔位、装配体跟着重建。README 的演示是从空白设计画一个树莓派 4 外壳：按板子实际尺寸（58×49 毫米孔位矩形）标草图、拉伸、圆角、抽壳、阵列 M2.5 螺柱、开端口和散热槽，最后把高度参数从 24 改到 32，整个模型自动重建[5]。参数还支持带单位的表达式，比如 2 * width + 5 mm。

2. 自研草图约束求解器

草图层的约束（重合、相切、平行、对称、尺寸驱动）由项目自己写的求解器处理，不依赖 OpenCASCADE 或 Sketcher。这意味着求解行为完全可控，也意味着坑要自己踩——这一点在「局限」里细说。

3. 内置 MCP server：agent 的建模通道

solidcraft-cli mcp 是一个标准 MCP 服务器（stdio 上的 JSON-RPC 2.0，兼容 2025-06-18、2025-03-26、2024-11-05 三个协议版本）。接入 Claude Code 只要一行命令。两种模式：headless 模式自带独立设计会话；--connect 桥接模式驱动正在运行的桌面应用，你能实时看着 agent 在时间线上逐步建模。安全设计做得细：文件访问默认限制在设计文件所在文件夹内，~/.ssh、.env、.git 等隐藏目录天然不可达，symlink 逃逸、Windows 的 UNC 路径、备用数据流、8.3 短文件名都在解析前直接拒绝，必要时用 --allow-path 显式扩权。还有 --param-check off|warn|strict 三档参数校验，strict 模式下不符合类型契约的调用会被拒绝、设计保持原样[6]。作者曾用 agent 通过 MCP 从零建出科学探测车 SELENE，时间线上 3,323 个可编辑步骤全程无错重建（sinapti.ca 转述早期 README）[4]。

4. 一切皆命令：桌面、网页、CLI、MCP 走同一套指令

桌面应用、浏览器版、headless CLI、MCP 服务器跑的是同一个命令注册表。UI 上点一个按钮，和 agent 调一个工具，和脚本里写一行 JSON，执行的是同一条命令。所以脚本就是「JSON 化的 UI 操作」：

{
  "commands": [
    {"command": "sketch.create", "params": {"plane": "XY"}},
    {"command": "sketch.rectangle.two_point", "params": {"p0": [0, 0], "p1": [40, 30]}},
    {"command": "solid.extrude", "params": {"distance": 20}},
    {"command": "solid.fillet", "params": {"edges": [[0, 0, 10]], "radius": 3}}
  ]
}

用 solidcraft-cli run examples/bracket.json --out bracket.step 就能无头重放。对工程团队的实际意义是：agent 生成的好零件，命令清单可以进版本库，在 CI 里重新生成 STEP，不依赖某个二进制文件[2]。

5. Oracle 参考测试：用解析解给自己对账

这是同类开源项目里少见的做法。每个测试用例是一个用 recipe.json 描述的零件，SolidCraft 重放命令生成实体，再与期望值比对体积、面积、质心、包围盒（相对容差 1e-3），部分用例还比对采样 Hausdorff 曲面距离。期望值来自两个途径：手算解析解（棱柱、圆柱、Pappus 定理、变半径圆角的精确积分），或者用 FreeCAD 的公开 Python API 独立构建同一零件做对照——FreeCAD 不是项目依赖，只当外部裁判。截至 2026-11-12 抓取的 docs/oracle.md 显示 90/90 用例通过（69 个解析解 + 21 个 FreeCAD 对照）[7]；README 正文仍写着 75/76，属于文档滞后，两处数字本文都如实标注。

6. 装配、钣金与多格式文件

装配体支持关节定义、运动研究、干涉检查和质量属性；钣金模块有法兰、折边、折弯/展开和平整图案；文件层面 STEP（含 AP242）、IGES、3MF、STL、OBJ、glTF 双向支持，另可导出 URDF 给机器人仿真用。

技术亮点

1. 自研内核的取舍：把最难的活留给自己，但留了一条接缝

SolidCraft 没有像多数新 CAD 项目那样直接包 OpenCASCADE，而是自写几何层（geom）、草图求解器、B-rep 内核，并把内核封装成独立的 vendored solidcore 组件。仓库架构文档把系统分成 L0–L5 六层：几何原语 → 求解器与内核 → 文档与时间线增量求值 → 文件 IO → 命令引擎 → GPU 渲染/UI/MCP 三个前端，并规定 L5 以下任何 crate 不得触碰 UI 工具包，由 cargo xtask layers 强制检查[8]。代价很明确：内核成熟度要靠时间换；收益是约束求解和重建行为完全自主可控，且渲染用 wgpu 写了 GPU 路径追踪，浏览器版和桌面版共用同一视口渲染器。这属于典型的「短期慢、长期快」押注，值不值得，要看内核能扛住多复杂的零件——HN 上对此有真刀真枪的争论（见局限）。

2. 「一切皆命令」的架构红利

把 UI 操作、脚本、CLI、MCP 统一到一个命令注册表，是本项目对 agent 生态最有参考价值的设计。它带来三个直接后果：agent 与人用的能力完全对等，不存在「只有 UI 能做的事」；命令清单可序列化、可版本化、可在 CI 重放；给 agent 的安全边界（路径白名单、参数契约）可以在命令层统一执行，而不是散落在各个前端。做 agent 工具集成的团队可以直接把这套设计当案例研究——explainx.ai 的分析也是这么建议的[3]。

3. 用测试文化对冲「AI 项目不可信」的天然质疑

AI 辅助开发的项目常被质疑质量靠不住。SolidCraft 的回应是把验证做成基础设施：oracle 文档生成自 cargo xtask oracle，每个用例公开公式和 FreeCAD 对照方法，连「期望值来自哪些解析几何公式」都写在表格里[7]。加上 clean-room 贡献规则（禁止阅读 OpenCASCADE、FreeCAD、SolveSpace 的 GPL 源码，所有图标代码绘制并逐条登记在 ATTRIBUTION.md）[9]，项目在「独立性」这个敏感点上交代的证据链比多数同类完整。

适用人群

  • 硬件/3D 打印爱好者：要画外壳、支架、结构件，改尺寸不用推倒重来；浏览器版免安装，先试手感再装桌面版。能省掉 Fusion 订阅费（前提是零件够简单，见局限）。
  • agent 工具开发者：想看「怎么给 AI 一个专业软件的操作面」，MCP 工具设计、沙箱规则、参数契约三样都是现成参考实现。
  • 用 Claude Code 等编码 agent 的工程师：需要参数化实体模型而不是一次性网格时，claude mcp add 一行接入，产出的零件可以直接交付给加工或打印。
  • 机械/结构工程师（轻度）：预算卡在商业授权上、又嫌 FreeCAD 重构不稳的，值得实测对比；重度装配和曲面加工需求暂时别迁移。
  • 教学场景：时间线 + oracle 公式表天然适合讲参数化建模原理，每一步都能看见。

快速上手

零安装先试浏览器版：打开 solidcraft.io/app（需要支持 WebGPU 或 WebGL2 的浏览器）。

桌面版安装（README 校对[5]）：

# Linux（Snap）
sudo snap install solidcraft

# 从源码构建（需要 Rust 工具链）
cargo run --release -p solidcraft -- --sample      # 桌面版，打开示例零件
cargo run --release -p solidcraft-cli -- commands  # 查看完整命令注册表
cargo run --release -p solidcraft-cli -- run examples/bracket.json --out bracket.step

接入 Claude Code：

claude mcp add solidcraft -- solidcraft-cli mcp

常见坑，README 明说的三条：Windows 安装包尚未签名，SmartScreen 弹窗要选「更多信息 → 仍要运行」；旧版 Windows 安装器没把 solidcraft-cli 放进 PATH，要用完整路径（默认 "C:\Program Files\SolidCraft\solidcraft-cli.exe"）；0.11–0.14 版本需要手动下载一次更新[5]。另外 Linux 发行版若有 Flatpak/Snap 版本差异问题，优先用官方 Release 页的 AppImage。

一百字点评：SolidCraft 的真实位置是「agent 原生的简单零件建模器」，不是 FreeCAD 或 Fusion 的即刻替代。命令注册表和 MCP 设计是它超出 CAD 本身的贡献；而把它当主力工具前，先想清楚你的零件是否落在它的能力圈内。

局限：在「能用」之前，它还有多远

正面材料已经很多，这一段集中说问题。

内核成熟度是最大的问号。 Hacker News 用户 bruckie 指出 SolidCraft 使用 Truck B-rep 内核，并认为写 B-rep 内核「工作量惊人」，担心成熟速度；SolveSpace 开发者 phkahler 直言不看好开放难题的快速进展，建议直接封装 OpenCASCADE[3]。oracle 测试目前 90/90 全过，但用例集中在解析解可覆盖的形状——变半径圆角、曲面布尔这些 CAD 里真正难的区域，测试覆盖远不如直壁零件密集。

能力边界清晰存在。 曲面建模、工程图、CAM、仿真都在路线图上但未实现[10]。有用户评价它「更偏 Tinkercad 一侧，而不是 Fusion 一侧」（@gelon1983，sudolabs 转述）[10]。

实测问题。 Uptodown 编辑实测提到部分版本间存档兼容问题，且复杂曲面建模选项缺失[11]；今日头条作者的实测中，无头浏览器环境下 WebGPU 画布渲染失败，网页版只显示空壳[1]。

长期性存疑。 HN 用户 zamalek 提出一个扎心的问题：CAD 文件的使用寿命以十年计，一个 AI 时代快速长出来的项目，五年后还在不在维护[3]？STEP 导出是当前的解法，但项目自己的文件格式（版本号已到 solidcraft/12）尚未冻结，explainx.ai 明确建议不要把生产设计放进 .solidcraft 文件[3]。

独立性争议没有完全平息。 尽管 clean-room 规则写得严密，HN 上仍有声音质疑 UI 与 Fusion 的相似度，更尖锐的意见（用户 dofm）认为「复制任何人的 CAD 程序都没有意义」，属于「AI 版重复造轮子」[9]。名字与 Solid Edge 的联想也给了批评者素材。

商业边界要看清。 MIT/Apache 双许可只覆盖代码，UI 外观、图标、主题与「SolidCraft」名称由单独的 LICENSE-BRAND 约束，fork 后换皮分发需要维护者书面许可[5]。

写在最后

两点判断。

第一，SolidCraft 真正改变的不是 CAD 市场格局——短期内核追不上 OpenCASCADE 三十年的打磨——而是「agent 与专业软件的对接范式」：不给 AI 生成权，给 AI 操作权；产物不是快照，是可回放、可编辑的命令序列。这套「一切皆命令 + MCP + 命令层安全边界」的架构，任何想把专业软件接上 agent 的团队都值得抄。

第二，对读者的具体行动建议：先开浏览器版花十分钟画个盒子感受参数重建；如果你有 Claude Code，接入 MCP 让它照着 README 的树莓派外壳提示词建模一次，然后自己改一个参数看它是否干净重建——重建得干净，说明 agent 建对了，这是官方给的验收标准，也是判断这类工具是否可用的最短路径。生产设计继续留在 STEP。
