📌 项目背景

当你在 VS Code 里打开一个 1000 行的新项目，向 Claude Code 发出第一条指令——"帮我理解这个代码库"——它会做什么？答案是：它会把你整个项目从头到尾读一遍。无论你只改了 3 个文件，还是有 10000 个文件，它都会重新扫描，因为每次对话对它来说都是"无状态"的。

这是所有 AI 编程工具的共同痛点——上下文开销随代码库规模线性增长。一位名叫 Tirth Kanani 的独立开发者，在一次代码审查任务中遭遇了这个问题的极端案例：那次审查消耗了 5500 个 Token，而实际上只需要 800 个。这促使他花了三个月开发了 code-review-graph。

它的核心思路是——在人类开发者和 AI 编程工具之间，插入一个"代码结构索引层"：用 Tree-sitter 把代码解析成结构化图谱，然后让 AI 只读真正相关的部分。GitHub 上线仅两个月，已获得 14.1k stars，被 AI 开发者社区广泛讨论。

🚀 核心功能

1. 增量代码知识图谱构建

首次运行 code-review-graph build 后，工具会用 Tree-sitter 解析整个代码库，将每个文件转换为 AST（抽象语法树），从中提取节点（函数、类、类型、测试）和边（调用、导入、继承、依赖、测试覆盖），全部存入本地 SQLite 数据库。一个 2900 个文件的 Python + TypeScript 项目，首次构建仅需约 10 秒。构建完成后图谱持久化存储，后续对话无需重新读取文件。

2. 精准影响半径分析

这是 code-review-graph 最有价值的功能。当文件发生变更时，图谱执行广度优先搜索（BFS），追踪所有可能受影响的上游调用者、下游依赖方和相关测试，从而精确定位变更的"影响范围"。AI 助手只需要读取这个精确的最小文件集。测试数据显示，在包含 27000+ 文件的 monorepo 中，仅修改 5 个文件时，影响半径仅涉及约 15 个文件——而不是 27000 个。

3. MCP 协议原生集成

code-review-graph install 一条命令即可自动检测你安装了哪些工具（Claude Code、Cursor、Codex、Kiro 等），为每个平台生成正确的 MCP 配置文件，将图感知指令注入平台规则文件。安装后直接重启编辑器即可使用。工具优先推荐使用 uvx 运行 MCP 服务（如系统安装了 uv），否则回退到标准 pip 模式。

4. 增量更新：不到 2 秒完成刷新

每次文件保存或 git 提交时，工具通过 SHA-256 哈希校验快速检测变更文件，仅对受影响的文件和依赖进行差异解析并更新图谱。一个 2900 个文件的项目，增量更新在 2 秒内完成。

5. 多维代码理解与导航

执行流（Flows）追踪从入口点到各函数的调用链，计算每个函数的"关键性"评分；社区检测（Communities）使用 Leiden 算法将代码按模块自然分组；语义搜索结合 SQLite FTS5 全文索引和可选向量嵌入，支持关键词和语义双重查询模式。

6. 自动化知识库生成

code-review-graph wiki 自动将图谱转化为 Markdown 文档；code-review-graph visualize 生成基于 vis.js 的交互式 HTML 图谱页面，在浏览器中自由探索代码结构。

⚙️ 技术亮点

亮点一：Tree-sitter AST — 精准到语言语义的代码理解

不同于简单的正则匹配，Tree-sitter 为每种编程语言提供正式的语法解析器，能准确识别函数签名、类定义、类型注解等语义结构。这意味着图谱中的节点是"语义完整"的——一个函数节点包含了它的名称、参数、返回值、docstring 以及它在代码中的实际位置。AI 不是在读"文本"，而是在读"结构化的语义网络"。

亮点二：MCP 协议 — 开放标准的 AI 工具互联

code-review-graph 选择 MCP（Model Context Protocol）作为与 AI 编程工具的通信协议，这是 Claude Code、Cursor、Kiro、OpenClaw 等多个主流工具采用的开放标准。这意味着一个图谱可以同时为多个 AI 工具提供上下文，无需为每个工具单独适配。MCP 工具集包含：图谱增删改查、blast 半径分析、审查上下文生成、执行流查询、架构概览等。

亮点三：Leiden 拓扑聚类 — 无需 embedding 的架构理解

传统工具依赖向量嵌入来做语义理解，需要额外运行 embedding 模型、消耗额外 Token。code-review-graph 使用 Leiden 算法直接基于图拓扑结构进行社区发现，同一社区内的节点在调用关系、导入关系和依赖关系上具有高度内聚性——这恰恰对应了代码的"模块化"设计。这种方法完全不依赖外部服务，在本地即可完成高质量的架构分析。

👥 适用人群

  • 大型项目开发者：代码库超过 1000 个文件，每次 AI 对话都要等待很长时间。影响半径分析能显著减少等待时间和 Token 费用，尤其适合 monorepo 场景。
  • 高频使用 AI 编程的团队：每天大量使用 Claude Code、Cursor 等工具处理代码审查、bug 修复、功能开发。增量更新确保图谱始终是最新的。
  • 需要理解陌生代码库的开发者：无论是接手遗留项目还是参与开源贡献，图谱的社区检测和架构概览能帮助快速建立对项目整体结构的认知。
  • AI 辅助开发研究者：基准测试数据是公开的，可通过 code-review-graph eval --all 复现，是研究 LLM + 代码理解工具效率的绝佳案例。

🚀 快速上手

# 1. 安装 pip install code-review-graph # 2. 进入项目目录并初始化 cd your-project code-review-graph install # 3. 构建知识图谱 code-review-graph build # 4. 可选：生成交互式图谱页面 code-review-graph visualize # 5. 可选：生成知识库文档 code-review-graph wiki # 6. 重启 AI 编程工具，开始使用

安装后，在 Claude Code 中直接说："Build the code review graph for this project"，或让 AI 助手使用 MCP 工具集查询图谱。也可指定平台：--platform claude-code、--platform cursor、--platform codex。

💡 选择建议

Graphify 的 71.5× 压缩效果来自其多模态处理能力（论文、图片、音视频都压缩），在纯代码审查场景下，code-review-graph 的 6.8×~49× 数据更具参考价值。如果你的需求是"让 AI 编程助手更高效地理解代码"，code-review-graph 是更专业的选择；如果你需要处理多模态文档并建立知识库，Graphify 更适合。
