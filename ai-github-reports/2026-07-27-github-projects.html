1000 万条 1536 维文档向量，float32 存储 31 GB，turbovec 压到 4 GB——压缩 8 倍，搜索速度还比 FAISS 快 12-20%。不需要训练码本，不需要重建索引，add() 即可搜。

项目背景：向量索引的"训练税"

几乎所有生产级向量量化器——包括 FAISS 的乘积量化（PQ）——都依赖一个痛苦的前提：先训练码本，再编码数据。你需要采样、跑 k-means 聚类、生成码本、编码全量向量。语料增长？分布漂移？重新训练、重建整个索引。

在实际生产环境中，文档是持续流入的。每次停下来训练码本，意味着系统有一个"不可用窗口"。turbovec 的底牌是 Google Research 2025 年 4 月发表的 TurboQuant 算法（ICLR 2026 录用）——一个"数据无感知"量化器，量化方案完全来自数学推导，不依赖任何输入数据。

核心区别：PQ 需要数据适应码本 → TurboQuant 用随机旋转抹平数据差异 → 量化桶边界纯数学预计算 → 无训练、无码本、无重建。

核心功能

1. 零训练在线索引

调用 index.add(vectors)，向量立即被量化并进入索引。没有 train() 步骤，没有参数调优。TurboQuant 的量化桶边界从数学公式预计算，不随数据变化。对流式写入场景（日志、实时文档管道）是决定性优势。

2. 2-4 bit 极致压缩

1536 维 float32 向量从 6,144 字节压缩到 384 字节（2-bit，16 倍）或 768 字节（4-bit，8 倍）。1000 万条 1536 维向量：FP32 需 31 GB，4-bit 需约 4 GB，2-bit 需约 2 GB。

3. 手写 SIMD 内核

ARM 平台用 NEON 指令，x86 平台用 AVX-512BW 和 AVX2 指令。Apple M3 Max 上比 FAISS IndexPQFastScan 快 12-20%（单线程和多线程均胜）；Intel Sapphire Rapids 上 4-bit 配置匹配或超过 FAISS。

4. 搜索时过滤

search() 接受 ID 白名单或 slot bitmask。SIMD 内核在 32 向量块粒度上执行过滤——没有允许项的块直接短路跳过。混合检索（SQL/BM25 筛选 + 向量精排）无额外开销。

5. IdMapIndex 稳定 ID

提供稳定的 uint64 外部 ID，支持 add_with_ids() 和 remove(id)——删除操作 O(1) 完成，不重建索引。

6. 持久化与双语言 API

write()/load() 序列化。Python 端 PyO3 + maturin 构建 wheel，Rust 端 cargo add turbovec。两套 API 功能对等。

7. 纯本地隐私优先

没有托管服务，数据不离开机器或 VPC。可搭配开源 embedding 模型构建完全气隙的 RAG 栈。

技术亮点

TurboQuant 四步数学管道

  1. 归一化：剥离范数，向量变成高维超球面上的单位方向
  2. 随机旋转：乘以同一个随机正交矩阵，使坐标遵循可预测的 Beta 分布（高维下收敛到高斯 N(0, 1/d)）——无论输入数据是什么分布
  3. Lloyd-Max 标量量化：旋转后分布解析已知，最优量化桶边界纯数学预计算。2-bit = 4 桶/坐标，4-bit = 16 桶/坐标
  4. 位打包：量化坐标紧密打包成字节
论文证明 TurboQuant 失真率与香农下界极其接近，仅差微小常数因子。LongBench 上 3.5-bit 与 FP16 完全持平（50.06 vs 50.06）；"大海捞针"测试中 4 倍压缩下检索准确率 0.997。

跨架构 SIMD：一份代码两种指令集

为 ARM 和 x86 分别手写内核。NEON 处理 128-bit 寄存器，AVX-512BW 处理 512-bit 寄存器。量化向量以 32 个为一组打包成块，SIMD 内核一次处理一个完整块。过滤逻辑嵌入内核：块级短路 + 向量级丢弃。

两阶段量化：MSE + QJL 残差校正

第一阶段用比目标位宽少 1 位的 MSE 量化器压缩；第二阶段对残差向量应用 1-bit Johnson-Lindenstrauss 变换（QJL），提供无偏内积估计。d=3072 2-bit 召回率 0.912，超过 FAISS 的 0.903。

快速上手

# Python 安装
pip install turbovec

# 创建索引并搜索
from turbovec import TurboQuantIndex
import numpy as np

index = TurboQuantIndex(dim=1536, bit_width=4)
index.add(np.array(vectors, dtype=np.float32))  # 无需训练，立即可搜
scores, indices = index.search(query, k=10)

# 带过滤的搜索
scores, indices = index.search(query, k=10, filter_ids=allowed_ids)

# 持久化
index.write("my_index.tv")
loaded = TurboQuantIndex.load("my_index.tv")

# Rust 安装
# cargo add turbovec

前置要求：Python ≥ 3.9，64 位平台，向量维度为 8 的正整数倍，x86 以 AVX2 为基线。

turbovec 是嵌入式向量索引库（类似 FAISS），不是向量数据库。定位：单机跑千万级向量、内存有限、数据持续流入、隐私要求高——这几乎是目前唯一的选择。

适用人群

  • RAG 系统开发者：语料超百万级，float32 撑不住，又不想引入重量级向量数据库
  • 边缘 部署团队：MacBook、边缘服务器或气隙环境，内存预算有限
  • 隐私 敏感场景：医疗、金融、法律要求数据不出内网
  • 流式 数据管道：文档持续写入，不能接受"停下来训练码本"
  • 基础设施 工程师：想理解 TurboQuant 如何从论文变成生产级库

写在最后

turbovec 最值得关注的不是 Star 数（4 个月 14.4k），而是它代表的趋势：学术论文到生产级工具的转化周期正在急剧缩短。TurboQuant 论文 2025 年 4 月发布，turbovec 2026 年 3 月底就上线了可安装的 Python wheel 和 Rust crate——从论文到 pip install 不到一年。

更重要的是，turbovec 证明了一件事：在 AI 基础设施领域，最锋利的武器未必是更大的芯片或更多的显存，也可以是更聪明的数学。一个随机正交旋转 + Lloyd-Max 标量量化的四步管道，就把 31 GB 压到 4 GB，还跑得比训练了码本的 FAISS 更快。
