这篇论文在说什么？

多模态大语言模型最近在 GUI 智能体方向上进展很快，但有个致命问题：泛化能力差，根本原因就是训练数据太少了。现有数据集靠人工标注，费时费力还覆盖不了多少场景。

北大和小米团队这次提出了一个很巧的办法——Video2GUI，直接从互联网上现成的 GUI 教程视频里自动提取交互轨迹，全程不需要人工参与。他们用这套流程处理了 5 亿条视频元数据，最终构建了 WildGUI 数据集，包含 1200 万条交互轨迹，覆盖 1500 多款应用和网站。

在 WildGUI 上对 Qwen2.5-VL 和 Mimo-VL 做预训练，在多个 GUI 定位和动作基准上取得了 5%~20% 的一致提升，追平甚至超过了当前最优水平。

*图源：项目主页 teaser figure*

为什么要关注？

GUI 智能体这个方向最近真的很热。OpenAI 的 Operator、Anthropic 的 Computer Use、谷歌的 Project Mariner——大厂都在抢这块。核心逻辑很简单：如果 AI 能像人一样操作任意软件界面，那"让 AI 帮你干活"就不再是空话。

但现实很骨感。训练一个靠谱的 GUI Agent 需要大量「指令-动作-界面」三元组，这种数据现在基本靠人工标注，一条条录屏、对齐、质检，成本高到离谱。而且人工标注覆盖的场景非常有限，导致训练出来的模型在真实场景中泛化能力很差。

这个痛点其实整个社区都意识到了，但一直没找到好的解决办法。Video2GUI 的切入点很聪明：互联网上有大量 GUI 教程视频（比如「如何用 Photoshop 抠图」「Excel 数据透视表教程」），这些视频天然包含了完整的操作轨迹，只是没有被结构化地利用起来。

把这批「免费数据」利用起来，就能低成本地构建大规模、多样化的 GUI 训练数据集——这个思路一旦跑通，对整个人工智能社区都有实际价值。

核心方法

关键思路

Video2GUI 的本质是一个三阶段全自动流水线，把「原始互联网视频」变成「结构化 GUI 交互轨迹」：

第一阶段：由粗到细的视频过滤

从 5 亿条视频元数据出发，先训练一个基于 DeepSeek-V3 标注数据微调过的 Qwen2.5-7B 分类器，筛出约 2000 万条候选 GUI 教程视频。再用细粒度内容评分器（指令清晰度、主题相关性、录屏质量三个维度）进一步筛选，最终得到 420 万条高质量 GUI 教程视频（总时长约 30 万小时）。

第二阶段：轨迹提取

把过滤后的视频切割成单段不超过 4 分钟的片段，然后用 Gemini-3-Pro 逐个处理。采用带历史上下文的滑动窗口策略，模型需要同时理解视频画面、字幕指令和之前的操作历史，最终输出结构化的「指令-轨迹」对。

第三阶段：动作空间定位

对每条交互动作，取动作发生前 0.5 秒、发生时、发生后 0.5 秒的三张高分辨率截图 + 对应的低层级指令，输入 Gemini-3-Pro 预测精确的交互目标边界框坐标。人工校验 200 条采样动作，超过 95% 的定位结果是正确的。

技术细节

为什么用 Gemini-3-Pro 而不是开源模型？ 轨迹提取需要同时理解视频帧序列、语音/字幕文本和 UI 元素，这个多模态理解任务对模型能力要求很高。作者尝试过用开源模型，但效果差距明显，最终选择 Gemini-3-Pro 作为核心标注模型。

如何处理视频中的「噪音」？ 教程视频里经常有与 GUI 操作无关的内容（比如作者闲聊、广告片段）。Video2GUI 的细过滤阶段用三个维度评分来排除这些噪音，同时滑动窗口策略也能在一定程度上过滤掉不相关的视频片段。

数据质量如何保证？ 除了 95% 定位准确率的人工校验外，作者还做了数据缩放实验——随着预训练数据量增加，下游基准精度平滑提升，没有出现饱和或能力下降，说明数据质量整体是可靠的。

"Applying this pipeline to 500 million video metadata entries, we construct WildGUI, a large-scale dataset containing 12 million interaction trajectories spanning over 1,500 applications and websites."

一句话：5 亿进 420 万进 1200 万，数据金字塔的每一层都有明确的质量门槛。

预训练数据缩放特性

模型性能随 WildGUI 预训练数据量的增加平滑提升，没有出现饱和现象。这意味着只要继续往流程里加视频，性能还能进一步提升——这是一个非常理想的缩放曲线。

和其他方案比有什么不同？

现有 GUI 数据集大致可以分为三类，WildGUI 在每个维度上都有明显优势：

对比维度 人工标注数据集 合成数据（模拟器） WildGUI（Video2GUI）
数据规模 千-万级 十万-百万级 1200 万级
覆盖场景 窄（特定应用） 中（模拟器支持范围） 宽（1500+ 真实应用）
构建成本 极高（人工） 中（需开发模拟器） 低（全自动）
真实度 高 低-中（模拟器偏差） 高（真实用户操作）
可扩展性 差 中 好（视频数据源源不断）

最重要的区别是：WildGUI 的数据来自真实用户操作，而不是模拟器合成。这意味着模型在 WildGUI 上预训练后，学到的交互模式更接近真实人类行为，泛化到新应用的能力也更强。当然，这个方法也有局限性。比如教程视频里的操作不一定是最优的（用户可能走弯路），而且某些专业软件的教程视频非常少，会导致数据分布不均衡。作者在论文里也坦诚地讨论了这些问题。

对开发者意味着什么？

最直接的价值：数据集要开源了。 论文明确说会发布 WildGUI 数据集和 Video2GUI 全流程代码。对做 GUI Agent 研究的开发者来说，这相当于白送了一套千万级训练数据——不管是用来预训练自己的模型，还是用来做基准测试，都有实际价值。

对工程落地的启发： Video2GUI 的核心思路（从互联网视频中提取结构化训练数据）并不局限于 GUI 场景。类似的方法可以扩展到其他需要「过程数据」的任务——比如从烹饪视频中提取机器人操作轨迹，从教学视频中提取代码编辑过程等等。这个范式一旦泛化，能解锁很多之前因为数据稀缺而做不了的方向。

对国内 AI 开发者的意义： 这篇论文是北大+小米联合完成的，已经被 ICML 2026 接收。这说明国内团队在 GUI Agent 这个热门方向上，不仅能跟上，还能做出有全球影响力的系统性贡献。WildGUI 开源后，国内开发者做 GUI Agent 就有了和国外团队站在同一起跑线上的机会。

如果你正在做 GUI 自动化相关的工作，这个数据集值得密切关注。GitHub 仓库已经建好了，代码和数据集应该近期就会发布。
