如果你已经习惯了 Claude Code、Codex 或 Cursor 帮你写代码，下一步最头疼的问题往往不是" agent 不够强"，而是" agent 太多管不过来"。同一个任务，能不能同时扔给 5 个 agent 各做一版？多个需求并行推进时，如何避免它们抢同一个分支、互相覆盖代码？Agent 跑在远端服务器或家里电脑时，出门后如何通过手机继续跟进？

**Orca** 就是围绕这些真实痛点设计的开源 **ADE（Agent Development Environment，智能体开发环境）**。它不替代任何单个编码 agent，而是做一个"调度中心"：把多个 CLI agent 放进相互隔离的 git worktree，统一监控、比较结果、合并最优方案。

## 项目背景：为什么需要 ADE？

2026 年的 AI 编程工具已经从"尝鲜"进入"日常生产"。开发者手里往往同时持有 Claude Code、OpenAI Codex、Cursor CLI、GitHub Copilot 等多个订阅。传统 IDE 或终端是为"一个人写代码"设计的，当屏幕上同时跑三四个 agent 时，常见的问题包括：

1. **分支冲突**：多个 agent 修改同一仓库，需要频繁 stash / 切分支；
2. **结果难比较**：同一任务让不同 agent 实现，散落在多个终端窗口，难以并排对比；
3. **状态不可见**：agent 是否在跑、是否被权限确认卡住、是否已完成，全靠人工盯屏；
4. **移动与远程断层**：出门后无法查看家里或服务器上 agent 的进度。

Orca 的解法非常直接：**每个任务一个独立 git worktree，每个 worktree 一个独立 agent 会话，全部汇总到一个桌面应用里管理。** 开发者从"指挥一个助手"变成"指挥一支舰队"。

## 核心功能（8 条）

### 1. 并行 Worktree：一个 prompt 扇出 5 个 agent
Orca 最核心的能力。你可以把同一个需求同时交给 Claude Code、Codex、OpenCode、Pi 等多个 agent，每个 agent 在各自的 git worktree 里独立实现。完成后并排比较 diff，挑选最优方案合并。官网 slogan 很直白："Every task runs in its own isolated git worktree — no stashing, no branch juggling."

### 2. Agent 舰队统一监控
主界面实时显示所有 worktree 中 agent 的状态：working（工作中）、idle（空闲）、blocked（等待输入/权限）、done（已完成）。再也不用切终端确认谁卡住了。

### 3. 移动端伴侣 App
支持 iOS（App Store / TestFlight）与 Android（APK）。agent 在桌面端跑，手机端可以查看实时终端流、接收完成通知、发送 follow-up 指令。适合"挂任务出门"的场景。

### 4. Design Mode：点击 UI 元素直接喂给 agent
每个 worktree 内置一个 Chromium 浏览器窗口。看到页面上的按钮、卡片、表单不满意，直接点击该元素，Orca 自动把对应的 HTML、CSS 和裁剪截图塞进 agent prompt，省去大量文字描述。

### 5. AI Diff 批注与回传
在 agent 生成的 diff 任意一行写 markdown 批注，攒一批后一键回传给 agent 修改。把"code review"直接做进 agent 工作流，避免反复复制错误信息。

### 6. GitHub & Linear 原生集成
在应用内浏览 PR、issue、Project 看板，直接从某个任务打开 worktree；支持 CI 检查、冲突解决、PR 创建，无需在浏览器与 IDE 之间来回切换。

### 7. SSH Worktrees
把 agent 派到远程高性能机器上运行，支持完整文件编辑、git 操作、终端会话。断线后自动重连，并带端口转发，适合本地机器配置不够或需要在服务器跑重活的场景。

### 8. Orca CLI：agent 也能反过来控制 IDE
提供 `orca worktree create`、`orca snapshot`、`orca click`、`orca fill` 等命令。这意味着 agent 不仅可以被 Orca 管理，还能主动调用 Orca 的能力来完成更复杂的工作流。

## 技术亮点（4 条）

### 1. Electron 三进程架构
采用 Main / Preload / Renderer 三进程模型：Main 进程负责应用生命周期、原生集成（Git、PTY、SSH）与持久化；Preload 通过 `contextBridge` 暴露安全 API；Renderer 用 React + Zustand 渲染 UI。系统级操作不阻塞界面。

### 2. Ghostty 级终端体验
终端基于 xterm.js + node-pty，WebGL 渲染，支持无限分屏、重启后恢复 scrollback、全量搜索。对从 Warp、Ghostty 迁来的用户比较友好。

### 3. 版本化持久化层
`Store` 类管理 `orca-data.json`，支持 schema 版本控制与迁移，保证数据结构向前兼容，避免升级后配置丢失。

### 4. "自带订阅"的中立定位
Orca 不卖模型、不赚 API 差价。用户需自己持有 Claude、Codex 等订阅，Orca 只提供编排层。这种中立性让它能同时支持 30+ 个 CLI agent，包括最新加入的小米 MiMo Code。

## 快速上手

```bash
# macOS 直接 Homebrew 安装
brew install --cask stablyai/orca/orca

# Arch Linux
yay -S stably-orca-bin

# Windows / Linux 或其他平台
# 访问 https://onorca.dev/download 下载安装包
```

安装后打开 Orca，登录你已安装的 agent（Claude Code、Codex 等），创建一个新的 workspace，然后：

1. 新建一个 worktree；
2. 在该 worktree 终端中启动 agent；
3. 点击"Duplicate to N agents"把同一个 prompt 扇出到多个 agent；
4. 等待结果，比较 diff，合并最优版本。

手机端下载 iOS App 或 Android APK 后，扫码与桌面端配对即可远程监控。

## 局限与风险

1. **生态尚早**：作为 2026 年 3 月才创建的项目，API 与插件生态还在快速迭代；
2. **重度依赖 Electron**：虽然功能丰富，但内存占用与启动速度不及纯终端工具（如 herdr、cmux）；
3. **IDE 厂商追赶**：VS Code、JetBrains、Cursor 都有动力把多 agent 工作流做进原生界面，Orca 的中立优势窗口期取决于大厂动作；
4. **需自带订阅**：Orca 本身免费，但实际使用仍需为每个 agent 单独付费，成本不低。
