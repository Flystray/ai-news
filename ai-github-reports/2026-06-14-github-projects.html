📌 项目背景

在 RAG（检索增强生成）和 LLM 训练数据准备的工作流中，文档解析是绕不开的基础环节——PDF 里的多栏排版、LaTeX 公式、跨页表格，每一项都是传统工具的噩梦。用 PyMuPDF 提取？乱码。用 Tesseract OCR？公式全废。用 GPT-4o 做 VLM 解析？精度不错但成本高昂，无法规模化。

MinerU 由上海人工智能实验室 OpenDataLab 团队开源（2024年7月首发），核心定位是将 PDF、图片、DOCX、PPTX、XLSX 等非结构化文档一站式转换为结构化 Markdown/JSON，专为 LLM 训练和 RAG 场景优化。项目在 GitHub 收获 67,454 Stars，是中文开源社区中 Star 数最高的文档解析项目，也是 2025 年 CVPR 发表的 OmniDocBench 评测基准的创建者。

MinerU 的技术演进路径极具启发性：从 1.x 的多模型 Pipeline，到 2.0 引入 0.9B VLM 实现"不到 1B 参数超越 72B VLM"，再到 2.5 以 1.2B 参数在 OmniDocBench 上全面超越 Gemini 2.5 Pro、GPT-4o、Qwen2.5-VL-72B，最后在 3.0 实现系统级跃迁——从单机工具演进为高并发企业级文档解析基座。小模型、专用化、持续迭代的路径，为"如何在垂直场景击败大模型"提供了教科书级的范例。

🚀 核心功能

1. 多后端协同架构，精度与速度兼得

MinerU 采用四类后端协同设计，用户无需理解底层差异，系统自动选择最优路径：

  • Pipeline 后端：多模型流水线（布局检测→OCR→公式识别→表格识别），纯 CPU 可运行，速度最快
  • VLM 后端：基于 1.2B InternVL 架构的视觉语言模型，单模型覆盖多语言/布局/表格/公式/阅读顺序
  • Hybrid 后端（3.0 默认）：文本 PDF 直接提取（零幻觉）+ 扫描 PDF 用 VLM 解析，兼顾精度与效率
  • Office 原生后端：DOCX/PPTX/XLSX 直接解析，无需经 PDF 渲染，速度比 PDF 路径快数十倍

2. 1.2B 参数的文档理解 VLM

MinerU 2.5 的核心模型基于 InternVL 架构（非 Qwen-VL），在结构化信息提取和细粒度视觉定位上有先天优势。两阶段推理流水线将布局分析与内容识别解耦，配合原生高分辨率架构，以 1.2B 参数实现了：

  • OmniDocBench 86.2 分（Pipeline 后端），超越前代 0.9B VLM
  • 文档类任务准确率比 Phi-3-vision、TinyLLaVA 等高出 18%+
  • PubLayNet 布局检测 F1 值达 92.3%

3. 复杂元素的精准还原

  • 数学公式：双阶段模型（MFD 检测 + MFR 识别），输出 LaTeX 格式，支持中英混合公式
  • 表格解析：区分有线/无线表格，支持旋转表格、跨页续表合并、表格内嵌图片/公式
  • 多语言 OCR：覆盖 109 种语言，PP-OCRv5 精度提升 40%+
  • 版式保留：完整还原标题层级、分栏排布、页眉页脚、图文关系

4. 企业级部署与高并发

3.0 版本实现了从工具到基础设施的跃迁：

  • mineru-router：多 GPU 一键部署 + 自动负载均衡
  • 异步任务 API：POST /tasks 提交+查询+获取结果
  • 线程安全：全面支持多线程并发推理
  • 滑动窗口：上万页长文档无需手动拆分，内存峰值可控
  • 流式落盘：已完成页面边解析边输出

5. 极致硬件兼容

支持 11 家国产计算平台：华为昇腾、寒武纪、海光、燧原、摩尔线程、天数智芯、昆仑芯等；Apple Silicon 通过 MLX 加速速度提升 100%~200%；INT8 量化后推理时间缩短 40%、内存下降 60%，可蒸馏至 600M 部署到移动端。

🔧 技术亮点

1. InternVL 架构的文档专用优化

MinerU 2.5 选择了 InternVL 而非更流行的 Qwen-VL 作为 VLM 基座，核心原因是 InternVL 在结构化信息提取和细粒度视觉定位上的天然优势——这正是文档解析的核心需求。Qwen-VL 更偏开放域问答和图像描述，而 InternVL 的视觉-语言对齐机制天然适合区域分割、单元格识别、公式语义解析等结构化任务。

2. Hybrid 后端的"零幻觉"设计

3.0 默认的 Hybrid 后端是一个精妙的设计：对于文本型 PDF，直接提取文本而非经过 VLM 推理，从根本上消除幻觉风险；对于扫描型 PDF，才启用 VLM 解析。这种"能直接取就不推理"的策略，在保证精度的同时大幅降低了计算成本。

3. Office 原生解析的数十倍加速

传统文档解析工具处理 DOCX 时，通常先转为 PDF 再解析，既丢失原生格式信息又浪费时间。MinerU 3.0 直接解析 Office 文档原生格式，速度提升数十倍，精度也更高——这是一个被多数竞品忽略的技术路径。

⚡ 快速上手

# 一键安装（含所有后端）
uv pip install mineru[all]

# 最简单的使用：单文件解析
mineru -p paper.pdf -o ./output

# 指定 Hybrid 后端（3.0 默认）
mineru -p document.pdf -o ./output --backend hybrid-auto-engine

# Python SDK
from mineru import do_parse
result = do_parse("paper.pdf", output_dir="./output")

# API 服务（生产部署）
mineru-api --host 0.0.0.0 --port 8000

# 多 GPU 负载均衡
mineru-router --workers http://gpu0:8000,http://gpu1:8000

⚠️ 使用注意

VLM 后端需要下载约 5GB 模型文件，首次运行较慢。Pipeline 后端对极复杂手写文档的识别精度有限，建议结合 Mathpix 等专用工具协同处理。3.0 版本移除了 AGPLv3 限制性模型许可，但部分下游依赖仍有各自许可条款。
  • 硬件推荐：Pipeline 后端纯 CPU 即可；VLM 后端推荐 NVIDIA GPU 8GB+ 显存
  • Office 格式：DOCX/PPTX/XLSX 原生解析为 3.0 新增，部分复杂格式可能存在边缘 case
  • 中文公式：Pipeline 后端中文公式需启用环境变量 MINERU_FORMULA_CH_SUPPORT=1
  • 性能优化：大规模部署建议使用 mineru-router + 多 GPU + INT8 量化
