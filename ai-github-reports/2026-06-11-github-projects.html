📌 项目背景

你在用 Claude Code、Cursor 等AI编程助手时，是不是经常遇到这些尴尬场景：

  • 聊着聊着，它就忘了最开始说的目标
  • 运行 /clear 清上下文，它又得重新理解项目
  • 50次工具调用后，它已经偏到不知哪去了
  • 同一个报错试了三遍——因为它不记得之前已经失败了

这些问题的根源都是同一个：AI的记忆是临时的，没有持久化。上下文窗口就像RAM——快但容量有限，重启就丢。

planning-with-files 就是为解决这个问题而生的。它的核心思路来自 Manus AI——那个8个月内从启动到1亿美元营收、2025年12月被Meta以20亿美元收购的AI Agent公司。Manus的核心秘诀就是："Markdown是我的'工作记忆'磁盘。由于我迭代式处理复杂任务，上下文窗口不可避免地会被压缩，所以我把任何重要信息都写入磁盘。"

planning-with-files 将这套思路在 Claude Code 生态中开源实现，通过持久化的文件系统替代易失的上下文窗口，让AI编程助手从"重启即忘"变成"永久记忆"。截至2026年6月，项目已获得 23k+ Stars，支持 60+ AI编程平台，v3.0.0新增了autonomous和gated两种运行模式。

🚀 核心功能

1. 三文件持久化记忆系统

将AI的"工作记忆"从易失的RAM转移到持久的磁盘，通过三个职责分明的Markdown文件构成完整的任务执行元认知框架：

文件职责更新时机对应问题
task_plan.md做什么——任务路线图、阶段划分、进度checkbox每个阶段完成后目标漂移
findings.md发现了什么——技术决策、代码库分析、踩坑记录每2次浏览/搜索操作后重复研究
progress.md做了什么——会话日志、测试结果、操作时间线整个会话期间上下文断裂

三文件设计的关键智慧在于"各司其职"：计划管进度，笔记管知识，日志管时间线。下次接手任务时，先看task_plan知道进度，再看findings知道背景——信息检索效率远高于在冗长上下文中翻找。

2. 五钩子自动化生命周期

项目利用Claude Code的Hook系统，在关键节点自动触发特定行为，形成闭环：

Hook触发时机核心动作
SessionStart启动时注入计划文件内容为系统背景
UserPromptSubmit用户提交指令前静默注入task_plan前50行 + progress末20行
PreToolUse ⭐每次工具调用前截取task_plan前30行，通过stderr"耳语"目标提醒（非阻塞）
PostToolUse文件修改后提醒更新progress.md并勾选checkbox
Stop ⭐想停止时运行check-complete.sh正则扫描，发现未完成则阻断退出（最多3次）

PreToolUse是防止"目标漂移"的核心武器：每次动手之前先看计划，就像导航每到路口都提醒方向。而Stop钩子则是"完成守门员"——不允许AI在任务没做完时擅自停止。

3. 会话恢复系统（session-catchup）

当上下文窗口满了执行 /clear 或开启新对话时，系统自动检测并生成恢复报告：

📋 会话恢复报告
上次活动: 2小时前 | 任务进度: ████████░░ 40%
✅ 已完成: Phase 1, Phase 2
🔄 进行中: Phase 3 (2/4)
💡 最近发现: next-mdx-enhanced 已停止维护
🚧 未解决问题: rehype 插件与 Next.js 冲突

session-catchup.py脚本从JSONL会话日志中深层扫描，智能截取自上次task_plan变动后的新对话，以不超过100行的精华摘要重新注入新会话——实现跨会话无缝接续。

4. v3.0 新增：autonomous 与 gated 模式

  • autonomous模式：AI自主规划并执行，适合长周期自动化任务
  • gated模式：引入确定性完成守门员（Completion Gate），AI必须等到计划所有阶段都真正标记为complete才能停止
  • 默认模式不变，现有设置无需任何更改，两种新模式均为opt-in

5. SHA-256 计划认证（attest-plan）

v2.37.0引入的安全机制：对task_plan.md生成SHA-256哈希值，提供密码学保证——防止计划在执行过程中被悄无声息地篡改。将安全机制直接嵌入AI Agent工作流，这是非常前沿的独特实践。

6. 多智能体并行计划管理

支持多智能体同时维护不同计划，通过三级优先级级联解析：

$MANUS_PROJECT (环境变量，最高优先级)
    ↓
.planning/.active.override.$SESSION_ID (会话级隔离)
    ↓
.planning/index.md 中的 active: 字段 (工作区默认)

利用终端唯一会话ID实现天然沙箱隔离，支持自然语言切换（如"switch to backend-api"）。

7. 四条黄金行为守则

守则机制
强制优先规划未创建task_plan.md前禁止写代码
读而后决架构决策前强制重读task_plan.md

三击错误防范错误记录 + 根因分析 + 变异解决方案

⚙️ 技术亮点

1. 文件系统即外部工作记忆的架构范式

将计算机体系结构的内存层次模型映射到AI Agent工作上下文：上下文窗口=RAM（易失、有限、快），文件系统=Disk（持久、无限、稍慢）。核心原则"任何重要信息都写入磁盘"看似朴素，实则是对AI编程最核心痛点的精准打击。对比传统做法——把所有信息塞进上下文窗口导致Token爆炸——planning-with-files的Hooks只在关键时刻读取，反而更节省Token。

2. PreToolUse stderr"耳语"注入机制

不同于UserPromptSubmit的静默注入（占上下文空间），PreToolUse采用了一个巧妙的技术实现：通过标准错误流（stderr）以非阻塞方式注入目标提醒。这种方式不占用正式上下文窗口空间，决策始终为allow（不阻止工具调用），只在AI的"注意力后台"轻声提醒当前目标——实现了真正的注意力刷新而非注意力堆砌。

3. 60+ 平台的标准化技能适配

项目通过SKILL.md标准实现了跨平台技能分发，覆盖Claude Code、Codex CLI、Cursor、Gemini CLI、Hermes Agent、Pi Agent、Kiro、OpenCode等60+ AI编程平台。同时提供Unix Shell脚本和Windows PowerShell脚本双版本支持，以及5种语言的国际化。

mkdir -p .claude/plugins

  .claude/plugins/planning-with-files

安装后，在处理复杂任务前运行 /plan 即可启动三文件模式。核心命令：

命令用途
/plan初始化或恢复规划会话
/plan:status查看当前进度报告
/plan-attestSHA-256锁定当前计划

⚠️ 使用注意

简单任务别用！对于"改个变量名"这种2分钟就能搞定的事，三个文件反而增加开销。判断标准：工具调用 > 5次才值得用。
  • 阶段别切太细也别太粗：10-30分钟一个阶段最合适。太细导致计划文件很长，太粗失去追踪意义
  • 有重要发现就更新findings：别等2次操作后才整理，临时记忆不可靠
  • 定期归档：完成的文件移到 .archive/ 目录，避免项目根目录变乱
  • 钩子版本要求：完整的Hook功能需要 Claude Code v2.1.0+
  • 计划不是死的：随时可以调整阶段——发现某阶段比预期复杂就拆分，不需要就删掉
