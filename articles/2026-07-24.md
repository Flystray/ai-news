## 🎯 它是什么

cmux 是一个**专为 AI 编码代理（AI Coding Agents）设计的原生 macOS 终端应用**。它由 Manaflow 团队基于 Ghostty 的底层渲染库 `libghostty` 构建，2026 年 1 月底开源，短短 6 个月斩获 25.0k Stars，社区讨论热度极高——Ghostty 创始人 Mitchell Hashimoto 也公开称赞它是 "another libghostty-based project... specifically targeted towards people who use a ton of terminal-based agentic workflows"。

简单来说：如果你每天在终端里同时跑 Claude Code、Codex、OpenCode、Gemini CLI、Aider 等 3 个以上 AI 代理，cmux 把传统的"终端标签页"升级为**带 Agent 状态感知的工作区指挥中心**——哪个代理正在工作、哪个卡在等待确认、哪个已经跑完，全部通过侧边栏和蓝色通知环一目了然。

---

## ✨ 核心功能

### 1. 垂直标签工作区：把"标签页"变成"任务上下文"
cmux 左侧边栏采用垂直标签设计，每个工作区不是简单的会话名，而是一个**高密度信息面板**，直接显示：
- 当前 Git 分支
- 关联 PR 的状态和编号
- 工作目录（CWD）
- 监听端口
- 最新通知文本

这让你一眼就能定位"refactor/db-migration"分支上的 Codex 会话，而不用在 10 个水平标签里反复寻找。

### 2. Agent 通知环：从"人找 Agent"到"Agent 找人"
当某个 Agent 完成任务或卡在确认 prompt 时，对应窗格会亮起**蓝色光环**，侧边栏标签同步高亮，并触发 macOS 桌面通知。通知来源有三条路径：
- **CLI 触发**：`cmux notify --title "Claude Code" --body "任务完成"`
- **OSC 777 标准转义序列**：任何 shell/Python/Node 脚本都能发送
- **OSC 9/99 协议**：兼容 Kitty 等现代终端的富通知格式

这意味着你可以睡前启动 10 个 Agent，早上只看带 badge 的标签，彻底告别"每个 pane 点一遍"的体力活。

### 3. 内置可编程浏览器：Agent 可以直接操作网页
终端旁可分割出一个真正的浏览器窗格，基于 WKWebView 实现，并暴露完整的自动化 API：
- 导航、DOM 快照、元素引用
- 点击、填表、执行 JavaScript
- 读取控制台和网络活动

Agent 在改完前端代码后，可以直接在内置浏览器验证渲染结果，无需你手动切到 Chrome。更妙的是，SSH 远程工作区里的浏览器窗格会自动通过远程网络路由，`localhost:3000` 在远端直接可用。

### 4. Claude Code Teams 原生支持
运行 `cmux claude-teams`，Claude Code 的 teammate 模式会被渲染成原生分屏，每个 teammate 拥有独立侧边栏元数据和通知状态。你不需要背诵 tmux 前缀键，也不用在 pane 之间手动调度——cmux 把多 Agent 协作变成可见、可控的 GUI 工作流。

### 5. CLI + Unix Socket API：完整可编程性
几乎所有 GUI 操作都能通过脚本驱动：
- 创建工作区、分屏、发送按键
- 读取屏幕内容、截图
- 控制浏览器行为
- 设置状态栏文本

这套 API 让 cmux 不只是终端，更是一个**本地 Agent 编排基础设施**——CI/CD 完成可以通知你，自定义脚本可以批量启动会话，外部工具可以读取 Agent 状态。

### 6. 原生 Swift + AppKit，拒绝 Electron
cmux 是原生 macOS 应用，不是 Electron/Tauri 封装。启动快、内存占用低、GPU 渲染流畅。它直接读取你现有的 `~/.config/ghostty/config`，主题、字体、颜色、键位绑定全部无缝迁移。

### 7. 会话恢复与 Agent Vault
关闭 cmux 时，窗口、工作区、pane 布局、工作目录、浏览器 URL 都会被快照保存，重启后可恢复。配合 Agent Vault（`SessionIndexStore`），Claude Code、Codex、OpenCode 等 Agent 会话也能被索引和恢复。

## ⚙️ 技术亮点

### 亮点一：把 libghostty 当作"终端界的 WebKit"
cmux 不是 Ghostty 的分支，而是把 `libghostty` 当作渲染库嵌入到 Swift/AppKit 外壳中——就像浏览器应用使用 WebKit 渲染网页一样。这种架构让它同时获得：
- Ghostty 的 GPU 加速渲染能力（120fps+ 流畅处理大量输出）
- 原生 macOS GUI 的鼠标、通知、窗口管理能力
- 对 `~/.config/ghostty/config` 的零迁移成本兼容

### 亮点二：基于标准 OSC 序列的 Agent 通知捕获
cmux 的通知系统没有搞私有协议，而是监听标准终端转义序列 OSC 9/99/777。任何能向 stdout 写字符的 Agent 或脚本都能触发通知，这让它**Agent 无关**——Claude Code、Codex、OpenCode、Aider、Goose、Gemini CLI 等全部开箱即用。

### 亮点三：SwiftUI + AppKit 混合架构与 Bonsplit 布局引擎
根据 DeepWiki 对代码结构的解析，cmux 采用 SwiftUI + AppKit 混合架构：
- `cmuxApp` 作为 `@main` 入口，初始化全局状态
- `TabManager` 管理核心应用状态
- `ContentView` 协调侧边栏与工作区内容
- `BonsplitController` 负责终端、浏览器、文件预览的复杂分屏布局
- `TerminalController` 监听 Unix socket，供外部 CLI 和 Agent 调用

这种分层让高性能渲染（libghostty）和现代 UI 开发（SwiftUI/AppKit）各得其所。

## 👥 适用人群

| 人群 | 说明 |
|------|------|
| 🧑‍💻 多 Agent 并行开发者 | 同时跑 Claude Code + Codex + Aider，需要视觉化状态监控 |
| 🍎 macOS 原生性能党 | 厌倦 Electron 终端的卡顿和高内存占用 |
| 🌐 全栈/前端开发者 | 需要终端和浏览器并排、Agent 自动验证网页改动 |
| 🏗️ 工具链/自动化工程师 | 想基于 Socket API 构建自定义 Agent 工作流 |
| 🚀 追求开箱即用的团队 | 不想写 200 行 tmux 配置，希望 GUI 即开即用 |

**不适用**：Windows/Linux 用户、重度依赖 tmux 会话持久化进行服务器远程开发的用户、只跑单个 Agent 的轻量用户。

## 🚀 快速上手

```bash
# 方式一：Homebrew
brew tap manaflow-ai/cmux
brew install --cask cmux
brew upgrade --cask cmux

# 方式二：DMG 下载（推荐首次安装）
# 访问 https://github.com/manaflow-ai/cmux/releases/latest/download/cmux-macos.dmg
# 打开 .dmg 后将 cmux 拖入"应用程序"文件夹

# 配置 CLI（方便外部脚本调用）
sudo ln -sf "/Applications/cmux.app/Contents/Resources/bin/cmux" /usr/local/bin/cmux

# 验证
cmux list-workspaces
cmux notify --title "Hello" --body "cmux CLI is working"

# 安装 Agent hooks（可选，支持会话恢复和精准通知）
cmux hooks setup
# 或指定 Agent
cmux hooks setup claude
cmux hooks setup codex
```

系统要求：**macOS 14.0+**，Apple Silicon 或 Intel。首次启动时 macOS 会提示"来自未验证开发者"，点击"打开"即可。

## 💡 为什么值得关注

1. **瞄准一个真实的新痛点**：AI 编码 Agent 普及后，"同时管理多个 Agent"成了日常，但传统终端完全没为此优化。cmux 是这个新品类的代表性产品之一。
2. **增长极快**：2026 年 1 月开源，6 个月到 25.0k Stars，社区口碑和官方认可度都很高。
3. **架构选择克制而聪明**：不重复造轮子，用 Ghostty 的渲染引擎 + 原生 macOS GUI，既保证性能又降低迁移成本。
4. **Agent 无关设计**：不绑定任何单一 Agent，支持 15+ 主流 CLI Agent，避免被某个厂商锁定。
5. **可编程性使其超越"终端"**：CLI + Socket API 让 cmux 成为本地 Agent 编排的可视化基础设施。

---

## ⚠️ 注意事项

- **macOS 独占**：目前不支持 Windows/Linux，跨平台团队需谨慎。
- **会话恢复不等于进程恢复**：cmux 恢复窗口布局和元数据，但运行中的 Agent 进程不会自动复活。
- **GPL 许可**：源码采用 GPL-3.0-or-later，商业嵌入或分发修改版需联系 Manaflow 获取商业授权。
- **相对年轻**：虽然增长快，但生态和插件成熟度不如 iTerm2/tmux 等十年级产品。
