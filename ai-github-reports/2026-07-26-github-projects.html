作者故事：从被裁到 AI 工程师

2025 年底，Mads Lorentzen 的地球物理学家职位被裁减。他没有马上海投，而是花了三个月用 Claude Code 搭建了自己的求职自动化框架——相同的 /scrape、/apply、/interview 工作流，每周跑一遍。

他对每个交谈的雇主都坦诚地谈论这件事，这通常引发了真正的技术对话而非成为障碍。69 份定制化申请、20 次初轮面试、1 份签约合同——2026 年 6 月，他正式以 AI 工程师身份入职。他把这套工具开源了，四个月不到收获 27.1k Star。

核心理念：Fork 仓库 → 填写你的职业档案 → 让 Claude 替你评估职位、定制简历、撰写求职信、准备面试。不是"AI 帮我写简历"的浅尝辄止，而是一个完整的求职 Agent 工作台。

核心功能：13 条命令构成求职流水线

1. /setup — 个人画像建模

三种路径自动检测已有材料：读取 documents/ 文件夹（CV PDF、LinkedIn 导出、学历证书、推荐信）、粘贴单份简历、或走结构化访谈。生成 7 个 Markdown 文件存储画像，涵盖教育、经验、技能、行为性格评估、写作风格、契合度评分框架、LaTeX 模板和 STAR 面试素材。预计 30+ 分钟，资料深度决定后续所有产出质量。

2. /scrape — 多门户岗位搜索与去重

协调 6 个 TypeScript CLI 代理搜索 Jobindex、Jobnet、Jobbank、Jobdanmark、LinkedIn 公共端点、freehire.me，使用 seen_jobs.json 去重，按契合度排序记录到 job_search_tracker.csv。

3. /rank — 批量并行评分

5 个维度（技能匹配、经验相关性、文化契合、地点匹配、职业轨迹逻辑）并行评估所有抓取结果，返回带诚实优势和差距的排名短名单。

4. /apply — 起草者-审查者工作流（8步状态机）

解析职位 → 评估五维契合度 → 起草 LaTeX 简历和求职信 → 生成审查者代理（全新上下文独立批评）→ 起草者修订 → 编译 PDF 并视觉验证（简历 2 页/求职信 1 页）→ ATS 文本层验证 → 呈现最终输出。审查者像招聘经理一样怀着敌意阅读，检查是否真正回应公司具体挑战、是否有夸大声明。

5. /interview — 面试准备

构建阶段特定准备包，研究公司和面试官，STAR 例子映射到可能问题，模拟面试。诚实桥接知识差距，绝不编造经验。

6. /expand — 公开来源画像丰富

扫描 GitHub、作品集、Kaggle、Google Scholar 等公开来源，发现你可能没提到的胜任力并添加到资料中。

7. /upskill — 技能差距分析

分析资料与岗位需求差距，生成优先级技能热图和学习计划，含网络搜索的学习资源和时间估算。

8. /outcome — 结果记录与反馈闭环

记录申请结果（面试/录用/拒绝/沉默），归档已提交材料到 documents/applications/。支持 followup 变体起草跟进邮件（仅起草不发送）。

9. /add-portal & /add-template — 可扩展架构

/add-portal 为任意本地招聘网站生成搜索技能——自动摸清搜索 URL 规律、结果结构、访问规则。/add-template 注册自定义 LaTeX 模板。

10. /gmail-sync & /notion-sync — 生态集成

读取 Gmail 获取申请状态信号，批量提议更改。发布只读管道视图到 Notion 数据库。

11. /html-report — 离线仪表板

从 job_search_tracker.csv 生成自包含 HTML 仪表板，统计卡片+漏斗图表+可过滤申请表，内联 SVG 无外部依赖。

技术亮点

1. 起草者-审查者对抗架构

第一个 Claude 代理起草，第二个代理以全新上下文生成——对草稿没有"忠诚度"，像招聘经理一样怀着敌意阅读，检查是否真正回应了公司的具体挑战（而非岗位标题）、CV 是否强调了正确项目（而非最亮眼的项目）、是否有超出资料支撑的夸大声明。起草者随后修订。这个模式可推广到合同起草、基金申请、客户提案等任何高风险 agent 场景。

2. PDF 验证循环 + ATS 文本层诚实检查

系统自己编译 LaTeX、自己看渲染结果、自己修。简历必须恰好 2 页无孤行标题，求职信必须恰好 1 页签名可见。然后提取 PDF 文本层验证 ATS 可读性：联系方式作为字面文本存在、无乱码、合理阅读顺序、关键词覆盖率评分。资料不支持的关键词被承认为差距，绝不填充。

3. 安全加固：职位发布视为不受信任输入

工作流不遵循职位发布中嵌入的指令，不从其正文中获取链接——针对 /apply 和 /rank 的提示注入加固。审查者研究约束于用户确认的公司身份。.gitignore 忽略任何深度的抓取器状态和面试记录，防止在公共 fork 上泄露隐私。

4. 相关性加权简历切割

当简历溢出 2 页时，按 (a) 与目标职位的相关性、(b) 文档中的独特性、(c) 求职信是否依赖它来评分每行，先切割最低总分行——智能保留最有价值的内容。

一句话总结：把求职材料视为对抗性文档而非表格填空，每一份简历和求职信都要经过"另一个 agent 假装是招聘经理来找茬"的审查环节。

核心差异：大多数工具的目标是让你"快速生成"，ai-job-search 的目标是让你"经得起审查"。它把求职材料视为对抗性文档——每一份都要经过另一个 agent 的敌意批评后才能输出。

快速上手

# 1. Fork 并克隆
gh repo fork MadsLorentzen/ai-job-search --clone
cd ai-job-search

# 2. 安装求职搜索工具（以 jobindex-search 为例）
cd .agents/skills/jobindex-search/cli && bun install && cd ../../../..

# 3. 进入 Claude Code 录入资料
claude
# 在 Claude Code 内执行：
/setup

# 4. 搜索岗位
/scrape

# 5. 申请（URL 或粘贴 JD 全文）
/apply https://jobindex.dk/job/1234567

前置依赖：Claude Code (CLI)、Python 3.10+、Bun、LaTeX 发行版（需 lualatex 和 xelatex）、可选 pdftotext（poppler，用于 ATS 检查）。

关键提示：资料深度决定一切。别只写职位名称——要写具体做了什么、用了什么工具、有什么可量化成果。

适用人群

  • 正在求职的人：想把重复的申请流程自动化，但要"能真投出去"的简历
  • 投海外岗位的人：尤其丹麦/北欧市场（自带 4 个门户），其他国家用 /add-portal 自定义
  • Claude Code 用户：想探索 agent skill 在非代码场景的落地模式
  • Agent 架构师：起草者-审查者对抗模式、验证门控、市场插件化——可直接借鉴的工程范式
  • 职业转型者：/upskill 的技能差距分析和学习计划，系统化规划转型路径

局限与风险

  1. Claude API 成本：/apply + 审查者 + /rank 并行代理消耗 token，频繁使用需注意费用
  2. LaTeX 依赖：深度绑定 LaTeX 简历体系，不用 LaTeX 需自行换模板
  3. LinkedIn 灰色地带：linkedin-search 走公开未认证接口，违反 ToS，仅限个人使用
  4. 门户覆盖：自带的 4 个门户均为丹麦市场，其他国家需用 /add-portal 自行扩展
  5. 个人框架而非 HR 软件：你对提交材料的真实性负最终责任
