## 项目背景

2026年2月，Google Gemini 团队主管、AngularJS 联合创始人 **Addy Osmani** 在 GitHub 上发布了一个令人眼前一亮的新项目——**Agent Skills**。

这个项目的诞生，源于一个所有 AI 编程工具都面临的共同困境：**AI 代理默认选择最短路径——跳过需求文档、跳过测试、跳过安全评审、省略那些让软件真正可靠的最佳实践。**

Agent Skills 的核心使命，是将 Google 二十年的工程实践封装成 AI 可执行的技能模块，通过 7 个 Slash 命令让 Claude Code、Cursor、Windsurf、Gemini CLI 等主流 AI 编程工具在工程成熟度上直接对齐 Google 标准。

从 2 月发布到 5 月，这个项目已狂揽 **4 万+ Stars**，成为 2026 年最受关注的 AI 编程辅助工具之一。

## 核心功能

### 1. 六阶段开发流程（DEFINE → PLAN → BUILD → VERIFY → REVIEW → SHIP）

Agent Skills 围绕软件开发的六个核心阶段设计了完整的工作流框架：

| 阶段 | 激活命令 | 核心理念 |
|------|----------|----------|
| **DEFINE（定义）** | `/spec` | 规约优先，在写代码之前定义清楚要做什么 |
| **PLAN（规划）** | `/plan` | 小的原子化任务，确保每个任务都可验证 |
| **BUILD（构建）** | `/build` | 一次只做一块，薄垂直切片实现 |
| **VERIFY（验证）** | `/test` | 测试就是证明，TDD 红-绿-重构 |
| **REVIEW（评审）** | `/review` | 五轴代码审查（功能/安全/可维护/性能/风格） |
| **SHIP（发布）** | `/ship` | CI/CD 流水线，质量门禁保障 |

这个六阶段流程通过技能系统自动触发——当你输入 `/spec` 时，系统自动激活 `spec-driven-development` 技能；输入 `/test` 时，自动激活 `test-driven-development` 技能。AI 代理不再是"自由发挥"，而是被结构化的工作流所约束。

### 2. 20 个核心技能模块

覆盖软件开发全生命周期的 20 个结构化技能：

**Define 层**：
- `idea-refine`：将模糊想法转化为结构化提案
- `spec-driven-development`：编写 PRD，覆盖目标、接口结构、代码风格、测试策略

**Build 层**：
- `planning-and-task-breakdown`：将 Spec 分解为可验证的小任务
- `incremental-implementation`：垂直切片开发，小步提交（约 100 行/次）
- `test-driven-development`：红绿重构、测试金字塔
- `context-engineering`：正确的上下文注入时机和方式
- `source-driven-development`：以官方文档为依据而非个人经验
- `frontend-ui-engineering`：组件架构、设计系统、无障碍标准
- `api-and-interface-design`：契约优先设计、Hyrum 法则

**Ship 层**：
- `browser-testing-with-devtools`：Chrome DevTools MCP 集成
- `debugging-and-error-recovery`：五步调试法
- `code-review-and-quality`：五轴 Review
- `code-simplification`：Chesterton 栅栏原则、500 行法则
- `security-and-hardening`：OWASP Top 10 防护
- `performance-optimization`：Core Web Vitals 分析
- `git-workflow-and-versioning`：基于主干的开发工作流
- `ci-cd-and-automation`：左移策略、质量门禁
- `deprecation-and-migration`：代码即负债思维
- `documentation-and-adrs`：架构决策记录
- `shipping-and-launch`：发布检查清单

### 3. 创新设计：反合理化机制（Anti-Rationalization）

这是 Agent Skills 最具创新性的设计——为每个技能配备的"常见借口表"：

| AI 常见借口 | 正确反驳 |
|------------|----------|
| "功能很简单，不需要测试" | 测试的目的是证明代码能做它应该做的事，不是证明代码"简单" |
| "我会在后面加上测试" | 后续测试的覆盖率平均只有 TDD 的 30%，且测试质量显著更低 |
| "手动测试过了" | 手动测试不能防止未来的回归，是一次性消耗 |
| "PR 太小了不用 Review" | 评审的价值不仅在于发现问题，还在于知识传播和团队标准对齐 |

这种设计从根本上解决了 AI 代理"偷懒"的问题——不是告诉 AI "要做什么"，而是显式列举"不要用哪些借口跳过"。

### 4. 多平台无缝集成

| 平台 | 支持方式 |
|-----|---------|
| **Claude Code** | 原生 7 个 Slash 命令支持（推荐） |

## 技术亮点

### 1. 技能 Anatomy 结构

每个 Skill.md 遵循统一的解剖结构：

```
name: skill-name
description: 指导AI完成[任务]。当[某些条件]时使用。
──────────────────────────────────────────
Overview          → 技能概述
When to Use       → 触发条件
Process           → 步骤1、步骤2、步骤3...
Rationalizations  → 借口表 + 反驳
Red Flags         → 警告信号
Verification      → 证据要求（必须通过什么才能结束）
```

这种标准化格式确保了技能的**可扩展性和一致性**——任何人都可以按照这个模板贡献新的技能。

### 3. 完整的工程实践封装

Agent Skills 不仅仅是代码规范，而是将 Google 的工程文化完整封装：

- **API 设计**：Hyrum 定律（暴露给用户的 API 难以更改）、一版本规则
- **测试实践**：Beyonce 规则（"If it doesn't work, that's on you"）、测试金字塔（80% 单元 / 15% 集成 / 5% E2E）
- **代码评审**：变更大小限制（约 100 行）、评审速度规范（24 小时内响应）
- **Git 工作流**：主干开发、原子提交、语义化提交信息
- **CI/CD**：左移策略、特性标志、质量门禁
- **债务管理**：专门的废弃迁移技能，"代码即负债"思维

## 快速上手

### Claude Code（推荐）

```bash
# Marketplace 安装
/plugin marketplace add addyosmani/agent-skills
/plugin install agent-skills@addy-agent-skills

# 验证安装
/help  # 确认 7 个新命令可用
```

### Cursor

```bash
# 在项目根目录创建规则文件夹
mkdir -p .cursor/rules

# 将需要的 Skill 复制到 rules 目录（以 TDD 为例）
cp -r agent-skills/skills/test-driven-development .cursor/rules/
```

### Gemini CLI

```bash
# 从仓库安装
gemini skills install https://github.com/addyosmani/agent-skills.git --path skills

# 从本地克隆安装
gemini skills install ./agent-skills/skills/
```

### 快速体验

```bash
# 体验六阶段流程的第一步
/spec 为我的个人博客写一个图片懒加载功能

# 体验 TDD 开发
/test 实现邮箱验证功能
```

| 维度 | Agent Skills | Cursor Rules |
|-----|--------------|--------------|
| **设计目标** | 工程流程标准化 | 代码风格约束 |
| **覆盖范围** | 完整开发周期（需求→发布） | 单点代码规范 |
| **执行方式** | 主动引导（Slash 命令） | 被动检查 |
| **工程实践** | ✅ 20 个 Google 技能 | ❌ 无内置 |
| **验证机制** | 明确的退出标准 + 证据要求 | 无 |

### vs 其他 AI 编程工具

| 维度 | Agent Skills | Cline | 其他 Agent |
|-----|--------------|-------|----------|
| **工作流** | 完整 SDLC 六阶段 | 任务自动化 | 单点执行 |
| **工程实践** | 20 个 Google 技能 | 插件生态 | 无 |
| **质量门禁** | 内置 | 无 | 无 |
| **适用场景** | 企业级开发 | 快速任务 | 简单脚本 |

**核心差异**：Agent Skills 不让 AI "更聪明"，而让 AI "更有纪律"。它是目前最完整的 AI 编程工程实践框架，将"什么是好代码"从主观问题变成**可执行、可验证的工作流**。

## 注意事项

- Agent Skills 当前主要围绕 Claude Code 生态设计，其他工具的支持程度略有差异
- 需要团队对六阶段开发流程有基本认知，流程有一定学习成本
- 技能文件的维护需要持续投入，建议建立内部贡献流程
- 快速原型验证场景下，完整流程可能显得过于"重"，需要灵活取舍
