📌 项目背景

AI 编程助手（Cursor、Claude Code、GitHub Copilot 等）已经能帮我们写代码、改 Bug，但它们有一个共同的盲区：不理解代码库的整体结构。

当你让 AI "修改用户认证逻辑"时，它往往不知道这个改动会影响哪些模块。结果就是：AI 改了一处，别处悄悄崩了。

GitNexus 正是来解决这个问题的——把整个代码库构建成知识图谱，让 AI Agent 在回答之前就能"看见"完整的依赖关系网络。

所有计算完全在本地机器上运行，代码永远不会离开你的设备。

🚀 核心功能

🕸️ 代码知识图谱

将整个代码库构建成完整关系图谱，追踪每个依赖、调用链、聚类和执行流程

🔌 MCP 集成

通过 16 个 MCP 工具向 AI 编辑器暴露代码上下文，一次调用返回完整依赖视图

🌐 完全本地运行

代码不上传任何服务器，通过 Bridge 模式配合 Web UI 可视化浏览知识图谱

🤖 4 个 Agent Skills

自动安装探索、调试、影响分析、重构 4 个 Skills，让 AI 深度理解代码库

📊 爆炸半径分析

改动前预判影响范围，附置信度评分，防止引入破坏性变更

🌍 14 种语言支持

TypeScript/JavaScript/Python/Java/C#/Go/Rust 等主流语言全覆盖

💡 技术亮点：预计算智能

为什么比传统 Graph RAG 更高效？

传统 Graph RAG：LLM 收到问题 → 查询图数据库 → 遍历边 → 收集上下文 → 生成答案。需要多次往返查询，Token 消耗大。

GitNexus：在索引阶段就把关系算好（聚类、调用链、置信度评分），当 AI 调用工具时直接返回预处理好的完整上下文，不需要 LLM 自己探索图。

✅ Token 消耗大幅降低 | ✅ 较小的 LLM 也能完成复杂任务 | ✅ 不会遗漏关键上下文

🔧 两种使用模式

模式一：CLI + MCP（推荐日常开发）

# 索引你的仓库（从仓库根目录运行）
npx gitnexus analyze

# 配置编辑器 MCP（仅首次需要）
npx gitnexus setup

# 启动 MCP 服务器
npx gitnexus mcp

支持 Cursor、Claude Code、Codex、Windsurf、OpenCode，数据存储在本地 .gitnexus/ 目录。

模式二：Web UI 可视化（Bridge 模式）

GitNexus 提供浏览器端可视化界面，需要配合本地服务器使用：

# 启动本地服务器
npx gitnexus@latest serve

# 浏览器打开 gitnexus.vercel.app
# 页面会自动检测本地服务器并连接

代码完全在本地处理，不会上传到任何云端服务器。支持查看所有已索引的仓库，无需重复上传。
