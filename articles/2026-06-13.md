# agent-browser：Vercel Labs 开源，专为 AI Agent 设计的浏览器自动化 CLI

> 📅 2026-06-13 | ⭐ 36,000+ | 🔧 Rust / TypeScript | 🔗 [GitHub](https://github.com/vercel-labs/agent-browser) | [官网](https://agent-browser.dev) | [DeepWiki](https://deepwiki.com/vercel-labs/agent-browser)

## 项目背景

2025 年以来，AI Agent 的爆发式增长带来了一个尴尬的工程现实：**AI 能理解自然语言，却无法直接操作网页**。传统的浏览器自动化工具（Playwright、Puppeteer、Selenium）都是为"人类写脚本"设计的——它们依赖 CSS 选择器、XPath，需要把整个 DOM 树塞进 LLM 的上下文窗口，导致一次简单登录操作就能消耗 20,000+ Token。

更棘手的是，网页 DOM 结构随时可能改变，写死的选择器像纸糊的一样脆弱。AI Agent 每操作一个网页，就要重新解析整页 HTML，既浪费 Token，又容易出错。

**agent-browser** 正是为解决这个核心痛点而生。它由 **Vercel Labs**（Next.js、Vercel 背后的团队）开源，采用 Apache-2.0 协议，目前已在 GitHub 收获 **36,000+ Stars**，是 2026 年 AI Agent 工具链中最受关注的浏览器自动化项目之一。

项目的核心设计哲学可以用一句话概括：**让浏览器适配 AI，而非让 AI 适配浏览器**。它用无障碍树（Accessibility Tree）替代 DOM 树，用稳定引用（Refs）替代 CSS 选择器，用纯 Rust 守护进程替代 Node.js 重型运行时——最终实现了一个 AI Agent 友好、高性能、生产可用的浏览器自动化方案。

## 核心功能

### 1. 快照-引用工作流（Snapshot-Ref Workflow）

这是 agent-browser 最具革命性的功能。传统方案需要 AI 解析整页 HTML（数万行），而 agent-browser 的 `snapshot` 命令只返回**可交互元素的精简列表**，每个元素被分配一个稳定引用编号（如 `@e1`、`@e2`）：

```bash
agent-browser open https://example.com
agent-browser snapshot -i --json
# 输出（精简版）：
# - 按钮 "登录" [ref=@e1]
# - 输入框 "用户名" [ref=@e2]
# - 链接 "忘记密码" [ref=@e3]
```

后续所有操作直接使用引用编号，无需重新解析页面：
```bash
agent-browser click @e1
agent-browser fill @e2 "my-username"
```

**效果**：相同登录任务，Token 消耗从 Playwright 的 ~20,000 降至 ~1,400，**节省 93%**。

### 2. 纯 Rust 守护进程架构——极致性能

agent-browser 采用**客户端-守护进程-浏览器**三层架构：

```
Rust CLI（命令解析，~1ms 启动）
    ↓ IPC（Unix Socket / TCP）
Rust 守护进程（持久化，管理浏览器生命周期）
    ↓ Chrome DevTools Protocol（CDP）
Chrome / Chromium（浏览器引擎）
```

关键设计：守护进程在首次命令时自动启动，后续命令**复用同一进程**，避免了每次操作都重启浏览器的巨大开销。热命令延迟优化至 **~1ms**，比传统方案快两个数量级。

Rust 守护进程直接通过 CDP 协议控制浏览器，无需 Playwright 或 Node.js 依赖（v0.16+ 已移除 Playwright 依赖，纯 Rust 实现）。

### 3. 会话管理与认证持久化

AI Agent 经常需要登录后执行操作，agent-browser 提供了多种认证方案：

- **Chrome Profile 复用**：直接使用本机 Chrome 的登录状态（`--profile Default`）
- **会话持久化**：`--session-name myapp` 保存完整的浏览器状态（Cookie、localStorage、IndexedDB），跨重启恢复
- **Auth Vault**：加密存储凭证，LLM 看不到密码
- **State 加密**：AES-256-GCM 加密会话数据，防止敏感信息泄露

### 4. AI Chat 集成——自然语言控制浏览器

agent-browser 内置 `chat` 命令，支持通过 **Vercel AI Gateway** 用自然语言控制浏览器：

```bash
agent-browser chat "帮我搜索 'agent-browser' 并打开第一个结果"
```

这使得 AI Agent 可以通过对话式指令完成复杂的多步浏览器操作，而无需预先编写任何脚本。

### 5. Skills 系统——无缝集成主流 AI 编程助手

agent-browser 提供了 `skills` 安装机制，一键集成到主流 AI 编程助手：

```bash
npx skills add vercel-labs/agent-browser
```

支持的目标平台包括：
- **Claude Code**（Anthropic 官方 CLI）
- **Cursor**（AI 编辑器）
- **GitHub Copilot**
- **OpenCode**
- **Windsurf**

安装后，AI 编程助手可以直接调用 `agent-browser` 命令，实现"让 AI 帮你写代码，同时让 AI 操作浏览器验证结果"的完整闭环。

### 6. 云浏览器提供商支持——Serverless 就绪

agent-browser 支持多种云浏览器基础设施，可在无本地浏览器的环境（如 Vercel Serverless Functions、AWS Lambda）中运行：

| 提供商 | 特点 |
|--------|------|
| **Browserless** | 成熟的云端浏览器基础设施 |
| **Browserbase** | 远程浏览器，支持会话持久化 |
| **Browser Use** | AI Agent 专用云浏览器 |
| **Kernel** | 支持隐身模式 + 持久化 Profile |
| **AgentCore** | AWS Bedrock AgentCore 集成（SigV4 认证） |

### 7. 高级调试与可观测性

- **React 内省**：`react tree` 命令查看页面 React 组件树，`react inspect <fiberId>` 深入查看组件状态
- **Web Vitals**：`vitals` 命令获取 LCP、CLS、FCP、TTFB、INP 等核心 Web 性能指标
- **可观测性仪表盘**：基于 Next.js 的 Web UI（端口 18790），实时查看会话状态、交互式调试
- **Trace / Profiler**：性能追踪，定位浏览器自动化瓶颈

## 技术亮点

### 1. 无障碍树替代 DOM 树——AI 友好的页面理解方案

传统浏览器自动化的根本问题是：**HTML DOM 树是为视觉渲染设计的，而非为程序理解设计的**。一个普通网页的 DOM 树可能包含数千个节点，其中绝大部分对自动化操作毫无意义（样式节点、广告脚本、隐藏元素等）。

agent-browser 的创新在于用**无障碍树（Accessibility Tree）**替代 DOM 树。无障碍树是浏览器为视障用户生成的语义化页面表示，天然过滤了视觉渲染细节，只保留**可交互元素的语义信息**。

更重要的是，无障碍树的结构远比 DOM 树稳定。网页改版时，CSS 类名、DOM 层级可能大变，但只要按钮的语义角色（`button`）和标签（`"登录"`）不变，`snapshot` 生成的引用就不会失效。这使得 AI Agent 的浏览器操作具有前所未有的**抗网页改版能力**。

### 2. 内容边界机制——防御恶意网页攻击 LLM

当 AI Agent 访问不可信网页时，存在一个微妙的安全风险：**网页内容可以伪造 CLI 输出，诱导 LLM 执行恶意操作**。例如，一个恶意网页可以在页面中插入看似 CLI 输出的文本，让 LLM 误以为这是 `agent-browser` 的返回结果。

agent-browser 通过 **内容边界标记（Content Boundary）** 机制解决这个问题：

- 使用 CSPRNG（密码学安全伪随机数生成器）生成随机 `BOUNDARY_NONCE`
- 所有页面内容输出都被 `BOUNDARY_NONCE` 包裹
- CLI 解析时只信任边界内的内容，边界外的均为不可信内容

此外，`truncate_if_needed` 方法会自动截断过大的页面输出，防止恶意网页通过超长内容导致 LLM 上下文溢出（Context Overflow Attack）。

### 3. 批处理命令——进一步降低 IPC 开销

对于需要连续执行多个浏览器操作的场景（如"打开页面 → 填写表单 → 点击提交"），每次命令都要经历"CLI 启动 → IPC 通信 → 守护进程处理 → 结果返回"的完整流程，累积延迟不可忽视。

agent-browser 提供了 `batch` 命令，允许将多个操作打包成一次 IPC 调用：

```bash
agent-browser batch << 'EOF'
open https://example.com
snapshot -i --json
fill @e2 "username"
fill @e3 "password"
click @e4
EOF
```

这在大规模自动化任务中可带来显著的性能提升，同时进一步减少 Token 消耗（一次返回所有结果，而非多次往返）。

## 适用人群

- **AI Agent 开发者**：正在构建需要浏览器操作能力的 AI Agent（如自动化测试 Agent、数据采集 Agent、RPA Agent）
- **LLM 应用工程师**：希望降低浏览器自动化任务的 Token 消耗，提升 AI 应用的运行效率
- **AI 编程助手用户**：使用 Claude Code、Cursor、GitHub Copilot 等工具，需要让 AI 直接验证网页操作结果
- **RPA（机器人流程自动化）工程师**：寻找比传统 RPA 工具更 AI 友好、更抗网页改版的浏览器自动化方案
- **Vercel 生态开发者**：已经在用 Next.js / Vercel 技术栈，希望将 AI 浏览器自动化集成到 Serverless 工作流

> **前置要求**：熟悉命令行操作；了解 AI Agent 的基本概念；有浏览器自动化经验（Playwright/Selenium）者更容易理解项目价值。

## 快速上手

```bash
# 方式一：npm 全局安装（推荐）
npm install -g agent-browser
agent-browser install   # 首次运行，自动下载 Chrome for Testing

# 方式二：Homebrew（macOS）
brew install agent-browser
agent-browser install

# 方式三：Cargo（Rust 开发者）
cargo install agent-browser
agent-browser install

# 验证安装
agent-browser --version
# 输出：agent-browser v0.27.3（或最新版本）

# 基础工作流（AI Agent 最佳实践）
agent-browser open https://agent-browser.dev
agent-browser snapshot -i --json   # AI 解析引用，决定下一步操作
agent-browser click @e1               # 使用引用执行点击
agent-browser screenshot --json       # 获取截图，验证结果

# 安装到 Claude Code / Cursor 等 AI 编程助手
npx skills add vercel-labs/agent-browser
```

**硬件/环境要求**：本地需有 ~200MB 磁盘空间用于下载 Chrome for Testing；支持 macOS ARM64/x64、Linux ARM64/x64、Windows x64。

## 对比分析：agent-browser vs Playwright vs Puppeteer

| 维度 | **agent-browser** | Playwright | Puppeteer |
|------|-------------------|------------|------------|
| **设计定位** | AI Agent 优先（AI-First） | 开发者优先（Developer-First） | 开发者优先 |
| **元素定位方式** | 无障碍树 + 稳定引用（@e1） | CSS 选择器 / XPath（脆弱） | CSS 选择器 / XPath（脆弱） |
| **Token 消耗** | ~1,400 / 简单登录任务 | ~20,000 / 相同任务 | ~20,000+ / 相同任务 |
| **Token 节省** | **基准（节省 93%）** | 基准 | 基准 |
| **底层依赖** | 纯 Rust + CDP 协议 | Node.js + Playwright | Node.js + Chrome DevTools |
| **守护进程** | ✅ 持久化，~1ms 热命令 | ❌ 每次启动新浏览器 | ❌ 每次启动新浏览器 |
| **多会话隔离** | ✅ 原生支持 | ✅ 通过 Context 实现 | ✅ 通过 Context 实现 |
| **云浏览器支持** | ✅ Browserless/Browserbase/Kernel 等 5+ | ✅ Browserless 等 | ⚠️ 有限支持 |
| **React 内省** | ✅ 内置 `react tree` 命令 | ❌ 需额外工具 | ❌ 需额外工具 |
| **AI Chat 集成** | ✅ 内置 `chat` 命令 | ❌ 需自行实现 | ❌ 需自行实现 |
| **Skills 集成** | ✅ Claude Code/Cursor/GitHub Copilot | ❌ 无 | ❌ 无 |
| **安全机制** | ✅ 内容边界 + 域名白名单 + 操作策略 | ⚠️ 有限 | ⚠️ 有限 |
| **跨平台** | macOS / Linux / Windows | macOS / Linux / Windows | macOS / Linux / Windows |
| **许可证** | Apache-2.0 | Apache-2.0 | Apache-2.0 |
| **维护团队** | Vercel Labs（活跃） | Microsoft（活跃） | Google（维护中） |
| **上手难度** | 低（AI 自动解析） | 中（需写选择器） | 中（需写选择器） |
| **适合 AI Agent** | ⭐⭐⭐⭐⭐ | ⭐⭐ | ⭐⭐ |

**核心差异总结**：Playwright 和 Puppeteer 是优秀的"开发者工具"，但它们诞生于 AI 时代之前，本质上是让"人写的脚本"控制浏览器。agent-browser 则从根本上重新思考了"让 AI 控制浏览器"这一需求——通过无障碍树、稳定引用、Rust 高性能架构，把 Token 消耗降低 93%，把元素定位的脆弱性降到最低。对于 AI Agent 开发者而言，这不是"又一个浏览器自动化工具"，而是**专为自己人设计的武器**。
