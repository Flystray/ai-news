这篇论文在说什么？

普林斯顿的研究者搞了一个很硬核的 Agent 评测：让 AI 去当一家初创公司的 CEO，管 500 天，看谁能赚钱。

结果是，大部分模型直接把公司干破产了。Grok 4.20 最惨，第 37 天就挂了。只有 Claude Opus 4.8 和 GPT-5.5 在 500 天后还能剩下比初始 100 万美元更多的钱——但也都不稳定盈利，随时可能翻车。

论文的名字叫 CEO-Bench，测试的不是"AI 能不能写代码"或者"能不能答对题"，而是一个更根本的问题：AI 能在不确定的环境里做长期决策吗？

图源：原文 Fig.1 · AI Agent 通过可编程接口运营一家名为 NovaMind 的虚构软件公司500天，需要管理定价、营销、研发、客户支持等多个方面

为什么要关注？

说实话，现在各种 AI 评测都快卷成军备竞赛了。MATH 500 已经 99.4% 了，GPQA Diamond 也快 90% 了，你再刷 benchmark 分数读者都麻了。

但 CEO-Bench 不一样。它测试的是一种截然不同的智能：

不是"给一个明确任务，快速完成"，而是"面对一个模糊目标，在噪声里摸爬滚打 500 天"。

这其实更接近真实世界的挑战。一个真正的 CEO 每天面对的是什么？行业里有哪些隐藏的客户需求？哪个广告渠道其实很划算？竞争对手突然降价了我该怎么应对？这些信息不是直接给你的，你得自己从一堆报表和碎片信号里拼出来。

"Many important human accomplishments are not isolated, crisp tasks. They are long chains of decisions under uncertainty: choosing priorities, allocating finite resources, interpreting noisy signals, and adapting as conditions shift."

说的很直白：人类很多重要成就都不是"做好一个任务"那么简单。真正难的是在不确定中持续做对的决策。这就是 CEO-Bench 的价值——它不是在测"会不会"，而是在测"能不能一直做得对"。

核心方法

关键思路

CEO-Bench 的设计其实很"接地气"——让你管一家叫 NovaMind 的虚构 SaaS 公司。

初始条件是：零客户，100 万美元现金。你需要在 500 个模拟天里，通过写 Python 代码来经营这家公司。AI Agent 的界面不是聊天对话框，而是一个完整的编程接口，有 34 个操作工具，19 张业务数据库表。

图源：原文 Fig.5 · CEO-Bench 的七大设计原则及其具体实现：包括细粒度模拟、机制规则确保鲁棒性、隐藏信息与间接反馈、相互关联的动态等

这 500 天里 AI 需要操心的事包括：

  • 定价：怎么给不同客户群体定价？要不要打折？
  • 增长：钱投哪个广告渠道最划算？
  • 产品：研发资金怎么分配？做通用优化还是针对细分群体？
  • 运营：买多少服务器容量？客服预算多少？
  • 企业销售：大客户谈判，怎么出价、怎么还价？

最狠的是，所有这些决策的信息都不是透明的。客户对你的产品到底满不满意？竞争对手下个月会放什么大招？广告渠道的真实转化率是多少？——你只能从财务报表和社交媒体帖子里"猜测"。

图源：原文 Fig.6 · AI Agent 通过 Python 接口管理公司：左侧展示数据库查询分析，中间展示细粒度操作，右侧展示工具组合成自定义工作流

技术细节

模拟器内置了 26 个客户群体和每个群体内的个体客户。每个客户有隐藏的偏好参数：

  • 最大支付意愿：愿意花多少钱？
  • 最低接受质量：产品烂到什么程度就会取消订阅？
  • 价格敏感度：涨价 10% 会跑多少客户？

而且客户之间还会互相影响。你在社交媒体上发了篇烂文章，可能影响一群潜在客户的购买决策。你在某个客户群体身上投入太多，竞争对手就会趁机在其他群体上超过你。

"The environment is partially observable: the agent can observe what a real startup manager reasonably could."

这个设定很妙。它不说"所有数据公开让你分析"，而是给了你一张和真人 CEO 差不多的信息牌。你能不能看懂这些牌，就是能力的差距。

效果怎么样？

结果可以说是相当惨烈。论文测试了 10 个主流模型，每个模型跑 3 次（每次随机种子不同），看谁能活过 500 天、谁能在最后赚到钱。

几个有意思的点：

1. Grok 4.20 最快阵亡，第 37 天就挂了，三次全破产。

2. Claude Opus 4.7 活到 500 天但几乎没赚钱（只剩 39 万美元）。策略是反复削减支出来保现金流——能活但不能赢。

3. GPT-5.5 不是每次都成功，3 次里面破产了 2 次。但运气好的那次赚了 2129 万，说明能力是有的，但不太稳定。

4. 估计上界是 22 亿美元。目前最好的模型成绩（2776 万）和这个上界之间差了将近 80 倍——"这个基准远未饱和"。

和其他方案比有什么不同？

CEO-Bench 创造的是一个全新的评估范式。跟现有的 Agent 基准做个对比就清楚了：

对比维度 SWE-bench WebArena CEO-Bench
时间跨度 单次 单次 500 天
环境动态性 静态 静态 持续变化
反馈延迟 即时 即时 延迟+噪声
需信息推断 否 否 是
多目标协调 否 否 是

CEO-Bench 跟之前所有 Agent 评测的最大区别就在于：它测的不是"单次任务做得好不好"，而是"长时间里决策能不能持续对"。这种评测维度的缺失，恰好是现在 Agent 研究的一个盲区。

对开发者意味着什么？

1. 长期决策是当前 LLM 的真实短板

即使是最强的 Claude Opus 4.8，也没有稳定盈利。这说明 LLM 在短期推理（解数学题、写代码）上的能力，并不能直接迁移到长期战略决策上。如果你的产品需要 AI 做"规划-执行-反馈-调整"的循环，需要额外下功夫。

2. 信息收集能力可能比推理能力更关键

强的模型有一个共同点：它们会频繁查询数据库、分析数据、做预测。GPT-5.5 和 Claude Opus 4.8 写的备忘录里大量使用"if-then"条件句，在做情景规划。弱的模型往往不怎么做这些事——不是不会，而是"不知道需要做"。

3. "细粒度操作"很重要

GPT-5.5 和 Claude Opus 4.8 将近 90% 的开发资金投入到了针对特定客户群体的定向改进上，而其他模型平均只有 43%。在复杂环境中，精准操作的能力比"一键优化"靠谱得多。

4. 评测方式需要革新

花了那么多精力做 SOTA 刷榜，结果让 AI 当个 CEO 就全翻车。如果你在搭建 AI 产品，别只看标准 benchmark 分数，用真实的长周期任务来测更靠谱。
