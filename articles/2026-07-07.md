# Graphify：让 AI 编程助手从"逐文件搜索"进化为"图谱导航"

**日期**: 2026-07-07 | **项目**: [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify) | ⭐78.8k | Python | MIT

---

## 项目背景

当代开发者与 AI 编程助手协作时，最大的痛点之一是"知识碎片化"。Claude Code、Codex 等工具依靠 Glob/Grep 逐文件扫描理解代码库——面对数百文件的工程，定位一个函数可能需要多轮对话；跨模块的调用链只能靠手动拼接；论文概念和代码实现之间的映射几乎无法自动建立。

2026 年初，Andrej Karpathy 分享了他的个人知识库工作流：将所有原始材料放入 raw 文件夹，用大模型持续"编译"成可维护的 wiki。这一思路引爆了开发者社区，但 Karpathy 方案的本质仍是**扁平 Markdown 文档集合**——实体关系只能通过文本链接隐式表达。

**Graphify** 正是在这一背景下诞生（2026-04-03 创建），它不仅复现了 Karpathy 的核心思路，更将"扁平 wiki"推进到了**结构化知识图谱**：每个代码函数、类、文档段落、论文概念都是一个节点，调用链、依赖关系、语义关联构成可遍历的边。一条 `/graphify .` 命令，30 秒安装后即可将整个项目映射为可查询图谱。

---

## 核心功能

1. **双通道提取引擎** — 代码文件通过 tree-sitter AST 确定性解析（36+ 语言，零 Token 消耗），非代码文件（PDF、图片、视频）通过 LLM 语义提取。两条通道结果合并入同一 NetworkX 知识图谱，边标记为 `EXTRACTED`（源码直接提取）或 `INFERRED`（模型推断），审计轨迹清晰透明。

2. **社区发现与"上帝节点"识别** — Leiden/Louvain 算法自动将节点聚类为功能模块社区，`analyze.py` 计算中心性指标，发现高连接度的"God Nodes"和跨社区的"惊喜关联"。无需人工维护索引，算法驱动的架构发现替代了逐文件阅读。

3. **12+ AI 编程助手即插即用** — 通过 `graphify install` 注册为 Skill，一条 `/graphify` 命令即可在 Claude Code、Codex、OpenCode、Cursor、Gemini CLI、Aider、OpenClaw、Kiro、Trae、Devin、Copilot、AMP 等 12+ 平台中使用。每个平台有专属 skill 文件，内置"快速路径"（检测已有 `graph.json` 则跳过提取直接查询）、环境发现（缓存 Python 解释器路径）、安全阈值（超 200 万词/200 文件自动暂停请求缩小范围）。

4. **增量更新与语义缓存** — `manifest.json` 跟踪文件哈希，`/graphify . update` 仅处理变更部分。合并 PR 后秒级同步图谱，语义缓存确保已处理文件不重复消耗 Token。

5. **跨模态知识融合** — `add` 命令可直接导入 arXiv 论文 URL，Graphify 自动下载、语义提取并将论文概念节点加入图谱，建立"论文概念 → 代码实现"的映射路径。实测中，一篇 A-MAC 论文的 5 个核心因子被自动对齐到项目代码的对应实现与权重参数。

6. **多格式输出** — `graph.html`（交互式可视化，点击节点/搜索/过滤）、`GRAPH_REPORT.md`（自然语言架构摘要 + 惊喜关联 + 推荐问题）、`graph.json`（完整图谱序列化，可随时查询无需重新读取文件）、Obsidian 知识库导出（双向链接 Markdown 笔记 + 社区文件夹组织）、GraphML/Neo4j 格式支持。

7. **path 路径追踪** — `/graphify path` 可追踪任意两个节点之间的完整路径，每条边附带类型说明（语义关联、实现关系、调用关系），可用于论文复现验证、技术债务评估、代码审查和知识溯源。

## 技术亮点

1. **"不是向量索引，是真正的图"** — Graphify 的核心哲学是拒绝 Embedding + 向量存储的 RAG 模式，转而构建可遍历的知识图谱。节点是具体实体（函数、类、概念），边是显式关系（调用、依赖、语义关联），查询通过图遍历而非近似匹配。这意味着回答的精确性不受向量相似度阈值影响——问"BM25 代码在哪个文件"，直接命中节点而非返回一堆可能相关的片段。

2. **skillgen 幂等生成系统** — 12+ 平台的 skill 文件由 `tools/skillgen/gen.py` 从统一的 fragment 模板渲染生成，保证跨平台行为一致且幂等（不含时间戳/版本号，不会产生无意义 diff）。`--check` 标志检测渲染漂移，`--audit-coverage` 确保原始 monolith skill 的每个 heading 都在新 split fragment 中保留。

3. **五层架构的线性阶段门模型** — File Detection → AST Extraction → Semantic LLM Extraction → Graph Assembly & Validation → Community Detection & Analysis，每层通过纯 Python dict 或 NetworkX 对象传递输出，模块边界清晰（`detect.py`、`extract.py`、`llm`、`build.py`、`validate.py`、`cluster.py`、`analyze.py`），便于独立测试和替换。

## 快速上手

```bash
# 安装 CLI（30 秒）
uv tool install graphifyy
# 或: pipx install graphifyy

# 注册到你的 AI 编程助手
graphify install

# 在项目中生成知识图谱
/graphify .

# 查询图谱
/graphify query "BM25代码在哪个文件"

# 增量更新（合并 PR 后）
/graphify . update

# 导入论文
/graphify add https://arxiv.org/abs/xxxx.xxxxx

# 追踪节点路径
/graphify path
```

输出文件在 `graphify-out/` 目录：`graph.html`（交互可视化）、`GRAPH_REPORT.md`（架构摘要）、`graph.json`（完整图谱）。

## 对比分析

| 维度 | Karpathy Wiki 工作流 | Graphify | 传统 RAG（Embedding + Vector Store） |
|---|---|---|---|
| **存储结构** | 扁平 Markdown + 索引 | NetworkX 知识图谱（节点+边+属性） | 向量索引 + 近似匹配 |
| **查询方式** | 大模型维护索引文件 | 图遍历查询 + 社区发现算法 | 相似度阈值检索 |
| **代码解析** | 大模型全量编译（消耗 Token） | AST 确定性解析（零 Token） | 不解析结构，纯 Embedding |
| **关系表达** | 文本链接隐式表达 | 显式边（EXTRACTED/INFERRED） | 无显式关系 |
| **跨模态** | 混合存放无区分 | 双通道分离后统一入图 | 统一 Embedding 丢失结构 |
| **增量更新** | 人工触发全量编译 | manifest.json 增量更新 | 重新 Embedding 全量 |
| **Token 消耗** | 每次全量 | AST 零消耗 + 语义缓存 | 每次查询消耗 |
| **平台兼容** | 无 | 12+ AI 编程助手即插即用 | 通常仅 API 接口 |

**核心数据**：Graphify 的 AST 通道覆盖 36+ 编程语言，零 Token 消耗处理代码结构；语义通道仅处理非代码文件，语义缓存避免重复处理；实测 BM25 查询精准定位到文件+行号（而非返回一堆可能相关片段）；arXiv 论文导入后自动完成 5 个核心因子与代码实现的逐一映射。

Graphify 代表了一种不同于主流 RAG 的代码理解范式——**用图而非向量来表达代码知识**。78.8k Star 和 Karpathy 的直接启发证明了社区对这种"结构化认知层"的强烈需求。对于任何与 AI 编程助手深度协作的开发者，这是一个值得立即纳入工具链的项目。
