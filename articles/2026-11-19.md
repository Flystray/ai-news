把一个跑得好好的 TypeScript 或 Python 应用整个搬进 Rust，是很多团队想了多年、试过多次、最后放弃的事。11 月 16 日出现在 GitHub 上的 rust-anything 换了条路：它不翻译代码，而是先给原程序「录像」，让 coding agent 照着重写，重写完的每一块都要和录像逐案比对，全对才准合入。三天拿了 3,634 个 star、发了 8 个 release，第三方评测已经出了四五篇——增速在近期新仓库里相当罕见。

---

## 项目背景：重写不难，敢合入才难

渐进式重写有两个经典死法。第一种是「大爆炸」：花半年把整个应用重写成新语言，上线那天没人敢赌新二进制和旧的一样，出一次事故整个项目就被叫停。第二种是「小块重写」：一次只搬一个函数，但调用方对不上——一个除零异常从 `ZeroDivisionError` 变成了 panic，一个 `-0.0` 被序列化成 `0`，都够在生产环境炸一次。

手工重写的验证成本也压不下来。要保证新旧版本行为一致，得自己写 FFI 绑定，再为边界情况补测试：非 ASCII 字符串、`NaN`、整数溢出、符号除法的舍入方向。这些用例写不全，不一致就藏在没测到的分支里。全量翻译工具（比如把 C 机器翻译成 Rust 的 c2rust）能省人力，但生成的是「机器风格的 Rust」——代码能跑，人读不懂，改不动，等于把维护债务换个语言续期。

coding agent 出现后，「让 AI 来写 Rust」听起来顺理成章，但 agent 最不缺的就是自信：它写完会说「测试通过了」，至于哪些行为没人测过，它不会告诉你。rust-anything 的立意就卡在这里——agent 能猜代码，猜不出「原程序对某个诡异输入到底返回了什么」，这恰恰是可以机器验证的部分。把验证做成流水线的地基，重写才从玄学变成工程。dev.to 的独立评测把它概括为「先移植行为，再移植代码」，这个定位是准的。

## 核心功能

### 1. 五步循环：先找热点，再出考卷

入口是五个命令串成的流水线：`profile` 挂各语言的原生分析器（Node、cProfile、`go test` pprof、JFR）跑真实负载，列出最热的函数和调用方，还会标出 numba、Cython、JAX 这类「已经编译过、搬 Rust 没什么赚头」的代码；`analyze` 扫描仓库，把代码切成移植单元，按依赖分层排出移植顺序，标出风险点（UTF-16 与 UTF-8 的偏移差异、`regex` crate 不支持的反向断言等）；`bridge` 生成带绑定层的 Rust crate 和一个叫 `port.rs` 的桩文件——这就是「考卷」，agent 往里面填实现；`record` 对原函数灌边界用例，把每次的返回值和异常存成 `cases.jsonl`；`diff` 把所有案例重放到 Rust 侧，逐条比对。

```sh
rust-anything profile . -- node bench.mjs      # 时间花在哪、谁在调用
rust-anything bridge . src/fuzzy.ts --batch fuzzyScore:text
# 你或 agent 写 src/port.rs，然后：
rust-anything record rust/fuzzy-rs && rust-anything build rust/fuzzy-rs
rust-anything diff rust/fuzzy-rs               # 每条录制案例必须一致
rust-anything gate rust/fuzzy-rs               # 过了才算移植完成
```

### 2. gate 门禁：移植完成的定义被写死

`gate` 是整个工具的裁决者，通过条件包括：`fmt` 无 diff、`clippy -D warnings` 零告警、测试全过、`unsafe` 审计干净、原函数每条错误路径都有一条录制的失败案例对应、以及禁止 `unwrap`/`expect`/`panic!`——除非用 `// INFALLIBLE: <理由>` 显式豁免。这把「移植完成」从口头约定变成了可机判的清单，agent 没法用一句「看起来没问题」糊弄过去。

### 3. shadow 影子模式：生产环境里双跑

`diff` 通过只是实验室结论。`shadow` 提供一个占位模块，同时调用原实现和 Rust 实现，返回原结果、记录不一致——`RUST_ANYTHING_MODE` 三个值切换旧路径、影子路径和新路径。重写代码可以先在生产流量里「隐身」跑一段时间，等不一致率降到零再切流量，出问题也不影响用户拿到的东西。

### 4. whole-app 模式：从 CLI 到纯 Rust 应用

单个函数之外，`app record` 把整个 CLI 或 HTTP 服务当黑盒录制（每个案例跑两遍以分辨随机值），`app front-door` 让 Rust 接管入口、原实现兜底，之后逐单元走标准循环，最后 `app lift` 把回退彻底摘掉，应用变成纯 Rust。全程原代码一个字节都不动。

### 5. --batch 批处理类：数据过桥一次

逐次调用跨 FFI 有固定开销，小函数单次搬过去甚至比 JIT 更慢。`--batch fn:param` 生成一个把数据一次性送进 Rust、每次调用在多核上跑完全量的类，配 mimalloc 分配器。这是 README 里所有「提速 20 倍」数字背后的真实机制（项目自述）。

## 技术亮点

### 1. 语义陷阱是生成出来的，不是靠运气

`record` 不是简单跑几个测试输入。它对每个参数自动构造「语义陷阱」：非 ASCII 和 emoji、`-0`、`NaN`、整数溢出边界、有符号除法、浮点打印格式、map 与 sort 的顺序；用了正则的文件还会追加正则陷阱——开尔文符号、长 s、阿拉伯-印度数字、行分隔符，专打各语言 Unicode 语义的分歧点。跨语言传值用的是生成的二进制 wire，JSON 表达不了的 `undefined`、`NaN`、`-0`、孤立代理对走 `{"$undefined": true}`、`{"$num": "NaN"}`、`{"$utf16": [...]}` 这类标记，由生成的绑定层翻译回来。相比之下 `record --from-tests` 还能把原项目自己的测试套件录进案例集，考卷覆盖面进一步扩大。

### 2. 指纹防漂移：原代码动了，考卷作废

`record` 会给被录制的源文件存指纹（`recorded-from.json`）。原代码后来改了，`diff` 会警告、`gate` 直接失败，逼你重新录制——避免「对着三个月前的行为验证今天的代码」这种静默错位。录制时跑两遍原实现，把两次结果不同的值（时间戳、随机 id）变成通配符、乱序输出（哈希 map、并发）改成无序比较，这是把「不确定的部分」显式建模，而不是假装它们确定。

### 3. 不翻译代码，只出考卷和判卷

这是它和全量翻译工具最本质的分界。rust-anything 输出的是：时间在哪（profile）、先搬哪个（analyze）、桥怎么搭（bridge）、行为是什么（record）、对没对（diff/gate）。Rust 代码本身由人或 agent 写。六种语言的桥接各有实现——TS 走 napi-rs 或 wasm-bindgen、Python 走 PyO3（abi3）、C 走 `extern "C"` 加 ctypes（每个案例 fork 一个进程，防原代码崩溃连坐）、Go 走 cgo、Ruby 走 magnus、Java 走 JNI——`src/` 下 48 个 Rust 源文件约 1.26 MB，`codegen_java.rs`、`codegen_go.rs` 这些文件名本身就说明生成层是按语言逐个写的，不是通用模板套壳。

## 局限

- **天花板就是录制的覆盖面。** 文档里「What it can't catch」一节说得直白：没人录过的输入，diff 就验证不到。建议把生产样本和 bug 报告喂给 `--inputs`，但这也意味着「通过」永远是「录制范围内一致」，不是数学意义上的等价。
- **数字都是作者基准。** 38,251 条录制案例零失配、x18n 搜索 20 倍提速，均出自仓库自带的 `demo/` 基准（项目自述）；截至目前没有第三方独立复测。MEDevel 的评测明确提醒「先在自己的硬件上跑 bench 再下结论」。
- **正则是已知雷区。** Rust 的 `regex` crate 不支持反向断言和环视，即便编译通过的 pattern，对土耳其无点 ı、零宽连接符的处理也可能和 JS/Python 不同——文档建议对真实 pattern 再做 fuzz。
- **录制有副作用。** `record` 和 `app record` 会对每个输入真实执行原代码，写文件、连数据库、发网络请求都会发生（且 whole-app 模式每案例跑两遍），必须在没有生产凭据的项目副本上跑。
- **覆盖面与成熟度。** PHP 和 C# 处于预览态（只支持整应用录制重放，单函数 FFI 桥接未完成），Kotlin 和 Swift 不支持；编译产物（EXE/JAR/APK）无法逆向移植；直连硬件、内联汇编的 C 代码会被标记「留在 C」。
- **项目只有三天大。** 单一维护者、8 个 release 全在 72 小时内发出，长期维护意愿和社区规模都待观察。

## 适用人群

- **被 Python/Node 性能卡住的工程师**：热点循环搬 Rust，调用方 API 不变，省掉手写 FFI 和补测试两大块工作。
- **管着 coding agent 的团队**：给 agent 一条机器可判的完成标准，合入判定从「agent 说好了」变成「gate 过了」，顺带把 `unsafe` 审计和错误路径覆盖也管起来。
- **维护多语言服务栈的后端**：Go、Java、Ruby 的批处理路径都能按同一套流程搬，迁移节奏由单元粒度控制，随时可停。
- **想把老 CLI/服务彻底 Rust 化的团队**：whole-app 模式的 front-door → 逐单元 → lift 提供了「永远可回退」的路径。
- **不适合**：想要全自动翻译器的人——Rust 代码得自己或 agent 写；Kotlin/Swift 项目；依赖编译产物逆向的场景。

## 快速上手

前置依赖：一个 Rust 工具链（或直接用 release 里的预编译二进制），加上你要移植语言的运行时。

```sh
cargo install rust-anything    # 或 npm install -g rust-anything
rust-anything setup            # 自动注册 MCP 到 Claude Code / Codex / Cursor / Gemini CLI
```

`setup` 会在改任何 agent 配置文件前先存 `.bak` 备份，可重复执行，`--remove` 可撤销。Claude Code 用户也可以走插件：`/plugin install rust-anything --marketplace erkamyaman/rust-anything`。常见坑有三个：录制会真实执行原代码，务必在项目副本上跑；浮点比较默认逐位一致，数值代码加 `--float-tolerance 1e-9`（只放宽舍入，不放宽格式）；逐次调用的小函数搬过去会变慢，先用 `profile` 找热点、再用 `--batch`。

## 对比分析

| 维度 | rust-anything | c2rust 类全量翻译 | 手工渐进重写 |
|------|--------------|------------------|--------------|
| Rust 代码来源 | 人或 coding agent | 机器翻译 | 人 |
| 行为一致性验证 | 录制案例逐条重放 + 门禁 | 依赖原测试套件 | 手写测试，覆盖靠人 |
| 调用方改动 | API 不变，绑定层生成 | 输出仍是 C 风格接口 | 自己设计 FFI |
| 代码可维护性 | 正常 Rust，可重构 | 机器风格，难读难改 | 好 |
| 迁移可回退性 | shadow 双跑 + 指纹校验 | 弱 | 看工程纪律 |
| 语言覆盖 | TS/Python/C/Go/Ruby/Java，PHP/C# 预览 | 以 C 为主 | 不限 |
| 局限/风险 | 只验证录制过的行为；三天新项目，基准均出自作者 | 产物难维护 | 成本最高，一致性最没底 |

表格之后说一句实话：rust-anything 买到的是「行为一致性」这个最难手工保证的性质，代价是你要接受「一致性」的边界止步于录制集。如果你要的是语义级重构（改数据结构、换算法），它帮不上忙——它保证的是「照原样快起来」，不是「照意图变好」。

## 写在最后

两点判断。第一，它把「大模型能不能安全重写老代码」这个问题从 prompt 层拉到了工程层：agent 写代码的问题从来不是写不出，而是没人能替它担保对错，录制-重放-门禁这套机制把担保变成了机器可判的东西，这个思路不限于 Rust 迁移，值得所有做 agent 工具链的人看一眼。第二，三天 3,634 star 里有多少是「演示效应」还有待时间检验，作者基准没有第三方复测，生产使用建议从单个热点函数开始，先跑 `shadow` 再谈切换。

行动建议按风险从低到高排：先拿一个纯函数的热点循环练手，感受录制和比对的手感；第二步用 `record --from-tests` 把现有测试套件并进案例集，覆盖面立刻上一个台阶；第三步才考虑 whole-app 迁移，并且把 `shadow` 双跑期至少留一两周。三天八个小版本说明作者在快速迭代，跟进 `CHANGELOG.md` 比记住任何一篇教程都重要——命令和门槛的细节随时会变。
