📌 项目背景

2025 年以来，AI Agent 的爆发式增长带来了一个尴尬的工程现实：AI 能理解自然语言，却无法直接操作网页。传统的浏览器自动化工具（Playwright、Puppeteer、Selenium）都是为"人类写脚本"设计的——它们依赖 CSS 选择器、XPath，需要把整个 DOM 树塞进 LLM 的上下文窗口，导致一次简单登录操作就能消耗 20,000+ Token。

更棘手的是，网页 DOM 结构随时可能改变，写死的选择器像纸糊的一样脆弱。AI Agent 每操作一个网页，就要重新解析整页 HTML，既浪费 Token，又容易出错。

agent-browser 正是为解决这个核心痛点而生。它由 Vercel Labs（Next.js、Vercel 背后的团队）开源，采用 Apache-2.0 协议，目前已在 GitHub 收获 36,000+ Stars，是 2026 年 AI Agent 工具链中最受关注的浏览器自动化项目之一。项目的核心设计哲学：让浏览器适配 AI，而非让 AI 适配浏览器。

值得一提的是，agent-browser 在 v0.16+ 版本后已完全移除 Playwright 依赖，改为纯 Rust 直接通过 Chrome DevTools Protocol（CDP）控制浏览器，成为真正意义上的轻量级、高性能 AI Agent 浏览器工具。

🚀 核心功能

1. 快照-引用工作流（Snapshot-Ref Workflow）

这是 agent-browser 最具革命性的功能。传统方案需要 AI 解析整页 HTML（数万行），而 snapshot 命令只返回可交互元素的精简列表，每个元素被分配一个稳定引用编号（如 @e1、@e2）：

agent-browser open https://example.com
agent-browser snapshot -i --json
# 输出（精简版）：
# - 按钮 "登录" [ref=@e1]
# - 输入框 "用户名" [ref=@e2]
# - 链接 "忘记密码" [ref=@e3]

后续所有操作直接使用引用编号，无需重新解析页面。效果：相同登录任务，Token 消耗从 Playwright 的 ~20,000 降至 ~1,400，节省 93%。

2. 纯 Rust 守护进程架构——极致性能

agent-browser 采用客户端-守护进程-浏览器三层架构：

  • Rust CLI：所有用户命令入口，参数解析、输出格式化，~1ms 启动
  • Rust 守护进程：持久化运行，管理浏览器生命周期，维护 RefMap（元素引用映射）
  • CDP 直接通信：纯 Rust 实现，无需 Playwright 或 Node.js 依赖

守护进程在首次命令时自动启动，后续命令复用同一进程，避免了每次操作都重启浏览器的巨大开销。热命令延迟优化至 ~1ms。

3. 会话管理与认证持久化

AI Agent 经常需要登录后执行操作，agent-browser 提供了多种认证方案：

  • Chrome Profile 复用：--profile Default 直接使用本机 Chrome 登录状态
  • 会话持久化：--session-name myapp 保存完整浏览器状态，跨重启恢复
  • Auth Vault：加密存储凭证，LLM 看不到密码
  • State 加密：AES-256-GCM 加密会话数据，防止敏感信息泄露

4. Skills 系统——无缝集成主流 AI 编程助手

agent-browser 提供 skills 安装机制，一键集成到主流 AI 编程助手：

npx skills add vercel-labs/agent-browser

支持：Claude Code、Cursor、GitHub Copilot、OpenCode、Windsurf。安装后，AI 编程助手可直接调用 agent-browser 命令，实现"让 AI 写代码，同时让 AI 操作浏览器验证结果"的完整闭环。

5. 云浏览器提供商支持——Serverless 就绪

支持多种云浏览器基础设施，可在无本地浏览器的环境（Vercel Serverless、AWS Lambda）中运行：

6. 安全机制——多层防护

  • 内容边界标记（Content Boundary）：CSPRNG 生成随机 NONCE 包裹页面内容输出，防止恶意网页伪造 CLI 输出
  • 输出截断：自动截断过大页面输出，避免 LLM 上下文溢出攻击
  • 域名白名单：AGENT_BROWSER_ALLOWED_DOMAINS 限制可访问域名范围
  • 操作策略：通过策略文件控制破坏性操作（文件删除、导航到不受信域名等）

🔧 技术亮点

1. 无障碍树替代 DOM 树——AI 友好的页面理解方案

传统浏览器自动化的根本问题是：HTML DOM 树是为视觉渲染设计的，而非为程序理解设计的。一个普通网页的 DOM 树可能包含数千个节点，其中绝大部分对自动化操作毫无意义。

agent-browser 的创新在于用无障碍树（Accessibility Tree）替代 DOM 树。无障碍树是浏览器为视障用户生成的语义化页面表示，天然过滤了视觉渲染细节，只保留可交互元素的语义信息。更重要的是，无障碍树的结构远比 DOM 树稳定——网页改版时，只要按钮的语义角色和标签不变，snapshot 生成的引用就不会失效。

2. 客户端-守护进程分离架构——性能与安全的双重保障

agent-browser 的架构设计在性能和安全性上都做了深度优化：

  • 零冷启动开销：守护进程持久化运行，CLI 命令通过 Unix Socket / TCP 与守护进程通信，热命令延迟 ~1ms
  • 纯 Rust 实现：守护进程和 CLI 均为 Rust 编写，内存安全、无 GC 停顿、二进制体积小
  • 多引擎支持：默认 Chrome，同时支持 Lightpanda（无头浏览器引擎）和 iOS Simulator（通过 Appium 控制 Mobile Safari）
  • 空闲自动关闭：通过 AGENT_BROWSER_IDLE_TIMEOUT_MS 设置守护进程空闲超时，自动回收资源

3. AI Chat 集成——自然语言控制浏览器

agent-browser 内置 chat 命令，支持通过 Vercel AI Gateway 用自然语言控制浏览器：

agent-browser chat "帮我搜索 'agent-browser' 并打开第一个结果"

这使得 AI Agent 可以通过对话式指令完成复杂的多步浏览器操作，而无需预先编写任何脚本。配合 batch 命令（将多个操作打包成一次 IPC 调用），可进一步降低延迟和 Token 消耗。

⚡ 快速上手

# 方式一：npm 全局安装（推荐）
npm install -g agent-browser
agent-browser install   # 首次运行，自动下载 Chrome for Testing

# 方式二：Homebrew（macOS）
brew install agent-browser
agent-browser install

# 方式三：Cargo（Rust 开发者）
cargo install agent-browser
agent-browser install

# 验证安装
agent-browser --version
# 输出：agent-browser v0.27.3（或最新版本）

# 基础工作流（AI Agent 最佳实践）
agent-browser open https://agent-browser.dev
agent-browser snapshot -i --json   # AI 解析引用，决定下一步操作
agent-browser click @e1               # 使用引用执行点击
agent-browser screenshot --json       # 获取截图，验证结果

# 安装到 Claude Code / Cursor 等 AI 编程助手
npx skills add vercel-labs/agent-browser

环境要求：本地需有 ~200MB 磁盘空间用于下载 Chrome for Testing；支持 macOS ARM64/x64、Linux ARM64/x64、Windows x64。

⚠️ 使用注意

agent-browser 仍快速迭代中（当前 v0.27.3），API 可能发生变更。建议在非生产环境先充分测试。无障碍树依赖网页自身的无障碍实现，部分无障碍支持较差的网页可能导致引用识别准确率下降。
  • 快照引用会重新生成：每次执行 snapshot 后引用编号会重新分配，页面跳转后需重新快照
  • 复杂页面可能不完整：无障碍树对复杂动态页面的覆盖可能不如完整 DOM 树，遇到问题时可配合 screenshot 命令验证
  • 云浏览器需额外配置：使用 Browserless / Browserbase 等云服务时需配置对应环境变量
  • 欢迎贡献：项目在 GitHub 活跃维护中，Issue 和 PR 均被积极响应
