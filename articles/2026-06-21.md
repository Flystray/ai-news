## 📌 项目背景：AI 黑箱之痛

当 AI Agent 越来越多地参与生产决策——从贷款审批到医疗诊断、从合规审查到政策制定——一个尖锐的问题浮出水面：**AI 做出的每一个决策，你能解释清楚为什么吗？**

现有 AI 技术栈存在六大结构性缺陷：

1. **数据孤岛**：知识分散在数据库、PDF、API、内部工具中，AI 无法跨源关联推理
2. **黑箱决策**：AI 做出决策后无法解释原因，缺乏因果关系追踪
3. **缺失上下文层**：向量存储仅返回相似文本，不理解实体、关系、时序变化
4. **调试困难**：AI 给出错误答案后，无法定位到具体的事实或推理步骤
5. **幻觉风险**：LLM 将真实数据和虚构内容混合，在高风险场景中极其危险
6. **合规噩梦**：GDPR、欧盟 AI 法案、HIPAA 等监管要求 AI 决策可解释，多数团队无法提供完整审计轨迹

**Semantica** 正是为解决这些问题而生——它是 AI 技术栈的**上下文与问责层（Context & Accountability Layer）**，让 AI 的每一个决策都可解释、可追溯、可审计。它不替代 LangChain、LlamaIndex 或你的 LLM 提供商，而是在这些工具之上叠加结构化记忆、因果推理和全链路溯源能力。

## 🚀 核心功能（12 大生产级模块）

### 1. 上下文图谱（Context Graphs）
结构化、可查询的图谱，持久化存储 AI 的所有知识、决策和推理过程。支持节点/边的 `valid_from`/`valid_until` 时间属性，可查询任意时间点的历史图状态。支持图遍历、语义邻域搜索和 N×N 距离矩阵分析。

### 2. 决策智能（Decision Intelligence）
每个决策都是一等公民对象（First-Class Object），包含完整输入、置信度、推理链。支持因果链追踪（`trace_decision_chain`）、先例语义搜索（`find_similar_decisions`）、影响分析（`analyze_decision_impact`）和策略规则校验（`check_decision_rules`）。

### 3. 全链路溯源（Full Provenance）
遵循 **W3C PROV-O** 标准，将每个事实追溯到其来源文档、提取算法和推理步骤。审计日志可导出为 RDF、JSON、CSV 格式，直接提交给监管机构。

### 4. 可解释推理引擎
提供五种推理引擎，所有推理路径完全透明：
- **Forward Chaining**：正向链 IF/THEN 规则推理
- **Rete 网络**：高吞吐量模式匹配
- **Datalog**：声明式逻辑编程，支持递归 Horn 子句
- **SPARQL**：基于 W3C 标准的 RDF 图查询推理
- **Abductive**：溯因推理，从结果反推最可能的前提

### 5. GraphRAG
将 LLM 的响应建立在知识图谱的已验证、有来源的事实上，在 LLM 响应前先查询可信事实，将幻觉转化为可控的检索问题。

### 6. 本体管理（Ontology Management）
自动生成 OWL 本体，支持导入 OWL/RDF/Turtle/JSON-LD 格式，通过 HermiT/Pellet 校验一致性，自动生成 SHACL 形状约束。内置可视化本体编辑器。

### 7. 时序智能（Temporal Intelligence）
支持 Allen 区间代数的全部 13 种时间关系，支持时间点查询、历史快照、双时态溯源（真实有效时间 + 记录时间）和时序 GraphRAG。

### 8. 冲突检测与解决
当多个来源对同一事实描述不一致时，自动检测值/类型/关系/时态/逻辑五类冲突，提供 5 种解决策略：优先最新来源、优先最可靠来源、多数投票、可信度加权、标记人工审核。

### 9. 实体消歧（Entity Disambiguation）
支持分块（Blocking）、混合（Hybrid）、语义（Semantic）三种去重策略，v2 版本速度提升 **6.98 倍**，支持带溯源的实体合并。

### 10. 图谱算法
内置 PageRank、介数中心性、Louvain 社区检测、Node2Vec 嵌入、余弦相似度、链路预测等高级网络分析能力。

### 11. 管道构建器（Pipeline Builder）
声明式流水线 DSL，支持阶段链式调用、并行 Worker、校验门、失败重试策略，可构建可扩展的知识管道。

### 12. 知识探索器 UI
基于 React 19 + Sigma.js 的浏览器端图谱工作区，支持时间线滑动、决策审计轨迹查看、实体解析查看、交互式图谱导航。

### 核心示例：构建可审计的决策图谱

```python
from semantica.context import ContextGraph

# 初始化上下文图谱，开启高级分析
graph = ContextGraph(advanced_analytics=True)

# 记录一个可审计的决策
decision_id = graph.record_decision(
    category="vendor_selection",
    scenario="Choose cloud provider for HIPAA workload",
    reasoning="AWS offers BAA, mature HIPAA tooling, and existing team expertise",
    outcome="selected_aws",
    confidence=0.93,
)

# 追踪完整因果链
chain = graph.trace_decision_chain(decision_id)

# 搜索相似历史决策（先例检索）
similar = graph.find_similar_decisions("cloud vendor", max_results=5)

# 分析决策下游影响
impact = graph.analyze_decision_impact(decision_id)

# 校验决策是否符合策略规则
compliant = graph.check_decision_rules({"category": "vendor_selection"})
```

### 端到端 GraphRAG 流水线

```python
from semantica.ingest import FileIngestor
from semantica.split import TextSplitter
from semantica.semantic_extract import NamedEntityRecognizer, RelationExtractor
from semantica.kg import GraphBuilder
from semantica.vector_store import VectorStore, HybridSearch
from semantica.context import AgentContext

# 1. 数据导入
docs = FileIngestor().ingest_directory("./docs/", recursive=True)

# 2. 实体感知分块（避免实体被拆分）
splitter = TextSplitter(method="entity_aware", chunk_size=1000)
chunks = [splitter.split(doc["text"]) for doc in docs]

# 3. 提取实体和关系
ner = NamedEntityRecognizer(confidence_threshold=0.7)
rel_ext = RelationExtractor(confidence_threshold=0.6)

# 4. 构建知识图谱（自动跨文档去重）
kg = GraphBuilder(merge_entities=True, enable_temporal=True).build(docs)

# 5. 混合检索（向量 + 图遍历）
vs = VectorStore(backend="faiss")
ctx = AgentContext(vector_store=vs, knowledge_graph=kg)
results = HybridSearch(vector_store=vs).search("who approved the renewal?")
```

## 总结

Semantica 瞄准了一个被主流 AI 框架忽视的关键问题：**AI 决策的问责制与可解释性**。在金融、医疗、法律等强监管领域，AI 不仅需要给出答案，更需要证明"为什么"——每一条事实的来源、每一次决策的推理链、每一个冲突的处理方式都必须可追溯、可审计。Semantica 通过知识图谱、上下文图、多种推理引擎和 W3C PROV-O 溯源标准，构建了完整的解决方案。
