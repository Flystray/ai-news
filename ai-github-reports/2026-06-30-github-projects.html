📌 项目背景

今天绝大多数 AI Agent 项目还停留在"代码生成器"层面：LLM 读 README、写 diff、提 PR。但 Neo.mjs 的设计者认为这远远不够——

"Where the industry runs one AI agent and gets slop, Neo.mjs runs a swarm of minds from rival labs — Claude, Gemini, GPT — that read each other's reasoning through shared memory."

它要解决三个真正棘手的问题：

① 单 Agent 的盲区：单个模型对自己的失误往往视而不见，需要"异源交叉审查"才能暴露。

② 静态代码 vs 活运行时：传统 Agent 只能"读代码"，但运行时状态、用户实际操作路径、生产 bug 现场，这些在代码里看不到。

③ 战术噪声 vs 战略方向：Agent 每天生成大量会话、调试记录、PR 评论，需要一个"做梦"机制把它们消化成长期路线图。

为此，Neo.mjs 提出了极其独特的两半球架构（Body/Brain Split）：浏览器里跑 UI 引擎（Body），Node.js 里跑跨模型 AI 蜂群（Brain），两者通过 Neural Link（JSON-RPC WebSocket）实时相连，让 AI 直接"住进"应用，操控活的运行时而非静态代码。

🌐 Body（身体）：浏览器 · App Worker / VDom Worker / Data Worker / Canvas Worker / Service Worker
📦 零编译 ESM · JSON VDOM · Web Workers 隔离 · 主线程仅 DOM 操作
🔗 Neural Link：JSON-RPC over WebSocket · 对象级引用图谱 · 双向状态同步
🧠 Brain（大脑）：Node.js · AgentOrchestrator · 跨模型蜂群（Claude/GPT/Gemini）
💾 Memory Core（ChromaDB）+ Knowledge Base + Native Edge Graph（SQLite）
🌙 DreamService REM Cycle → 战术噪声消化为 Golden Path 拓扑

🚀 核心功能

🌐 Body：真多线程引擎

App/VDom/Data/Canvas/Service 五类 Web Worker 隔离，主线程仅 DOM 操作。零编译开发模式，浏览器直跑 .mjs 无 transpile 延迟。VDOM 用纯 JS 对象表示，无模板引擎开销。

🐝 Brain：跨模型蜂群

Claude、GPT、Gemini 在同一仓库里互相审阅 PR。Verify-Before-Assert 强制准则（AGENTS.md 硬约束），Ticket Gate 校验工单 ID，No Direct Merges 保留人类合并权。

🕸️ Active Hybrid GraphRAG

SQLite Native Edge Graph + ChromaDB 向量库双路召回。Semantic + Structural 融合结果，能回答"哪个文件历史上出过最多自愈修复"等带时间维度的复杂查询。

🌙 DreamService（做梦）

REM cycle 把过去所有 session、PR 评论、运行时崩溃、ticket 摘要消化为新图谱边、skill、priority 列表。本质是"持续反思"管道（Continuous Reflection）。

🔗 Neural Link（神经链）

AI 操控活应用的关键通道。Brain 订阅 Body 中任意 VDom 节点变化，可直接 mutate 客户端 UI；Body 反向 push 用户轨迹给 Brain 分析。"聊天面板"→"应用内协作体"。

📚 Progressive Disclosure Skills

.agents/skills/ 目录里挂着几十个 skill 文件，按需 lazy-load。pull-request、ticket-intake 等工作流被触发时，对应 instructions 才被加载进 prompt。

💡 技术亮点

1. 跨模型异源审查（Cross-Model Review）

让 GPT 审 Claude 的 PR、让 Gemini 审 GPT 的实现 —— 真的能抓到单模型盲区。ReputAgent 把它列为"Semantic Capability Matching Pattern"代表案例，纳入 AI Agent 学术研究的对比基线。

2. 活运行时操控（Neural Link）

通过 Neural Link，agent 不再是"读代码"而是"在应用里协作"，是 Agent OS 概念的具体落地。订阅 VDom 状态变化、直接 mutate UI、反向 push 用户轨迹 —— 把 Agent 协作界面从侧栏升级为应用内协作体。

3. REM Dream Pipeline：持续反思而非持续集成

用"做梦"机制把战术噪声消化成战略图谱。每当 swarm 不忙时，DreamService 自动触发 REM cycle，把短期 session 整合为长期拓扑 —— 借鉴人脑 REM 睡眠的记忆整合机制。

🔥 关键差异：蜂群 vs 流水线

其他 Agent 项目的"协作"基本是"流水线工人"模式（拆任务 → 各自完成 → 拼装），而 Neo.mjs 更接近"蜂群"模式 —— 不同模型互相 review、互相指正、共享 memory，把"单模型幻觉"的根本问题从工程上拆解掉。
