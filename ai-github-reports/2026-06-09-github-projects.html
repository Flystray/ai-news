📌 项目背景

你用 Claude Code 写代码，每月烧几百块的 API 费；你手上又攒了好几个平台的免费额度——Gemini 每天 1500 次、Groq 每分钟 30 次、Qwen 的免费 tier……但每次切换模型都得改配置、换 SDK，烦得要命。而且单靠一个付费 API，配额一打满你的 Agent 工作流就断了。

OmniRoute 就是为这个痛点而生的。它是一个本地优先的开源 AI 网关，核心理念极其简单：一个端点，连接 177 个 AI 供应商，自动帮你把免费额度用到极致，永远不会因为配额耗尽而卡住。

它用 TypeScript/Next.js 构建，在本地启动一个 OpenAI 兼容的 API 端点（http://localhost:20128/v1），你写的代码、用的 Claude Code/Cursor/Copilot 都指向这个地址，OmniRoute 在背后做四件事：智能路由、自动回退、Token 压缩、格式翻译。对调用方完全透明——你只看到一个"永远可用的 AI API"。

项目由巴西开发者 diegosouzapw 于 2026 年 2 月创建，4 个月即获 5.9k stars、1026 forks，以 MIT 协议开源。官方统计每月有约 19 亿个免费 Token 通过其管道流动。

🚀 核心功能（7 大能力）

1. 四级 Combo 自动回退：永远不断供的 AI 服务

OmniRoute 最核心的撒手锏。把供应商按付费优先级分成四层，请求按层自动降级：

  • Subscription（订阅）：Claude Pro、OpenAI Plus 等，优先消耗
  • API Key：DeepSeek、Groq、xAI 等按量付费，订阅耗尽后切
  • Cheap（低价）：GLM 0.6$/M token、MiniMax 0.2$/M token
  • Free（免费）：Qoder、Kiro、Qwen、Gemini CLI 完全免费端点

触发条件综合了 429 限速 + 402 余额不足 + 连接超时 + 熔断器状态。你的代码永远看到 200 OK。

2. 14 种智能路由策略

priorityweighted round-robinP2C cost-optimizedcontext-relay fill-firstquota-aware P2C

远超市面工具的 "轮询+FIFO"。其中 Context-Relay 可在跨账号切换时注入对话摘要保持上下文连续性；Quota-aware P2C 综合配额余量、回退冷却、错误率、命中次数挑选最优账号。

3. RTK + Caveman 双层 Token 压缩：最高节省 95%

RTK 层负责上下文压缩——智能摘要 + 上下文窗口管理；Caveman 层对请求体格式精简——去冗余字段、压缩 tool call 结果。官方数据：压缩率 15%-95%。

4. 三态熔断器 + Quota 预检

经典 Closed→Half-Open→Open 三态熔断器，状态持久化到 SQLite 重启不丢失。Quota Preflight 在发请求前主动探测限额，而非等 429 再被动处理。

5. Hub-and-Spoke 格式翻译：一套 OpenAI SDK 调用所有模型

以 OpenAI Chat 格式为 Hub，Claude Messages、Gemini、OpenAI Responses 为 Spoke，双向互转。你只需一套 OpenAI SDK。

6. 多协议统一：REST + MCP + A2A

同一端口提供 OpenAI 兼容 API + MCP Server（29 工具） + A2A JSON-RPC 2.0。

7. 完整 Dashboard：Combo Builder + Health + Playground + Eval

React 19 + Tailwind 4 + Recharts + Monaco Editor。可视化构建回退链、实时健康监控、内置 Playground 测试路由策略、成本分析看板。

⚙️ 技术亮点

1. 单进程 Next.js 16 撑起企业级网关能力

所有模块同进程运行，数据层 better-sqlite3（WAL 模式）共 26 张表。npm install -g omniroute && omniroute 即上线，零配置部署。

2. Provider Executor 策略模式：一个供应商一个执行器

open-sse/executors/ 下每个供应商独立 Executor 实现 BaseExecutor。DefaultExecutor 处理通用，CodexExecutor、KiroExecutor 等定制特殊协议。新增供应商只需加一个文件。

3. Context-Relay 上下文接力：跨供应商不掉记忆

contextHandoff 服务在供应商切换时自动注入上一轮摘要，确保 AI 不"失忆"。对 7×24 运行的 Agent 工作流至关重要。

4. 防重试风暴：Anti-thundering-herd mutex + semaphore

供应商不可用时，所有请求同时重试导致"惊群效应"。OmniRoute 用互斥锁+信号量控制并发重试，支持 Wait-For-Cooldown 排队等待。

5. TLS 指纹伪装 + Header 重排：绕过反爬

模拟真实浏览器的 JA3 指纹 + 正版 CLI 的 Header 顺序，提高免费端点反爬通过率。

⚡ 快速上手

# 5 秒启动
npm install -g omniroute
omniroute start
# Dashboard: http://localhost:20128

# Docker 部署
docker run -d -p 20128:20128 \
  -v omniroute-data:/app/data \
  --restart unless-stopped \
  diegosouzapw/omniroute:latest

# Claude Code 中使用
export ANTHROPIC_BASE_URL=http://localhost:20128/v1

⚠️ 使用注意

TLS 指纹伪装可能违反某些免费平台的服务条款，使用前请评估合规风险。
  • 单进程架构不适合 ≥100 QPS 的高并发场景
  • 14 种路由策略有学习成本，新手建议先用默认配置
  • API Key 存储在 ~/.omniroute/ 的 SQLite 中，注意保护权限
  • 上游免费端点 API 变动时需等 OmniRoute 更新
