指向一个网址、一个安装包或一个游戏目录，说一句「照这个做个我自己的」，剩下的交给它：先取证，再让本机的 coding agent 动手写，写完拿原版对比，差在哪就回去改。二十三天冲到四万一千星，靠的不是模型更聪明，而是把「像不像」变成了可以复算的数字——默认模式下，它连目标的一行源码都不许看。

项目背景：逆向的瓶颈不在工具，在证据

传统逆向的开场是打开 Ghidra 或 IDA，对着一屏汇编和伪 C 啃。工具本身没问题，问题在流程：分析结论写在笔记里，靠人记住；换个人接手，得从头再走一遍；报告里的「这里应该是加密函数」既没有置信度，也没有覆盖率，错了也没人知道错在哪一步。

让大模型来干这件事，多了两个新坑。第一，模型会凭记忆补齐。你说「复刻这个落地页」，它可能直接吐出一个记忆里相似的页面，看起来像，实际和原版没关系。第二，产出无法验收。截图对比肉眼看着差不多，究竟差 3% 还是差 30%，全凭感觉。

法律边界是第三个变量。今年十月那波「逆向一切」的热潮之后，读别人源码这件事被讨论得很充分：能跑起来不等于能拆开看，能拆开看不等于能照着重建。多数工具的态度是「你自己负责」，把边界留给用户判断。

Craft Anything 的切入点是重排这条流水线：把「看懂」拆成一系列带出处的观测动作，把「重建」交给本机的编码 agent，把「验收」变成相似度和差异清单，最后用一次次的对比把结果推到阈值之上。它假设的不是模型有多强，而是每一步都能被查。

核心功能

1. 四步流水线：观测、构建、比对、交付

一次任务分四步。Study 阶段采集目标：网页按多档宽度截图、读取可见文本、测量布局与配色字体、展开菜单和弹窗记录状态；桌面应用和游戏则抓窗口画面、跑一遍交互路径。采集结果落成结构化证据，再压成一份 brief 和分步计划。

Build 阶段不自己写代码，而是把你本机装好的 coding agent 拉起来干活，在 app/ 目录里新建工程。Check 阶段拿新工程和原件逐项对比，列出「哪些还不一样」。Ready 阶段可以预览、试玩，或者在底部输入框里继续提要求，进入下一轮。

需要人拍板的地方不会静默略过：core_person_ask 会抛问题卡，core_action_approve 会拦下规则外的命令等你点同意。每个项目目录结构是固定的——craft.json 存请求、目标和历史，capture/ 存从原件采到的东西，checks/ 存每一轮比对，investigation.cany/ 存证据，inbox/ 存待答问题。项目可以随时中断再续，--continue-in 指回目录就行。

2. 净室与深潜：默认不往里看

两种模式决定了「能看多深」。

净室（Clean room）是默认档。它只允许看访客能看到的东西：截图、可见文字、实测出来的布局尺寸与间距、颜色和字体、菜单展开后的状态。任何会「往里看」的工具在这一档会被拒绝调用，并提示怎么切到深潜。这条规则写在引擎层，不是靠提示词劝模型自觉。

深潜（Deep）放开全部工具：ELF、PE、Mach-O 解析，自带的反汇编与反编译，可选接 Ghidra，Android 侧接 adb、Frida、JEB，.NET 走 IL 结构，Java 走 Vineflower。适合自家遗留系统、有授权的私有软件，或者纯粹想搞清楚某个二进制在干什么。

这里的边界要说清楚：净室是产品规则，不是操作系统沙箱。它管的是「Craft Anything 提供什么工具、拒绝什么工具」，不隔离你的电脑。被拉起来的 agent 仍然以你的身份、你的权限在跑，它能读写什么，取决于它自己的设置。

3. 305 个工具，一套接口三种外壳

引擎里有 305 个工具，分 17 组：核心会话与证据 36 个、原生程序 55 个、文件格式 36 个、网页 24 个、安卓设备 24 个、项目 21 个、应用比对与重建 17 个、Apple 14 个、安卓静态 14 个、运行时 14 个、Electron 与 JS 11 个、Frida 9 个、安装与设置 9 个、.NET 8 个、Java 6 个、构建 6 个、数据库 1 个。加上 AI 层和安装层自己的十几个（rebuild_*、ai_model_*、setup_*），对外宣称 320 个左右。

每个工具同时是三样东西：MCP 工具、CLI 子命令、agent 可调的函数。所以 craft-anything-cli commands 能列全，craft-anything-cli mcp 能把同一批工具挂给任意 MCP 客户端，桌面应用用的也是这一套。这个设计的好处很直接——你可以不用图形界面，让 Claude Code 自己在终端里跑完一次复刻；也可以不用 agent，纯手工一个个工具查。

4. 证据台账：每条结论都带置信度和覆盖率

这是整个项目最值得看的部分。所有工具返回同一个 Evidence 结构，字段包括：看了什么（subject，带目标文件的 SHA-256）、问了什么（operation 与参数）、结果是什么、有多确定（Confidence）、凭什么（Authority）、哪里没查到（Limitation、Coverage）、指向目标里的哪个位置（Location）。

Confidence 只有三档，界面上翻成人话：Observed 是「亲眼看到」——字节、报文头、抓到的请求；Derived 是「算出来的」——控制流图、调用图这类确定性推导；Inferred 是「猜的」——启发式命名、模型解读。Authority 记来源：原件本身、我们控制的运行、历史记录（HAR、崩溃转储）、外部服务、还是某人的推理。

Coverage 记查了多少：状态是完整、部分还是未知，已查数量和总量分别是多少，下一页从哪个偏移续。所以「我看了 200 个函数中的 43 个」是写在记录里的，不会被含糊成「分析完成」。

证据的 id 是它规范化 JSON 的 SHA-256。同一次观测永远得到同一个 id，记录存下来之后改一个字节都会被发现。配合导出、导入、两份证据包互比这几个工具，一次分析可以交给别人复核，也可以在两个版本之间做差集。

还有一类对象容易被忽略：Unknown，记录「还不知道什么，以及什么能定论」。它的态度是「没找到不等于不存在」——这在一个会自动补全的行业里，算是难得的自我约束。

5. 比对是量出来的

网页复刻的默认设置写在引擎的构建配置里：比对宽度 1440、768、390 三档（可改，最多四档），最多四页，目标相似度 90 分，最多六轮，两路并行。

像素比对的输出不是一个模糊的「挺像」，而是两个 0 到 1 的数：layout_similarity 按 16 像素的色块算有多少块平均颜色对得上，perceptual_similarity 算亮度 SSIM 的均值。尺寸不一致时比对两者重叠的区域，并在结果里写明。为了让两次截图可比，浏览器环境被固定：1280×720 视口、en-US、UTC、浅色、开减弱动画、关 Service Worker。

游戏走另一条路：用项目自己的自测跑行为，比对两边的运行结果。应用则比对两次运行的界面与调用。

技术亮点

1. 反汇编器和反编译器是自己写的

深潜需要的那套底层能力，Craft Anything 没外包。crates/disasm 提供反汇编、伪 C 反编译、调用图、交叉引用；crates/formats 处理 PE、ELF、Mach-O、Unity 资源包、Unreal pak 与 IoStore、固件、pcap、SQLite；crates/engines 只管外部工具（Ghidra、apktool、JADX、tshark、rtl_433）的探测与调用。Ghidra 是可选项，不是前置条件。

代价是还原度。伪 C 对函数参数的处理依赖一张 arity 表，表外的导入函数只能显示出调用块里已经设好的那几个参数——这一点在他们自己的状态表里明确标为「部分可用」。换来的是零外部依赖、跨平台、能在浏览器里跑（apps/craft-anything-web 编译成 WASM，用来识别文件类型）。

2. 用证据约束模型，而不是用提示词

大多数 agent 类项目靠系统提示词约束行为：不要说谎、不要猜测、给出来源。这套写法在长任务里会衰减。Craft Anything 换了个位置——模型不是证据的生产者，只是证据的消费者：工具产出带置信度的记录，模型基于记录写 brief 和代码，比对环节再拿新记录去验证结论。

好处是可审计。判错能定位到「哪一条观测的置信度被误读」，而不是笼统地怪模型。代价是每个工具都得按统一结构封装，工具越多，封装和维护成本越高；305 个工具意味着 305 份这样的契约，任何字段改动都是全量回归。

3. 一个仓库，十三块拼图

工作区拆成 13 个 crate：engine（工具与调度）、formats（文件格式）、ui-egui（桌面界面）、ai（重构流程与 agent 适配）、analysis、engines、disasm、js、platform、setup、evidence、mcp、testkit。仓库里 897 个 .rs 文件，crates/ 自身约 12.5 MB（另有约 2 MB vendored 依赖源码）。桌面、CLI、MCP、WASM 四个入口共用同一套引擎，这是它能做到「每个工具既是界面按钮又是命令行」的前提。

构建侧的接入方式也值得记一笔：它不改你装的 Claude Code，直接把你自己的 claude 程序当子进程跑，用你自己的登录。Codex 的适配器写了但没在真实安装上验证过，Copilot CLI 与 Grok Build 走 ACP 接入，Gemini CLI、Qwen Code、opencode、goose 等也能切过去。

适用人群

  • 前端与全栈：想弄明白某个网站的交互动效怎么做的，净室模式下采集布局与状态流，产出一个可运行的同构版本。省的是逐个元素量尺寸、反复比对截图的时间。
  • 维护遗留系统的团队：手上只有二进制或没人敢动的老项目，深潜模式读自家代码，证据包可以当交接材料，两份证据包互比能看出两个版本之间改了什么。
  • 独立游戏开发者：想复用某款游戏的玩法机制，让它把状态机、关卡节奏、手感参数拆出来，用自己的美术重做。这条路的前提是只借机制、不搬素材。
  • 技术教学与安全审计：证据链带置信度和覆盖率，讲「这个函数为什么判定是加密」时能指到具体观测，比口头结论扎实。
  • Agent 工具链开发者：305 个工具全部走 MCP，可以直接当自己 agent 的取证后端，不必从零搭一套二进制分析接口。

快速上手

最省事的是下预编译包：Windows 有 msi 与 portable，macOS 是签名并公证过的 dmg，Linux 有 AppImage、Flatpak、deb、rpm、tarball，FreeBSD 给 tar.gz。想从源码来：

git clone https://github.com/storytold/craft-anything && cd craft-anything
cargo run --release -p craft-anything          # 桌面应用
cargo install --path apps/craft-anything-cli   # 装 CLI
craft-anything-cli doctor                      # 体检：Rust、引擎、agent

然后就可以命令行直接干活：

craft-anything-cli commands                                    # 列出全部工具
craft-anything-cli rebuild https://example.com "复刻这个页面"
craft-anything-cli rebuild - "用 Rust 写个贪吃蛇" --rounds 1
craft-anything-cli mcp                                         # 挂给任意 MCP 客户端

几个必踩的坑：Rust 需要 1.97 以上，第一次 cargo build 时间不短；Linux 编译桌面端要装一堆 X11、Wayland、GTK 开发包；必须本机已登录一个编码 agent，doctor 会告诉你缺什么；Flatpak 版本是沙箱的，起不了浏览器，学网页那部分得换别的包；构建时会执行 npm install、cargo 这类命令，安装脚本本身就在跑代码，不信任的依赖别随手点「总是允许」。

边界在哪：它擅长「界面与行为可观测」的目标，网站、桌面应用、小游戏这类；对需要协议逆向、加密算法还原、大规模服务端逻辑的场景，305 个工具也顶不上一个有经验的逆向工程师。跟四天前写过的 rust-anything 也不是一回事——那个是边迁移边拿原行为对拍，管的是「改写得对不对」；这个管的是「看懂了多少、复刻得像不像」。

局限与风险

  1. 早期 alpha，接口还会动。十二天发了七个版本（v0.1.0 → v0.6.1），520 个 open issue 里大量是路线图编号条目。行为比对（应用、游戏）仍标为部分实现，除 Claude Code 外的后端多是「写完没实跑」。
  2. 工具实测极不均匀。docs/tool-status.md 那张表很诚实：Frida 9 个工具全部未验证、安卓设备 23 个未验证、运行时 5 个未验证、Apple 6 个未验证，审计主要在 Windows 11 上做，Linux 和 macOS 只有零星抽样。305 个工具的能力清单，不能当成 305 个都能用。
  3. 净室不等于安全边界。它是规则层拦截，不是内核隔离。拿它跑来源不明的二进制，仍然该放虚拟机里。同理，依赖安装会执行第三方脚本。
  4. 保真度缺公开基准。90 分是工具内部的收敛阈值，不是「可用」的标准；某篇中文评测给了一个具体例子——某页与原版 87% 像，差距落在导航行高、按钮圆角和一段文案。这类样本目前只有个案，没有跨站点、跨应用的系统评测。
  5. 成本落在自己账号上。一轮四页、最多六轮，每轮都是真实 token；复杂页面往往要人再验收一遍。
  6. 法律风险没有消失。净室降低了「接触源码」的风险，但不等于免责。默认提示不复制 logo、照片、文案，DRM、登录、反作弊一律不绕。复刻别人的产品，商标和不正当竞争这两条线仍在。
  7. 关注度结构偏中文社区。四万一千星的同时，Hacker News 上那条发布帖只有 6 分 3 条评论（2026-11-05），英文独立评测很少，中文侧的实测与转述更多。星数涨得快，独立复现的样本还薄。

写在最后

第一点判断：它真正改的不是逆向工具的效率，而是「结论要不要留证据」这件事的门槛。以前这套做法只在取证和合规场景里出现，现在被写进了默认流程——每个工具返回带置信度、覆盖率、可校验哈希的记录。哪怕你不用这个项目，这套结构也值得抄。

第二点判断：净室模式是个聪明的产品决策，把最容易踩线的那部分（读源码）从默认路径里拿掉，同时把深潜保留给自有资产。它解决不了版权问题，但把「我该不该看」变成了一个显式开关。

想动手的话，建议这样起步：先下 release 包，doctor 跑通，挑一个自己写过的静态站点做净室复刻——你对原版熟悉，才看得出那 90 分是真是假。等比对逻辑摸熟了，再拿自家老项目的二进制试深潜。
