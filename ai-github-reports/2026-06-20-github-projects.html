📌 项目背景：AI 编码工具碎片化之痛

2026 年上半年，AI 编码助手（Claude Code、Codex、Cursor 等）的能力突飞猛进，但使用体验却愈发碎片化。Databricks 工程团队（5000+ 人）在实践中发现：工程师们经常同时打开 4-5 个 AI 编码工具，在它们之间来回复制粘贴文本；每个工具拥有独立的 CLI、配置、会话历史和上下文管理机制，彼此之间完全隔离，无法协同工作。

更深层的问题在于：当工程师希望"让 Claude Code 写完代码后自动交给 Codex Review"或"用手机查看桌面上跑着的 Agent 进度"时，现有的单点工具完全无法满足。行业最佳实践正在从"单一 Harness 内的单一模型"向"多模型、多 Harness 协同编排"跃迁——Anthropic 的研究团队早已将其产品构建为"主 Agent 编排并行子 Agent"的模式；Harvey 通过给开源工作者模型配备前沿顾问模型，在质量和成本上同时击败了前沿模型。

2026 年 6 月 13 日，Databricks 团队（Matei Zaharia、Kasey Uhlenhuth、Corey Zumar）正式开源了 Omnigent——一个位于所有 Agent "之上"的元编排框架（Meta-Harness），将这些孤岛式的工具统一为一个可互操作系统。采用 Apache-2.0 协议，截至 2026 年 6 月 20 日已获得约 4100 GitHub Stars，9 天内获得如此关注，反映了开发者对"AI 工具碎片化"问题的强烈共鸣。

🚀 核心功能（7 大功能详解）

🌐 跨设备会话同步

终端、浏览器、手机访问同一会话，消息/子Agent状态/终端/文件实时同步。手机访问 http://192.168.x.x:6767 即可查看桌面任务进度

🤝 多 Agent 统一编排

一个会话内同时运行多个Agent，互相评审工作。内置Polly示例：技术主管规划任务→分派给Claude Code/Codex/Pi→并行执行→交叉Review

🔑 四种凭据一等公民

API Key / 订阅账号(Claude Pro/ChatGPT) / 网关(OpenRouter/Ollama/vLLM) / Databricks，首次运行自动检测，无需逐个配置

👥 实时团队协作

URL共享会话，支持三种模式：实时观察、共同操作、对话分叉（复制到本机独立继续）。会话成为团队协作的主要场所

☁️ 云端沙箱运行

在Modal/Daytona/Islo临时云端环境运行，无需本地在线。沙箱按会话独立分配，支持出口代理注入凭据（Agent看不到原始token）

🛡️ 三层策略治理体系

服务端全局/Agent级/会话级三层策略，裁决结果ALLOW/DENY/ASK。支持：npm安装后需审批git push、仅可写自己创建的文档、成本预算上限

🔄 跨 Harness 可移植 YAML

一个YAML定义Agent，一行更改即可在Claude Code/Codex/Pi/Cursor/OpenAI Agents SDK之间移植，彻底解决"Harness锁定"问题

🔬 技术亮点一：统一的消息/文件 API 抽象层

Omnigent 架构的核心洞察是：无论每个 Agent Harness 内部如何调用其 LLM，面向用户的接口都是相同的——消息和文件输入，文本流和工具调用输出。基于此，Omnigent 构建了一个通用 API，既能包装基于终端的编码 Agent（Claude Code、Codex、Pi 等），也能包装 SDK（OpenAI Agents、Claude Agents SDK 等）。

📱 应用层：Terminal UI (omnigent_ui_sdk) / Web UI (React+TypeScript) / macOS Desktop App / Python Client SDK
⚙️ 服务端层：FastAPI Server，REST API管理Agent/会话/策略/主机，认证(OIDC)，多用户，在线状态
🔌 Runner 层：FastAPI子进程管理，路由工具调用，MCP连接管理，WebSocket隧道暴露
🛠️ Inner Harness 层：Claude SDK/Native、Codex、OpenAI Agents、Pi、Databricks执行器；bwrap/seatbelt沙箱；出口代理
📋 Agent Spec 层：YAML定义(AgentSpec/ExecutorSpec/ToolSpec/PolicySpec)，统一解析校验，跨Harness可移植

这种抽象使得"Harness 可以在其下不断演进，而用户侧的会话、策略和技能保留不变"——类似于 Kubernetes 在基础设施层做的事情，Omnigent 在 Agent 编排层做了同样的事情。Databricks 博客中将这种转变类比为基础设施领域的重大抽象层迁移。

🔬 技术亮点二：基于 Databricks 安全方案的 OS 级沙箱

沙箱实现方案

Linux: bubblewrap (bwrap) — 非特权沙箱，不需要root权限
macOS: 内置 seatbelt 框架
️ 网络代理: 出口代理透明注入凭据（如GitHub token），Agent进程本身看不到原始令牌
️ 策略联动: 策略引擎可基于沙箱状态做出智能决策（如：npm安装新包后，git push需人工审批）

这种沙箱方案比 Docker 更轻量，且专门针对 AI Agent 的操作模式设计（需要网络访问但应限制敏感信息泄露）。Omnigent 的 Runner 组件通过 Inner Harness 层提供沙箱隔离，结合出口代理（egress proxy）能力，可以拦截和转换网络请求，实现"Agent 能用 GitHub 但看不到 token"的精细权限控制。

🔬 技术亮点三：上下文感知的策略引擎

三层策略层级（严格的优先）

服务端全局：管理员配置，适用于所有Agent和会话（最严格）
Agent 级：开发者在YAML中配置，适用于该Agent的所有实例
会话级：用户临时设定，仅适用于当前会话（最宽松，但受上层约束）

策略通过 Python 函数实现（omnigent.policies.builtins.safety.*、omnigent.policies.builtins.cost.*），用户也可以通过自然语言描述需求，让 Omnigent 的 Agent 自动生成策略配置。这比传统的"允许/拒绝"静态规则强大得多——策略可以跟踪每个会话的动态状态并做出智能决策。

# 策略配置示例 (YAML) policies: approve_shell: type: function handler: omnigent.policies.builtins.safety.ask_on_os_tools cap_calls: type: function handler: omnigent.policies.builtins.safety.max_tool_calls_per_session factory_params: limit: 50 budget: type: function handler: omnigent.policies.builtins.cost.cost_budget factory_params: max_cost_usd: 5.00 ask_thresholds_usd: [3.00]

🔬 技术亮点四：MCP（模型上下文协议）原生集成

Omnigent 的 Runner 组件内置 MCP 连接管理，支持接入 MCP 服务器以扩展工具能力。MCP 是 Anthropic 推出的标准协议，用于在大模型应用之间共享上下文和工具。Omnigent 作为 Meta-Harness，天然适合作为多个 Agent 共享 MCP 工具的中间层。

路线图中还提到了"Omnigent Server MCP"计划，将让 Agent 能够跨会话工作，进一步提升协作能力。这意味着未来 Omnigent 不仅管理单个会话内的多个 Agent，还可以管理跨会话、跨项目的 Agent 协作。

⚡ 快速上手

安装（一行命令）

curl -fsSL https://raw.githubusercontent.com/omnigent-ai/omnigent/main/scripts/install_oss.sh | sh

或使用 uv tool install omnigent（推荐），或 brew install omnigent-ai/tap/omnigent（macOS）

启动第一个会话

omni # 自动引导选择模型，启动会话（同时启动本地Web UI）
omni claude # 直接启动Claude Code
omni codex # 直接启动Codex
omni run examples/polly/ # 运行内置Polly多Agent编排示例

CLI 有两个等价命令名：omnigent 和 omni

配置策略（自然语言方式）

在 Omnigent 聊天中输入："Add a policy that asks me before running shell commands." — Agent 会自动配置相应的策略 YAML。
