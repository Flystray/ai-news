一条 70 秒的产品宣传片，12 个镜头，83% 的画面是代码驱动的动效，12% 是录屏（项目自述）——这种「制作方式结构」过去只能靠人眼一帧帧猜，现在有一套工具能在本地把它拆出来，连每条字幕的进出时间都列清楚。rea-video 干的就是这件事：逐个镜头判断素材是实拍、AI 生成、3D 渲染还是代码渲染，再告诉你怎么复刻。它最反直觉的一点是：判断「是不是 AI」不是靠一个分类器打分，而是把帧率指纹、传感器噪声、平面运动这些可测量的硬证据摆在前面，「看起来像」只许兜底。

## 项目背景：爆款结构肉眼拆不动，AI 检测器又在转码面前失灵

短视频行业有一个公开的秘密：爆款是可以拆解的。钩子在前几秒、剪辑卡不卡点、口播和 BGM 怎么分层，这些结构规律决定了一条视频能不能被复用。但拆解的劳动强度极高——一条 30 秒带货视频可能有 29 个镜头，逐帧看哪些是手机拍的、哪些是 AI 生成、字幕几点进几点出，熟练剪辑师也要花上一个小时。

另一头的痛点是 AIGC 检测。市面上多数「AI 视频检测器」是一个单帧分类器，看整段视频给一个百分比。问题在于视频从抖音、微信下载下来都被二次压缩过，压缩会抹掉传感器噪声这类关键证据。rea-video 的评测记录里有一条很扎眼：一条 72 秒的实拍开箱视频，离线工具判定 35% 的画面是 AI——这是压缩后噪声证据失效导致的典型误报。误报对普通用户只是体验问题，对做内容审核、买号投放的团队就是真金白银的决策错误。

还有一层：就算你判断对了每个镜头的做法，怎么复刻又是另一门学问。AI 镜头要拼提示词、实拍镜头要列布光清单、代码动效要写成 Remotion 项目，三种工序完全不同。没有一个统一的「拆解结果格式」，拆完的笔记也无法交给下一个 AI 继续干活。rea-video 把这三件事——判定、拆解、复刻规划——装进了同一条流水线。

## 核心功能

### 1. 逐镜判定制作方式：11 类标签，每镜独立裁决

先把视频切成镜头（HSV 直方图距离加自适应阈值找切点，交叉溶解还要用光流验证中间帧是不是首尾帧的线性混合），每个镜头给出基础画面的制作方式：实拍、AI 视频、数字人、3D 渲染、代码渲染、录屏、静图推拉、定格动画、影视混剪素材等 11 类。叠在画面上的字幕、贴纸、画中画单独列一层，所以一个镜头可以同时是「AI 视频 + 代码字幕」。判定靠的是可测量证据：帧率指纹（生成模型多输出 24fps，转 30fps 后约 20% 的帧是重复帧）、Immerkær 噪声估计、8×8 平坦块占比、覆盖 95% 像素所需的颜色数、手持抖动，以及元数据里的 GB 45438 隐式 AIGC 标签和 C2PA 凭证。

### 2. 证据链与概率融合：硬证据压过「看起来像」

融合公式在代码里写得很直白：最终概率正比于确定性概率的 0.6×信任权重次幂乘上视觉模型的概率（我核过 `rea_video/classify.py`，`DET_WEIGHT` 定格 1.6、静图推拉 1.4、代码渲染 1.0，实拍和 AI 只有 0.6——确定性强的类别少让步，AI 与实拍的边界交给看图的模型）。两条硬约束兜底：画面冻结的镜头不允许判成任何视频生成；整幅画面刚性推拉的不允许判成实拍或数字人。工具和看图方打架时标记「待复核」，不许直接改判。

### 3. VIDEO.md：给 AI 读的分层拆解包

完整拆解动辄几十万 token，直接喂给 agent 太贵。rea-video 把结果写成 VIDEO.md——一个开源格式：顶层是几百 token 的卡片，往下依次是总览、逐镜时间线（每镜一行）、每镜一个文件，每个文件都标注自己的大小，屏幕上看到的和工具推断的分开记录。任何 agent 或工具装一个 `pip install videomd` 就能读，不必了解 rea-video 本身。同时产出给人看的 `report.html`（或 PDF），含结构时间线、人物场景道具清单、布光与剪辑分析、复刻方案。

### 4. 复刻规划：按目标模型的能力表排工序

拆解不是终点。`rea_video/capabilities/` 里维护着视频、图像、音频模型的能力表（最长片段、是否支持多镜、吃几张参考图），复刻方案按你指定的模型生成——默认对齐 MiniMax H3 的规格，也可以换成别的。11 类标签在路由表里各有去处：代码动效直接重建成 Remotion 项目，录屏镜头提醒你自己去录，实拍镜头给出布光清单。配套的姊妹项目 capsule-cinema 能把 AI 镜头自动生成并放回原时间线，先免费干跑、确认后才调付费模型。字幕全程可导出 SRT/ASS。

## 技术亮点

### 1. 确定性取证优先，视觉模型只补弱区

多数同类产品的路径是「把帧喂给多模态模型问一遍」。rea-video 反过来：先用 ffmpeg 层面的确定性测量建立证据，视觉模型只在实拍/AI/3D 这条弱边界上起作用，音效识别干脆整体让给 Gemini 这类能听的模型——因为评测里测出确定性层的音效精度只有约 0.2，与随机相当。这种「知道自己在哪不行」的设计，比堆模型参数更难得。

### 2. 对平台转码做了专门的对抗规则

从微信、抖音下载的视频带着 `Tencent CAPD MTS` 这类转码水印，噪声证据整体失效。项目为此加了一组规则：转码视频里「没有噪声」不再推向 AI；30fps 文件中实拍类镜头 70% 以上时长没有重复帧则倾向手机直出。这组规则把转码视频集的平均得分从 0.79 拉到 0.92（项目自述，开发集口径）。能专门为「国内用户实际拿到的视频形态」调规则，是这个项目区别于海外同类工具的地方。

### 3. agent 复核有自己的纪律，不盲从也不盲拒

没有外接视觉模型时，agent 自己看逐镜联系表来复核，但规则写死了「看不了图时不得推翻工具的制作方式判断」——这条规则来自一次实测：用不能看图的 DeepSeek Flash 复核 11 条有真值的视频，推翻工具 4 次只对 2 次，凭像素统计乱改判反而把分数拉低。看图来源只有一个时也不强制多数表决：三方任意多数的方案在转码视频集上实测从 98.4% 掉到 91.9%，因为两个看图模型常把同一画面错成同一类。

## 适用人群

- **短视频创作者/操盘手**：拆爆款不再靠逐帧人肉，一条 70 秒宣传片的制作成本结构（该拍、该生成、该写代码）几分钟摆上桌，复刻方案直接可执行。
- **投放与风控团队**：判断达人交来的「实拍素材」是否掺 AI，转码误报问题有专门对抗，逐镜结论比整片百分比可追责。
- **AI 工作流开发者**：VIDEO.md 是开放格式，拆解结果可以直接成为下游 agent 的输入，等于给视频内容做了一次结构化索引。
- **内容研究与教学**：结构时间线、钩子分析、布光清单，做媒介素养和创作教学的素材现成。
- **对 AIGC 取证感兴趣的安全研究者**：OffSec Blog 把它归类为 AIGC 取证（AIGC forensics）工具，逐镜证据链比单帧分类器更适合溯源分析。

## 快速上手

前置依赖只有 ffmpeg 和 Python 3.10+。最省事的方式是把安装也交给 agent：

```text
Install https://github.com/JuneYaooo/rea-video, then break down this video: /path/to/video.mp4
```

或者装成插件，让 skill 常驻：

```bash
# Codex
codex plugin marketplace add JuneYaooo/rea-video
codex plugin add rea-video@rea-video

# Claude Code
claude plugin marketplace add JuneYaooo/rea-video
claude plugin install rea-video@rea-video
```

三个常见坑：一，首次拆解会下载 UVR MDX-Net（人声/音乐分离）和 BandIt v2（音效分离）的权重，不是卡死；二，默认中文输出，要英文报告跑 `rea-video prefs lang en`；三，不配视觉模型也能跑，但平台转码视频建议接一个 Gemini 或豆包的端点，能把判定拉回 99% 以上（项目自述）。评测可复现：`rea-video eval eval/holdout.yaml -o out/eval_hold`，不过评测视频清单不随仓库分发，第三方只能复现流程、拿不到同一批样本。

## 局限

评测文档的诚实程度罕见地高，把家底都亮了，以下几条值得掂量：

1. **未见过的内容类型掉分明显**。抖音带货这种首次遇到的内容，只用工具准确率 46.4%，要靠 agent 看图复核才到 97.5%；影视混剪更是只有 15%——工具测不出「影视片段」这一类，必须看图。
2. **固定机位是重灾区**。画面几乎不动时只剩纹理和噪声可用，转码后的手机实拍（俯拍手部、拍真实手机屏幕）容易被当成 3D 或代码渲染；整图缓慢推拉的 3D 动画会被当成静图推拉。
3. **音效与音乐来源是确定性层的短板**。音效精度约 0.2 与随机相当，完整音效清单要靠能听的模型；普通视频里的 Suno 生成 BGM 从信号上与曲库分不开，不开 VLM 时音乐来源判断 5 条只对 2 条。
4. **评测规模小且部分集合不独立**。实拍样本只有 3 条；holdout 的规则是在看过首轮错误后加的，作者自己在文档里承认「留出集的数字应按相近样本上的表现理解」。
5. **生态依赖偏国内视频模型**。复刻方案默认对齐 MiniMax H3，视觉模型点名 Gemini 与豆包；海外用户接不上这套组合时，能力表路由的价值会打折扣。
6. **热度带来了仿冒**。仓库顶部专门声明项目方不发任何加密代币；issue #16 里作者对第三方搭的在线版 rea-video.com 做了切割说明。用的时候认准原仓库。

## 对比分析

| 维度 | rea-video | Hypit（一键复刻） | 通用 AIGC 检测器（单帧分类器） |
|------|-----------|------------------|------------------------------|
| 核心输出 | 逐镜判定 + 证据链 + 复刻方案 | 直接生成一条新视频 | 整片「AI 含量」百分比 |
| 对转码的对抗 | 专门规则 + agent 复核 | 不处理判定问题 | 无，压缩后误报率高 |
| 复刻能力 | 按镜头分工（拍/生成/写代码） | 端到端生成，强于口播类 | 无 |
| 运行成本 | 工具层离线免费，看图按量付费 | 依赖其支持的生成模型 | 多为云端 API |
| 局限/风险 | 固定机位与影视混剪仍弱，评测样本小 | 不回答「原片怎么拍的」 | 单帧分类器无逐镜可解释性 |

一句话点评：想要快速出一个像样的仿片，Hypit 更快；要弄清楚原片是怎么做出来的、并且把复刻成本压到最低，rea-video 的路径更省。两者并不互斥，拆解和生成各管一段。

## 写在最后

rea-video 真正立住的不是「又一个 AI 检测器」，而是两件事：把视频拆解从手艺活变成可复现的取证流程，以及把拆解结果定义成 agent 能直接消费的开放格式（VIDEO.md）。前者让「学爆款」从玄学变成工序，后者让拆解结果进入 AI 工作流——下一个 agent 可以接着拆解结果写复刻脚本，不用从头看视频。

对读者的建议很具体：如果你在做短视频或投放，先拿一条自己知道的底细的视频跑一遍工具层（离线免费），对照真值看看它在你的内容类型上的表现，再决定要不要接视觉模型；如果你在做 agent 工作流，值得研究 VIDEO.md 的分层设计，这种「按需读取、标明证据与推断边界」的格式思路，同样适用于拆解网页、拆解 App。项目由 REA（Reverse Engineer Anything）方法论启发而来，这条「从成品反推做法、每个论断挂证据」的路线，值得顺着它的引用链多看几眼。
