---

## 一、它到底在解决什么问题？

今天绝大多数 AI Agent 项目还停留在"代码生成器"层面：LLM 读 README、写 diff、提 PR。但 Neo.mjs 的设计者认为这远远不够——

> "Where the industry runs one AI agent and gets slop, Neo.mjs runs a swarm of minds from rival labs — Claude, Gemini, GPT — that read each other's reasoning through shared memory."

它要解决三个真正棘手的问题：

1. **单 Agent 的盲区**：单个模型对自己的失误往往视而不见，需要"异源交叉审查"才能暴露。
2. **静态代码 vs 活运行时**：传统 Agent 只能"读代码"，但运行时状态、用户实际操作路径、生产 bug 现场，这些在代码里看不到。
3. **战术噪声 vs 战略方向**：Agent 每天生成大量会话、调试记录、PR 评论，需要一个"做梦"机制把它们消化成长期路线图。

为此，Neo.mjs 提出了一个极其独特的**两半球架构（Body/Brain Split）**：

| 半球 | 环境 | 角色 | 关键技术 |
| --- | --- | --- | --- |
| **Body**（身体） | 浏览器 | 高性能 UI 渲染、VDOM 管理、用户交互 | Web Workers、ESM、Virtual DOM |
| **Brain**（大脑） | Node.js | 认知循环、语义 RAG、自主任务执行、自愈 | Node.js、ChromaDB、SQLite、MCP |

两个半球通过 **Neural Link** 桥接（一个 JSON-RPC over WebSocket 通道），使得 AI 蜂群可以"附身"到正在运行的应用上，读取真实的运行时状态、修改 UI、注入数据——把"聊天面板"变成"应用内的协作体"。

## 二、核心功能：六大子系统

### 1. Body：真多线程应用引擎

不是 Web Worker 的简单封装，而是完整的**多线程架构**：

- **Main Thread**：仅负责 DOM 操作和事件转发
- **App Worker**：业务逻辑、组件生命周期、应用状态
- **VDom Worker**：虚拟 DOM diff 与 delta 计算
- **Data Worker**：后端通信和数据操作
- **Canvas Worker**：GPU 加速的图形渲染
- **Service Worker**（可选）：离线缓存

**零编译开发模式**：直接以原生 ES Modules 在浏览器中执行，迭代时无 transpile 延迟，HMR 几乎瞬时。VDOM 用纯 JS 对象表示，无模板引擎开销。

### 2. Brain：跨模型蜂群（Cross-Model Swarm）

不同家族的模型（Claude、GPT、Gemini）在同一个仓库里**互相审阅对方的 PR**——这是它的杀手锏。每个 agent 都有自己的：

- **Verify-Before-Assert** 操作准则（AGENTS.md 强制）
- **Ticket Gate**：没有合法工单 ID 不允许 commit
- **No Direct Merges**：agent 永远不执行 `gh pr merge`，合并权保留给人类

支撑这套机制的是**四阶段认知循环**（Cognitive Loop）：每个 agent 行动前必须先在 Memory Core 中检索上下文，行动后必须把结果反思回写。

### 3. Active Hybrid GraphRAG

比传统 RAG 强的地方在于——它**不只做语义检索**：

- 底层是 SQLite 支持的 **Native Edge Graph**（原生边图）
- 每次 agent session 都会被消化为带语义标签的"边"
- 战略层面的 **Golden Path Topology** 由图谱提炼，战术层面的 **Lazy Edges** 按需加载

查询时同时跑**语义匹配**（Chroma 向量库）+ **结构遍历**（图谱）两条路径，再融合结果。这让它能回答"哪个文件历史上出过最多自愈修复"这种带时间维度的复杂问题。

### 4. DreamService（做梦服务）

听起来玄学，实际是**离线整合管道**：当 swarm 不忙时，DreamService 触发"REM cycle"，把过去一段时间的所有 session、PR 评论、运行时崩溃、ticket 摘要"消化"成新的图谱边、新的 skill、新的 priority 列表。这就是 `learn/agentos/rem-state-model.md` 描述的"REM 状态模型"——agent 真的会"做梦"来重新组织记忆。

### 5. Neural Link（神经链）

AI 操控活应用的关键通道。它不是简单的 RPC，而是**对象级引用图谱**：

- Brain 可以订阅 Body 中任意 VDom 节点的状态变化
- Brain 可以直接 mutate 客户端 UI（用户在浏览器里能看到 agent 改了他的页面）
- Body 也可以反向 push 用户操作轨迹给 Brain 做分析

这让"AI 协作界面"从"聊天侧栏"升级为"应用内协作体"。

### 6. Progressive Disclosure Skills（渐进披露技能）

LLM 上下文窗口永远不够用。Neo 的解法是**按需 lazy-load**——`.agents/skills/` 目录里挂着几十个 skill 文件，只有当某个具体工作流被触发（如 `pull-request`、`ticket-intake`）时，对应 skill 的 instructions 才被加载进 prompt。

> 类比一下：就像 IDE 的"按需加载代码补全"，只不过这里是"按需加载 agent 行为规范"。

## 三、技术亮点：为什么值得关注

1. **跨模型异源审查**：让 GPT 审 Claude 的 PR、让 Gemini 审 GPT 的实现，是真的能抓到单模型盲区的（[ReputAgent 报告](https://reputagent.com/ecosystem/neomjs-neo)专门把它列为"Semantic Capability Matching Pattern"的代表案例）。

2. **活运行时操控**：通过 Neural Link，agent 不再是"读代码"而是"在应用里协作"，是 Agent OS 概念的具象化落地。

3. **REM Dream Pipeline**：用"做梦"机制把战术噪声消化成战略图谱，本质上是把"持续集成"扩展到了"持续反思"。

4. **Verify-Before-Assert 强制准则**：所有 agent 在断言前必须先运行经验性工具验证。这是在 AGENTS.md 写死的硬约束，不是建议。

5. **真正的零编译 ESM**：浏览器直接跑 `.mjs`，无 Webpack/Vite 中间层，启动延迟和调试体验都更接近原生 Node.js。

6. **MCP Server 一等公民**：Brain 把文件系统、GitHub Workflow、Memory Core、Knowledge Base、Neural Link 都暴露为 MCP server，意味着任何兼容 MCP 的客户端（Claude Desktop、Cursor 等）都能直接接入。

## 五、快速上手

```bash
# 创建新应用（脚手架）
npx neo-app

# 或克隆主仓库参与贡献
git clone https://github.com/neomjs/neo
cd neo
npm install
npm run dev
```

零编译模式下，修改源码后刷新浏览器即可看到效果。AI 协作部分需要配置 LLM API key（OpenAI / Anthropic / Google 任选），然后启动 Brain：

```bash
npm run ai:start    # 启动 AgentOrchestrator
npm run dream:run   # 手动触发一次 DreamService REM cycle
```

`learn/gettingstarted/Setup.md` 里有更详细的 MCP server 配置和 ticket 工作流说明。
