这篇论文在说什么？

一句话：他们搭了一个多 Agent 协作系统，不用人管，自己就能完成从方案搜索到代码实现、再到效果验证的全流程机器学习算法开发。

具体来说，MLEvolve 是一个"自己会进化"的 Agent 框架。它接手一个 ML 竞赛任务后，会同时派多个 Agent 去尝试不同的解法，然后把各自的经验汇总到一个"群体记忆"里，后面的 Agent 就能站在前人肩膀上继续优化。整个过程像一个逐渐收紧的漏斗——前期广泛探索，后期集中突破。

在 MLE-Bench 的 75 个 ML 竞赛任务上，MLEvolve 只用 12 小时（标准预算的一半）就拿到了 65.3% 的平均奖牌率，超过了所有现有方法，包括用 Gemini-3-Pro 的 MARS+（62.7%）和 Claude-Opus-4.6 的 AIBuildAI（63.1%），而且有效提交率直接干到了 100%。

为什么要关注？

自动做机器学习不是新概念——AutoML 已经搞了好多年了。但之前的方案有几个很要命的毛病。

第一个毛病：信息孤岛。典型的 AutoML Agent（比如 AIDE、ML-Master）用的是树状搜索——像一个分支一个分支地试，A 分支试出来的经验不能传给 B 分支。这就很蠢，相当于一个团队里每个人都在闷头干活，谁也不跟谁交流。

第二个毛病：没有记忆。这轮搜索做完，下一轮从零开始。上次实验暴露出某个数据预处理的问题，下次照样踩坑。

第三个毛病：规划和执行绑太死。策略规划和代码生成耦合在一起，一旦规划改了，代码大概率得重写，稳定性很差。

MLEvolve 的核心思路就是解决这三个问题。ML Agent 正处在一个"临界点"：从"能写代码"到"自己做实验、积累经验、迭代优化"，MLEvolve 给出了一个具体的答案。

核心方法

关键思路

第一块：Progressive MCGS（渐进式蒙特卡洛图搜索）
传统的树搜索每个分支独立运行。MLEvolve 把"树"改成了"图"——不同分支之间可以通过"参考边"互相通信。搜索策略不是一成不变的：前期用高"温度"鼓励随机探索，时间推移逐渐收敛到最有潜力的方向。

第二块：Retrospective Memory（回溯记忆）
两层记忆：一层是"冷启动知识库"（领域基础知识，相当于教科书），另一层是"动态全局记忆"（每次实验的经验提炼）。Agent 接手新任务时先翻"全局记忆"，看有没有前人趟过的路。

第三块：Hierarchical Planning + Adaptive Code Generation
策略规划和代码生成是分开的两层。上层定"大方向"，下层写"具体代码"。三种编码模式：快速原型（先跑通）、精细调优（深入优化关键部分）、补丁修复（增量改，不动整体架构）。

技术细节

"Progressive MCGS enables cross-branch information flow through graph-based reference edges and gradually shifts the search from broad exploration to focused exploitation with an entropy-inspired progressive schedule."

说得直白一点：用图的边打通了分支间的通信，用熵驱动的时间衰减策略控制了"探索 vs 利用"的节奏。搜索调度公式是 选择概率 ∝ 验证分数 + λ(t) × 潜在价值，其中 λ(t) 随时间衰减。早期 λ 大，Agent 更愿意冒险；后期 λ 趋近零，只选已验证有效的方向。

记忆的存储和检索都用"语义子目标"做键。比如"为表格数据做特征选择"就是一条经验的键。检索时用 embedding 做语义匹配——即使任务描述不完全一样，经验也能被复用。这套设计在工程上很实用，有点像给 Agent 装了一个"团队 Wiki"。

效果怎么样？

核心实验在 MLE-Bench 上跑，这是目前 ML Agent 领域最严格的测试集——75 个真实的 Kaggle 风格竞赛任务，按难度分 Low / Medium / High 三档。

Agent 时间(h) Low(%) Med(%) High(%) All(%) Valid(%) Gold(%)
AIDE (o1-preview) 24 35.9 8.5 11.7 17.1 82.8 9.4
ML-Master 2.0 (DeepSeek) 24 75.8 50.9 42.2 56.4 95.6 19.6
MARS+ (Gemini-3-Pro) 24 78.8 60.5 44.4 62.7 100.0 33.8
AIBuildAI (Claude-Opus) 24 77.3 61.4 46.7 63.1 100.0 25.8
MLEvolve (ours) 12 80.3 64.0 46.7 65.3 100.0 34.7

几个值得注意的点：12 小时预算就把所有 24 小时预算的对手全超了；100% 有效提交率——生成的方案没有一个因为语法错误或格式问题被拒；Gold 率 34.7%——每 3 个任务就有一个达到金牌水平。另外在数学算法优化任务上，MLEvolve 也超过了专为此设计的 AlphaEvolve 和 AlphaEvolve-v2，展现了跨域泛化能力。

和其他方案比有什么不同？

维度 传统 AutoML Agent MLEvolve
搜索结构 线性/树状，分支独立 图状，分支间通过"参考边"通信
经验积累 无记忆，每轮从零开始 双层记忆系统，越跑越聪明
探索策略 固定（贪心/MCTS） 渐进式：前期探索 → 后期聚焦
规划与编码 耦合，改动成本高 分层解耦，三种自适应编码模式

最核心的差异是"自进化"的概念。大部分 Agent 是你给它一个任务跑、跑完就结束。MLEvolve 的设计是让它"越跑越强"——每次跑完都把经验存进群体记忆，长期来看整个系统会持续改进。跟同样是图搜索的 AlphaEvolve 比，MLEvolve 多了一个 Retrospective Memory 层，从"一次性搜索"变成了"带记忆的持续性搜索"。

对开发者意味着什么？

能不能直接用？代码已开源（InternScience/MLEvolve），需要配置 LLM API + 计算资源。目前支持表格型数据为主，图像和 NLP 任务的支持还在开发中。

什么场景适用？如果你经常需要"试试哪个模型效果最好"、"调一调特征工程方案"、"对比几种训练策略"这类工作，MLEvolve 可以帮你省掉大量手动实验的时间。它本质上是一个"会自己写实验代码、自己跑、自己总结经验"的自动化实验助手。

局限性要清楚：依赖强 LLM（论文用 DeepSeek-V3.2-Speciale），模型能力直接影响搜索质量；12 小时对个人开发者来说仍不短；群体记忆刚部署时效果不如跑了几百个任务之后。

一个有意思的展望：MLEvolve 的"自进化"思路可能比它当前的具体表现更重要。如果把这套机制接到一个持续运行的 CI/CD 管道里，每次模型上线后自动收集反馈、自动做实验优化、自动更新模型——这才是"真正的 MLOps 自动化"。这种"越用越好"的系统，才是 Agent 真正区别于传统 AutoML 的地方。
