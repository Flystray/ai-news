# 微软把 coding agent 当黑盒，六轮后账单降三成

> GitHub AI 项目日报 · 2026-11-11 · 公众号「fly的AI学习」

## 项目速览

- **项目地址**：[microsoft/TokenEconomizer](https://github.com/microsoft/TokenEconomizer)
- **Star/Fork**：⭐ 5,664 · 🍴 353（截至 2026-11-11 抓取，创建于 2026-10-13）
- **主要语言**：Python（约 96%，代码约 241 万字节；另有 Shell 与 TypeScript 适配层）
- **开源协议**：Apache-2.0
- **形态**：coding agent 插件 + 纯标准库 Python 包（Claude Code / Codex / Copilot CLI / Pi）
- **文档**：[项目主页](https://tokeneconomizer.github.io)、[论文 arXiv:2610.22732](https://arxiv.org/abs/2610.22732)

它做的事用一句话讲完：让同一个 agent 在同一个仓库里越跑越便宜。不改模型、不改 agent 源码，只借 prompt、工具配置和事件流这三条缝，把上一次会话学到的东西塞进下一次。论文报的是 SWE-Bench 上平均成本降 18.4%–30.9%，Pass@1 五组里四组还升了。

反直觉的地方在于省钱的第一天是亏的。多家独立实测（[CyberQ](https://cyberq.tw/2026/11/01/microsoft-tokeneconomizer-test-claude)、[AITopic](https://www.aitopic.com/microsoft-and-uc-berkeley-release-tokeneconomizer-to-cut-coding-agent-costs-by-up-to-309.html)）都指向同一条曲线：前四五个任务是学习期，装与不装几乎没差别，甚至略贵，到第六个任务才稳定低于基线。

## 项目背景：同一个仓库里，agent 每天重新学一遍怎么跑测试

SWE-Bench 这类基准把每个任务当独立事件，agent 一题一提交，环境干净。真实开发不是这样：你连续两周让 Claude Code 改同一个后端，它每天早上都要重新发现「这台机器上没有 pytest，得用 .venv/bin/python -m pytest」，重新试一遍「测试前要先跑 gen_rates.py」，重新加载 100 个工具的定义却只用其中 6 个。

论文把这笔钱量了出来。作者在 6 个仓库、60 个 SWE-Bench 任务上做画像，结果三条：

- **工具空转**。每次请求都带 23 个工具 schema，实际没有一个仓库用到超过 7 个；16 个从头到尾没被调用过，3 个覆盖了 98% 的调用。
- **事实重学**。当前面已经跑了 5 个任务之后，仍有约 30% 的工具调用是在重复早前任务做过的动作。反复出现的动作占工具调用字节量的 12%–28%。
- **失败循环**。失败任务只占 17%，却吃掉 32% 的总花费。在 60 个任务里，51% 的支出发生在一段轨迹开始原地打转之后。

这三条都不是「模型不够聪明」，而是「每次都从零开始」。也是现有省 token 工具的盲区：RTK 压 shell 输出、RepoMap 排符号表、Serena 换符号级检索，都是固定的、与仓库无关的策略。论文实测这三种固定策略没有一个能做到处处更便宜——RTK 在 30 个「仓库×组合」格子里有 12 格反而更贵，RepoMap 有 15 格更贵。原因是每个仓库的浪费不一样，Django 的浪费点和 SymPy 不是一回事。

## 核心功能

### 1. Micro-skills：把「这个仓库怎么跑」写成一行事实，下次开局就注入

机制分两路取事实。一路是纯规则：跨会话重复出现的同一条失败，直接抽成事实，不花模型调用。另一路花钱：每 *k* 个会话（默认 3）让一个提案模型读最近几段会话摘要，提出候选事实。

事实要过证据门槛才升级。同一条事实在**编辑文件互不重叠**的三个任务上被确认，才允许注入；需求率（need rate）还得 ≥ 0.4。反过来，一次反驳按 5 次确认计，所以错的事实退得很快。每条事实自带正则检测器，后续验证不花模型调用。

CyberQ 那篇实测里，它学出来的东西长这样：

> The project's Python environment is `.venv/` at the repo root… Canonical test command in invkit: `.venv/bin/python scripts/gen_rates.py && APP_ENV=test .venv/bin/python -m pytest`

正好是他们埋在 repo 里、只写在 CONTRIBUTING.md 的三颗雷。这是这个机制真正的价值点：**它学的是环境知识，不是任务知识**，而环境知识恰好是每次开局最贵、最难猜的部分。

### 2. Tool pruning：不用的工具从 agent 自己的设置里摘掉

判定条件是双轨的：一个工具连续 *p* 个提示（默认 10）没用且跨越至少 *m* 个会话（默认 2），或者横跨 *s* 个会话（默认 5）没用过，就写进该仓库的 deny 清单。Shell、读、写、编辑这几个核心工具永远保留。全量目录每 5 个任务回扫一次，防止工具被永久埋掉。

关键在于它**不碰 agent 代码**，只改 agent 自己的配置文件：

| Agent | 摘掉什么 | 写到哪里 |
|---|---|---|
| Claude Code | 单个工具 | `.claude/settings.local.json` |
| Codex | capability packages | `.codex/config.toml` |
| Copilot CLI | 整个 MCP server | `.github/copilot/settings.local.json` |
| Pi | 无（只加载四个工具） | — |

写入还有一个时点条件：`toolprune_quiet_minutes` 默认 60 分钟，要求你在这个仓库的会话闲置够久才写。原因是改了工具集之后，被恢复的会话必须把整段历史重新写进 prompt cache 而不能读缓存，而缓存本来一小时就过期。这个细节挺讲究——省 token 的工具如果让缓存失效，省的还不如赔的。

效果上，论文给的例子是 Django 配 Claude Code，第一个请求从 43,351 token 降到 16,295。

### 3. Failure-loop intervention：只提醒，不杀进程

它先学「这个仓库里正常一轮有多长」：等到 *e* 个（默认 5）自己跑完、且最后一次编辑之后没有失败检查的回合，建立一个回合长度包络，预算取成功回合长度的 90 分位乘 1.25。

之后回合出现重复失败或错误密集，先走便宜的规则检查，再交给裁判模型判断是否卡住。裁判置信度 ≥ 0.7 才插一条转向提示（「换个思路」），每回合最多 *r* 次（默认 1）。如果还是卡着，它只打印一行提示你按 Esc，**从不自己终止回合**。

这条边界划得很清楚：成本控制不该拥有否决权。

### 4. 一个插件适配九个 agent，各按各的 hook 能力打折

正式支持四个（Claude Code、Codex、GitHub Copilot CLI、Pi），实验性支持五个（opencode、Cursor Agent、Grok Build、Hermes Agent、Antigravity CLI）。每个适配器不是等价翻译，而是如实标注能力缺口：Pi 只加载四个工具所以不需要剪枝，工具剪枝在 Cursor、Grok、opencode、Hermes、Antigravity 上暂时不生效，Antigravity 没有「关掉全部工具跑一次 prompt」的开关所以只能学不花钱的那部分事实，Grok 学到的事实要到会话第一次工具调用才到模型手里。

README 里还有一张「回合卡住时提示出现在哪、怎么停」的表，逐个 agent 写清楚 Esc 之后还要不要 `/stop`、headless 模式打到 stdout 还是 stderr。这种把边角料写进主文档的做法，比一句「全面支持」有用得多。

### 5. 每一步都可回退，状态全在本机

`toolprune restore` 把工具还回去，还回去的不会再被摘；被反驳的事实直接失效；deny 清单只追加自己的条目，不碰你手写的规则，且自动进 `.git/info/exclude` 防止误提交。学到的东西存在 `~/.tokeneconomizer`，不出本机；插件自己不持有任何凭据，模型调用走你自己的 agent 登录。

## 技术亮点

### 1. 三个机制不知道 agent、也不知道领域，全靠四个接口隔离

这是我认为这个仓库最值得抄的部分。`tokeneconomizer/` 下不是一坨脚本，而是把变化点抽成了四个窄接口：

- `trace`：唯一读会话日志的地方，一个 agent 一个 reader，加新 agent 只写这里；
- `ledger` + `pricing`：唯一的成本定义，机制只上报自己的开销，插件和论文实验都从同一处读，**保证「账上记的」和「论文报的」不可能漂移**；
- `domain.DomainAdapter`：读会话、哪些工具要保护或排除、轨迹的循环信号、可选裁判要看的任务文本、事实词表；换领域只换 adapter；
- `stage.Stage`：机制对外提供的四个钩子 `before_task` / `build_tools` / `run_kwargs` / `after_task`。

两个调用方（插件、benchmark harness）都不被机制 import，`tests/test_plugin_package.py` 还专门钉死这两条边界：机制不许 import 插件，`tokeneconomizer/` 不许 import `experiments/`。所以论文实验和线上插件跑的是同一套机制代码，不是两份实现各说各话——这在产学合作的项目里不常见。

### 2. 成本按账单算，不按 token 数算

大部分省 token 工具宣传的是 token 降幅，而账单上看到的是美元。两者差得很远，因为一个会话里大部分 token 是缓存重读，按 5%–10% 计价。

TokenEconomizer 的成本口径写死为「按实际计费方式算，含缓存价」，并且把插件自身的模型调用（提案者、裁判、转向文案）全算进去。这一点直接决定了它的可信度：省下来的钱如果不够付自己的开销，结论就是负的。CyberQ 的实测正好撞上这个坑（下面会讲）。

### 3. 把「学习」做成可撤销的，而不是可信任的

跨会话学习最容易翻车的地方是学到错的、然后一直错。这个项目的处理方式不是提高模型能力，而是降低错误残留时间：

- 事实要三次非同源确认才生效，一次反驳抵五次确认；
- 工具的摘除需要跨会话、跨提示的双重证据，且每 5 个任务回扫一次；
- 回合预算来自本仓库成功回合的分位数，不是全局常数；
- 所有动作在会话里打印一行，出任何问题会话照常继续，等同没装。

代价是冷启动慢。论文自己也承认：Claude Code 的五组跑批里，除了 xarray，每个仓库前几个任务都更贵，到第六个才全面低于基线。这套设计换的是「不会突然崩」，付的是「不会立刻见效」。

## 适用人群

- **每天在同一个大仓库里用 Claude Code / Codex 的工程师**：连接器装得多、工具列表长（实测环境里 100 个工具），剪枝收益最直接。省的是每天重复付的那部分固定开销。
- **给团队管 agent 预算的平台/SRE**：成本口径含缓存价、含插件自身调用，`te status` 能给出按仓库的账，比自己拿 token 数乘单价靠谱。
- **维护环境复杂的老项目的人**：monorepo、私有测试脚本、必须带环境变量的构建流程，micro-skills 学的正是这类「文档里没写、老员工才知道」的东西。
- **做 agent 基础设施的开发者**：`trace` / `ledger` / `domain` / `stage` 这套切分，是「如何让同一份策略同时跑在论文 harness 和真实插件里」的一个可复用答案。
- **不建议**：一周换八个仓库、每次都是新项目的人。学习期还没过就换地方了，省不到钱。

## 快速上手

前置条件只有两个：Python 3.10+ 在 `PATH` 里，以及一个已登录的 agent。插件不需要自己的 API key。

```sh
# Claude Code
git clone https://github.com/microsoft/TokenEconomizer.git
claude plugin marketplace add "$PWD/TokenEconomizer"
claude plugin install tokeneconomizer@tokeneconomizer
# 启动 claude，信任目录后：
#   /tokeneconomizer:status
#   /tokeneconomizer:toolprune refresh-catalog   # 每台机器一次，Claude Code 升级后重跑
```

```sh
# Codex
git clone https://github.com/microsoft/TokenEconomizer.git
codex plugin marketplace add "$PWD/TokenEconomizer"
codex plugin add tokeneconomizer@tokeneconomizer
# 启动后选 Trust and continue -> Hooks need review 选 Trust all and continue
# 钩子下次会话生效，退出后重开，用 $tokeneconomizer:status 检查
```

```sh
# GitHub Copilot CLI
git clone https://github.com/microsoft/TokenEconomizer.git
copilot plugin marketplace add "$PWD/TokenEconomizer"
copilot plugin install tokeneconomizer@tokeneconomizer
```

想打开 micro-skills 并指定便宜模型（强烈建议一起设，原因见下节）：

```text
/tokeneconomizer:config set microskills=on
/tokeneconomizer:config set paid_model=claude-haiku-5-5
```

几个 README 明确写了的坑：

1. **marketplace 路径要给绝对路径**。Copilot CLI 会把 `./TokenEconomizer` 当成 GitHub 仓库名去解析。
2. **clone 目录别删**。Claude Code、Codex、Copilot CLI、opencode 是直接从 clone 目录跑插件的。
3. **版本窗口很窄**。官方验证范围是 Claude Code 2.1.300–2.1.310、Codex 0.153.1–0.164.0、Copilot CLI 1.0.83–1.0.102、Pi 1.2.0–1.3.0。agent 升级后先跑一次 `te status` 和 `~/.tokeneconomizer/errors.log`。
4. **临时关掉**用环境变量：`TE_DISABLE=1 claude` 全关，`TE_LOOPGUARD=off codex` 关单个机制。

## 对比分析

| 维度 | TokenEconomizer | RTK | Aider RepoMap / Serena |
|------|-----------------|-----|------------------------|
| 作用层 | 会话级：跨会话学策略 | 工具输出级：压缩 shell 输出 | 上下文级：符号表 / 符号检索 |
| 是否按仓库学习 | 是（事实、工具证据、回合包络都按仓库存） | 否 | 否 |
| 需要改 agent | 不需要，只走 hook 与 agent 自身设置 | 需要接入其调用链 | RepoMap 内置于 Aider；Serena 走 MCP |
| 论文实测平均成本变化 | −18.4% 到 −30.9% | −8.9% 到 +4.5% | 未进主实验；画像阶段抬高总成本 |
| 30 格中反而更贵的格子 | 0 | 12 | 15 |
| 见效时点 | 第 6 个任务起 | 立即可用 | 立即可用 |
| 主要局限 | 学习期倒亏、agent 版本强绑定、附加调用可能倒赔 | 只在输出冗长时有收益 | 与仓库结构强相关，跨仓库不稳定 |

表格里的成本行来自论文，许可证与接入方式来自各项目仓库。这四者不是替代关系：RTK 压的是「一条命令吐 800 行日志」，TokenEconomizer 压的是「同一个仓库重复付的固定成本」，叠着用不冲突——论文里 Opus 4.8 组合叠加 RTK 后从 −30.9% 进一步到 −33.2%。

## 局限与风险

**一、默认配置可能不省钱，甚至倒赔。** CyberQ 用 288 次 Claude Code 会话做了独立实测，这是目前最值得看的一份第三方证据。结论是：默认配置（剪枝 + 循环防护）在主会话上平均省 6.2%、稳态省 10.8%；打开 micro-skills 后主会话再省一截，但**总账反而多花 2.9%**。原因很具体——插件调用 `claude -p --model haiku`，在他们那台机器的 Claude Code 2.1.314 上，`haiku` 这个别名实际解析到 Sonnet 5.5，单次调用约 0.27 美元，比真正的 Haiku 5.5 贵近 20 倍。把 `paid_model` 显式设成 `claude-haiku-5-5` 后，总账从 +2.9% 变成 −13.0%，稳态 −22.4%。**换句话说，装完之后第一件事是核对别名解析到哪个模型。**

**二、论文数字在你的场景大概率要打折。** 同一份实测里，Sonnet 5.5 省 13.0%、Fable 5.1 省 14.8%、Opus 5.5 只省 6.3%——只有论文区间的三分之一到二分之一。作者在论文里也留了两条诚实的口子：SWE-Bench 的任务流是「相关但独立」的修复，不是真实用户会话；Pi 没有参与实验。CyberQ 的归因是任务太短（每题约 7 个回合）、强模型少撞墙、prompt cache 稀释了剪枝收益。**任务越长、环境越脏，论文数字越可能出现；短任务、干净仓库、文档齐全时，收益有限但确实存在。**

**三、逐 token 省钱 ≠ 逐美元省钱。** 剪枝在他们环境里把首请求 prompt 从约 24,300 token 降到 17,300，少 29%；但快照缓存读取只按 5% 计价，所以美元只少 6.2%。任何拿 token 降幅做卖点的工具，都值得自己按牌价重算一遍。

**四、micro-skills 是注入面。** 事实来自命令输出与会话摘要，而这些内容由仓库控制。在不信任的仓库上开 micro-skills，等于允许仓库往你的系统提示里写东西。官方默认关闭 micro-skills，一部分原因就是这个。裁判和转向文案会把最近动作的摘要（命令、搜索模式、被编辑文件名、错误特征）发给模型供应商，不含文件内容与任务描述，但确实出本机。

**五、版本绑定紧得有点痛。** 支持范围精确到小版本号（2.1.300–2.1.310），因为 transcript 格式是各 agent 的内部格式，不是公开接口。agent 一升级就可能读错。Cursor、Grok、Antigravity 三个适配器还明确写着「transcript 不是公开接口」，也就意味着这条路随时可能断。

**六、二手报道的质量参差。** 我核到的第三方文章里，至少有一篇把许可证写成 MIT（实际 Apache-2.0），还说它支持 AutoGPT 和 Devin（README 里没有）。引用这类内容当证据要小心，数字以论文表格和项目主页为准。

## 写在最后

这个项目真正改变的，不是某个省钱技巧，而是把「coding agent 的成本」从一次性问题变成了**按环境累积的问题**。此前所有省 token 的方案都在单次请求里做减法——压输出、砍上下文、换检索；它换了个坐标系，认为同一个仓库里第 20 次会话的浪费结构，和第 1 次不是一回事，所以策略应该是学出来的，不是配置出来的。这个转向本身比 30% 这个数字更值钱。

给读者的两条具体建议。第一，如果你是重度用户，装，但只装默认配置先跑两周，看 `te status` 里的实际账再决定要不要开 micro-skills；开之前务必确认 `paid_model` 解析到的真实模型。第二，如果你是做 agent 基础设施的，别急着抄那三个机制，先看 `docs/ARCHITECTURE.md` 里那四个接口怎么切的——那才是让同一份策略既能在论文 harness 跑 benchmark、又能在真实插件里跑用户会话的原因。
