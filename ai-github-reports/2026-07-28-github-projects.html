项目地址：Fortemi/fortemi

一句话定位：An intelligent database for AI-ready applications——为 AI 时代重新设计的智能数据库底座

技术栈：Rust（7 crates）+ PostgreSQL 18（pgvector + PostGIS）+ Node.js MCP Server + Ollama

Rust PostgreSQL BSL-1.1 Hybrid Search Knowledge Graph MCP Server Agent Memory Multimodal

今天不推荐爆款。这个项目只有 26 颗星，却是近期工程密度最高的自托管知识库：16 万行 Rust、43 个 MCP 工具、13 种多模态适配器、自动知识图谱、溯源追踪。它押注的命题是 2026 年最关键的一个：AI Agent 的记忆到底应该长什么样。

项目背景：从"存储数据"到"理解数据"

大多数知识系统的逻辑是"存进去，等你精确查询"。你存了 500 篇笔记、200 个 PDF、几十条录音，真要找某个结论时却想不起当时用的词——传统全文搜索直接失效。而纯向量方案（RAG 常规做法）走向另一个极端：把文档切成碎片塞进向量库，检索出来的是无上下文的片段，没有来源追踪，没有关联结构。

Fortémi 的出发点是把两者合成一个"主动理解内容"的系统：找到概念相关的结果（即使你忘了准确术语），自动发现新知识与已有知识的连接，并从图片、音频、视频、3D 模型、邮件、表格中提取可搜索的信息。

隐私优先、边缘优先：无云依赖，8GB 显存的消费级显卡（RTX 3060/4060 级别）即可运行完整栈，默认模型 qwen3.5:9b + nomic-embed-text，提供 edge / gpu-12gb / gpu-24gb 三档硬件配置。可以塞进气隙内网的完整 AI 记忆系统。

核心功能

1. 三路混合搜索：BM25 + 向量 + RRF 融合

PostgreSQL FTS 做 BM25 词法检索，pgvector 做稠密语义检索，知识图谱做关联检索，RRF（Reciprocal Rank Fusion）融合排名后经 MMR 重排保证多样性。支持 AND/OR/NOT/短语操作符；多语言下沉到分词层：CJK 二元/三元组、6+ 语言词干提取、emoji 三元组。中文零配置。

2. 自动知识图谱：链接是"长"出来的

新笔记入库后计算与已有内容的嵌入相似度，超过 70% 自动建立双向链接，相似度存为边权重。图质量靠 SNN 评分、PFNET 稀疏化、Louvain 社区发现三个算法维护。附带"知识健康仪表板"，专门找孤立标签、陈旧笔记、未链接的冷点内容。

3. 43 个 MCP 工具：为 Agent 而生的记忆接口

内置 Node.js MCP Server（核心 43 工具 / 完整 205 工具）：capture_knowledge（写入）、search（联邦混合搜索）、record_provenance（知识来源血缘）、explore_graph（图遍历）、manage_archives（多记忆切换）等。AI Agent 从此有了结构化、可溯源、可遍历的外部记忆，而不是碎片化的向量快照。

4. 13 种多模态提取适配器 + 131 种文档类型

图像走视觉 LLM 描述，音频走 Whisper 转写 + pyannote 说话人分离，视频做关键帧场景检测与转写对齐，GLB/glTF 3D 模型多视角渲染，邮件按 RFC 2822/MIME 解析，表格转 Markdown。131 种文档类型（19 大类）按文件名、扩展名和内容魔数自动检测，并按类型选择分块策略——散文语义分块、代码语法分块、文档按节分块。

5. 多记忆归档 + 联邦搜索

一个实例承载多个 schema 隔离的"记忆归档"（14 张共享表 + 41 张每记忆表），工作知识库、个人笔记、每个 Agent 的独立记忆互不污染，又能一次跨库联邦检索。配合 X25519/AES-256-GCM 公钥加密共享、OAuth2 + API Key 认证、SSE/WebSocket/webhook 实时事件。

6. Matryoshka 嵌入集：12 倍存储节省

支持 MRL 套娃表示学习：同一嵌入按维度截断使用，两阶段检索先短向量粗筛再全维精排，官方数据存储节省 12 倍。嵌入规则可自动化，换模型不需推倒重来。

技术亮点

1. PostgreSQL 单库承载全部检索负载的架构赌注

不引入 Elasticsearch、Milvus、Neo4j 中的任何一个，把全文检索（FTS）、向量检索（pgvector + HNSW，O(log N)）、空间检索（PostGIS）、图遍历（递归 CTE）全部压进一个 PostgreSQL 18。7 个 Rust crate 分层清晰：

Crate职责
matric-apiAxum HTTP REST API + OpenAPI/Swagger
matric-search混合检索（BM25 + 稠密 + RRF）
matric-jobs异步 NLP 流水线（embed / revise / link / extract / diarize / chunk）
matric-inference多提供商 LLM 抽象（Ollama / OpenAI / OpenRouter / llama.cpp 热切换）
matric-dbPostgreSQL 仓库（sqlx，106 迁移）
matric-cryptoX25519/AES-256-GCM 公钥加密
matric-core核心类型、特征、错误处理

运维面只有一个数据库，备份、迁移、监控全走 PostgreSQL 成熟工具链——对自托管用户是实打实的负担减半。

2. 溯源（Provenance）作为一等公民

record_provenance 把"这条知识从哪来"记录为结构化数据：来源文档、提取时间、处理链路。RAG 最被诟病的"答案无法追责"问题在数据模型层面解决。W3C SKOS 标准词汇表管理层级概念标签——标签不再是随手打的字符串，而是有语义结构的受控词汇。

3. 同一 schema 三端锁步

服务端、浏览器版、HotM 桌面应用共享同一套数据 schema 和同一个 matric-api 二进制（HotM 打包为 sidecar），功能永远同步。单机用户下载 HotM 即用（免 Docker 免 Postgres 配置）；团队和 Agent 集群用 Docker bundle 一条命令拉起五个容器。一套代码覆盖从个人笔记本到企业内网的完整光谱。

适用人群

  • AI Agent 开发者：需要结构化、可溯源、多归档隔离的 Agent 长期记忆
  • 隐私敏感的知识工作者：法律、医疗、研究场景，数据不出内网，8GB 显卡跑完整多模态栈
  • 重度多模态收藏者：录音、会议视频、扫描件、邮件归档统一变成可搜索资产
  • RAG 基础设施工程师：研究"PostgreSQL 单库混合检索 + 知识图谱"技术路线
  • Rust 学习者：16 万行生产级 Rust，Axum/sqlx/异步任务管道完整参考

快速上手

方式一：HotM 桌面版（单机用户推荐）

从 HotM Releases 下载对应平台安装包（.msi / .dmg / .deb / .AppImage），UI 与 API 打包在一起，免 Docker 免数据库配置。

方式二：Docker Bundle（服务端 / Agent 集群）

# 前置：主机安装 Ollama 并拉取模型
ollama pull qwen3.5:9b
ollama pull nomic-embed-text

# 一条命令拉起完整栈（PostgreSQL 18 + Redis + API + MCP + Open3D）
docker compose -f docker-compose.bundle.yml up -d

# 验证
curl http://localhost:3000/health

端口：3000（REST API，Swagger 在 /docs）、3001（MCP Server）。按显卡设置 COMPOSE_PROFILES=edge|gpu-12gb|gpu-24gb。

接入 Claude Desktop（MCP）

{
  "mcpServers": {
    "fortemi": { "url": "http://localhost:3001/mcp" }
  }
}

搜索 API 示例

# 混合搜索（默认 RRF 融合）
curl "http://localhost:3000/api/v1/search?q=检索增强生成"

# 纯语义 / 纯词法
curl "http://localhost:3000/api/v1/search?q=RAG&mode=semantic"
curl "http://localhost:3000/api/v1/search?q=RAG&mode=fts"

Khoj 赢在多端覆盖，AnythingLLM 赢在团队开箱即用，而 Fortémi 押注的是下一层——当 AI Agent 成为知识系统的主要"用户"时，人类友好的聊天界面不再是核心，结构化、可溯源、可编程的记忆接口才是。

风险提示：26 星意味着社区极小，BSL-1.1 对多用户商用部署收费（2030 年转 AGPL-3.0），生态几乎为零。适合技术选型参考和早期尝鲜，暂不适合直接押注生产。

写在最后

Fortémi 最有启发的地方，不是任何单一功能，而是它对一个趋势的判断：RAG 正在从"向量数据库"进化为"结构化知识平台"。碎片化向量检索解决了"找到相关内容"，但解决不了"知识从哪来、如何关联、能否审计"。Fortémi 用 PostgreSQL 单库 + 图谱 + 溯源 + MCP 的组合拳给出了自己的答案。

另一个值得玩味的细节：这个项目不做 LLM，不做 UI 竞争，只做"AI 时代的数据基础设施"。就像当年的 SQLite 之于移动应用，Fortémi 想成为 Agent 应用的默认记忆层。16 万行 Rust 砸在一个 26 星的项目上，要么是过度工程的独角戏，要么是提前卡位的基础设施——无论哪种，代码本身已经值回阅读时间。
