项目背景

2026年2月，Google Gemini 团队主管、AngularJS 联合创始人 Addy Osmani 在 GitHub 上发布了一个令人眼前一亮的新项目——Agent Skills。

这个项目的诞生，源于一个所有 AI 编程工具都面临的共同困境：AI 代理默认选择最短路径——跳过需求文档、跳过测试、跳过安全评审、省略那些让软件真正可靠的最佳实践。

Agent Skills 的核心使命，是将 Google 二十年的工程实践封装成 AI 可执行的技能模块，通过 7 个 Slash 命令让 Claude Code、Cursor、Windsurf、Gemini CLI 等主流 AI 编程工具在工程成熟度上直接对齐 Google 标准。从 2 月发布到 5 月，这个项目已狂揽 4 万+ Stars，成为 2026 年最受关注的 AI 编程辅助工具之一。

核心功能

1. 六阶段开发流程

/spec → /plan → /build → /test → /review → /ship

Agent Skills 围绕软件开发的六个核心阶段设计了完整的工作流框架，每个阶段都有对应的激活命令和核心技能：

阶段激活命令核心理念
DEFINE（定义）/spec规约优先，在写代码之前定义清楚要做什么
PLAN（规划）/plan小的原子化任务，确保每个任务都可验证
BUILD（构建）/build一次只做一块，薄垂直切片实现
VERIFY（验证）/test测试就是证明，TDD 红-绿-重构
REVIEW（评审）/review五轴代码审查（功能/安全/可维护/性能/风格）
SHIP（发布）/shipCI/CD 流水线，质量门禁保障

2. 20 个核心技能模块

覆盖软件开发全生命周期的 20 个结构化技能，分为三大层：

  • Define 层：`idea-refine`（想法精炼）、`spec-driven-development`（PRD 编写）
  • Build 层：`planning-and-task-breakdown`（任务拆解）、`incremental-implementation`（增量实现）、`test-driven-development`（TDD）、`context-engineering`（上下文工程）、`source-driven-development`（源码驱动）、`frontend-ui-engineering`（前端工程）、`api-and-interface-design`（API 设计）
  • Ship 层：`browser-testing-with-devtools`（浏览器测试）、`debugging-and-error-recovery`（调试）、`code-review-and-quality`（代码评审）、`code-simplification`（代码简化）、`security-and-hardening`（安全加固）、`performance-optimization`（性能优化）、`git-workflow-and-versioning`（Git 工作流）、`ci-cd-and-automation`（CI/CD）、`deprecation-and-migration`（废弃迁移）、`documentation-and-adrs`（文档）、`shipping-and-launch`（发布）

3. 创新设计：反合理化机制（Anti-Rationalization）

这是 Agent Skills 最具创新性的设计——为每个技能配备的"常见借口表"，从根本上解决 AI 代理"偷懒"的问题：

AI 常见借口正确反驳
"功能很简单，不需要测试"测试的目的是证明代码能做它应该做的事，不是证明代码"简单"
"我会在后面加上测试"后续测试的覆盖率平均只有 TDD 的 30%，且测试质量显著更低
"手动测试过了"手动测试不能防止未来的回归，是一次性消耗

平台支持方式

对比分析

Agent Skills 的核心价值在于让 AI "更有纪律"，而非"更聪明"。与 Cursor Rules 和其他 AI 编程工具的对比：

维度Agent SkillsCursor Rules其他 Agent 工具
设计目标工程流程标准化代码风格约束单点执行
覆盖范围完整开发周期（需求→发布）单点代码规范任务自动化

核心差异：Cursor Rules 本质上是代码约束规则，用于保持代码风格一致；Agent Skills 是工程工作流框架，覆盖需求分析→代码实现→测试验证→发布上线的完整闭环。它强调的是"让 AI 像 Google Senior Engineer 一样思考工程问题，而不只是生成代码"。

注意事项

  • Agent Skills 当前主要围绕 Claude Code 生态设计，其他工具的支持程度略有差异
  • 需要团队对六阶段开发流程有基本认知，流程有一定学习成本
  • 技能文件的维护需要持续投入，建议建立内部贡献流程
  • 快速原型验证场景下，完整流程可能显得过于"重"，需要灵活取舍
