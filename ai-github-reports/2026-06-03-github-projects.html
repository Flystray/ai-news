项目背景

2026 年，AI 编程 Agent（Claude Code、Cursor、GitHub Copilot、Codex CLI 等）已成为开发者的日常工具。但它们都有一个共同的痛点：上下文窗口是临时的。每次新会话开始，Agent 就忘记了一切——你不得不反复解释项目约定、历史决策、踩过的坑。各 Agent 提供的"记忆"方案（Claude Code 的 MEMORY.md、Cursor 的 Notepad、Cline 的 Memory Bank）本质上是便签式存储，既不可搜索，也无法跨工具共享。


AgentMemory（rohitg00/agentmemory）正是为解决这个问题而生。它于 2026 年 2 月创建，TypeScript 编写，Apache-2.0 许可证，目前已获得 20,700+ GitHub Stars。项目的核心理念是：将 Karpathy 的 LLM Wiki 模式工程化，加入置信度评分、生命周期管理、知识图谱和混合搜索，打造一个真正可搜索、可检索、可跨 Agent 共享的持久记忆系统。

核心功能

1. 四层记忆整合架构

AgentMemory 模仿人类记忆系统，设计了四层递进式记忆架构：


记忆层级存储内容解决的问题
Working（工作记忆）工具调用产生的原始观测保留最接近现场的短期数据
Episodic（情节记忆）压缩后的会话摘要"上一次发生了什么？"
Semantic（语义记忆）抽取的事实、模式与稳定知识"这个项目长期成立的事实是什么？"
Procedural（程序记忆）工作流、决策套路与可复用做法"这类事情通常怎么做？"

2. 三路混合检索

融合 BM25 关键词检索 + Vector 语义检索 + Knowledge Graph 关系遍历，通过 Reciprocal Rank Fusion（RRF）统一排序。当搜索 "database performance optimization" 时，BM25 关键词召回率为 0%，而向量检索直接拉到 40%，两者互补而非替代。


3. 12 个自动 Hooks + 53 个 MCP 工具

通过 12 种生命周期事件（PostToolUse、SessionStart、SessionEnd 等）自动捕获 Agent 行为，配合 53+ 个 MCP 工具，覆盖记忆的存、查、删、改、导出全链路。


4. 跨 Agent 统一记忆库

所有 Agent 共享同一个记忆服务器。Claude Code 中积累的项目知识，切换到 Cursor 时同样可用。支持 Claude Code、Cursor、Codex CLI、GitHub Copilot CLI、Gemini CLI、Hermes、OpenClaw 等。


5. 实时 Viewer + iii Console

Viewer（localhost:3113）查看会话、记忆、图谱和健康仪表盘；iii Console（localhost:3114）支持函数级执行追踪、流处理监控和完整 OTEL 可观测性链路。

技术亮点

基于 iii-engine 的运行时架构

AgentMemory 本身是一个 iii 运行时实例，提供 HTTP Triggers（事件驱动）、KV State（持久化状态）、Streams（数据流处理）三大核心原语，支持 cron 定时任务、otel 可观测性、queue 重试队列和 database 后端扩展。
