### 📌 项目背景

在 AI 编程助手（Claude Code、Cursor、Windsurf 等）迅速普及的今天，一个突出的矛盾逐渐显现：**AI 能写代码，但写不出好设计**。

绝大多数 AI 生成的 UI 代码存在以下问题：配色随机、字体搭配不协调、忽略无障碍标准、风格前后不一致。根本原因不在于大模型的能力不足，而在于 **AI 在生成 UI 时缺乏结构化的设计知识库可以参照**——就像让一个没有学过设计理论的程序员凭直觉画界面一样。

`UI UX Pro Max Skill` 的解决思路非常独特：**它不是给人类用的设计工具，而是给 AI 用的设计知识库**。项目将 344+ 条设计资源以 CSV 文件形式结构化存储，通过 BM25 概率排名算法实现智能检索，再经由推理规则引擎（Reasoning Engine）进行设计决策推理，最终由设计系统生成器（Design System Generator）输出完整的规范文档。

整个架构分为三大核心组件：**知识库**（344+ CSV 结构化数据）→ **搜索引擎**（BM25 + 领域检测 + 技术栈过滤）→ **设计系统生成器**（推理规则引擎 + Master/Overrides 架构），形成一条从"设计知识检索"到"设计决策推理"再到"设计系统输出"的完整链路。

项目诞生于 2025 年 11 月，在不到 6 个月的时间里获得了 7.56 万星，v2.0（2026 年 3 月）新增了智能设计系统生成器和 161 条行业推理规则，标志着项目从"设计资源检索工具"进化为"设计智能引擎"。

### 🚀 核心功能

1. **344+ 结构化设计资源数据库** — 覆盖 10 个设计领域、16 种技术栈，具体包括：67 种 UI 风格（Glassmorphism、Claymorphism、AI-Native UI 等）、161 套行业专属配色方案（SaaS、电商、医疗、金融科技等）、57 组 Google Fonts 字体搭配、25 种图表类型（趋势图、对比图、漏斗图、热力图）、99 条 UX 最佳实践指南，以及 v2.0 新增的 161 条行业推理规则。所有数据以 CSV 格式存储，每行一个设计资源，列定义属性和关系——这种设计让知识库对 Git 版本控制友好、可被非技术用户编辑、支持大规模扩展。

2. **智能设计系统生成器（v2.0 旗舰功能）** — 通过推理规则引擎分析项目需求，秒级生成完整的定制化设计系统规范。工作流程：多领域联合搜索 → 推理规则应用（如"SaaS 着陆页需要信任元素 → 搜索 testimonials 模式"） → Master + Overrides 模式输出。输出包括：推荐布局模式（Hero-Centric、Feature-First 等 24 种）、配色方案（Primary/Secondary/CTA/Background/Text）、字体搭配（衬线+无衬线组合）、关键动效参数（200-300ms 平滑过渡）、反模式警告列表。

3. **推理规则引擎（Reasoning Engine）** — 这是 v2.0 最核心的创新。不同于简单的关键词匹配检索，推理引擎能根据上下文进行设计决策推理：输入"SaaS 着陆页"→ 推理出"需要信任元素"→ 自动搜索 testimonials 模式 → 输出完整着陆页设计方案。161 条行业推理规则覆盖了从 SaaS 到医疗到电商的各类场景，使项目从"搜索工具"升级为"设计决策引擎"。

4. **BM25 智能搜索引擎** — 在 `scripts/core.py` 中完整实现了 BM25 算法类（k1=1.5 控制词频饱和度，b=0.75 控制文档长度归一化），包含分词器（过滤长度>2 的词、去除标点）、TF-IDF 评分函数和领域自动检测（基于关键词评分路由查询到正确的 CSV 文件）。相比简单搜索，相关度提升约 60%。搜索引擎同时提供 CLI 接口（`search.py`），支持直接在终端查询。

5. **18+ AI 平台全覆盖** — 同时支持 Claude Code、Cursor、Windsurf、Antigravity、Codex CLI、Continue、Gemini CLI、OpenCode、Qoder、CodeBuddy、Droid、KiloCode、Warp、Augment、Kiro、Roo Code、GitHub Copilot、Trae 等主流 AI 编程助手。通过 JSON 配置文件实现平台适配，新增平台只需添加一个 JSON 配置。

6. **零配置平台自动检测** — CLI 工具（`uipro-cli`）通过扫描项目目录特征自动识别 AI 平台：检测到 `.claude/` → Claude Code，`.cursor/` → Cursor，`.windsurf/` → Windsurf，`.github/` → GitHub Copilot，`.warp/` → Warp，`.trae/` → Trae。用户只需运行 `uipro init`，无需指定平台。

7. **Master + Overrides 设计系统架构** — 采用"主模板 + 覆盖层"模式组织生成的设计系统规范：基础规范保存在 `design-system/MASTER.md`，页面特定覆盖规则保存在 `design-system/pages/{page}.md`。这种架构保证了设计一致性（Master）的同时支持技术栈定制（Overrides），是首次在 AI 辅助设计工具中实现的模式。

8. **预交付质量检查清单** — 设计系统实施完成后自动执行质量保证检查：无障碍性（对比度 ≥ 4.5:1、ARIA 标签完整）、性能优化（WebP/AVIF 格式、懒加载、CSS 压缩）、交互规范（触控目标 ≥ 44px）、视觉一致性（间距统一、深/浅色模式支持）。

### ⚙️ 技术亮点

1. **推理规则引擎：从"搜索"到"推理"的范式升级** — 传统设计工具只能搜索已有资源，而本项目的推理引擎能进行上下文感知的设计决策推理。技术实现上，推理引擎位于 `scripts/design_system.py`，工作方式：接收用户需求 → 多领域联合搜索获取基础数据 → 应用 `reasoning_rules` 领域的推理规则进行决策树推理 → 合成多领域数据 → 输出一致性设计系统。例如：用户要求"SaaS 着陆页"，引擎推理出"需要信任元素"→ 搜索 testimonials 模式 → 推理出"需要 CTA 转化"→ 搜索 conversion patterns → 最终输出完整的着陆页设计方案。这种"检索 + 推理"的架构，使 AI 不仅知道有哪些设计资源，还知道在什么场景下应该用哪些资源。

2. **CSV 作为知识库格式的设计工程化实践** — 与传统的"设计系统文档"或数据库不同，项目将每一类设计知识都结构化为独立的 CSV 文件，通过 `CSV_CONFIG` 和 `STACK_CONFIG` 映射 10 个设计领域和 16 种技术栈。这种设计看似简单，实则精妙：① CSV 是纯文本，对 Git diff 友好，社区贡献者可以像审查代码一样审查设计知识的变更；② CSV 可被非技术用户直接用 Excel 编辑，降低了贡献门槛；③ CSV 可被 BM25 算法高效索引和查询；④ 344+ 条记录的结构化数据通过列定义属性和关系，支持领域权重调整和技术栈相关性评分。这是"设计工程化"（Design Engineering）的创新实践——将设计知识像代码一样管理。

3. **双模式平台集成 + 符号链接开发架构** — 项目创新地提供了两种集成模式：① **Skill 模式**（适合 Claude Code、Cursor、Windsurf 等支持技能系统的平台）—— 完整知识库安装（full 类型），自动检测激活；② **Workflow 模式**（适合 Kiro、GitHub Copilot 等平台）—— 轻量引用安装（reference 类型），需手动斜杠命令触发。full 类型提供完整知识库以适应强上下文平台，reference 类型提供快速参考以适应上下文受限平台——这是"上下文最小化设计"的体现。开发层面，项目使用符号链接（symlinks）实现 `src/ui-ux-pro-max/` ↔ `.claude/` ↔ `.shared/` 的实时同步，开发者修改一处代码，所有平台配置自动生效，大幅提升开发效率。

### 👥 适用人群

- **AI 编程助手用户** — 在使用 Claude Code、Cursor、Windsurf 等平台进行前端/全栈开发时，希望 AI 生成的 UI 具有专业设计水准的开发者。
- **前端开发者** — 需要快速生成符合行业标准的 UI 代码，尤其在使用 React、Next.js、Vue、Svelte、Tailwind、shadcn/ui 等技术栈时。
- **独立开发者和初创团队** — 没有专职设计师，需要快速搭建具有专业水准的 MVP 界面和 Landing Page。
- **产品经理** — 需要为 AI 辅助开发提供设计系统指导，确保产品 UI 的一致性和专业性。
- **设计系统工程师** — 需要构建和维护跨平台设计系统，可将本项目作为"设计知识库"的基础架构参考，尤其是 CSV 驱动的知识管理方式和 Master/Overrides 模式。
- **AI Skill 开发者** — 想学习如何为 AI 编程助手构建技能包（Skill），本项目的平台检测、双模式集成、符号链接开发等架构模式值得借鉴。

### ⚡ 快速上手

**方式一：通过 CLI 安装（推荐，零配置）**

```bash
# 全局安装 CLI 工具
npm install -g uipro-cli

# 进入你的项目目录
cd /path/to/your/project

# 初始化（自动检测 AI 平台，无需指定）
uipro init          # 自动检测 .claude/、.cursor/ 等目录
uipro init --ai claude    # 或手动指定平台
```

**方式二：直接在 Claude Code 中使用**

安装 Skill 后，直接用自然语言描述需求，技能会自动激活：

```
Build a landing page for my SaaS product with hero section,
features, testimonials, and pricing table.
```

AI 会自动执行完整链路：① 平台检测（detectAIType）② 调用搜索引擎（core.py）③ 多领域查询（10 个领域）④ 推理规则应用（reasoning rules）⑤ 设计系统生成（design_system.py）⑥ 输出完整解决方案。

**方式三：CLI 直接生成设计系统**

```bash
# 生成设计系统（ASCII 格式）
python3 .claude/skills/ui-ux-pro-max/scripts/search.py \
  "beauty spa wellness" --design-system -p "Serenity Spa"

# 生成 Markdown 格式设计系统文档
python3 .claude/skills/ui-ux-pro-max/scripts/search.py \
  "fintech banking app" --design-system -f markdown

# 持久化设计系统到文件（生成 MASTER.md + pages/*.md）
python3 .claude/skills/ui-ux-pro-max/scripts/search.py \
  "SaaS dashboard" --design-system --persist -p "MyApp"
```

**系统要求**：Python 3.x（必需，用于运行搜索脚本和设计系统生成器）

### 🔬 对比分析

| 维度 | UI UX Pro Max Skill | 传统设计系统（如 Material Design） | Figma 设计文件 | 纯 AI 生成（无设计知识注入） |
|------|------|------|------|------|
| **知识来源** | 344+ 结构化设计资源（CSV 可检索） | 固定设计规范文档（不可检索） | 设计师手动创建（不可检索） | 大模型预训练知识（无专门设计知识） |
| **AI 可访问性** | ✅ AI 编程助手可直接读取 CSV 数据 | ❌ 需人工转换为代码 | ❌ 需手动导出为代码 | ⚠️ 质量不稳定 |
| **推理能力** | ✅ 161 条行业推理规则，上下文感知决策树 | ❌ 通用规范，无推理能力 | ❌ 静态文件，无推理 | ❌ 无专门设计推理 |
| **设计系统生成** | ✅ 秒级自动生成 Master + Overrides 规范 | ❌ 需人工编写 | ⚠️ 需设计师手工制作 | ❌ 输出不一致 |
| **行业定制** | ✅ 医疗/金融/电商等行业推理规则 | ❌ 通用规范，无行业定制 | ⚠️ 取决于设计师经验 | ❌ 无行业意识 |
| **技术栈适配** | ✅ 16 种技术栈最佳实践 + 技术栈过滤 | ⚠️ 仅提供通用指导 | ❌ 与技术栈无关 | ❌ 常生成过时或错误的代码 |
| **平台覆盖** | ✅ 18+ AI 平台，零配置检测 | ❌ 不适配 AI 平台 | ❌ 不适配 AI 平台 | - |
| **质量保证** | ✅ 预交付检查清单（无障碍/性能/一致性） | ⚠️ 部分覆盖 | ⚠️ 取决于设计师 | ❌ 常忽略无障碍和性能 |
| **开源协议** | ✅ MIT（可商用、可修改、可分发） | ⚠️ 各系统不同 | ❌ 闭源 | - |

**核心差异**：传统设计系统和 Figma 文件都是"人读"的格式，而 `UI UX Pro Max Skill` 的设计知识库是**"AI 读"的格式**——这不仅是格式差异，更是**范式转变**。它不仅让 AI 能"看到"设计知识，还通过推理规则引擎让 AI 能"理解"和"推理"设计决策，最终输出完整的设计系统而非零散的设计建议。
