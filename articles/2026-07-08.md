# PageIndex：告别向量数据库，用推理重塑 RAG

> 📑 VectifyAI/PageIndex ⭐33.9k | Python | MIT License | 2025-04-01 创建

## 项目背景

RAG（检索增强生成）是当前 LLM 应用的基石架构，但传统向量 RAG 存在一个根本性缺陷：**相似性 ≠ 相关性**。向量数据库通过余弦距离找"语义相近"的文本块，却无法判断"真正有用"的内容。这在金融年报、法律文书、学术论文等专业长文档中尤为致命——200页的 SEC 文件里，几十段关于"financial stability"的描述语义几乎雷同，但只有一小节才是你需要的答案。

PageIndex 的创始团队受 AlphaGo 的启发，提出了一个反直觉的问题：**向量数据库真的对高效 RAG 必须吗？答案是——根本不。** 他们用 LLM 的推理能力替代了向量检索，构建了一个"无向量、无分块、基于推理"的全新 RAG 系统，在 FinanceBench 基准测试中达到了 **98.7% 准确率**，远超各类向量 RAG 方案。

## 核心功能

1. **层级树索引（Tree Index）**：将 PDF/Markdown 文档解析为 JSON 层级树结构，每个节点包含标题、页码范围、LLM 生成的摘要和子节点，相当于为 LLM 定制了一份"智能目录"——不是固定 512 token 的粗暴分块，而是保留文档自然章节的语义完整性。

2. **推理式检索（Reasoning-based Retrieval）**：检索时 LLM 先"读"整棵树（仅标题+摘要，不含全文），通过推理判断哪些节点包含答案，再只取这些节点的全文。每步推理都留下 `thinking` 字段记录推理路径，让检索过程完全可审计、可追溯。

3. **上下文感知多轮检索**：支持注入对话历史，LLM 能理解"刚才问了资产，现在问负债——应该找同一份报告的负债章节"，而非每轮独立查询。还能跟踪文档内部引用（如"参见附录 G"），自动跳转到引用位置。

4. **PageIndex File System（大规模扩展）**：文件级树索引层让 PageIndex 从单文档推理扩展到百万级文档库的搜索，支持三种多文档检索策略——元数据 SQL 过滤、语义向量评分（DocScore 选文档→树搜索精读）、描述 LLM 选文档。

5. **多模态无 OCR 检索**：对 PDF 中的图表、图像建立视觉节点，直接提供页面图像作为上下文，跳过 OCR 畸变。未来方向包括更精细的摘要模型和多人协作注释节点。

6. **多部署模式即插即用**：本地 CLI（`run_pageindex.py`）、Python 包（`from pageindex import PageIndexClient`）、Cloud REST API、Chat UI（chat.pageindex.ai）、MCP 集成（Claude/Cursor 等一键接入）——五条路径覆盖从个人实验到企业集成。

7. **Agentic Vectorless RAG Demo**：基于 OpenAI Agents SDK 的完整 agentic 示例，展示如何用 PageIndex 构建自托管的多步推理 RAG Agent，无需向量数据库。

## 技术亮点

1. **双管线架构（PDF vs Markdown）**：PDF 管线通过 `find_toc_pages()` 和 `toc_extractor()` 从文档自带目录页提取结构，Markdown 管线通过 `extract_nodes_from_markdown()` 解析标题层级。两管线独立但输出统一的 JSON 树格式，核心处理逻辑完全解耦。

2. **超大节点递归细分而非粗暴分块**：当某节点超过 `max_page_num_each_node` 或 `max_token_num_each_node` 限制时，`process_large_node_recursively()` 不是按字符数切割，而是沿该节点内部子标题结构细分——保留语义完整性是第一原则。

3. **MCTS（蒙特卡洛树搜索）增强检索**：Cloud API 版本在树搜索中引入 Monte Carlo Tree Search 算法优化节点选择，将 AlphaGo 的搜索策略直接应用于文档导航——从"读目录选章节"进化到"模拟评估最优路径"。

4. **统一 LLM 层（litellm）**：所有模型交互集中在 `utils.py` 的 `llm_completion()` 和 `llm_acompletion()`，通过 litellm 统一接口支持 OpenAI/Claude/本地模型，自带重试和 JSON 提取机制。

## 适用人群

- **金融分析师**：SEC 年报 200+ 页嵌套章节，向量检索常漏掉关键细节，PageIndex 在 FinanceBench 达 98.7% 准确率
- **法律从业者**：案例法和合约需要精确段落引用，树结构保留页码范围，答案可附带精确位置参考
- **学术研究者**：论文多级子章节按主题检索不可靠，节点摘要引导 LLM 精准定位
- **RAG 系统开发者**：想摆脱向量数据库的维护成本和相似性陷阱，构建可解释、可追溯的检索管线
- **AI Agent 构建者**：通过 MCP 一行配置即可让 Claude/Cursor 等 Agent 直接调用 PageIndex 的推理检索能力

## 快速上手

```bash
# 克隆仓库并安装依赖
git clone https://github.com/VectifyAI/PageIndex.git
cd PageIndex
pip install -U -r requirements.txt

# 设置 API Key
echo "CHATGPT_API_KEY=sk-..." > .env

# 对 PDF 生成树索引
python run_pageindex.py --pdf_path /path/to/document.pdf

# 对 Markdown 生成树索引
python run_pageindex.py --md_path /path/to/document.md
```

可选参数：
- `--model gpt-4o`：指定 LLM 模型
- `--toc-check-pages 20`：扫描目录的页数范围
- `--max-pages-per-node 10`：每节点最大页数
- `--if-add-node-summary yes`：为每个节点添加摘要

## 对比分析

| 维度 | 传统向量 RAG | PageIndex 推理 RAG |
|------|-------------|---------------------|
| 检索机制 | 嵌入向量余弦距离 | LLM 推理 + 层级树导航 |
| 文档表示 | 512/1000 token 固定分块 | 自然章节层级树节点 |
| 向量数据库 | 必需（Chroma/Pinecone等） | **不需要** |
| 分块 | 必需，常切断语义 | **不需要**，保留完整章节 |
| 可解释性 | 低（近似匹配，无法解释为何选此块） | **高**（推理路径可追溯，页码引用精确） |
| 上下文感知 | 不支持多轮对话历史 | **支持**，多轮推理考虑先前上下文 |
| 文档引用 | 无法跟踪"参见附录G" | **自动跟踪**，跳转到引用位置 |
| FinanceBench 准确率 | 多方案 70-85% | **98.7%** |
| 基础设施成本 | 需向量数据库+嵌入模型服务 | 仅需 LLM API（或本地模型） |
| 适用文档类型 | 通用短文本 | 长篇结构化专业文档（金融/法律/学术） |

核心洞察：向量 RAG 在"语义相似但相关不同"的场景下严重失准——金融报告里大量段落语义高度相似（都在讲 financial stability），但只有特定小节才有你需要的具体数字。PageIndex 让 LLM 像人类专家一样"先看目录判断位置→再读相关章节→必要时跟踪引用跳转"，从根本上解决了"相似 ≠ 相关"的问题。

值得注意的是，PageIndex 并不排斥向量方法——在多文档检索的"Search by Semantics"策略中，向量搜索用于初步筛选文档（计算 DocScore），然后再对入选文档执行高精度树搜索。这是**向量做粗筛、推理做精读**的混合策略，而非简单对立。
