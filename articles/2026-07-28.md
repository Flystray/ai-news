今天不推荐爆款。这个项目只有 26 颗星——但它是我近期见过**工程密度最高的自托管知识库**：16 万行 Rust、106 个数据库迁移、13 种多模态提取适配器、43 个 MCP 工具（完整模式 205 个）、131 种文档类型自动识别。作者的野心写在 README 第一句里："An intelligent database for AI-ready applications"——不是又一个笔记应用，而是一个**为 AI 时代重新设计的智能数据库底座**。

为什么值得关注？因为它踩中了 2026 年最关键的一个命题：**AI Agent 的记忆到底应该长什么样**。当所有人还在用"向量数据库 + 分块"的碎片化方案时，Fortémi 给出了一个完全不同的答案：结构化、可溯源、带知识图谱、原生 MCP 的记忆基座。

## 项目背景：从"存储数据"到"理解数据"

大多数知识管理系统的逻辑是"存进去，等你精确查询"。你存了 500 篇笔记、200 个 PDF、几十条录音，真要找某个结论时，却想不起当时用的词——传统全文搜索直接失效。而纯向量方案（RAG 常规做法）又走向另一个极端：把文档切成碎片塞进向量库，检索出来的是无上下文的片段，没有来源追踪，没有关联结构。

Fortémi 的出发点是把两者合成一个"主动理解内容"的系统：找到概念相关的结果（即使你忘了准确术语），自动发现新知识与已有知识的连接，并从图片、音频、视频、3D 模型、邮件、表格中提取可搜索的信息。README 里那句话很动人："如果你曾希望你的笔记能回应你——浮现被遗忘的连接、从积累的知识中回答问题、随着每条信息变得更聪明——Fortémi 就是那个系统。"

另一个关键背景是**隐私优先、边缘优先**：无云依赖，8GB 显存的消费级显卡即可运行完整栈（默认模型 qwen3.5:9b + nomic-embed-text），从纯 CPU 到 24GB GPU 提供 `edge` / `gpu-12gb` / `gpu-24gb` 三档硬件配置。这是一个可以塞进气隙内网的完整 AI 记忆系统。

## 核心功能

### 1. 三路混合搜索：BM25 + 向量 + RRF 融合

搜索不是单一算法，而是三路并行：PostgreSQL FTS 做 BM25 词法检索，pgvector 做稠密向量语义检索，知识图谱做关联检索，最后用 RRF（Reciprocal Rank Fusion，Cormack et al. 2009）融合排名，再经 MMR 重排保证结果多样性。支持 AND/OR/NOT/短语操作符，多语言处理直接下沉到分词层：CJK 二元/三元组、6+ 语言词干提取、甚至 emoji 三元组。中文用户不需要任何额外配置。

### 2. 自动知识图谱：链接是"长"出来的，不是手动画的

新笔记入库后，系统计算它与已有内容的嵌入相似度，超过 70% 自动建立双向链接，相似度存为边权重。图质量靠三个算法维护：SNN（共享最近邻）评分修正相似度、PFNET 稀疏化剪掉冗余边、Louvain 社区发现聚类主题。探索用递归 CTE 遍历，还有一个"知识健康仪表板"专门找孤立标签、陈旧笔记、未链接的冷点内容。

### 3. 43 个 MCP 工具：为 Agent 而生的记忆接口

这是 Fortémi 与传统笔记工具的分水岭。它内置一个 Node.js MCP Server（端口 3001），核心模式暴露 43 个工具，完整模式 205 个：`capture_knowledge`（写入）、`search`（联邦混合搜索）、`record_provenance`（记录知识来源血缘）、`explore_graph`（图遍历）、`manage_archives`（多记忆归档切换）等。Claude Desktop 一段 JSON 配置即接入。AI Agent 从此有了一个结构化、可溯源、可遍历的外部记忆，而不是碎片化的向量快照。

### 4. 13 种多模态提取适配器 + 131 种文档类型

上传即理解：图像走视觉 LLM 场景描述，音频走 Whisper 时间戳转写 + pyannote 说话人分离，视频做关键帧场景检测与转写对齐，GLB/glTF 3D 模型多视角渲染后生成视觉描述，邮件按 RFC 2822/MIME 解析，表格转 Markdown，压缩包列目录并抽文本。文档类型注册表预置 131 种类型（19 大类），按文件名、扩展名和内容魔数自动检测，并为不同类型选择不同分块策略——散文语义分块、代码语法分块、文档按节分块。

### 5. 多记忆归档 + 联邦搜索

一个实例可以承载多个 schema 隔离的"记忆归档"（默认上限 10 个，随内存扩展）——工作知识库、个人笔记、每个 Agent 的独立记忆互不污染，又能通过 `POST /api/v1/search/federated` 一次跨库检索。配合 X25519/AES-256-GCM 公钥加密笔记共享、OAuth2 + API Key 认证、SSE/WebSocket/webhook 实时事件，这是按多租户生产标准设计的。

### 6. Matryoshka 嵌入集：12 倍存储节省

嵌入管理支持 MRL（Matryoshka Representation Learning, 2022）：同一模型生成的嵌入可按维度截断使用，两阶段检索先用短向量粗筛再用全维精排，官方数据存储节省 12 倍。嵌入规则可配置自动化，换模型不需要推倒重来。

## 技术亮点

### 1. PostgreSQL 单库承载全部检索负载的架构赌注

Fortémi 没有引入 Elasticsearch、Milvus、Neo4j 中的任何一个，而是把全文检索（FTS）、向量检索（pgvector + HNSW，O(log N) 查询）、空间检索（PostGIS 时空查询）、图遍历（递归 CTE）全部压进一个 PostgreSQL 18。7 个 Rust crate 分层清晰：`matric-api`（Axum REST + OpenAPI）、`matric-search`（混合检索）、`matric-jobs`（异步 NLP 流水线）、`matric-inference`（多提供商 LLM 抽象，支持 Ollama/OpenAI/OpenRouter/llama.cpp 热切换）、`matric-db`（sqlx + 106 迁移）、`matric-crypto`、`matric-core`。运维面只有一个数据库，备份、迁移、监控全部走 PostgreSQL 成熟工具链——这对自托管用户是实打实的负担减半。

### 2. 溯源（Provenance）作为一等公民

`record_provenance` 工具把"这条知识从哪来"记录为结构化数据：来源文档、提取时间、处理链路。RAG 系统最被诟病的"答案无法追责"问题，在这里被数据模型层面解决。W3C SKOS 标准词汇表（2009 规范）管理层级概念标签，让标签系统不再是随手打的字符串，而是有语义结构的受控词汇。这两个设计都在对抗同一件事：AI 时代知识系统的"不可审计性"。

### 3. 同一 schema 三端锁步：Server、浏览器版、桌面 HotM

Fortémi 服务端、浏览器版和 HotM 桌面应用共享同一套数据 schema 和同一个 `matric-api` 二进制（HotM 把它作为 sidecar 打包），功能永远同步。单机用户下载 HotM 安装包即用——无 Docker、无 Postgres 配置、无后端运维；团队和 Agent 集群用 Docker bundle（PostgreSQL 18 + Redis + API + MCP + Open3D 五个容器一条命令拉起）。一套代码覆盖从个人笔记本到企业内网的完整光谱。

## 快速上手

**方式一：HotM 桌面版（单机用户推荐）**

从 [HotM Releases](https://git.integrolabs.net/Fortemi/HotM/releases/latest) 下载对应平台安装包（.msi / .dmg / .deb / .AppImage），UI 与 Fortemi API 打包在一起，免 Docker 免数据库配置。

**方式二：Docker Bundle（服务端 / Agent 集群）**

```bash
# 前置：主机安装 Ollama 并拉取模型
ollama pull qwen3.5:9b
ollama pull nomic-embed-text

# 一条命令拉起完整栈（PostgreSQL 18 + Redis + API + MCP + Open3D）
docker compose -f docker-compose.bundle.yml up -d

# 验证
curl http://localhost:3000/health
```

端口：3000（REST API + Swagger 文档在 /docs）、3001（MCP Server）。按显卡设置 `COMPOSE_PROFILES=edge|gpu-12gb|gpu-24gb`。

**接入 Claude Desktop（MCP）**：

```json
{
  "mcpServers": {
    "fortemi": { "url": "http://localhost:3001/mcp" }
  }
}
```

**搜索 API 示例**：

```bash
# 混合搜索（默认 RRF 融合）
curl "http://localhost:3000/api/v1/search?q=检索增强生成"

# 纯语义 / 纯词法
curl "http://localhost:3000/api/v1/search?q=RAG&mode=semantic"
curl "http://localhost:3000/api/v1/search?q=RAG&mode=fts"
```

## 对比分析

| 维度 | Fortémi | Khoj (⭐34k+) | AnythingLLM (⭐55k+) | Obsidian + 插件 |
|------|---------|--------------|---------------------|-----------------|
| **定位** | AI-ready 智能数据库底座 | 个人 AI 第二大脑 | 团队文档 RAG 平台 | 本地笔记 + 生态 |
| **检索方案** | BM25+向量+图三路 RRF 融合 + MMR | 语义搜索为主 | 向量 RAG 为主 | 插件各自为战 |
| **知识图谱** | 自动构建（SNN/PFNET/Louvain） | 无 | 无 | 手动双链 |
| **MCP 支持** | 原生 43-205 个工具 | 无原生 MCP Server | Agent 内置 MCP 客户端 | 社区插件 |
| **多模态摄取** | 13 适配器（视频/3D/邮件/说话人分离） | PDF/图片/笔记 | 文档为主 | 基本无 |
| **多用户/多记忆** | schema 隔离归档 + 联邦搜索 | 单用户为主 | 工作区 + 权限 | 单用户 |
| **溯源追踪** | 一等公民（provenance API） | 无 | 引用级 | 无 |
| **技术栈** | Rust + PostgreSQL 单库 | Python + Postgres | Node.js + 多向量库 | Electron |
| **硬件门槛** | 8GB VRAM 跑全栈（CPU 亦可） | 中 | 低（可全 CPU） | 极低 |
| **许可证** | BSL-1.1（单用户免费商用） | AGPL-3.0 | MIT | 闭源+付费同步 |
| **成熟度** | 早期（26 星，5 个月） | 成熟（YC 投资） | 成熟 | 非常成熟 |

定位差异一目了然：Khoj 赢在多端覆盖（Obsidian/手机/WhatsApp），AnythingLLM 赢在团队开箱即用，而 Fortémi 押注的是**下一层**——当 AI Agent 成为知识系统的主要"用户"时，人类友好的聊天界面不再是核心，**结构化、可溯源、可编程的记忆接口**才是。43 个 MCP 工具、多归档隔离、provenance 追踪，全都是为 Agent 集群设计的能力。

风险也要说清楚：26 星意味着社区极小，BSL-1.1 对多用户商用部署收费，文档虽有 65+ 篇但生态几乎为零。这是典型的"架构领先于采用"项目——适合技术选型的参考和早期尝鲜，暂不适合直接押注生产。

## 写在最后

Fortémi 最有启发的地方，不是任何单一功能，而是它对一个趋势的判断：**RAG 正在从"向量数据库"进化为"结构化知识平台"**。碎片化的向量检索解决了"找到相关内容"，但解决不了"知识从哪来、如何关联、能否审计"。Fortémi 用 PostgreSQL 单库 + 图谱 + 溯源 + MCP 的组合拳给出了自己的答案——这条路线是否会赢不确定，但问题本身是真实的。

另一个值得玩味的细节：这个项目不做 LLM，不做 UI 竞争，只做"AI 时代的数据基础设施"。就像当年的 SQLite 之于移动应用，Fortémi 想成为 Agent 应用的默认记忆层。16 万行 Rust 砸在一个 26 星的项目上，要么是过度工程的独角戏,要么是提前卡位的基础设施——无论哪种，代码本身已经值回阅读时间。
