🚀 今日推荐：PageIndex

VectifyAI/PageIndex 是一个无向量数据库、无分块、基于推理的全新 RAG 系统。受 AlphaGo 启发，它用 LLM 的推理能力替代了向量检索——构建层级树索引让 LLM 像"读目录"一样导航文档，而非在嵌入空间中做最近邻搜索。在 FinanceBench 基准上达到98.7% 准确率，远超各类向量 RAG 方案。

核心洞察：相似性 ≠ 相关性。200 页 SEC 文件中几十段关于 "financial stability" 的描述语义几乎雷同，但只有一小节才是你需要的答案。向量检索无法区分它们——PageIndex 让 LLM 像人类专家一样推理判断"去哪里找答案"。

🎯 一句话定位：不是向量数据库，不是分块管道——是受 AlphaGo 启发的推理型文档索引，让 LLM 通过层级树导航+推理检索实现"类人阅读"，彻底绕开向量相似性的陷阱。

🔧 核心功能

1. 层级树索引（Tree Index）

将 PDF/Markdown 文档解析为 JSON 层级树，每个节点包含标题、页码范围、LLM 生成的摘要和子节点——相当于为 LLM 定制了一份"智能目录"。不是固定 512 token 的粗暴分块，而是保留文档自然章节的语义完整性。PDF 管线从文档自带目录页提取结构（toc_extractor()），Markdown 管线解析标题层级（extract_nodes_from_markdown()），两管线独立但输出统一的 JSON 树。

2. 推理式检索（Reasoning-based Retrieval）

检索时 LLM 先"读"整棵树（仅标题+摘要，不含全文），通过推理判断哪些节点包含答案，再只取这些节点的全文。每步推理都留下 thinking 字段记录推理路径，让检索过程完全可审计、可追溯。Cloud API 版本还引入MCTS（蒙特卡洛树搜索）优化节点选择——将 AlphaGo 的搜索策略直接应用于文档导航。

3. 上下文感知多轮检索

支持注入对话历史，LLM 能理解"刚才问了资产，现在问负债——应该找同一份报告的负债章节"。还能自动跟踪文档内部引用（如"参见附录 G"），跳转到引用位置——向量检索完全做不到这一点。

4. PageIndex File System（大规模扩展）

文件级树索引层让 PageIndex 从单文档推理扩展到百万级文档库的搜索，支持三种多文档检索策略：

策略机制适用场景
元数据过滤SQL 结构化查询按日期/地区/ID 精确定位
语义评分向量 DocScore 选文档 → 树搜索精读大规模多样化主题
描述选择LLM 读取文档描述选文档小集（<50）不同主题

5. 多模态无 OCR 检索

对 PDF 中的图表、图像建立视觉节点，直接提供页面图像作为上下文，跳过 OCR 畸变。保留原文布局，特别适合包含大量表格的金融/法律文档。

6. 多部署模式即插即用

五种路径覆盖从个人实验到企业集成：

  • 本地 CLI：python run_pageindex.py --pdf_path ...
  • Python 包：from pageindex import PageIndexClient
  • Cloud REST API：PageIndex API SDK
  • Chat UI：chat.pageindex.ai
  • MCP 集成：Claude/Cursor 等一键接入

7. Agentic Vectorless RAG Demo

基于 OpenAI Agents SDK 的完整 agentic 示例，展示如何用 PageIndex 构建自托管的多步推理 RAG Agent——无需向量数据库，无需分块管道。

💡 技术亮点

双管线架构（PDF vs Markdown）

PDF 管线通过 find_toc_pages() 和 toc_extractor() 从文档自带目录页提取结构；Markdown 管线通过 extract_nodes_from_markdown() 解析标题层级。两管线独立但输出统一 JSON 树格式，核心处理逻辑完全解耦。

超大节点递归细分而非粗暴分块

当某节点超过 max_page_num_each_node 或 max_token_num_each_node 时，process_large_node_recursively() 不是按字符数切割，而是沿该节点内部子标题结构细分——保留语义完整性是第一原则。

统一 LLM 层（litellm）

所有模型交互集中在 utils.py 的 llm_completion() 和 llm_acompletion()，通过 litellm 统一接口支持 OpenAI/Claude/本地模型，自带重试和 JSON 提取机制。

专业知识注入

树搜索支持注入领域专家规则——如"If the query mentions EBITDA adjustments, prioritize Item 7"。这让检索不是纯通用推理，而是可定制专家知识的领域搜索。

🚀 快速上手

# 1. 克隆仓库并安装依赖
git clone https://github.com/VectifyAI/PageIndex.git
cd PageIndex
pip install -U -r requirements.txt

# 2. 设置 API Key
echo "CHATGPT_API_KEY=sk-..." > .env

# 3. 对 PDF 生成树索引
python run_pageindex.py --pdf_path /path/to/document.pdf

# 4. 对 Markdown 生成树索引
python run_pageindex.py --md_path /path/to/document.md

# 可选参数：
# --model gpt-4o          指定 LLM 模型
# --toc-check-pages 20    扫描目录的页数范围
# --max-pages-per-node 10 每节点最大页数
# --if-add-node-summary yes 为每个节点添加摘要

核心洞察：向量 RAG 在"语义相似但相关不同"的场景下严重失准——金融报告里大量段落语义高度相似（都在讲 financial stability），但只有特定小节才有你需要的具体数字。PageIndex 并不排斥向量方法——在多文档检索的"Search by Semantics"策略中，向量搜索用于初步筛选文档（计算 DocScore），然后再对入选文档执行高精度树搜索。这是向量做粗筛、推理做精读的混合策略，而非简单对立。

✨ 一句话总结

PageIndex 用 AlphaGo 式的推理搜索替代了向量相似度检索——层级树索引让 LLM 像"读目录"一样导航长文档，98.7% FinanceBench 准确率证明"相似≠相关"的问题可以被彻底解决。如果你在金融/法律/学术长文档上对向量 RAG 失望过，这是今天最值得试的替代方案。
