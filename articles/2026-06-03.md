# AgentMemory：让 AI 编程 Agent 拥有真正可搜索的持久记忆

> AI 编程助手每次新会话都会"失忆"——你需要反复解释项目架构、编码规范、之前修复过的 Bug。AgentMemory 是一个专为编码 Agent 设计的持久记忆引擎，零外部数据库依赖，三流混合检索 R@5 达 95.2%，让 Claude Code、Cursor、Codex 等工具拥有跨会话、跨工具的统一记忆。

## 项目背景

2026 年，AI 编程 Agent（Claude Code、Cursor、GitHub Copilot、Codex CLI 等）已成为开发者的日常工具。但它们都有一个共同的痛点：**上下文窗口是临时的**。每次新会话开始，Agent 就忘记了一切——你不得不反复解释项目约定、历史决策、踩过的坑。

各 Agent 提供的"记忆"方案（Claude Code 的 MEMORY.md、Cursor 的 Notepad、Cline 的 Memory Bank）本质上是便签式存储，既不可搜索，也无法跨工具共享。随着观测量增长，MEMORY.md 的 Token 消耗线性膨胀：积累到 1,000 条时需要 5 万 Token，且只能覆盖 20% 的历史；到 5,000 条时需要 25 万 Token，可达率仅剩 4%。

**AgentMemory**（rohitg00/agentmemory）正是为解决这个问题而生。它于 2026 年 2 月创建，TypeScript 编写，Apache-2.0 许可证，目前已获得 **20,800+ GitHub Stars**，在 Trendshift 趋势排行中进入第 19 位，并获得 AlphaSignal（18 万订阅）和 Linux Foundation 支持的 AAIF 媒体关注。项目的核心理念是：**将 Karpathy 的 LLM Wiki 模式工程化**，加入置信度评分、生命周期管理、知识图谱和混合搜索，打造一个真正可搜索、可检索、可跨 Agent 共享的持久记忆系统。

## 三层运行时架构

AgentMemory 基于 iii-engine 构建，整个运行时是**单进程 Node.js 应用，零外部数据库依赖**（无 Redis、Kafka、Postgres、Qdrant、Neo4j），状态以 JSON 形式持久化到本地磁盘。架构分为三层：

| 层级 | 名称 | 核心职责 |
|------|------|----------|
| **01 HOOKS** | 钩子层 | 12 个自动捕获钩子接入每个编码 Agent，每次工具调用、每个提示词、每次停止都被压缩为观测记录 |
| **02 RECALL** | 召回层 | 三流检索（BM25 + 向量 + 知识图谱），设备端重排序，P50 延迟低于 20ms |
| **03 CONSOLIDATE** | 整合层 | 每小时扫描，将原始观测压缩为语义记忆，合并重复项，衰减过期数据，每次删除生成审计记录 |

## 12 大核心功能

### 1. 四层记忆整合架构

AgentMemory 模仿人类记忆系统，设计了四层递进式记忆架构：

| 记忆层级 | 存储内容 | 解决的问题 |
|----------|----------|------------|
| **Working（工作记忆）** | 工具调用产生的原始观测 | 保留最接近现场的短期数据 |
| **Episodic（情节记忆）** | 压缩后的会话摘要 | "上一次发生了什么？" |
| **Semantic（语义记忆）** | 抽取的事实、模式与稳定知识 | "这个项目长期成立的事实是什么？" |
| **Procedural（程序记忆）** | 工作流、决策套路与可复用做法 | "这类事情通常怎么做？" |

信息在不同层级间逐步沉淀：原始观测被压缩为结构化事实和情节叙事，记忆会衰减、强化、自动淘汰，系统还能处理陈旧记忆和矛盾事实的冲突。

### 2. 三流混合检索（BM25 + 向量 + 知识图谱）

AgentMemory 的检索不是单一方式，而是融合三路信号后通过 **Reciprocal Rank Fusion（RRF）** 统一排序：

- **BM25 关键词检索**：精确匹配文件名、函数名、术语
- **Vector 语义检索**：捕捉语义相似度，支持本地 embedding（all-MiniLM-L6-v2），零 API 成本
- **Knowledge Graph 关系遍历**：基于实体关系做图遍历推理，压缩时自动提取实体和关系，支持时序边

这种设计的优势非常直观：当你搜索 "database performance optimization" 时，BM25 关键词召回率为 0%，而向量检索直接拉到 40%——两种方式互补而非替代。

### 3. 12 个自动 Hooks，全生命周期捕获

12 种生命周期事件（PreToolUse、PostToolUse、SessionStart、Stop 等）**自动捕获** Agent 行为，无需手动调用记忆 API，无需任何胶水代码，安装插件即完成。这是 AgentMemory 与竞品最显著的差异：Mem0、Letta、Cognee 均有 **0 个自动 Hook**。

### 4. 53 个 MCP 工具 + 126 个 REST 端点

配合 53 个 MCP 工具和 126 个 REST 端点（每个 MCP 工具都有对应的 REST 接口），覆盖记忆的存、查、删、改、导出全链路。主要工具包括 `memory_save`、`memory_recall`、`memory_smart_search`、`memory_sessions`、治理、审计、导出等。

### 5. 跨 Agent 统一记忆库

所有 Agent 共享**同一个记忆服务器**。你在 Claude Code 中积累的项目知识，切换到 Cursor 时同样可用。支持 Claude Code（12 hooks + MCP，一等公民集成）、Copilot CLI（11 hooks）、Codex CLI（6 hooks + native plugin）、Hermes、OpenClaw、pi、Cursor、Gemini CLI 等 20+ 平台。

### 6. Token 效率优化

AgentMemory 采用"按需召回"策略，Token 消耗与历史量无关：

| 观测量 | MEMORY.md Token | AgentMemory Top-10 Token | Token 节省率 | MEMORY.md 可达率 |
|--------|----------------|-------------------------|------------|-----------------|
| 240 条 | 12,000 | 3,142 | 74% | 83% |
| 1,000 条 | 50,000 | 3,142 | **94%** | 20% |
| 5,000 条 | 250,000 | 3,142 | **99%** | 4% |

### 7. 自动整合（每小时调度）

系统每小时自动扫描，将原始观测压缩为语义记忆，合并重复项，衰减过期数据。每次删除操作都生成审计记录，确保记忆库保持精准而非膨胀。

### 8. 会话回放

支持导入 Claude Code JSONL 格式的会话记录，完整还原观察、工具使用、时间线。一位 Product Hunt 用户这样描述：*"我把过去一个月的 Cursor 代理记录全部回填进去，准确率出乎意料地高，甚至捕捉到了我已经放弃的东西。"*

### 9. 网格联邦（P2P 同步）

注册其他 agentmemory 节点，通过认证 HTTPS 推/拉记忆，Bearer Token 鉴权，无静默同步。支持 `TEAM_ID` 配置，具备团队级记忆共享能力。

### 10. Obsidian 导出

将记忆镜像到沙箱 vault 目录，生成带 Frontmatter 标签的 Markdown，兼容 Obsidian 图谱视图。

### 11. 多 LLM 支持

支持 Claude 订阅（默认，零配置）、Anthropic API、Gemini、MiniMax、OpenRouter 5 个提供商，自动从环境变量检测，无需手动切换。

### 12. 双 UI 控制台

| 界面 | 端口 | 功能 |
|------|------|------|
| **Viewer（记忆查看器）** | 3113 | 实时观察流、会话浏览、记忆过滤、知识图谱可视化、健康仪表盘 |
| **iii Console（引擎控制台）** | 3114 | 函数/触发器/OTEL Span 管理、KV 浏览器、OTEL 瀑布图 |

## 技术亮点

### 学术级基准测试

AgentMemory 在两个基准测试上展示了量化效果：

**内部基准 Coding-Agent-Life-v1**：Hybrid 检索的精确率（P@5）达到 0.578，是 grep（0.267）的 **2.2 倍**，召回率持平（96.7%），延迟仅 14ms。

**学术基准 LongMemEval-S**（500 题，约 115K tokens）：

| 系统 | R@5 | R@10 | NDCG@10 | MRR |
|------|-----|------|---------|-----|
| agentmemory (Hybrid) | **95.2%** | **98.6%** | **87.9%** | **88.2%** |
| agentmemory (BM25-only) | 86.2% | 94.6% | 73.0% | 71.5% |

Hybrid 检索相比纯 BM25，R@5 提升 9 个百分点，MRR 提升 16.7 个百分点。827 个通过的测试用例（另有 1392 个测试）为可靠性提供了工程保障。

### Circuit Breaker + Fallback Chain

系统内置断路器机制（3 次失败触发熔断）和回退链，确保 LLM 摘要、embedding 生成等外部依赖异常时，核心记忆存取不受影响。

### OTEL 可观测性

每个操作生成 span，支持本地内存导出或 OTLP（Jaeger/Honeycomb/Tempo），iii Console 提供完整的 OTEL 瀑布图视图。

## 快速上手

```bash
# 安装（Node.js >= 20）
npm install -g @agentmemory/agentmemory

# 启动记忆服务器（默认 :3111，Viewer 在 :3113）
agentmemory

# 另一终端：导入演示数据验证
agentmemory demo

# 打开实时 Viewer
# 浏览器访问 http://localhost:3113
```

**Claude Code 深度集成**（推荐方式，获得完整 12 Hooks）：

```bash
# 终端 1：启动完整服务
agentmemory

# 在 Claude Code 中安装插件
npx skills add rohitg00/agentmemory -y
```

**Cursor / Cline / Gemini CLI 等 MCP 客户端**：

```json
{
  "mcpServers": {
    "agentmemory": {
      "command": "npx",
      "args": ["-y", "@agentmemory/mcp"],
      "env": {
        "AGENTMEMORY_URL": "http://localhost:3111"
      }
    }
  }
}
```

注意：纯 MCP 模式无 hooks，记忆需手动存取，无法自动捕获会话。
