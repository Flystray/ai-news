这篇论文在说什么？

如果你关心大模型的推理能力是怎么训练出来的，大概率听过 GRPO——DeepSeek-R1 用这个方法把模型的数学能力拉到了新高度。GRPO 的方便之处在于它不需要额外训练一个"裁判网络"（Critic），实现起来简单。但代价是，它把一整段回复当成一个整体打分，每个 token 得到的信号完全一样——就好像裁判只看你整场比赛的输赢，却不管你每个球是怎么打的。

UC Berkeley 的 Sergey Levine 和 Dawn Song 团队显然觉得这不是最优解。他们发了一篇新论文，提出 VIMPO（Value-Implicit Policy Optimization），核心思路很有意思：从数学上推导出一个由策略自身隐含的价值函数，不训练 Critic，却能做到 token 级别的精细信用分配。

说人话就是——不用多训练一个模型，就能知道你的推理链里哪几步走得对、哪几步是蒙的，然后有针对性地优化。

为什么要关注？

2026 年，基于可验证奖励的强化学习（RLVR）已经默认成为 LLM 后训练的核心范式。 DeepSeek-R1 带火的 GRPO，几乎所有做推理模型的团队都在用或改着用。但 GRPO 有一个越来越难忽视的问题：

它把整个回复的轨迹级优势平均分配到所有 token 上。一句话总结就是："你整段答对了，所有 token 都有功；答错了，所有 token 都背锅。" 这对长文本推理任务来说尤其粗糙——关键推理步骤和普通连接词被一视同仁。

那为什么大家不直接用 Actor-Critic 方法（比如 PPO）呢？因为 Critic 网络自己训练起来很不稳定——随着策略更新，Critic 需要不断重新校准，一不小心就炸了。

VIMPO 的野心就在这：它想同时吃掉两条路的好处——像 GRPO 一样简单（不用训 Critic），像 Actor-Critic 一样精细（token 级信用分配）。

核心方法

关键思路

VIMPO 最核心的 insight 可以用一个等式来理解：最优价值函数可以通过策略相对于冻结参考模型的 log 似然比来隐式表示。

什么概念？传统的 RL 里，价值函数告诉你"当前状态下，未来还能拿多少分"，需要单独训练一个网络来估计。但 VIMPO 发现，在 KL 正则化的 RL 框架下，这个价值函数其实已经藏在你的策略里了——就是当前策略和冻结参考策略在每个 token 上的 log 概率差。

你可以把这个过程想象成三步：

① 你有一个正在训练的模型（策略 π）和一个冻结的参考模型（π_ref）
② π 和 π_ref 对每个 token 给出不同概率，两者的 log 比 + 贝尔曼递归 = 隐式价值函数
③ 到轨迹结束时未来奖励为 0——"终端条件"锚定整个递归链

于是 VIMPO 不需要训练 Critic，只需要同时优化一个价值损失（让策略隐含价值与真实奖励对齐）和一个 PPO 风格的演员更新（用 token 级 TD 信号指导策略改进）。

最关键的设计：这两个过程是解耦的。 奖励融入通过价值损失完成，策略改进通过演员更新完成。比 GRPO 那种"一笔糊涂账"精细得多，比 PPO 那种"Critic 随时可能崩"稳定得多。

图源：原文 Fig.2 — VIMPO 是无 Critic 但具有 token 级信用分配能力的 RL 方法

技术细节

对于想深入理解的同学，VIMPO 的推导可以概括为三步：

第一步：把自回归生成建模为 MDP。 将 token-by-token 的生成过程看作确定性转移的马尔可夫决策过程，每个 token 是一个状态，下一个 token 是唯一的后续状态。

第二步：从 KL 正则化目标推导价值恒等式。 在最大化期望奖励的同时限制与参考策略的 KL 散度，最优策略满足一个著名关系式——最优价值函数等于策略与参考策略的 log 似然比加上归一化常数。

第三步：蒙特卡洛估计 + 终端条件锚定。 价值损失的核心是贝尔曼一致性，VIMPO 用训练时采样的 rollout 来估计这个一致性，然后用"轨迹结束时没有未来奖励"锚定递归。整个过程不需要额外训练的 Critic 网络。

"Rather than learning a separate critic, we bootstrap the initial values from the same set of Monte-Carlo rollouts used in RLVR, and anchor the recurrence with the terminal condition that no future reward remains at the end of a trajectory."

—— 不是重新训一个 Critic，而是直接用同一批采样结果来引导初始价值，再用"轨迹结束就没人给分了"来锚定递归。思路干净利落。

效果怎么样？

VIMPO 在 Qwen3-4B-Base 上用 54.4K 条数学训练样本进行 RL 后训练，四个基准全面领先 GRPO：

方法 MATH-500 AIME 2024 AIME 2025 OlympiadBench 平均分
Qwen3-4B-Base 54.0 8.6 3.6 18.0 21.1
Naive GRPO 80.4 20.0 14.6 31.3 36.6
GRPO 79.6 19.3 17.6 33.2 37.4
VIMPO 81.6 21.7 20.8 34.0 39.5

数据来源：原文 Table 1。AIME 为 avg@32，其余为 avg@1

竞赛级别的提升最大。 AIME 2025 上 VIMPO 比 GRPO 高出 3.2 个百分点——竞赛题推理链长、步骤多，token 级信用分配的价值就体现出来了。

图源：原文 Fig.3 — 干净奖励下 VIMPO vs GRPO 训练曲线对比

更惊喜的是噪声鲁棒性。论文把 25% 的训练奖励随机翻转，结果如下：

方法 MATH-500 AIME 2024 AIME 2025 OlympiadBench 平均分
GRPO（噪声） 75.2 13.0 11.7 28.9 32.2
VIMPO（噪声） 78.2 18.3 14.9 32.3 35.9

25% 奖励翻转条件下，VIMPO 领先 GRPO 3.7 个平均分

AIME 2024 噪声条件下 GRPO 跌到 13.0，VIMPO 还保持在 18.3——精细的 token 级信号天然抗噪，即使最终奖励被污染，对中间步骤的判断仍有区分力。

和其他方案比有什么不同？

方案 需要 Critic？ 信用分配粒度 训练稳定性 实现复杂度
PPO / Actor-Critic 需要 Token 级 不稳定 高
GRPO（DeepSeek-R1） 不需要 轨迹级（粗） 稳定 低
FIPO / 注意力锚点法 不需要 近似 Token 级 稳定 中
VIMPO 不需要 Token 级 稳定 中

VIMPO 是目前唯一同时做到"不用 Critic"和"token 级信用分配"的方法。FIPO 这类改进虽然也试图恢复 token 级粒度，但本质还是在 GRPO 框架上打补丁，没有从目标函数层面重新设计。

"These augmentation approaches retrofit fine-grained credit assignment onto an objective that was not designed for it."

—— 这些改进是在一个本来不是为细粒度信用分配设计的目标函数上打补丁。VIMPO 的做法是从头推导适合细粒度信号的目标。

对开发者意味着什么？

如果你的团队在做 LLM 的 RL 后训练，VIMPO 值得认真关注，三个理由：

① 实现成本不高。 不需要额外训练 Critic 网络，核心只需要计算策略和参考模型的 log-ratio，然后维护两个损失。论文实验和 GRPO 共享了大部分超参数，迁移成本可控。

② 噪声环境下更稳定。 如果你的奖励函数不够完美（LLM-as-Judge 打分、数据标注噪音），VIMPO 的 token 级信号天然有更好的容错能力。25% 奖励翻转测试中 GRPO 掉了 5 分，VIMPO 只掉了不到 4 分。

③ 长推理链场景收益更大。 竞赛题、复杂代码调试、多步推理——这些场景"关键步骤"和"普通连接"的区别最明显，VIMPO 的 token 级优势估计价值最大。

局限也要说清楚：目前实验基于 Qwen3-4B，规模不算大；训练数据是数学题，代码、对话等场景效果待验证；PPO 风格演员更新会带来策略偏移，需要根据任务调参。

但总体而言，这是一个方向性的改进——VIMPO 证明了"不用 Critic 也能做精细信用分配"是完全可行的，且不需要额外训练代价。对于正被 GRPO 各种限制困扰的团队，多了一个重要的新选择。
