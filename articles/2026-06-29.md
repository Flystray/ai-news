# codebase-memory-mcp：让 AI 编程助手告别「逐文件搜索」的代码知识图谱引擎

## 项目背景

AI 编程助手（Claude Code、Cursor、Copilot 等）在理解代码时有个致命短板：它们只能逐文件搜索。想知道「谁调用了 `processOrder`」，就得先 grep 搜一遍，再挨个文件读，再 grep 再读……5 次结构查询能吃掉 412,000 个 Token，而结果还常常遗漏跨文件的类型推断和接口实现关系。这不是效率问题——在 $3-15/M Token 的定价下，探索成本是真金白银；在「中间遗忘」效应下，信息噪声是真真切切的答案质量下降。

**codebase-memory-mcp**（DeusData 团队开发，MIT 许可，2026 年 2 月创建）提出了根本性解法：不再让 Agent 在文件系统里跑迷宫，而是把整个代码库**索引为一张持久化的 SQLite 知识图谱**，Agent 直接对图谱做结构查询——亚毫秒响应、99.2% Token 缩减、83% 答案准确率（31 个真实代码库评测，arXiv:2603.27277）。整个系统编译为**单个纯 C 静态二进制文件**，零运行时依赖，所有数据本地处理，代码不出机器。

## 核心功能

### 1. 极速索引：Linux 内核 3 分钟搞定
索引管线采用**内存优先策略**——LZ4 压缩 + 内存版 SQLite + Aho-Corasick 模式匹配融合，索引完成后立即释放内存。实测数据：
- **Linux 内核**（28M LOC / 75K 文件）完整索引 3 分钟 → 481 万节点 + 772 万边
- **Django**完整索引约 6 秒 → 4.9 万节点 + 19.6 万边
- Cypher 图查询 <1ms；调用路径追踪（depth=5）<10ms；死代码检测约 150ms

### 2. 158 语言 Tree-sitter + 9 语言 Hybrid LSP 双层语义解析
**第一层 Tree-sitter**：内嵌 158 种编程语言的语法解析器（全编译进二进制），提取函数定义、类定义、调用关系、导入关系。**第二层 Hybrid LSP**：轻量级 C 实现的类型推断引擎（结构兼容 tsserver、pyright、gopls、rust-analyzer 等主流 Language Server），覆盖 Python、TypeScript/JS/TSX、PHP、C#、Go、C/C++、Java、Kotlin、Rust 共 9 个语言家族，解析泛型、继承、标准库类型追踪、接口实现、async/await 等——这是 Tree-sitter 纯语法层做不到的。

### 3. 丰富边类型：不只是 CALLS 和 IMPORTS
知识图谱的边类型远超传统调用图：
- `CALLS`/`ASYNC_CALLS`：同步/异步调用
- `HTTP_CALLS`：跨服务的 REST 路由匹配（含置信度评分）
- `EMITS`/`LISTENS_ON`：Socket.IO、EventEmitter 等通道检测
- `DATA_FLOWS`：参数到形参映射 + 字段访问链（追踪数据如何流动）
- `SIMILAR_TO`：MinHash + LSH 近似克隆检测
- `SEMANTICALLY_RELATED`：词汇不匹配的语义关联（评分 ≥ 0.80）
- `CROSS_*`：跨代码库的实体链接（gRPC、GraphQL、tRPC 服务检测）

### 4. 语义向量搜索：按含义找代码，不只按名字
内嵌 **nomic-embed-code 768 维 int8 向量**（编译进二进制，无需 API Key/Ollama/Docker），搜索「retry」能找到 `publish`、`emit`、`dispatch`——词汇不同但语义相近的函数。排名融合 **11 种信号**（TF-IDF + API/类型签名 + AST 轮廓 + 数据流 + Halstead 复杂度 + MinHash + 模块距离 + 图扩散等）。

### 5. 变更影响分析 + 增量自动索引
`detect_changes` 工具将未提交的 git diff 映射到受影响符号及其「爆炸半径」，附带风险分类——部署前就知道改动波及了什么。后台 Watcher 线程通过 sha256 + mtime 哈希比对检测文件变更，触发增量索引（仅重新解析变更文件），完成后运行 Louvain 社区发现算法自动生成架构视图。

### 6. 14 个 MCP 工具 + Cypher 查询 + 3D 可视化
提供 `search_graph`、`trace_path`、`query_graph`（只读 openCypher 子集）、`get_architecture`、`get_code_snippet`、`manage_adr`（架构决策记录）、`ingest_traces`（运行时追踪数据接收）等 14 个工具。可选 UI 二进制在 `localhost:9749` 提供交互式 3D 图可视化。

## 技术亮点

### 1. 纯 C 单二进制架构，零依赖无服务器
所有库（yyjson、SQLite、LZ4、tree-sitter 158 语言语法、nomic-embed-code 向量）编译时静态内嵌进一个二进制——不需要 Docker、不需要 Language Server 进程、不需要 API Key。MCP Server 采用单线程事件循环 + stdio JSON-RPC 2.0 协议，Pipeline 异步执行不阻塞响应，Watcher 独立线程监听文件变更，SQLite WAL 模式支持并发读写。

### 2. 知识图谱存储：SQLite + WAL + FTS5 + 预编译语句缓存
每项目独立数据库文件，节点按 Qualified Name（如 `myproject.src.mcp.cbm_jsonrpc_parse`）唯一寻址并支持后缀匹配。FTS5 虚拟表对节点名建全文索引支持正则查询。预编译语句缓存避免重复 SQL 编译开销，实现亚毫秒级查询。Upsert 语义保证幂等性——增量索引不会破坏已有图谱。

### 3. 安全链：SLSA Level 3 + VirusTotal + CodeQL + Sigstore
每次发布经 70+ 杀毒引擎扫描（零检出要求），GitHub Actions 加密构建来源证明（SLSA 3），Sigstore cosign 无密钥签名，CodeQL SAST 阻断存在未解决告警的发布，SHA-256 校验和附随发布——这是工业级安全标准，不是个人项目的松散配置。

```bash

curl -fsSL https://raw.githubusercontent.com/DeusData/codebase-memory-mcp/main/install.sh | bash

Invoke-WebRequest -Uri https://raw.githubusercontent.com/DeusData/codebase-memory-mcp/main/install.ps1 -OutFile install.ps1

# 安装器自动检测并配置所有已安装的 Agent

# "Index this project"
```

## 对比分析

| 维度 | codebase-memory-mcp | Sourcegraph / 传统代码搜索 | LSP（gopls/pyright 等） | AST 工具（Semgrep/SonarQube） |
|------|---------------------|--------------------------|------------------------|-------------------------------|
| **索引速度** | Linux 内核 3 分钟 | 数小时建索引 | 每项目冷启动 30-60 秒 | 规则匹配，无全库索引 |
| **Token 效率** | 5 次查询 ~3,400 Token | 逐文件 ~412,000 Token（120x 差距） | 需启动 LSP 进程 + 逐文件跳转 | 规则匹配不解决探索成本 |
| **语言覆盖** | 158 语言语法 + 9 语言深度语义 | 有限语言索引 | 每语言独立 Server | 有限语言规则集 |
| **部署方式** | 单静态二进制，零依赖 | 需 Docker / 多服务 | 每语言独立进程 + 项目配置 | 需 Docker / 服务部署 |
| **跨服务追踪** | HTTP/gRPC/GraphQL/tRPC/Async | 仅文本搜索 | 单语言内部 | 不支持 |
| **语义搜索** | 内嵌向量，按含义搜索 | 仅关键词/正则 | 不支持 | 仅规则模式 |
| **数据流追踪** | DATA_FLOWS 边（参数→形参→字段链） | 不支持 | 类型推断但无图谱 | 不支持 |
| **安全性** | SLSA 3 + VirusTotal + CodeQL + 本地处理 | 部分需上传代码 | 本地但无供应链安全 | 企业级但需服务部署 |

**核心数据**：在 31 个真实代码库的评测中（arXiv:2603.27277），codebase-memory-mcp 的答案质量达 83%，Token 消耗减少 10 倍，工具调用减少 2.1 倍。5 次典型结构查询的 Token 对比——按模式找函数（200 vs 45,000，225x）、追踪调用链（800 vs 120,000，150x）、死代码检测（500 vs 85,000，170x）、列出路由（400 vs 62,000，155x）、架构概览（1,500 vs 100,000，67x）。
