Understand-Anything

把 20 万行代码变成一张可交互的知识地图。Tree-Sitter + LLM 双引擎 · 多 Agent 流水线 · 15 平台全覆盖 · 业务语义映射。

Understand-Anything 通过 Tree-Sitter 语法解析 + LLM 语义理解 双引擎架构，将任意代码库转化为可交互的知识图谱。每个文件、函数、类都是图谱上的节点，你可以像逛地图一样探索代码。核心理念："Graphs that teach > graphs that impress"——图谱教你理解，而非炫技。

🔧 核心功能

1. 结构化代码知识图谱

运行 /understand 后，5~7 个专用 Agent 流水线自动启动：project-scanner 扫描项目 → file-analyzer 提取函数/类/依赖 → architecture-analyzer 识别架构分层（API/Service/Data/UI/Utility）→ graph-reviewer 验证图谱完整性 → 输出 knowledge-graph.json。Dashboard 以力导向布局（Force Layout）渲染，每个节点可点击查看自然语言摘要和关联关系。

2. 业务领域视图

/understand-domain 调用 domain-analyzer Agent，将技术代码映射到领域 → 流程 → 步骤的横版图。接手遗留系统时，不再困惑"这段代码到底属于哪个业务"。这对于业务与技术之间存在巨大鸿沟的团队尤其有价值。

3. 交互式 Dashboard

/understand-dashboard 启动本地 Web 界面，基于 Zustand 状态管理 + Force Layout 布局引擎。支持节点搜索、按架构层着色、点击查看自然语言摘要和依赖关系。大图谱管理建议使用 git-lfs。

4. Diff 影响分析

/understand-diff 可视化展示改动涟漪效应——一个看似简单的修改实际波及了 3 个 Service 层和 2 个 API 路由。在 PR Review 中彻底改变 Code Review 方式：从凭经验猜测到工具有确证。

5. 知识库分析

/understand-knowledge 分析 Karpathy 模式的 LLM Wiki（Markdown + WikiLinks），将个人知识库转化为可导航的关系图谱。article-analyzer Agent 自动发现你写 Wiki 时未曾意识到的文章间隐含关联。

6. 更多消费方式

角色适配 UI（新人/PM/资深开发者自动调整图谱详细度）、对话式查询（/understand-chat「支付流程是怎么走的？」）、导览模式（/understand-onboard 自动生成新成员学习路径）、深度解读（/understand-explain 文件/函数级别分析）。

🏗️ 核心技术亮点

01
Tree-Sitter + LLM 双引擎混合架构 Tree-Sitter（确定性层）：解析语法树，提取 imports/exports、函数定义、调用点——同样输入永远同样输出。 LLM（语义层）：在语法树基础上生成摘要、分架构层、识别业务域——智能但不影响图谱骨架。即使 LLM 版本升级，图谱结构本身仍然稳定。
02
代码理解"资产化"——从临时推理到持久基础设施 分析结果以 JSON 持久化为 knowledge-graph.json，可提交 Git 仓库、全团队共享。AI 编程助手先读图谱获得全局视图再局部深入源码，避免每次会话都"盲读"。从"单机临时工具"升级为"团队协作基础设施"。
03
增量更新 + 并发批处理 + Monorepo 多平台 file-analyzer 最多 5 并发、每批 20~30 文件。增量更新只分析变更文件，通过 /understand --auto-update 自动触发。pnpm monorepo + Plugin 模式：一套代码适配 Claude Code / Cursor / Copilot / Codex / Gemini CLI 等 15 个平台。

💡 核心差异：Understand-Anything 的独特优势在于语义理解 + 业务映射 + 知识资产化三位一体。不同于 CodeGraph 侧重 Agent 工具调用优化、Sourcegraph 侧重代码搜索，它构建了一条从"代码读不懂"到"团队知识可积累"的完整链路。业务域抽取和 Onboarding 导览是其独有的差异化能力。

👥 适用人群

🎯 强烈推荐

  • 刚入职的开发者：/understand-onboard 自动生成学习路径，上手时间从两周缩短到两天
  • 项目维护者：/understand-diff 快速判断改动影响范围，不再凭经验猜测
  • 技术 Leader：架构展示、团队知识共享，图谱可提交仓库全员使用
  • 开源项目学习者：分析优秀开源项目的代码结构，理解架构设计的精妙
  • AI 编码助手重度用户：先读图谱再局部深入源码，大幅减少 Token 消耗和探索时间

⚠️ 需要评估

  • 小项目（几十个文件）：图谱价值有限
  • 高度动态语言项目（PHP/Ruby）：Tree-sitter 精度有差距
  • 超大型图谱（>5000 节点）：Dashboard 渲染需优化
  • 增量更新 CI 成本：大型 monorepo 需评估每次提交的分析开销
