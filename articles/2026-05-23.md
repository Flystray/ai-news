# ARIS：让 AI 睡着做研究，醒来论文写好了

> GitHub: [wanshuiyin/Auto-claude-code-research-in-sleep](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep) | ⭐ ~9.9k | MIT | 2026年3月创建
> 论文: [arXiv:2605.03042](https://arxiv.org/abs/2605.03042) | 上海交通大学李帅课题组

## 项目背景

当 AI Agent 尝试自主完成长周期科研任务时，最大的问题不是"跑不下去"或"模型能力不够"——而是**"看起来很对，其实全错"**。长时间运行的 Agent 会产生表面合理但证据不完整或暗含执行模型自身预设偏见的结论。这种"虚假合理性"（Plausible Hallucination）是当前自主科研领域的核心瓶颈。

上海交通大学李帅老师课题组（杨若枫、李永灿、李帅）在 2026 年 5 月发布论文《ARIS: Autonomous Research via Adversarial Multi-Agent Collaboration》，提出了一种基于**跨模型对抗协作**的开源自主研究框架。arXiv 上传当天即登上 Hugging Face Daily Papers 第一名。其核心理念直击痛点：**不靠模型自己骗自己，而是让两个不同家族的模型互相对抗，把分歧暴露出来。**

## 核心功能

### 1. 四大端到端工作流

ARIS 封装了从"研究方向"到"终稿论文"的完整科研流程，通过四条串行工作流实现一键式自主研究：

- **Workflow 1 — 创意发现**：文献调研 → GPT-5.4 xhigh 头脑风暴 8-12 个想法 → 新颖性检查 → GPU 试点实验（最多并行 3 个） → 排序报告。命令：`/idea-discovery "your direction"`
- **Workflow 1.5 — 实验桥接**：解析实验计划 → 代码实现 → GPT-5.4 代码审查 → Sanity Check → GPU 部署 → 结果回收。命令：`/experiment-bridge`
- **Workflow 2 — 自动审查循环**：跨模型评分 → 提取行动项 → 触发 GPU 实验 → 修订 → 收敛检查。实测从 5.0/10 提升至 7.5/10（4 轮，8 小时隔夜运行，触发 20+ 次 GPU 实验）。命令：`/auto-review-loop "topic"`
- **Workflow 3 — 论文写作**：Claims-Evidence Matrix → 逐节 LaTeX 生成 → PDF 编译 → 2 轮自动改进（4/10 → 8.5/10）。命令：`/paper-writing "NARRATIVE_REPORT.md"`
- **Workflow 4 — Rebuttal 管线**：解析审稿意见 → 拆问题 → 策略规划 → 起草回复 → 3 道安全检查 → 压力测试 → 定稿。命令：`/rebuttal "paper/" — venue: ICML`

### 2. 跨模型对抗协作

ARIS 的核心创新——**强制执行模型和审查模型来自不同模型家族**。默认配置是 Claude Code 执行 + GPT-5.4 xhigh 审查。为什么必须跨家族？因为同家族模型的盲区高度相似（相同训练数据、相同对齐方法），"自己审自己"形同虚设。Claude 容易批评 GPT 过于啰嗦，GPT 容易质疑 Claude 表达不清——**互相揭短，覆盖单一模型的盲区**。

审查者不只是打分员，更像是拥有"手和眼"的 Senior Researcher：可以自己跑 Executor 写的代码验证是否能跑通，可以自己读数据集验证主张，可以自己写测试用例验证算法。

### 3. 三阶段证据-主张审计级联

保障层是 ARIS 的"真正心脏"，采用级联式三阶段审计：

1. **实验审计**：排查伪标签、幽灵结果、未执行指标、超范围外推
2. **结果到主张映射**：支持度判定（支持 / 部分支持 / 不成立）
3. **全新审查者终审**：不知道前面发生过什么，只看原始结果文件 vs 论文定量主张是否一致

此外还有五轮科学编辑流水线（冗余→主动语态→局部连贯→术语一致→数字一致）、数学证明检查（GPT-5.4 Pro 逐条核验）、PDF 视觉审查、引用三轴核验（存在性 + 元数据 + 论断支持度）。

### 4. Markdown Skills — 零依赖的极简设计哲学

整个系统由 **74 个 Markdown 文件（SKILL.md）** 组成，零框架、零数据库、零 Docker、零守护进程。每个 Skill 是一个可读文件，任何 LLM 都能理解。热替换能力意味着编辑 `.md` 文件无需重启服务，30 分钟即可通读全部 Skill 逻辑。团队将其定位为"方法论，不是平台"——可移植到 Codex CLI、Cursor、Trae、Antigravity、OpenClaw 等任何 Agent。

### 5. 持久化 Research Wiki — 螺旋式累积学习

失败经验进入禁试清单，成功经验进入下一轮起点池。研究不是从头开始，而是在已有知识基础上螺旋上升。配合 Meta-Optimization 外循环，系统分析运行日志自动提出 Skill 改进建议。

### 6. 灵活模型组合与国内适配

支持 9 种以上的执行-审查模型组合，包括全免费方案（ModelScope 2000 次/天）。国内用户可用阿里 Coding Plan 一个 key 调用 Kimi-K2.5 + Qwen3.5+ + GLM-5 + MiniMax-M2.7 四个模型。还有 Zotero（语义搜索 + PDF 注释）、Obsidian（知识库集成）、飞书通知、W&B 实验追踪等集成。

## 技术亮点

1. **"分歧即真相"设计模式**：首次将跨模型对抗作为自主研究的核心架构特征，类比随机 Bandit vs 对抗 Bandit 的理论差异——两人博弈比 n 人博弈更高效地收敛到 Nash 均衡
2. **三层架构（执行层/编排层/保障层）**：执行层用 Markdown Skills 提供原子能力，编排层用 4+1 条工作流串联全流程，保障层用级联审计确保输出可信——三层解耦，每一层可独立替换和扩展
3. **16 个可调旋钮**：difficulty（medium/hard/nightmare）、effort（lite 0.4x / balanced / max 2.5x / beast 5-8x）、reviewer 模型、AUTO_PROCEED 开关等，精粒度控制研究投入与可靠性

## 适用人群

- **ML 研究者**：加速文献调研、想法验证、实验迭代、论文写作全流程
- **博士生 / 博后**：隔夜运行自动审查循环，早上醒来发现弱点已被发现并修正
- **研究组负责人**：统一研究流程，减少人为审阅遗漏
- **AI 工程师**：研究 Skills 系统的极简架构设计范式

## 快速上手

```bash
# 1. 安装 Claude Code 和 Codex CLI
npm install -g @openai/codex
claude mcp add codex -s user -- codex mcp-server

# 2. 克隆并安装 Skills
git clone https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep.git
cp -r Auto-claude-code-research-in-sleep/skills/* ~/.claude/skills/

# 3. 初始化研究 Wiki
claude
> /research-wiki init

# 4. 跑第一个轻量任务
> /research-lit "your research direction" — effort: lite

# 5. 上正式工作流
> /research-pipeline "your direction" — effort: balanced, reviewer: codex
```

**注意**：Workflow 1-2 无需 LaTeX，Workflow 3（论文写作）需安装 LaTeX 环境。国内免费方案可通过 ModelScope 免费层零成本运行。

## 局限性（作者自述）

1. 观察性证据 ≠ 因果证据，不能严格证明跨家族审查一定优于同家族审查
2. 审查者偏好风险：可能优化"审查口味"而非真正科学质量
3. 仓库级审查需把代码给外部 API，本地审查路由仍在规划中
4. 最终责任在人：方向选择、证据核验、提交决定仍需由人负责

---

*ARIS 的真正价值不在"自动写论文"，而在通过跨模型对抗 + 持久 Wiki + 证据-主张审计级联三大机制，解决长程 Agent 的"幻觉信用"问题。*
