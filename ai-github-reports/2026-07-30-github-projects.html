3.4K Star 在本栏目里不算亮眼，但 Rapid-MLX 是那种用架构级优化把一件事做到极致的工程：纯 MLX 内核、连续批处理、量化 KV 缓存、投机解码——很多 vLLM 级别的服务端技术，第一次被系统性搬到 Mac 本地。项目已被阮一峰周刊收录。

项目背景：Ollama 的"够用"，和 M 系芯片被浪费的带宽

在 Mac 上跑本地大模型，Ollama 几乎是默认答案。但它的底层是 llama.cpp——一个为"CPU + 独立显卡"异构体系设计的引擎。而 Apple M 系芯片是统一内存架构（UMA）：CPU 和 GPU 共享同一块内存池，本不需要任何跨总线数据拷贝。用 llama.cpp 的思路跑 M 系芯片，等于给跑车挂了拖拉机的变速箱。

Rapid-MLX 的答案是彻底放弃 llama.cpp：纯 MLX 内核，无回退、无 Metal 垫片。MLX 是 Apple 官方的机器学习框架，为 UMA 原生设计，模型权重直接驻留在共享内存池中做零拷贝张量运算。在这个地基上再叠加连续批处理、量化 KV 缓存（int4/int8 + TurboQuant K8V4 编解码器）、radix 树提示缓存 + DeltaNet RNN 状态快照、DFlash 块扩散投机解码等一整套推理优化。

一个耐人寻味的细节：代码包名至今仍叫 vllm_mlx——这个项目的野心从名字就能看出来：做 Apple Silicon 上的 vLLM。

核心功能

1. 极速推理：实测数据全公开

官方基准（M3 Ultra，Qwen3.5-9B）：Rapid-MLX 108 tok/s，Ollama 46 tok/s，上游 mlx-lm 62 tok/s——比 Ollama 快 2.3 倍，比 Apple 自家 mlx-lm 快 1.7 倍。GPT-OSS-20B 上优势拉大到 4.2 倍（127 vs 79 tok/s）。16GB MacBook Air 跑 Qwen3.5-4B 可达 160 tok/s（仅占 2.4GB 内存）。还提供 rapid-mlx bench --submit 提交数据到公开天梯榜。

2. 提示缓存：多轮对话"免费重启"

为 Transformer 维护 KV 缓存，为 Qwen3.5 这类混合架构额外记录 DeltaNet 状态快照：Devstral-24B 的 TTFT 从 0.38s 降到 0.13s（2.9 倍）；Qwen3-Coder-Next 从 0.66s 降到 0.16s（4.3 倍）；Kimi-Linear-48B 缓存命中低至 0.08 秒——几乎无感。

3. 17 种工具调用解析器 + 11 个 Agent CLI 实测认证

每家模型的 function calling 格式都不一样（Qwen、Hermes、GLM、MiniMax……）。Rapid-MLX 内置 17 种模型专属解析器，按等级维护兼容矩阵：Tier-1（Claude Code、Codex CLI、Hermes、Aider）每版本端到端重验；Tier-2 覆盖 OpenCode、GitHub Copilot、Kimi Code 等 7 个。工具调用"降级为纯文本"时还能自动恢复解析。

4. OpenAI + Anthropic 双协议

实现 /v1/chat/completions、/v1/responses（Codex）、/v1/messages（Claude Code）、/v1/embeddings、/v1/audio/*、/v1/videos。一条 rapid-mlx launch claude-code 自动改写配置，把 Claude Code 路由到本机模型。LangChain、PydanticAI、smolagents 均做在线验证。

5. 全模态：视觉、音频、视频、嵌入

基础安装仅 460MB（纯文本），按需扩展视觉（Qwen-VL）、音频 STT/TTS（26 个别名）、甚至 LTX-2.3 文生视频。DeepSeek V4 Flash Day-0 支持——158B-A13B MoE 在 128GB Mac Studio Ultra 上以 2bit 量化跑出 56 tok/s，支持 1M 上下文。

6. 一条命令分享到公网

rapid-mlx share qwen3.6-27b-8bit 内置 HTTPS 隧道，把 Mac Studio 上的模型安全暴露给远程设备——家里的 Mac 变成团队的私有推理服务器。

技术亮点

1. 自动配置引擎："模型指纹识别"

DeepWiki 架构解析显示，detect_model_config 会检查模型元数据，自动选择正确的 tool_call_parser 和 reasoning_parser，自动应用缓存与量化策略。用户只需 rapid-mlx serve qwen3.5-9b，复杂度被引擎吃掉——这是它比裸用 mlx-lm 体验好一个量级的原因。

2. 流式推理分离：<think> 标签实时路由

针对 DeepSeek-R1、Qwen3 等推理模型，StreamingPostProcessor 与 StreamingThinkRouter 在流式生成中实时剥离特殊 token，把思维链路由到 reasoning 字段、正文路由到 content 字段——客户端拿到结构化的"思考/回答"分离输出。

3. DFlash 投机解码：按家族验证，拒绝"静默出错"

块扩散投机解码在 Qwen3.5/3.6 27B 上实测带来 1.31-1.49 倍吞吐增益。工程态度值得称道：opt-in 且按模型家族逐个验证——因为错误应用投机解码会产生"没有报错的错误输出"，这种克制在追求跑分的推理引擎里很稀缺。

适用人群

  • Mac 上跑本地模型、嫌 Ollama 慢的开发者：改一个 URL 即可迁移，速度翻 2-4 倍
  • Claude Code / Cursor / Aider 重度用户：0.08 秒 TTFT，隐私代码不出本机、零 token 费用
  • 本地 Agent 开发者：17 种工具解析器 + 双协议兼容，function calling 稳定性是核心卖点
  • 大内存 Mac Studio 团队：share 命令一键变身私有推理服务器，122B 级模型也能跑
  • MLX 生态研究者：连续批处理、量化 KV、投机解码的 MLX 实现是极好的学习样本

快速上手

# 方式一：一键安装（自动检测内存并推荐模型）
curl -fsSL https://rapidmlx.com/install.sh | bash

# 方式二：Homebrew
brew install rapid-mlx

# 启动服务（16GB Mac 推荐）
rapid-mlx serve qwen3.5-4b-4bit

# 任何 OpenAI 客户端直接调用
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "qwen3.5-4b", "messages": [{"role": "user", "content": "你好"}]}'

# 一键接入 Claude Code
rapid-mlx launch claude-code

内存选型：8-23GB 跑 4B 级、24-47GB 跑 20B 级、48-95GB 跑 35B 级、96GB+ 可上 120B 级。

一句话总结：Ollama 赢在生态和跨平台，Rapid-MLX 赢在 Apple Silicon 上的绝对性能和 Agent 工程化。M 系 Mac + 编码助手场景几乎是无脑升级；需要跨平台或长尾模型仍选 Ollama。两者并不互斥。

局限：仅支持 Apple Silicon；模型库长尾覆盖不如 Ollama；项目仅 5 个月、迭代极快，API 可能变动；官方基准均为自测数据。

写在最后

第一，"平台专用"是性能的杠杆，不是包袱。Ollama 用一套 llama.cpp 通吃三平台，代价是任何平台都拿不到极致性能；Rapid-MLX 反其道而行，赌注全押 Apple Silicon 的统一内存架构，换来 2-4 倍的性能差距。敢于收窄目标平台反而打开了优化空间。

第二，本地推理的竞争焦点正在从"能跑"转向"好用"。裸速度只是入场券，真正的护城河是那些"脏活"：17 种工具调用格式的逐一适配、11 个 Agent CLI 的端到端回归测试、投机解码的按家族验证。谁能让 Claude Code 无感切换到本地模型，谁就抓住了下一波端侧 AI 的入口。

如果你手上有一台 M 系 Mac，花 5 分钟装一个试试——brew install rapid-mlx，你可能会重新认识这台机器的算力。
