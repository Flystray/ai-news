# AgentMemory：让 AI 编程 Agent 拥有真正可搜索的持久记忆

> AI 编程助手每次新会话都会"失忆"——你需要反复解释项目架构、编码规范、之前修复过的 Bug。AgentMemory 是一个专为编码 Agent 设计的持久记忆引擎，基于真实基准测试排名第一，让 Claude Code、Cursor、Codex 等工具拥有跨会话、跨工具的统一记忆。

## 项目背景

2026 年，AI 编程 Agent（Claude Code、Cursor、GitHub Copilot、Codex CLI 等）已成为开发者的日常工具。但它们都有一个共同的痛点：**上下文窗口是临时的**。每次新会话开始，Agent 就忘记了一切——你不得不反复解释项目约定、历史决策、踩过的坑。各 Agent 提供的"记忆"方案（Claude Code 的 MEMORY.md、Cursor 的 Notepad、Cline 的 Memory Bank）本质上是便签式存储，既不可搜索，也无法跨工具共享。

**AgentMemory**（rohitg00/agentmemory）正是为解决这个问题而生。它于 2026 年 2 月创建，TypeScript 编写，Apache-2.0 许可证，目前已获得 **20,700+ GitHub Stars**。项目的核心理念是：**将 Karpathy 的 LLM Wiki 模式工程化**，加入置信度评分、生命周期管理、知识图谱和混合搜索，打造一个真正可搜索、可检索、可跨 Agent 共享的持久记忆系统。

## 核心功能

### 1. 四层记忆整合架构（4-Tier Memory Consolidation）

AgentMemory 不是简单地把所有信息平铺存储，而是模仿人类记忆系统，设计了四层递进式记忆架构：

| 记忆层级 | 存储内容 | 解决的问题 |
|----------|----------|------------|
| **Working（工作记忆）** | 工具调用产生的原始观测 | 保留最接近现场的短期数据 |
| **Episodic（情节记忆）** | 压缩后的会话摘要 | "上一次发生了什么？" |
| **Semantic（语义记忆）** | 抽取的事实、模式与稳定知识 | "这个项目长期成立的事实是什么？" |
| **Procedural（程序记忆）** | 工作流、决策套路与可复用做法 | "这类事情通常怎么做？" |

信息在不同层级间逐步沉淀：原始观测被压缩为结构化事实和情节叙事，记忆会衰减、强化、自动淘汰，系统还能处理陈旧记忆和矛盾事实的冲突。

### 2. 三路混合检索（BM25 + Vector + Knowledge Graph）

AgentMemory 的检索不是单一方式，而是融合三路信号后通过 **Reciprocal Rank Fusion（RRF）** 统一排序：

- **BM25 关键词检索**：精确匹配文件名、函数名、术语
- **Vector 语义检索**：捕捉语义相似度，支持本地 embedding（all-MiniLM-L6-v2），零 API 成本
- **Knowledge Graph 关系遍历**：基于实体关系做图遍历推理

这种设计的优势非常直观：当你搜索 "database performance optimization" 时，BM25 关键词召回率为 0%，而向量检索直接拉到 40%。两种方式互补而非替代。

### 3. 12 个自动 Hooks + 53 个 MCP 工具

AgentMemory 通过 12 种生命周期事件（PostToolUse、SessionStart、SessionEnd 等）**自动捕获** Agent 行为，无需手动调用记忆 API。配合 53+ 个 MCP 工具、6 个 Resource、3 个 Prompt 和 4 个 Skill，覆盖了记忆的存、查、删、改、导出全链路。

### 4. 跨 Agent 统一记忆库

所有 Agent（Claude Code、Cursor、Codex CLI、GitHub Copilot CLI、Gemini CLI、Hermes、OpenClaw 等）共享**同一个记忆服务器**。你在 Claude Code 中积累的项目知识，切换到 Cursor 时同样可用。这打破了工具孤岛，让记忆成为基础设施而非 Agent 的附属品。

### 5. 实时 Viewer + iii Console 双调试入口

AgentMemory 提供两个可视化入口：**Viewer**（localhost:3113）用于查看会话、记忆、图谱和健康仪表盘；**iii Console**（localhost:3114）用于函数级执行追踪、流处理监控和 KV 状态检查，支持完整的 OTEL 可观测性链路。

### 6. Token 效率优化

传统方案（如 MEMORY.md）把历史记忆全量塞进上下文，Token 消耗随时间线性膨胀。AgentMemory 采用"按需召回"策略：

| 观测量 | MEMORY.md Token | AgentMemory Top-10 Token | Token 节省率 | MEMORY.md 可达率 |
|--------|----------------|-------------------------|------------|-----------------|
| 240 条 | 12,000 | 3,142 | 74% | 83% |
| 1,000 条 | 50,000 | 3,142 | **94%** | 20% |
| 5,000 条 | 250,000 | 3,142 | **99%** | 4% |

关键发现：当历史记忆积累到 1,000 条以上时，MEMORY.md 只能覆盖 20% 的历史，而 AgentMemory 始终保持 100% 可达率，同时节省 94%+ 的 Token。

## 技术亮点

### 基于 iii-engine 的运行时架构

AgentMemory 本身就是一个 iii 运行时实例。iii-engine 提供三大核心原语：**HTTP Triggers**（事件驱动）、**KV State**（持久化状态）、**Streams**（数据流处理），并支持通过 Worker 扩展模块添加定时任务（cron）、可观测性（otel）、重试队列（queue）和数据库后端（database）。这种架构使得 AgentMemory 既是记忆引擎，也是一个可扩展的事件驱动运行时。

### 学术级基准测试

AgentMemory 在两个基准测试上展示了量化效果：

**内部基准 Coding-Agent-Life-v1**：Hybrid 检索的精确率（P@5）达到 0.578，是 grep（0.267）的 **2.2 倍**，召回率持平（96.7%），延迟仅 14ms。

**学术基准 LongMemEval-S**（500 题，约 115K tokens）：

| 系统 | R@5 | R@10 | NDCG@10 | MRR |
|------|-----|------|---------|-----|
| agentmemory (Hybrid) | **95.2%** | **98.6%** | **87.9%** | **88.2%** |
| agentmemory (BM25-only) | 86.2% | 94.6% | 73.0% | 71.5% |

Hybrid 检索相比纯 BM25，R@5 提升 9 个百分点，MRR 提升 16.7 个百分点。

### Circuit Breaker + Fallback Chain 生产级设计

系统内置断路器机制（3 次失败触发熔断）和回退链，确保 LLM 摘要、embedding 生成等外部依赖异常时，核心记忆存取不受影响。827 个通过的测试用例为可靠性提供了工程保障。

## 竞品对比

| 维度 | AgentMemory | Mem0 | Letta (MemGPT) | Claude-Mem |
|------|------------|------|----------------|------------|
| **定位** | 编码 Agent 记忆引擎 | 通用记忆平台 | Stateful Agent 平台 | Claude Code 专用记忆 |
| **存储方式** | 本地，零外部依赖 | SDK/API/Cloud | 内置于 Agent 运行时 | 本地 Markdown |
| **检索方式** | BM25+向量+图谱 RRF | 向量检索为主 | 向量检索 | 全文搜索 |
| **跨 Agent** | 所有 Agent 共享记忆 | 应用级共享 | Agent 内部 | 仅 Claude Code |
| **集成成本** | 低（MCP 即插即用） | 中（需 SDK 接入） | 高（需切换 Agent 运行时） | 低（Claude Code 原生） |
| **适合场景** | 多工具编码工作流 | 面向用户的 AI 应用 | 长期运行的自改进 Agent | 单一 Claude Code 工作流 |

**选型建议**：如果你日常在多个 AI 编码工具间切换，AgentMemory 是最合适的选择——不需要换掉现有 Agent，只需加一层记忆基础设施。如果你做的是面向终端用户的 AI 产品（客服、个性化助手），Mem0 的 SDK/API 更顺手。如果需要 Agent 自主学习和改进，Letta 提供了更完整的 Agent 运行时。

## 适用人群

- **多工具开发者**：在 Claude Code、Cursor、Codex 之间频繁切换，希望保持一致的上下文记忆
- **大型项目维护者**：项目决策多、规范复杂，需要 Agent 记住长期约束
- **AI Agent 开发者**：为自己的 Agent 产品集成持久记忆能力（MCP 协议标准接入）
- **效率极致追求者**：减少重复解释，让每一轮对话都高效利用已有知识

## 快速上手

```bash
# 安装（Node.js >= 20）
npm install -g @agentmemory/agentmemory

# 启动记忆服务器（默认 :3111）
agentmemory

# 另一终端：导入演示数据验证
agentmemory demo

# 打开实时 Viewer
# 浏览器访问 http://localhost:3113
```

**Claude Code 深度集成**（推荐方式）：

```bash
# 终端 1：启动完整服务
agentmemory

# 终端 2：在 Claude Code 中安装插件
# Claude Code 内执行：
npx skills add rohitg00/agentmemory -y
```

安装后自动注册 12 个 hooks + 4 个 skills + MCP 连接，无需手动配置。

**Cursor / Cline / Gemini CLI 等 MCP 客户端**：

在 MCP 配置中添加：

```json
{
  "mcpServers": {
    "agentmemory": {
      "command": "npx",
      "args": ["-y", "@agentmemory/mcp"]
    }
  }
}
```

注意：纯 MCP 模式无 hooks，记忆需手动存取，无法自动捕获。
