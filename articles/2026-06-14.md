**MinerU** 由**上海人工智能实验室 OpenDataLab 团队**开源（2024年7月首发），核心定位是将 PDF、图片、DOCX、PPTX、XLSX 等非结构化文档**一站式转换为结构化 Markdown/JSON**，专为 LLM 训练和 RAG 场景优化。项目在 GitHub 收获 **67,454 Stars**，是中文开源社区中 Star 数最高的文档解析项目，也是 2025 年 CVPR 发表的 OmniDocBench 评测基准的创建者。

## 核心功能

### 1. 多后端协同架构，精度与速度兼得

MinerU 采用四类后端协同设计，用户无需理解底层差异，系统自动选择最优路径：

- **Pipeline 后端**：多模型流水线（布局检测→OCR→公式识别→表格识别），纯 CPU 可运行，速度最快，适合常规文档
- **VLM 后端**：基于 1.2B InternVL 架构的视觉语言模型，单模型覆盖多语言/布局/表格/公式/阅读顺序，精度最高
- **Hybrid 后端**（3.0 默认）：文本 PDF 直接提取（零幻觉）+ 扫描 PDF 用 VLM 解析，兼顾精度与效率
- **Office 原生后端**：DOCX/PPTX/XLSX 直接解析，无需经 PDF 渲染，**速度比 PDF 路径快数十倍**

### 2. 1.2B 参数的文档理解 VLM

MinerU 2.5 的核心模型基于 **InternVL 架构**（非 Qwen-VL），在结构化信息提取和细粒度视觉定位上有先天优势。两阶段推理流水线将布局分析与内容识别解耦，配合原生高分辨率架构，以 1.2B 参数实现了：
- **OmniDocBench 86.2 分**（Pipeline 后端），超越前代 0.9B VLM
- 文档类任务准确率比 Phi-3-vision、TinyLLaVA 等**高出 18%+**
- PubLayNet 布局检测 F1 值达 **92.3%**

### 3. 复杂元素的精准还原

- **数学公式**：双阶段模型（MFD 检测 + MFR 识别），输出 LaTeX 格式，支持中英混合公式、行间公式编号
- **表格解析**：区分有线/无线表格，支持旋转表格、跨页续表合并、表格内嵌图片/公式，输出 HTML 嵌入的 Markdown

### 4. 企业级部署与高并发

3.0 版本实现了从工具到基础设施的跃迁：

## 技术亮点

### 🔬 InternVL 架构的文档专用优化

MinerU 2.5 选择了 InternVL 而非更流行的 Qwen-VL 作为 VLM 基座，核心原因是 InternVL 在**结构化信息提取**和**细粒度视觉定位**上的天然优势——这正是文档解析的核心需求。Qwen-VL 更偏开放域问答和图像描述，而 InternVL 的视觉-语言对齐机制天然适合区域分割、单元格识别、公式语义解析等结构化任务。

### 🏗️ Hybrid 后端的"零幻觉"设计

3.0 默认的 Hybrid 后端是一个精妙的设计：对于文本型 PDF，直接提取文本而非经过 VLM 推理，从根本上**消除幻觉风险**，同时速度极快；对于扫描型 PDF，才启用 VLM 解析。这种"能直接取就不推理"的策略，在保证精度的同时大幅降低了计算成本和幻觉概率。

### ⚡ Office 原生解析的数十倍加速

传统文档解析工具处理 DOCX 时，通常先转为 PDF 再解析，既丢失原生格式信息又浪费时间。MinerU 3.0 直接解析 Office 文档原生格式，速度提升数十倍，精度也更高——这是一个被多数竞品忽略的技术路径。

## 快速上手

```bash
# 一键安装（含所有后端）
uv pip install mineru[all]

# 最简单的使用：单文件解析
mineru -p paper.pdf -o ./output

# 指定 Hybrid 后端（3.0 默认）
mineru -p document.pdf -o ./output --backend hybrid-auto-engine

# Python SDK
from mineru import do_parse
result = do_parse("paper.pdf", output_dir="./output")

# API 服务（生产部署）
mineru-api --host 0.0.0.0 --port 8000

# 多 GPU 负载均衡
mineru-router --workers http://gpu0:8000,http://gpu1:8000
```

最低要求：Python 3.10+，纯 CPU 即可运行 Pipeline 后端；VLM 后端推荐 8GB+ 显存 GPU。
