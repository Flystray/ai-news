📌 项目背景：同样的预算，更高的智能密度

AI Agent 成本和质量的零和博弈——OpenClaw 固定配置跑强模型，简单问候也按推理 Token 计费；Hermes Agent 关键词+字数粗糙判断难度，只有一条省钱链路。主流框架要么全程"专车接送"，要么省钱逻辑硬编码。

OpenSquilla 的核心命题：同样的预算，更高的智能密度。LightGBM 分类器实时判断 prompt 难度→简单坐公交、复杂叫专车；四层认知记忆积累上下文；MetaSkills 自进化协议让 Agent 自己长能力；系统调用级安全沙箱不依赖 Docker。微内核架构：百行级核心编排器，所有能力插件接入，崩溃不影响核心。3 周星数从 1k→3k+，Apache-2.0 开源，完整中文支持。

🚀 核心功能

🔀 SquillaRouter 智能路由

LightGBM+ONNX 双引擎推理管道，c0(极简)→最廉价模型、c1(低)→flash、c2(中等)→平衡、c3(高)→强推理模型。混合手工+嵌入语义特征多维度判断。情绪升级机制遇抱怨词自动升tier。思维深度分级：简单问题不收推理Token。60-80%成本节省

🧠 四层认知记忆

Working(TurnContext即时)→Episodic(SQLite时序因果)→Semantic(sqlite-vec向量索引)→Raw(MEMORY.md事实之源)。热门记忆冒泡晋升，冷门沉底。时间指数衰减，永久知识不受影响。混合检索：向量+FTS5关键词双管齐下，向量低分自动兜底

💤 Dream 整合

每24h让AI"做梦"——Phase1: LLM分析transcript提取常青事实；Phase2: 子Agent精确编辑MEMORY.md。从volatile→persistent→semantic的分层升华，像睡眠巩固一样整理记忆

💡 技术亮点

🔍 SquillaRouter V4Phase3 三级管道

用户 Prompt → Channel Adapter → TurnRunner 管道
Step 1: Context Assembly → 收集消息+路由历史+上下文Token数
Step 2: InferenceCore → LightGBM(lgbm_main.bin) + ONNX 双引擎推理
Step 3: Post-Processing → 概率向量推导 thinking_mode(T0-T3) + prompt_policy(P0-P2)

低置信度时注入策略指令如 [RESPONSE_POLICY: Answer directly]。ML资产缺失时回退 _unavailable_classify，默认安全 tier c1 + 日志警告——从不崩溃，只是降级。情绪升级：用户说"wrong""redo"等抱怨词→自动升 tier 确保高质量修正。

🧠 记忆分层与 Dream 整合的工程实现

Markdown 是知识事实之源，MemorySyncManager 跟踪 hash+mtime 持 SQLite 索引同步。向量存储前 L2 归一化确保 cosine 精度。SessionFlushService 把 transcript 转入 archives，原始 fallback 不进语义索引防污染。Dream 两阶段：Phase1 LLM 分析提取 → Phase2 子 Agent 精确编辑 + session locking 防并发。这是认知科学"睡眠巩固"的工程化实现。

📊 微内核可观测性与合规审计

决策日志存 hash 不存原文——天然合规审计，管线每个环节强制留痕。每次调用自带实付金额+额度钩子用超自动断流。成本追踪是运行时内嵌，不是事后统计——Agent 用超预算自动停止。扩展开发：5 行 duck-typed 类，无基类/manifest/发包，崩溃不影响核心。
