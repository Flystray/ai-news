2025 年底，Mads Lorentzen 的地球物理学家职位被裁掉了。他没有马上海投简历，而是花了三个月用 Claude Code 给自己搭了一套完整的求职自动化框架——`/scrape` 搜岗位、`/apply` 改简历写求职信、`/interview` 备面试。每周跑一遍，69 份定制化申请、20 次初面、1 份签约合同。2026 年 6 月，他正式以 AI 工程师身份入职。

他把这套工具开源了，叫 **ai-job-search**。四个月不到，27.1k Star，8.8k Fork——因为每一个找过工作的人都知道，求职最累的不是面试，是那无穷无尽的重复。

## 项目背景：为什么"AI 写简历"远远不够？

市面上不缺"AI 简历工具"——把你的名字和岗位标题丢进模板，生成一份看起来还行的 PDF。但真正用过的人都知道三个致命痛点：

1. **表面定制，实为填空**：写出"针对这个特定岗位、突出这段真实经历、规避那个经验短板"的简历，绝大多数工具做不到；
2. **ATS 系统把 PDF 读成乱码**：你精心排版的 LaTeX 简历投进 Workday/Lever 后，联系方式变成方块字、bullet 列表消失、多列布局读出火星文——因为 ATS 读的是 PDF 文本层，不是渲染效果；
3. **AI 文案一眼可辨**：单次 LLM 生成的求职信听起来专业但空洞，招聘经理一天看 50 封，秒识别。

ai-job-search 不是又一个聊天壳子。它把 Claude Code 变成一个**结构化的求职运营系统**：从个人画像建模、岗位发现与评分、到 LaTeX 简历起草-审查-修订-编译-ATS 验证，形成完整闭环。

## 核心功能：13 条 Slash 命令构成的求职流水线

### 三大核心命令

**1. `/setup` — 个人画像建模**

提供三条路径自动检测你有什么：读取 `documents/` 文件夹（CV PDF、LinkedIn 导出、学历证书、推荐信）、粘贴单份简历进对话、或走结构化访谈。生成的资料存储在 7 个 Markdown 文件中，涵盖教育经历、工作经验、技能、行为性格评估（PI/DISC）、写作风格偏好、求职契合度评分框架、LaTeX 模板和 STAR 面试素材。这不是一个 5 分钟表单——想得到有区分度的产出，预计花 30 分钟以上。

**2. `/scrape` — 多门户岗位搜索与去重**

协调 6 个 TypeScript CLI 代理搜索求职门户（Jobindex、Jobnet、Jobbank、Jobdanmark、LinkedIn 公共端点、freehire.me），使用 `seen_jobs.json` 去重，结果按契合度排序后记录到 `job_search_tracker.csv`。结果太多时用 `/rank` 批量并行评分——5 个维度（技能匹配、经验相关性、文化契合、地点匹配、职业轨迹逻辑），返回带诚实优势和差距的排名短名单。

**3. `/apply <url>` — 起草者-审查者工作流**

这是整个框架最硬核的部分，8 步状态机：

1. 解析职位发布（URL 或粘贴文本）
2. 评估五维契合度
3. 起草定制 LaTeX 简历和求职信
4. 生成审查者代理（全新上下文，独立研究公司后批评草稿）
5. 起草者根据审查反馈修订
6. 编译 PDF（简历用 `lualatex`，求职信用 `xelatex`），Claude 视觉检查渲染页面并迭代 LaTeX，直到简历恰好 2 页无孤行标题、求职信恰好 1 页签名可见
7. ATS 验证：用 `pdftotext` 提取 PDF 文本层，验证联系方式可读、无乱码、阅读顺序合理，评分关键词覆盖率——**资料真正支持的关键词才添加，真正的差距保持可见，绝不填充**
8. 呈现带验证清单的最终输出

### 扩展命令矩阵

| 命令 | 功能 |
|------|------|
| `/interview` | 构建阶段特定准备包，研究公司和面试官，STAR 例子映射，模拟面试。诚实桥接知识差距，绝不编造经验 |
| `/outcome` | 记录申请结果（面试/录用/拒绝/沉默），归档已提交材料。`/outcome followup` 变体起草跟进邮件（仅起草不发送） |
| `/expand` | 扫描 GitHub、作品集、Kaggle、Google Scholar 等公开来源丰富能力画像 |
| `/upskill` | 分析资料与岗位需求差距，生成技能热图和学习计划 |
| `/rank` | 批量并行评分所有抓取结果，返回排名短名单 |
| `/add-template` | 注册自定义 LaTeX 简历/求职信模板 |
| `/add-portal` | 为任意本地招聘网站生成搜索技能——自动摸清搜索 URL 规律、结果结构、访问规则 |
| `/html-report` | 生成自包含 HTML 仪表板，统计卡片+漏斗图表+可过滤申请表 |
| `/gmail-sync` | 读取 Gmail 获取申请状态信号，批量提议更改（不自动写入） |
| `/notion-sync` | 发布只读管道视图到 Notion 数据库 |

## 技术亮点

### 1. 起草者-审查者对抗架构

这是项目爆火的真正原因。单个 LLM 生成求职信，产出专业但空洞——招聘经理一眼识别。ai-job-search 的解法是：第一个 Claude 代理起草，第二个代理以**全新上下文**生成——它对草稿没有"忠诚度"，像招聘经理一样怀着敌意阅读，检查是否真正回应了公司的具体挑战（而非岗位标题）、CV 是否强调了正确项目（而非最亮眼的项目）、是否有超出资料支撑的夸大声明。起草者随后修订。

这个模式可以推广到任何高风险 agent 场景——合同起草、基金申请、客户提案——都能受益于第二个代理的对抗性审查。

### 2. PDF 验证循环 + ATS 文本层诚实检查

系统不只是生成 LaTeX 然后交给你编译——它自己编译、自己看渲染结果、自己修。简历必须恰好 2 页无孤行标题，求职信必须恰好 1 页签名可见。然后提取 PDF 文本层验证 ATS 可读性：联系方式作为字面文本存在、无乱码字形、合理阅读顺序、关键词覆盖率评分。**关键设计：资料不支持的关键词被承认为差距，绝不填充。** 这是"帮你申请的 AI"和"替你撒谎的 AI"的本质区别。

### 3. 安全加固：职位发布视为不受信任输入

工作流不遵循职位发布中嵌入的指令，不从其正文中获取链接——针对 `/apply` 和 `/rank` 的提示注入加固。审查者研究约束于用户确认的公司身份。写作风格验证规则收紧到独立定位的来源。`.gitignore` 忽略任何深度的抓取器状态和面试记录，防止在公共 fork 上泄露隐私。

## 适用人群

- **正在求职的人**：想把重复的申请流程自动化，但要的是"能真投出去"而非"看着像"的简历
- **投海外岗位的人**：尤其丹麦/北欧市场（自带 4 个门户），其他国家可用 `/add-portal` 自定义
- **Claude Code 用户**：想探索 agent skill 在非代码场景的落地模式
- **Agent 架构师**：起草者-审查者对抗模式、验证门控、市场插件化——这里有可直接借鉴的工程范式
- **职业转型者**：`/upskill` 的技能差距分析和学习计划功能，帮助系统化规划转型路径

## 快速上手

```bash
# 1. Fork 并克隆
gh repo fork MadsLorentzen/ai-job-search --clone
cd ai-job-search

# 2. 安装求职搜索工具（以 jobindex-search 为例）
cd .agents/skills/jobindex-search/cli && bun install && cd ../../../..

# 3. 进入 Claude Code 录入资料
claude
# 在 Claude Code 内执行：
/setup

# 4. 搜索岗位
/scrape

# 5. 申请（URL 或粘贴 JD 全文）
/apply https://jobindex.dk/job/1234567
```

**前置依赖**：Claude Code (CLI)、Python 3.10+、Bun、LaTeX 发行版（需 `lualatex` 和 `xelatex`）、可选 `pdftotext`（poppler，用于 ATS 检查）。

**关键提示**：资料深度决定一切。别只写职位名称——要写具体做了什么、用了什么工具、有什么可量化成果。"用 Python 和 scikit-learn 为客户流失预测构建 ML 管道"远胜于"Python，机器学习"。

## 对比分析

| 维度 | ai-job-search | ChatGPT/Claude 直接生成 | 专业简历工具（如 Teal, Rezi） |
|------|--------------|----------------------|--------------------------|
| **定制深度** | 五维契合度评估 + 相关性加权切割 | 岗位标题填空 | 关键词匹配 |
| **输出格式** | LaTeX → PDF 编译 + 视觉验证循环 | 纯文本 / 简单 PDF | 在线编辑器导出 |
| **ATS 验证** | pdftotext 文本层提取 + 关键词覆盖率评分 + 诚实差距标记 | 无 | 部分有基础检查 |
| **审查机制** | 独立审查者代理，全新上下文对抗批评 | 单次生成，无审查 | 人工自查 |
| **岗位搜索** | 6 门户并行抓取 + 去重 + 批量评分 | 无 | 部分集成 |
| **面试准备** | 阶段特定准备包 + STAR 映射 + 模拟面试 | 可对话但无结构化素材 | 基础题库 |
| **可扩展性** | `/add-portal` + `/add-template` 插件化 | 不可扩展 | 封闭系统 |
| **隐私** | 全部本地运行，数据不离开你的机器 | 数据上传云端 | 数据上传云端 |
| **成本** | Claude Code API 费用（按 token） | 订阅制 | 订阅制 $10-30/月 |
| **作者验证** | 69 申请 → 20 面试 → 1 录用（真实数据） | 无 | 营销话术 |

ai-job-search 最本质的区别在于：它把求职材料视为**对抗性文档**而非表格填空。每一份简历和求职信都要经过"另一个 agent 假装是招聘经理来找茬"的审查环节，然后才允许输出。这种设计哲学在 AI 求职工具领域是罕见的——大多数工具的目标是让你"快速生成"，而这个项目的目标是让你"经得起审查"。

## 写在最后

Mads Lorentzen 的故事之所以打动人，不仅是因为他成功找到了工作，更因为他把一个普遍的痛苦——求职中的无意义重复——变成了一个可编程的工程问题。他是地球物理学家，不是软件工程师，但 Claude Code 让他能把自己的领域知识（知道什么样的求职材料有效）转化为结构化的 agent 工作流。

这个项目也预示了一个更大的趋势：AI agent 的价值不在于"替你做你能做的事"，而在于"把你独有的专业判断编码成可复用的系统"。每一个行业、每一个职能里，都有人掌握着难以言传的经验——这些经验现在可以被 agent 承载和放大。
