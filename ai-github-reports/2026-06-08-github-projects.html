Headroom

AI Agent 上下文可逆压缩层。Token 减少 60-95%，答案一字不差。Library · Proxy · MCP · 6 种压缩算法 · 本地优先 · 完全可逆。

Headroom 在 AI Agent 调用 LLM 之前，把 prompt 里的工具输出、日志、RAG chunks、文件内容进行智能压缩。Token 减少 60-95%，但答案质量完全不变——因为它不是有损截断，而是可逆压缩。CCR 系统确保 原始内容永不丢失，LLM 随时可以取回。

🔧 核心功能

1. 四合一接入形态

模式命令代码改动适用场景
Agent Wrapheadroom wrap claude零已有编码 Agent
透明代理headroom proxy --port 8787改环境变量不想改代码
Library SDKcompress(messages)1 行自研 AI 应用
MCP Serverheadroom mcp install1 行配置MCP 客户端

2. 三路专用压缩引擎

输入内容
→
ContentRouter 类型检测
→
SmartCrusher JSON (Rust)
CodeCompressor AST
Kompress-base ML (8B)

不同内容走不同压缩器——不让 LLM 总结 JSON，规则压缩比模型生成更高效、更稳定、零幻觉风险。

3. CCR 可逆压缩系统

压缩后的原文 永不删除，存储在本地磁盘。LLM 需要细节时调用 headroom_retrieve(ref_id)，直接从本地取回原文——零 API 调用成本、零延迟。

4. CacheAligner · 账单降幅 20×

稳定 prompt 前缀，最大化 Anthropic/OpenAI 的 KV cache 命中率。cache 命中 vs 未命中有 10 倍成本差距，CacheAligner 让 token 压缩和 cache 命中协同增效。

5. 跨 Agent 共享记忆

Claude Code、Cursor、Codex 共用的上下文去重后跨 Agent 共享。后续 Agent 可节省 40-60% 的初始扫描 token。

6. headroom learn · 自学习改进

扫描失败 session，自动将 "哪条命令错了、为什么错" 写入 CLAUDE.md，Agent 越用越聪明。

🏗️ 技术架构

01
ContentRouter — 内容类型智能分发 JSON → SmartCrusher | 代码 → CodeCompressor | 自然语言 → Kompress-base。通过 json.loads + 文件扩展名 + shebang 匹配做多信号类型判断，不做"统一 LLM 处理"的省力捷径。
02
CCR — 完整可逆架构保障 原始内容存入 CompressionStore（本地），压缩后生成短哈希 ref_id。LLM 可主动调用 headroom_retrieve 取回原文，信息精度 100%，展开成本为零。这是 Headroom 敢于追求 90%+ 压缩率的底气。
03
Rust 核心 + TOIN 联邦学习 SmartCrusher / Tokenizer / Relevance Engine 用 Rust 重写，压缩延迟 <50ms。TOIN 通过结构指纹和联邦学习跨用户共享压缩模式，但不共享原始数据，隐私保护到位。

👥 适用人群

🎯 强烈推荐

  • AI 编码助手重度用户：每天使用 Claude Code / Cursor / Codex，token 消耗大
  • LLM 应用开发者：月 API 支出 > $20，希望系统性降低成本
  • 多 Agent 协作场景：同项目多人多 Agent 并行开发，需要共享上下文
  • SRE/运维自动化：大量日志和 JSON 需要交给 LLM 分析

⚠️ 需要评估

  • 无状态/分布式部署：CCR 本地存储需额外适配
  • 资源受限环境：Kompress-base 模型约 500MB
