## 项目背景

2025年9月，vLLM 官方团队发布了一个令人眼前一亮的扩展项目——**vLLM-Omni**。我们知道，vLLM 最初专为文本大语言模型设计，凭借 PagedAttention 和连续批处理成为 LLM 推理的事实标准。但当模型从"纯文本生成"扩展到"图像生成、视频生成、语音合成、任意模态相互转换"时，传统 vLLM 的单一自回归推理架构就力不从心了。

vLLM-Omni 的核心使命，是将 vLLM 的高性能推理能力扩展到**全模态（omni-modality）**场景——既支持传统 LLM 的自回归推理，也支持扩散模型（Diffusion Transformer）的并行推理，还能将两者编排成多阶段流水线，实现"语音→思考→语音"这类复杂的端到端多模态应用。

这个项目目前已有 4,692 颗星、903 个 fork，2026 年 3 月刚发布 0.18.0 稳定版，3 天前（2026-05-12）还有 push 更新，非常活跃。

## 核心功能

### 1. 全模态模型统一推理服务

vLLM-Omni 实现了**三大执行模式**的统一支持：

- **单阶段扩散推理**：用于文本到图像、图像到视频生成（如 Wan-AI/Wan2.2-I2V 模型），系统实例化 `DiffusionEngine` 处理基于 DiT 的并行去噪过程
- **单阶段 LLM / 多模态推理**：用于传统 LLM 或图像理解（如 Qwen2.5-Omni、Qwen-Image）
- **多阶段全模态流水线**：用于"任意到任意"复杂模态转换，例如 Qwen3-Omni 的 thinker→talker→code2wav 三阶段管道，`Orchestrator` 编排器负责管理跨阶段的生命周期和 KV 缓存传输

这意味着无论是文生图、视频生成、语音合成，还是更复杂的多模态组合，vLLM-Omni 都提供了统一的推理接口。

### 2. 扩散模型专用加速：TeaCache + Cache-DiT

vLLM-Omni 内置了专为扩散模型设计的缓存加速技术，在质量损失极小的前提下实现显著提速：

| 模型 | 任务 | Baseline | TeaCache 加速 | Cache-DiT 加速 |
|------|------|----------|---------------|---------------|
| Qwen-Image | 1024×1024 图像生成 | 20.0s | **1.91x** (10.47s) | **1.85x** (10.8s) |
| Qwen-Image-Edit | 图像编辑 | 51.5s | **1.47x** (35.0s) | **2.38x** (21.6s) |
| Qwen-Image-Edit (NPU) | 图像编辑 | 142.38s | — | **2.2x+** (64.07s) |

**TeaCache** 是原生钩子式自适应缓存，通过监控输入差异动态决定是否复用上一时间步的计算结果；**Cache-DiT** 则是一个完整的技术套件，包含 DBCache（基于残差差异的 Transformer 块输出缓存）、TaylorSeer（基于泰勒展开的预测特征技术）和 SCM（步数计算掩码）三个组件。

### 3. 全平台异构执行支持

vLLM-Omni 支持跨平台的动态硬件适配，包括 NVIDIA GPU（CUDA）、AMD GPU（ROCm）、华为昇腾 NPU 和 Intel XPU。这是 vLLM 家族中平台覆盖最广的成员。系统会自动检测运行环境，配置平台特定的 PyTorch Profiler Activity（`torch.profiler.ProfilerActivity.CUDA/NPU/XPU`）。

### 4. 先进的分布式并行策略

对于大规模部署，vLLM-Omni 提供多种并行化手段：

- **USP（Ulysses Sequence Parallel）**：对序列维度分片，专门优化视频生成等长上下文扩散任务，显著减少内存和延迟
- **VAE Patch Parallel**：VAE 编解码跨 GPU 并行，大幅降低视频生成中的编码瓶颈
- **Tensor/Pipeline/Expert 并行**：适用于超大规模扩散和 LLM 模型
- **CFG 并行**：Classifier-Free Guidance 并行，加速扩散推理

### 5. OpenAI 兼容 API + 多模态扩展

vLLM-Omni 提供与 OpenAI 兼容的 API 服务端点，扩展支持图像生成（Image Generation API）和语音 API（Speech API），支持 Chat Completions API 和 Python API（`Omni` 和 `OmniLLM` 两种离线/在线入口）。这使得现有应用无需修改代码即可接入多模态推理能力。

### 6. 完整的性能基准测试框架

内置 `diffusion_benchmark_serving.py` 基准测试工具，支持请求轨迹重放，自动采集 TTFT（首字延迟）、TPOT（每输出 token 耗时）、E2EL（端到端延迟）和峰值内存等指标，附有可视化性能仪表板。

## 技术亮点

### 1. 完全分解架构（Fully Disaggregated Architecture）

不同于传统将所有模态处理放在同一进程的方案，vLLM-Omni 通过 `OmniConnector` 实现跨阶段的数据流和动态资源分配，允许不同模态的处理使用不同的引擎和硬件，实现了真正的异构流水线抽象。

### 2. KV 缓存的多模态扩展

vLLM 标志性的 PagedAttention 在 vLLM-Omni 中扩展到多模态场景——`OmniARScheduler` 负责处理自回归调度和 KV 缓存的跨阶段传输，`Model Intermediate Buffers` 管理模型中间激活值，确保多阶段流水线中的状态高效传递。

### 3. FP8 量化与推理引擎集成

基于上游 vLLM v0.16.0+ 的量化基础设施，vLLM-Omni 支持 FP8 W8A8 量化（在 H100/B200 等支持原生 FP8 的 GPU 上可实现 1.6 倍吞吐量提升），以及 Int8 和 GGUF 格式。同时还支持 CPU 卸载和 VAE 分块（Tiling）以处理超大分辨率图像。

## 快速上手

### 安装

```bash
pip install vllm-omni
```

### 单阶段扩散模型推理（图像生成）

```python
from vllm_omni import Omni

model = Omni("Qwen/Qwen2.5-Omni-7B")
output = model.generate({"prompt": "A cyberpunk city at night"})
print(output)
```

### 多阶段流水线（Qwen3-Omni）

```python
from vllm_omni import AsyncOmni

model = AsyncOmni("Qwen/Qwen3-Omni-7B")
# thinker → talker → code2wav 三阶段自动编排
result = await model.chat({"messages": [{"role": "user", "content": "Hello"}]})
```

### OpenAI 兼容 API 服务

```bash
vllm-omni serve Qwen/Qwen2.5-Omni-7B --host 0.0.0.0 --port 8000
```

```bash
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "Qwen2.5-Omni-7B", "messages": [{"role": "user", "content": "Hello"}]}'
```

## 对比分析

在多模态推理框架赛道，vLLM-Omni 的主要竞争对手是 SGLang 和 llama.cpp：

| 维度 | **vLLM-Omni** | SGLang | llama.cpp |
|------|---------------|--------|-----------|
| 多模态支持 | ✅ 文本/图像/音频/视频/扩散 | ⚠️ 基础多模态 | ❌ 主要文本 |
| 扩散模型推理 | ✅ 完整支持 DiT/VAE | ❌ | ❌ |
| 多阶段流水线 | ✅ Orchestrator 编排 | ❌ | ❌ |
| TeaCache/Cache-DiT | ✅ 1.5-2.4x 加速 | ❌ | ❌ |
| 硬件平台 | CUDA/ROCm/NPU/XPU | NVIDIA/AMD | 全部 |
| 前缀缓存 | PagedAttention + APC | RadixAttention（75-95% 命中率） | ❌ |
| vLLM 基础推理性能 | 3,000-12,500 tok/s (H100) | ~16,200 tok/s (H100) | 80-100 tok/s (边缘) |
| 许可证 | Apache-2.0 | Apache-2.0 | MIT |
| 社区规模 | 成长中（vLLM 生态） | 较大 | 庞大 |

**核心差异**：SGLang 强在前缀缓存命中率和多轮对话场景，llama.cpp 强在边缘设备和本地部署。vLLM-Omni 的独特价值在于它是**唯一将扩散模型推理、多模态 LLM 和多阶段流水线整合在 vLLM 高性能推理基础设施之上的框架**，填补了从"文本推理"到"全模态服务"的关键空白。

对于已在使用 vLLM 的团队，vLLM-Omni 提供了一条低迁移成本的多模态扩展路径。

## 注意事项

1. vLLM-Omni 仍处于活跃开发期，API 可能在版本间有 Breaking Change
2. 扩散模型的缓存加速（TeaCache/Cache-DiT）对质量有一定影响（官方描述为"minimal/可忽略"），建议在关键场景中进行质量评估
3. 多阶段流水线的部署需要更多 GPU 资源，单卡场景建议使用单阶段模式
4. 华为 NPU 平台的支持在 0.18.0 版本已大幅改善，但部分功能仍在完善中
